## Design Specificity Verdict

**半身特异性：句子是这个产品的，形状不是。**

**LLM 判定（证据）**：概念词汇垂直贯通（世界包/角色卡/世界实例/时间线/冻结/激活/倍率/补卡/披露/已完成水位），顶栏「实例·角色·时间线」三元组就是这个世界模型本身；风险文案写在决定发生的那一刻并带后果（生成前报出模型名、地址、调用上限 3–6 次；补卡前说明加入语义与「失败或取消不会留下半个角色」；转换前说明「只在副本上做，原实例失败时一字不动」）——这是全页最懂自己的部分。反面：管理页是一个通用「select + input + button 行」列表（约 45 控件/8 组），把词换成客户/合同/订单就是发票工具；确认系统是浏览器原生 `window.confirm`（8 处）；**时间线——产品的核心对象——在界面上不可管理**（选择查看/归档/删除/从提交创建全缺）；聊天页放之四海而皆准。

**确定性扫描（B 路实测）**：CLI `detect.mjs --json desktop/index.html` = **`[]`，exit 0，无规则命中**；对 `desktop/src/*.ts`、`*.css`、构建产物亦然；`--no-config` 复跑一致，且仓库无 `.impeccable/config.json`（不是被 ignore 吞掉）——**根因**：`index.html` 里没有 `<link>` 到 CSS，样式由 `main.ts` 动态 import，文件级正则引擎看不到。阳性对照（手工植入 `Inter` + 回弹缓动）→ exit 2，证明检测器没空转。**渲染态扫描（注入技能自带 `detect-antipatterns-browser.js`）→ 2 条 computed-style 警告**：`overused-font: arial (38% of text)`、`flat-type-hierarchy: 11/12/13/13.3/14/16px (ratio 1.5:1)`。台账：81 个元素是 `Segoe UI`，**29 个是 `Arial` 且全部落在管理面按钮**（`#pane-manage .row` 的 `button` 没拿 `font: inherit`，同一规则只覆盖了 `input/select`）。

**两条扫的交叉验证（本次最重要的信号）**：A 从代码说「28 个按钮走 UA 默认外观」，B 从渲染量到「29 个元素 Arial + 13.3px 字号档」——**同一处缺陷的两种独立测量，互相证实**。反过来，B 明确标了两条**标签误报**：代码里从未出现 Arial（字体栈是 `Segoe UI/Microsoft YaHei/system-ui`），「品牌选了 Arial」的表述不成立；准确说法是「按钮没继承字体 → 回退到 UA 默认」。方法学结论：**CLI 干净 ≠ 渲染后干净**，这个项目以后跑 critique 要同时对构建产物做浏览器态扫描。

## Overall Impression

这是一个**诚实但没长完的操作面**。它的文案水平（风险披露、失败不毁数据、状态机 chip）超过大多数成品工具；它的仪表水平（反馈位置、进行中状态、破坏性闸门、无障碍）停在一个内部调试台的阶段。最大的机会不是「让它更好看」，而是**把已经存在于数据和文案里的诚实，搬到用户目光所在的地方**：动作的结果回到动作旁边、生成过程有仪表、时钟回到聊天页、破坏性操作离开它的目标 5 像素。

## What's Working

1. **顶栏状态 chip 是会自动消失的可执行状态机**（`coreStatusText` 六态各有文案：`存储不可用：<原因>；日志：<路径>`、`兼容性阻断：…核心整体只读；管理面仍可用（导出或按提示处理后「重启核心」）`），「重启核心」恰好在可恢复时出现、成功即消失——多数工具这一格只写「出错了」。
2. **风险文案写在决定发生的那一刻，并如实回报每条取消路径**（`已取消，未转换`、`已取消，未改动任何数据`、`已取消，未覆盖：<原因>`）——这是一个知道自己后果的界面。
3. **消息流拒绝伪造内容**：`排队中/生成中/已完成/生成失败/已作废/已固化` 逐条 chip，`投递：delivered` 单独一枚，系统通知用虚线气泡与角色气泡区分，多分段按批去重——spec §4「不用假消息冒充角色发言」在代码层面是真的。

## Priority Issues

**[P0-1] 首次运行没有引导，且空态自相矛盾** — `还没有对话。发一条消息试试。`（`main.ts:212`）与 chip `已就绪（还没有世界实例：先在管理面创建）`（`main.ts:510`）同屏互斥，新用户会往没有角色的占位会话里打字；管理页第一屏是 8 行版本号；唯一零知识的路径「AI 生成」藏在世界包组第二行且无标签。**改**：空态按状态分支（无实例 → 「创建你的第一个世界」直达并聚焦 `#pkg-brief`）；`world.instances.length===0` 时把版本表折叠/下移；`#manage-facts` 与 `关于·诊断` 重复，删一处。**命令**：`onboard`

**[P0-2] 管理页的反馈通道在动作点之外** — 约 1800px 长页（默认窗口 720px ≈ 3 屏）只有一个页顶 `#world-note` 承接全部 18 个动作的结果：滚到「运行」点激活 → 结果渲染在屏幕外 → 用户再点一次（激活幂等，同样机制用在「创建实例」上就会造出两个实例）。**改**：推广已有的行内槽（`#card-import-note`/`#clock-note`/`#draft-note`/`#role-note`）到全部 8 组，`#world-note` 只留跨组事件 + 点击锚定滚回。**命令**：`polish`

**[P0-3] 10 分钟的付费生成：没有仪表、没有取消、可以重入** — `GENERATE_TIMEOUT_MS = 600000`，进行中唯一反馈是 `AI 生成中，可能需要一两分钟…`（代码兑现不了这句），按钮不 disable、无 in-flight 守卫（连点即第二次调用），确认框已知上限 6 次却不显示「已用 2/6」。**改**：进行中禁用生成相关控件；状态行换成 `已用 1:23 / 上限 10:00 · 调用 2/6`（`runtime.budget` 已有计数）；把「一两分钟」改成实际量级；要么接取消 op，要么在确认框里诚实写「过程中无法取消」。**命令**：`harden`

**[P1-4] 破坏性操作在界面里，恢复能力在界面外** — 文案写着「撤回只能靠回滚」，但界面没有回滚、没有手动提交、没有时间线管理（归档/删除/改名/从提交创建都缺，spec §3.2 有）；而「删除」离实例 select 5px、原生 OK 即执行、明说不可撤销；恢复备份是全库替换且只给文件名。**改**：删除移出实例行，要求键入实例名确认，并在同处显示「将保留：世界包 / 角色卡 / 导出件」（真实存在的资产，降低误删恐惧）；要么补上回滚入口，要么把文案里对回滚的引用删掉。**命令**：`distill`（结构分层）→ 二次 `harden`（删除闸门）

**[P1-5] 管理页的视觉语言与壳的其他部分断裂** — 28 个按钮是 UA 默认外观（渲染态实测 29 个元素回退 Arial、字号档 13.3px），同排 select 是手工样式；`h3`(13px) 比正文(14px) 小，分组标题只靠灰度承载层级；`.row` 没有 `flex-wrap`，min 宽 820 时 5 控件行靠压缩硬塞；`--danger` 变量从未定义，`.muted.bad` 回退硬编码 `#b3261e`（暗色下实测 **2.87:1**，全应用错误文本都走这条规则）。**改**：一条基础 `button` 规则 + `.primary`（激活/创建实例/AI 生成）+ h3 改 13px/600 + `.row{flex-wrap:wrap}`、按钮 `flex-shrink:0`；`.muted.bad` 改用已存在的 `--bad`（暗色 `#d98b7f` 对 `#121212` ≈ 6.5:1）。**命令**：`layout` → `typeset`

**Alex（效率老手）**：① 三个 select 重复同一个 12 项文件名优先列表，WebView2 前缀匹配选项文本 → 输「格雷」无效；② 实例行没有创建时间（spec 要求有），「我周二建的那个」只能靠猜；③ 每次生成都要重敲文件名，无快捷键/无批量/无「复制实例」；④ 他一天要确认 20 次的「世界在不在跑、跑多快」只在管理页可见时轮询；⑤ 侧栏 `角色 · 时间线` 不含实例名 → 导入实例会造出两行一模一样的会话。

**Sam（无障碍）**：① `#status`/`#degrade` 没有 `role="status"`/`aria-live`，最关键的实时状态读屏一字不报（`#messages` 反而有）；② `renderMessages()` 每次 `innerHTML=""` 全量重建（一次问答至少 4 次）却挂着 `aria-live=polite` → 要么不停打断要么什么都不报；同时每次渲染强制 `scrollTop=scrollHeight`，读屏翻旧消息会被 status 信封拽回底部；③ `.nav:focus-visible` 只把边框从透明换成 `--border`（白底 1.43:1 / 暗底 1.65:1，远低于焦点指示 3:1），管理页 24 个按钮则完全靠浏览器默认焦点环；④ 10 个输入框只有 placeholder 当标签（值一填标签就消失），而 select 都写了 `aria-label`——作者知道有这回事；⑤ 值得表扬：错误不只靠颜色区分（文本本身就不同），spec §4 这条满足。

## Minor Observations

- **[建议升格 P1] 世界时钟放错了页，顶栏在打印内部 id**：spec §3.1 要求顶栏显示「仅当前查看且已激活的线」的世界时钟；实现里时钟只在管理页、只在可见时轮询，而顶栏最显眼处是 `实例名（in-xxxx）`（`#title` 是 ellipsis 截尾 → 窄窗先丢时间线名，保留内部 id）。
- **[建议升格 P1] 默认安装会被自己的顶栏判为异常**：未配记忆向量化 → chip 永久显示 `语义召回不可用（已降级为全文）`；设置页对应组只读，唯一的修法是手改配置文件——而全应用能「打开日志目录」「打开备份目录」，**唯独没有「打开配置目录」**。死胡同告警。
- `retryMessage` 在 `message.envId` 缺失时静默 return，而 `sendMessage` 抛错路径恰好不设 envId → 渲染出按不动的「重试」。
- 消息只有 `HH:MM` 无日期（历史每页 200 条，跨天消息分不出今天）。
- 三条 muted 提示通道（`#history-note`/`#notice-note`/`#composer-note`）常驻占位，空时也吃 2×12px gap。
- `.facts dd` 用 `word-break: break-all`（应 `overflow-wrap: anywhere`），会把 URL 与中文词组劈断。
- 侧栏「世界 / 时间线」组是 25% 的永久装饰（世界不可列出、时间线不可点，外观却与会话列表相同）。
- 600ms 的 `exit_pending` 轮询为一个一生命周期一次的事件常驻（纯损耗）。
- spec §3.3「外观」组在实现里不存在（跟随系统明暗由 CSS 完成）——文档/实现漂移，属可接受，建议在 spec 划掉。
- 两处值得保留的手笔：`#app` 行高钉死防长历史顶出输入栏；`loadMoreHistory` 用「距底部距离」锚定视口而非滚动位置。

## Questions to Consider

1. 如果「世界在自运行」是唯一承诺，为什么用户在 90% 时间所在的聊天页看不到世界在走？时钟、数据、轮询都在——只是被放在另一个 pane 里，且只在那个 pane 可见时才跑。你要的是「世界在跑」，还是「世界在跑并且你能感觉到」？
2. 删除实例离它的目标 5 像素，而回滚在界面上不存在，同时文案写着「撤回只能靠回滚」。接受这个代价，是因为用户只有一个、没有备份团队，还是因为分期顺序让破坏性路径先于恢复路径落地了？若是后者，这不是设计取舍，是排期泄漏成了产品性格。
3. 默认安装对你说的第一句话是「语义召回不可用（已降级为全文）」，且没有任何按钮能修它。这是有意的产品立场（创作者不必碰这些旋钮），还是「只读」被当成了「不用设计」的借口？前者的话这条 chip 该消失、降级该是默认状态的正常表述；后者的话，设置页缺的不是开关，而是「打开配置目录」与对齐 spec §3.3 的配置表单。
