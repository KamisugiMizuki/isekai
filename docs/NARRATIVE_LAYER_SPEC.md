# 叙事中介层（NARRATIVE_LAYER_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 事件与认知细则：[`EVENT_ENGINE_SPEC.md`](EVENT_ENGINE_SPEC.md)、[`WORLD_RUNTIME_SPEC.md`](WORLD_RUNTIME_SPEC.md) · 主动表达与投递：[`SESSION_CORE_SPEC.md`](SESSION_CORE_SPEC.md)
> 来源：2026-09-20 外部评估材料复核与 2026-09-21 设计收敛。
> 状态：设计规范，尚未实现。本文只定义叙事中介层的职责、边界和验收，不宣称现有主动发言链路已经具备本层能力。

## 一、设计判断

### 1.1 评估结论

附件对项目现状的主要判断成立：事件、生活线、认知、经历和记忆已经提供了可持续的世界素材，但“素材如何被角色选择、组织并主动讲述”仍缺少独立的中介契约。只依赖近期事件列表，会使对话偏向问答；只依赖提示词，则无法稳定保证跨轮回接、信息范围和事实来源。

新增本层是合理的，但附件中的几个说法需要收紧：

1. **叙事筛选器不筛选世界真相。** 它只从角色合法可见的经历、说法、当前处境和对话中生成叙事候选，不决定事件是否发生，不补造幕后原因。
2. **故事质量不成为在线事实闸门。** “有戏剧性”是候选排序信号，不是世界推进条件。没有故事感时，系统必须允许平淡、未解决或无可讲述的状态。
3. **角色叙事能动性不是新的自由规划器。** 主动讲述仍须经过既有的素材资格、节律、配额、表达取舍、会话固化和投递规则；它不能绕过认知边界或创建世界效果。
4. **认知一致性不能简化成词语检查。** “我听说”“可能”等词只能作为辅助证据；后验检查的核心是来源、获知时刻、说法身份、确定性和角色处境是否相容。
5. **叙事弧是派生观察，不是世界状态机。** 系统可以识别目标、阻碍、选择、代价和局部结果之间的关系，但不能为了补齐弧线强行制造转折、秘密或结局。

### 1.2 目标

本层的目标是让角色能够在合法认知范围内：

- 从多个近期或相关经历中选择一个值得分享的主题；
- 将已有片段组织成可追溯的微型叙事单元；
- 在适合的时机主动提起、回接、补充、保留或暂缓；
- 保持对同一经历的表达取舍跨轮连续；
- 让语言反映获知来源、时间距离、主观确信和当前处境；
- 在不影响世界事实推进的情况下，为用户提供可理解的故事入口。

### 1.3 非目标

本层不负责：

- 生成或修改世界事实、事件效果、角色卡、公理、制度或历法；
- 从实情层向角色或会话层提供秘密；
- 取代事件引擎、认知接口、记忆系统或主动消息投递；
- 建立通用任务系统、剧情任务列表、好感 / 信任 / 情绪数值；
- 保证每次对话都有悬念、冲突、转折或完整结局；
- 将内部候选、评分、知识图谱或故事状态展示给用户。

## 二、位置与责任边界

### 2.1 数据流

```text
世界运行 / 事件引擎
    -> 角色经历、已获知说法、当前处境、有效后果
    -> 认知过滤 + 记忆召回 + 最近对话
    -> 叙事中介层：候选、编织、择时、表达约束
    -> 会话核心：角色生成、后验校验、固化、投递
    -> 用户可见消息
```

叙事中介层是派生层。它读取一个一致的实例 / 时间线 / 角色水位快照，并输出候选或表达约束；不得把候选直接当成消息，也不得直接向通道发送文本。

### 2.2 责任表

| 问题 | 唯一责任方 |
|---|---|
| 事件是否发生、效果是否生效 | 世界运行层 / 事件引擎 |
| 角色是否看见、听说或亲历 | 认知接口 / 事件获知链 |
| 哪些经历可被召回 | 记忆系统与角色经历层 |
| 哪些素材值得考虑 | 叙事中介层 |
| 角色现在是否愿意讲、讲到什么程度 | 叙事中介层提供依据，角色表达取舍最终决定 |
| 是否生成并固化消息 | 会话核心 |
| 是否投递、是否重试 | 通道与会话核心 |

同一个事件可以没有叙事候选，也可以在不同角色或不同水位形成不同候选；这不改变事件本身。

## 三、叙事材料与叙事单元

### 3.1 输入材料

叙事中介层只接受经过作用域过滤的材料。每项材料至少带有：

- 所属实例、时间线、角色与一致水位；
- 来源类型与稳定引用：经历、已获知说法、有效后果、实际活动、角色打算、对话片段或合法记忆；
- 发生时刻、获知时刻和材料时效；
- 角色可知的主体、地点、目标和结果；
- 主观确信、来源渠道和是否亲历 / 转述；
- 是否允许主动表达，以及禁止暴露的范围。

实情文本、未获知事件、未来计划和仅供校验的幕后字段在进入本层前必须被过滤。

### 3.2 叙事候选

叙事候选是“可以考虑讲述什么”的派生记录，不是事实。候选可引用一个或多个材料，但每个引用必须能回溯到角色可知来源。

候选应表达：

| 内容 | 说明 |
|---|---|
| 主题 | 角色可能想讲的共同指涉对象或经历集合 |
| 入口 | 当前活动、刚完成经历、旧话题回接、后果变化或犹豫中的打算 |
| 关系 | 材料之间是连续、对照、因果、补充、质疑还是未能解释 |
| 角色立场 | 想分享、想倾诉、想求意见、想确认、想保留或暂不确定 |
| 叙事范围 | 允许使用的事实 / 说法 / 经历边界 |
| 时效 | 何时失去主动分享价值，或何时需重新计算 |
| 选择依据 | 角色性格、当前处境、表达取舍和已有承诺 |

候选不得携带“必须讲完”“必须揭示真相”或“用户需要被引导到某结论”等隐含义务。

### 3.3 叙事单元

叙事单元是一个或多个候选材料的组合视图，用于描述局部叙事是否已经形成可表达结构。建议结构为：

- 角色在意的对象或正在处理的事；
- 她实际知道的阻碍或不确定性；
- 已发生的选择、拒绝、行动或等待；
- 已产生的代价、余波或改变；
- 当前局部结果：达成、失败、持续、延期、放弃或仍未知；
- 每一项的来源和可表达范围。

叙事单元允许只有入口、阻碍或持续后果，不要求完整闭环。`未解决` 是合法结果，不是生成失败。

叙事单元是组合视图，不能作为新的世界事件、效果、记忆事实或角色承诺写回。

## 四、候选生成与筛选

### 4.1 生成原则

候选生成使用确定的输入边界和稳定引用；在相同实例、时间线、角色、水位、材料版本和规则版本下，不能因读取顺序产生不同候选集合。候选的语言摘要可以由模型生成，但摘要不拥有事实写权限。

候选至少经过以下检查：

1. 所有引用属于当前角色可见材料；
2. 所有时间关系不晚于当前水位，且没有把计划当经历；
3. 所有说法保留其来源身份，转述不变成亲历；
4. 组合关系没有把相关性自动写成因果；
5. 没有新增人物、死因、责任人、效果或幕后动机；
6. 没有绕过角色归档、成员资格、回滚和运行世代；
7. 候选可以被当前表达边界拒绝、延后或降级。

### 4.2 排序信号

排序只决定优先考虑顺序，不决定必须发送。起点信号如下：

1. 当前实际活动与刚完成经历；
2. 仍有效且角色已获知的后果；
3. 对旧话题具有合法共同指涉的补充或重新解释；
4. 角色自己的未竟打算与相关阻碍；
5. 近期重复出现、但尚未形成完整理解的材料；
6. 较旧但仍有角色表达价值的经历。

可使用分享价值、时效、表达适配度和重复惩罚进行排序。不得用“每日必须有故事”作为补偿信号。

### 4.3 编织

当多个候选材料可以合法互相解释时，编织器可以产出一个叙事单元，供会话生成器参考。编织只允许：

- 连接已有材料；
- 标出材料之间的时间、对照或因果引用；
- 保留矛盾、空白和不确定性；
- 选择角色当前愿意表达的范围。

编织禁止：

- 为了戏剧性增加冲突、秘密、责任人或转折；
- 把角色未知的真实原因填进解释；
- 把不同角色的私聊、经历或记忆拼接给当前角色；
- 把模型写出的漂亮句子反向登记为经历或事实。

## 五、角色叙事能动性

### 5.1 能动性来源

角色的主动讲述由以下既有状态共同决定：

- 合法可知材料与其分享价值；
- 角色当前活动、有效后果与短期反应；
- 角色性格单元与表达倾向；
- 对用户的联络处境与已有对话共同指涉；
- 已有打算、承诺、犹豫、拒绝或暂缓记录。

本层不新增一个“故事欲望”数值。若未来需要表达稳定的分享 / 倾诉倾向，应作为角色卡或性格单元的可追溯表达倾向进入既有模型，不能在本层另立平行人格状态。

### 5.2 表达取舍

角色对同一叙事单元可以：

- 完整讲述当前允许的部分；
- 只讲入口或局部结果；
- 以转述、猜测或保留说法表达；
- 先询问用户是否愿意听或是否能提供意见；
- 明确暂时不想讲；
- 在没有合适时机时不主动提起。

取舍跨轮保持，除非出现新的可知材料、处境变化、角色自身决定或合法的关系 / 对话依据。重复追问本身不提升访问权限，不自动解锁秘密。

### 5.3 与主动消息的关系

叙事中介层只能为现有主动消息链提供素材与表达约束：

- 仍受睡眠、角色归档、时间线状态、主动配额、目标 thread、投递状态和回滚失效约束；
- 不因候选存在就发送消息；
- 投递失败不撤销角色经历或获知；
- 同一叙事单元不得因重启、换通道或重试重复消费；
- 离线补算不补发已经错过的讲述时机；
- 没有合法候选时允许无主动消息。

## 六、生成与认知一致性

### 6.1 注入内容

会话层可将当前叙事单元注入为结构化表达约束，而不是把内部评分、候选池或实情文本原样放入提示。约束至少保留：

- 可以讲哪些来源；
- 哪些内容只能作为听说、观察或推测；
- 时间距离与当前处境；
- 角色愿意讲到哪一层；
- 必须保留的未知、矛盾和空白；
- 不得宣称已执行的打算或未发生的结果。

### 6.2 后验检查

后验检查检查生成文本与结构化约束是否相容，重点不是寻找固定措辞：

| 检查 | 失败示例 |
|---|---|
| 来源身份 | 只有转述材料，却写成“我亲眼看见” |
| 时间关系 | 三日前获知，却声称刚刚得知；未来计划被说成已完成 |
| 确信程度 | 明确未知或低确信材料被写成无依据的确定断言 |
| 范围 | 角色只知道局部，却补出幕后责任人或全局结论 |
| 关系类型 | 两件同时发生的事被写成已证实因果 |
| 处境 | 角色当前未醒、未到场或已归档，却声称正在现场行动 |
| 取舍 | 明确暂缓的内容被重复追问后自动泄漏 |

检查可以结合结构解析、来源引用和语言信号，但不得要求每条低确信表达都出现固定的“可能 / 也许”词。无法可靠判定时，优先保留文本并记录低置信审计结果，不能根据单个词误杀合法叙述。

### 6.3 失败处理

- 一次后验失败只允许有界重试；重试不能扩大可见材料范围；
- 仍失败时降级为不新增事实的模板、局部回答或明确保留；
- 后验失败不修改事件、获知、经历或记忆；
- 已固化文本不因新模型或新规则回写，审计只影响未来候选；
- 离线审计可以标记疑似不一致，但不能自动重写历史对话。

## 七、持久化、版本与回滚

### 7.1 派生记录

候选、叙事单元、表达取舍、消费记录和后验审计结果都属于实例 / 时间线 / 角色作用域的派生状态。它们必须带来源水位、规则版本和生成产物版本。

叙事记录的保存策略可分为：

- **必须持久化**：已固化消息引用的叙事单元、消费记账、表达取舍和审计结果；
- **可重建**：尚未被消息使用的候选缓存、排序分数和临时编织结果；
- **不可保存为叙事事实**：模型自由补写的未验证背景、秘密和新因果。

### 7.2 版本语义

- 回滚必须同时撤销被回滚水位之后的候选消费、表达取舍、叙事单元引用、未完成审计和未投递任务；
- 从旧提交分叉产生新线时只继承提交中已经固化的叙事状态；原线后续选择不回流；
- 生成迟到时检查运行世代、材料水位、角色成员资格和绑定版本；不匹配则作废；
- 同一材料可在新水位重新形成新候选，但不能把旧消息重新计为新近主动素材。

## 八、接口契约

| 上游 / 下游 | 输入 | 输出与保证 |
|---|---|---|
| 世界运行层 | 一致水位、活动、有效后果、角色状态 | 只读；不写世界事实 |
| 事件引擎 | 已固化事件、说法、获知与经历引用 | 只读取角色合法可见投影 |
| 记忆系统 | 作用域内记忆候选 | 不能跨角色 / 跨线放宽召回 |
| 会话核心 | 候选、叙事单元、表达约束 | 由会话核心决定是否生成、固化和投递 |
| 主动消息链 | 通过会话核心进入素材消费 | 不新增旁路投递，不改变统一配额 |
| 审计工具 | 已固化文本与其来源元数据 | 报告疑似不一致，不重写世界与历史 |

## 九、实施分期

### 9.1 P0：数据与边界

- 明确候选与叙事单元的作用域、来源引用和失效语义；
- 让主动素材能够表达“回接旧话题”和“多个经历组合”，仍沿用现有主动消息配额；
- 补齐行为测试：未获知材料、未来计划、转述 / 亲历、回滚和重启不越界。

### 9.2 P1：候选排序与有限编织

- 实现可重建候选；
- 支持入口、阻碍、选择、代价、局部结果的组合视图；
- 支持自然开场与主动消息使用叙事单元；
- 不引入新的人格数值、剧情任务状态或通道旁路。

### 9.3 P2：角色表达取舍与后验审计

- 让暂缓、部分讲述、转述和旧话题回接跨轮保持；
- 结构化记录表达范围与原因；
- 增加离线一致性审计和有限重试；
- 用真实模型回归验证表达质量，FakeLLM 只验证边界和事务语义。

### 9.4 暂不纳入

- 自动构建全局故事图谱的用户界面；
- 以“戏剧性评分”驱动世界事件；
- 自动补齐完整三幕结构；
- 角色之间因叙事层自动共享私聊；
- 独立的分享欲、信任或关系数值。

## 十、行为验收

1. 角色只能从自身在当前水位已经历 / 已获知的材料形成候选。
2. 未获知事件、实情文本、未来计划和幕后原因不会进入叙事单元或会话约束。
3. 同一事实以转述获知时，生成可以表达为“听说”，但不能声称亲历；低确信不因模型偏好变成确定真相。
4. 多个材料只有在共同指涉和关系依据存在时才编织；缺依据时保持并列、矛盾或未知。
5. 没有候选、候选过期或角色不愿讲时，系统可以平淡回答或不主动发送，不补造故事。
6. 角色可以只讲入口、暂缓或拒绝；反复追问不自动扩大认知权限。
7. 同一叙事单元在重启、重试、换通道和主动投递失败后不重复消费；投递失败不撤销经历。
8. 回滚撤销该水位之后的叙事选择、消费记录和派生单元；从旧提交分叉不改变原线。
9. 叙事层不写入事件、效果、计划、公理、角色卡或未经验证的记忆事实。
10. 后验检查能识别来源、时间、范围、关系和处境矛盾；不依赖固定关键词作为唯一判据。
11. 后验失败不扩大上下文、不改写世界状态；重试耗尽后降级为不新增事实的表达。
12. 在同一固定输入下，连续推进与分批补算得到等价的候选引用和事实边界；语言可不同，但不能越权。
13. 至少一个真实模型回归样例能表现“发生了什么 / 角色知道什么 / 她愿意讲什么”三者不同；该样例不把故事质量当作世界事实正确性的证明。

## 十一、与现有 SPEC 的修改边界

- `EVENT_ENGINE_SPEC.md` 继续负责事实、说法、获知与素材资格；叙事中介层只消费其角色可见输出。
- `WORLD_RUNTIME_SPEC.md` 继续负责一致水位、角色处境、短期反应、打算、提交与回滚；本层不复制这些状态。
- `SESSION_CORE_SPEC.md` 继续负责表达生成、主动配额、固化、投递与失败恢复；本层不直接发送消息。
- `MEMORY_SPEC.md` 继续负责记忆写入与召回；叙事候选引用记忆，但不把候选自动写成规范记忆。
- `DESIGN.md` 只需登记本模块地图与阶段关系，不把本层能力写成已有阶段的完成证明。
