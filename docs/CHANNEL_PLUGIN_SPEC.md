# 通道插件层（CHANNEL_PLUGIN_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「通道插件层」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分（V1.9 收敛内容）；未决细则在模块设计阶段补齐。

本模块职责：统一消息协议、插件式通道、第三方插件开放与进程隔离、内建聊天窗口。
范围：桌面端通道插件层；安卓端内建实现见 `ANDROID_SPEC.md`。

## 一、架构原则：通道与内容生成解耦

聊天通道与聊天内容生成完全解耦。核心逻辑不感知消息来自何处，通道适配器不感知内容如何生成。

```
┌──────────────────────────────────────────────┐
│              通道适配层（可插拔）              │
│  内建聊天界面 │ QQ 适配器 │ Discord 适配器 │ … │
└──────────────────┬───────────────────────────┘
                   │ 统一消息协议
                   ▼
┌──────────────────────────────────────────────┐
│              会话核心层（稳定）                │
│  会话管理 · 消息路由 · 角色绑定 · 世界绑定      │
└──────────────────┬───────────────────────────┘
                   │ 查询角色认知 / 请求生成
                   ▼
┌──────────────────────────────────────────────┐
│              世界运行层（核心）                │
│  世界时钟 · 角色状态 · 事件日志 · 认知接口      │
└──────────────────┬───────────────────────────┘
                   │ 加载 / 修改 / 版本管理
                   ▼
┌──────────────────────────────────────────────┐
│              世界设定层（世界包 + 版本）        │
└──────────────────────────────────────────────┘
```

#### 统一消息协议

所有通道使用同一套消息协议。通道适配器只做两件事：

- 将外部消息转为统一协议
- 将统一协议回复转为外部消息

这意味着：

- 内建聊天界面是一种适配器
- QQ 是一种适配器
- Discord 是一种适配器
- 未来任何通道都是适配器

#### 通道切换

用户可在同一会话中快速切换通道。会话状态、世界状态、角色状态与通道无关。切换通道不中断对话，不重置世界，不改变角色认知。

## 二、插件式通道

| 特性 | 说明 |
|---|---|
| 插件独立 | 每个通道适配器是独立插件，可独立安装、启用、停用 |
| 协议统一 | 所有插件遵循同一套消息协议 |
| 核心无感 | 会话核心不感知消息来自哪个通道 |
| 可并行 | 同一会话可同时通过多个通道收发 |
| 可替换 | 停用某插件不影响其他插件和会话状态 |

#### 插件职责边界

通道插件只做两件事：

- 将外部消息转为统一协议
- 将统一协议回复转为外部消息

插件不参与：内容生成、世界状态查询、角色认知、时间线管理。

#### 内建聊天界面

内建聊天界面本身也是一个插件，只是随项目默认提供。它与其他通道插件地位相同，可被停用或替换。

## 三、第三方开放与接口文档

#### 开放性

- 通道插件允许第三方开发。
- 项目提供**插件接口文档**。
- 项目提供**参考实现**（内建聊天插件即为参考）。
- 第三方插件可独立发布、安装、启用、停用。

#### 接口文档内容

接口文档应包含：

- 统一消息协议规范
- 插件生命周期接口
- 消息收发接口
- 错误处理约定
- 认证与授权约定（如涉及）
- 版本兼容性说明
- 示例插件

#### 核心与插件的关系

- 核心不依赖任何具体插件。
- 内建聊天插件与其他插件地位相同。
- 第三方插件不修改核心代码。
- 插件崩溃不影响核心与其他插件。

## 四、进程隔离与版本兼容

#### 约束方式

- **接口约束 + 进程隔离。**
- 第三方插件作为**独立进程**运行。
- 插件崩溃不影响主程序。
- 接口版本变化时提示用户，尝试运行，报错则反馈并停止插件进程。

#### 进程隔离

| 特性 | 说明 |
|---|---|
| 独立进程 | 每个第三方插件运行在独立进程中 |
| 崩溃隔离 | 插件进程崩溃不影响核心进程 |
| 通信方式 | 插件与核心通过进程间通信交互 |
| 生命周期 | 核心管理插件进程的启动、停止、重启 |
| 资源限制 | 可对插件进程施加资源限制（具体实现阶段确定） |

#### 版本兼容策略

当核心接口版本发生变化时：

1. **向用户提示**：该插件依赖旧接口版本，可能与当前版本不兼容。
2. **尝试运行插件**。
3. **若无报错信息**：正常使用。
4. **若有报错信息**：
   - 将报错信息反馈给用户。
   - 停止该插件进程。
   - 不影响核心与其他插件。

#### 接口文档

- 向第三方开发者提供接口文档。
- 文档包含：统一消息协议、插件生命周期接口、消息收发接口、错误处理约定、版本兼容性说明、示例插件。
- 接口版本号显式声明，便于兼容性判断。

#### 内建聊天窗口的地位

- 内建聊天窗口与其他插件在**功能地位**上相同（遵循同一套消息协议）。
- 进程归属不同：内建聊天窗口属于核心进程；第三方插件运行在独立进程中。
- 内建聊天窗口作为参考实现，展示接口用法。

## 五、插件进程间通信

#### 进程间通信

- 进程间通信机制在**具体实现时确定**。
- 总设计层面不锁定具体机制。
- 候选机制：标准输入输出、本地 socket、其他。

## 六、内建聊天窗口

- 内建聊天窗口作为**核心进程的一部分**。
- 内建聊天窗口不运行在独立进程中。
- 内建聊天窗口作为参考实现，展示接口用法。
- 第三方插件仍运行在独立进程中。
- 内建聊天窗口与第三方插件地位在功能上相同，但在进程归属上不同。

#### 设计含义

- 核心进程包含：会话核心、世界运行层、内建聊天窗口。
- 第三方插件进程独立于核心进程。
- 内建聊天窗口的稳定性由核心保证。
- 第三方插件的稳定性由插件自身与隔离机制保证。

#### 当前形态

- 内建聊天窗口作为核心进程的一部分。
- 遵循统一消息协议。
- 作为参考实现。

#### 拆分后形态

- 架构上预留可拆为独立插件。
- 若拆分，桌面端仅保留插件版本，不再保留内建版本。
- 拆分后的插件与核心进程兼容。

#### 安卓端处理

- 安卓端始终使用内建聊天实现。
- 安卓端内建实现遵循统一消息协议。
- 安卓端内建实现保持独立，不随桌面端拆分而同步拆分。
- 两端的内建实现可以共享代码，但作为独立模块维护。

### 6.1 功能范围

新项目自带聊天功能，包含：

- 会话界面
- 角色选择
- 世界切换
- 历史记录
- 世界时间显示
- 角色状态提示

外部通道（如 QQ、Discord）未来可作为适配器，但不是核心依赖。
