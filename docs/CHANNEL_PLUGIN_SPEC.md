# 通道插件层（CHANNEL_PLUGIN_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「通道插件层」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分；同日模块深化（决策：核心 Python + Tauri 壳；首批只做内建聊天与协议，外部通道后置；插件 = 协议即接口）。

## 一、模块职责与边界

**职责**：消息出入口的承载与治理——统一消息协议（UMP）、通道适配器（内建窗口 / 外部通道）、插件宿主与进程隔离、插件生命周期与版本兼容。

**范围**：桌面端通道插件层 + UMP 协议本身（两端共用）；安卓端内建实现见 `ANDROID_SPEC.md`。

**边界**（承总设计）：
- 通道与内容生成完全解耦：核心逻辑不感知消息来自何处，通道不感知内容如何生成。
- 插件不参与：内容生成、世界状态查询、角色认知、时间线管理。
- 核心不依赖任何具体插件；停用某插件不影响其他插件与会话状态。
- **关键不变量：插件只接触消息流。** UMP 中不出现世界 / 会话 / 时间线的内部标识；世界对插件不可见。

```
┌─────────────────────────────────┐
│ 通道层（可插拔）                 │
│ 内建聊天窗口 │ 外部通道插件（后置）│
└───────────────┬─────────────────┘
                │ 统一消息协议（UMP）
                ▼
┌─────────────────────────────────┐
│ 核心进程（会话核心 · 世界运行 · 世界设定）
└─────────────────────────────────┘
```

## 二、统一消息协议（UMP）

### 2.1 设计原则
- 只做两件事：把外部消息译为统一信封；把统一信封译回外部消息。
- 与承载无关：同一套信封可运行在子进程 stdio 上，也可运行在本地 WebSocket 上。
- 与内容无关：不携带生成过程、世界内部数据或提示词。

### 2.2 信封
```json
{
  "ump": "1.0",
  "type": "user_message",
  "id": "e-8f3a1c",              // 信封 id：去重与引用
  "ts": 1789803972.99,           // 发送侧时间戳（现实时间）
  "thread": {"id": "dm-42"},     // 通道侧会话载体（不透明字符串）
  "payload": { }                 // 按 type 定义
}
```
- 一次连接 = 一个通道实例；`thread` 由通道生成并保持稳定（如某个外部对话），核心维护 thread ↔ 会话的绑定（见 §八）。
- 去重：`id` 重复即丢弃。顺序：同 thread 内保序；跨 thread 无顺序承诺。

### 2.3 消息类型（v1 基线）
| 方向 | type | 用途 |
|---|---|---|
| 通道 → 核心 | `hello` | 握手：声明协议版本与能力 |
| 核心 → 通道 | `hello_ack` | 握手确认：核心版本、生效策略 |
| 通道 → 核心 | `user_message` | 用户消息（v1 只承载文本） |
| 核心 → 通道 | `reply` | 角色回复（分段数组） |
| 核心 → 通道 | `status` | 状态提示（思考中 / 空闲 / 异常），仅发给声明支持的通道 |
| 双向 | `error` | 错误信封 |
| 双向 | `ping` / `pong` | 心跳 |

`hello` 能力声明示例：
```json
{"channel": {"id": "builtin", "name": "内建聊天窗口", "version": "0.1.0"},
 "capabilities": {"segments": true, "status": true, "max_text_len": 4000, "max_parts": 10}}
```
- 核心按能力裁剪输出：超长回复由核心拆分 / 多条发送；切分逻辑不在通道侧。
- `reply.payload`：`{"reply_to": "e-…", "parts": [{"text": "…"}]}`。

### 2.4 承载（transport）
| 场景 | 承载 | 说明 |
|---|---|---|
| 插件子进程 | stdio，换行分隔 JSON（NDJSON） | 核心 spawn 插件；stdin/stdout = 协议流；stderr = 插件日志（核心收集） |
| 内建窗口 / 壳 | 本地回环 WebSocket（JSON 帧，同一信封） | 核心监听 `127.0.0.1` 随机端口；启动时把端点与一次性令牌交给壳 |

选型理由：stdio 对任意语言零依赖、无端口冲突、生命周期与核心天然绑定；WebSocket 是 WebView 原生唯一可用通道。

### 2.5 通道切换
用户可在同一会话中切换通道。会话状态、世界状态、角色状态与通道无关；切换不中断对话、不重置世界、不改变角色认知。

## 三、插件模型

### 3.1 插件形态
- 一个插件 = 独立进程 + 一份清单（manifest）；语言不限（协议即接口）。
- 目录制安装：每插件一个目录（manifest + 代码 + 资源）。
```json
// manifest.json
{"id": "my-channel", "name": "某通道", "version": "0.1.0",
 "ump": "1.x", "entry": ["python", "main.py"],
 "description": "…", "author": "…"}
```

### 3.2 生命周期
状态机：`已安装 → 已启用 → 运行中 ⇄ 已停止`；异常退出 → `失败`。

| 事件 | 核心行为 |
|---|---|
| 安装 | 扫描插件目录，校验 manifest（含 ump 版本），登记 |
| 启用 | spawn 进程 → 等待 `hello` 握手 |
| 停用 | 关闭连接 → 终止进程 |
| 崩溃 / 无响应 | 标记「失败」，记录日志，提示用户；**不自动重启**（避免崩溃循环），由用户手动重启 |
| 核心退出 | 插件随核心一并停止 |

### 3.3 进程隔离
| 特性 | 说明 |
|---|---|
| 独立进程 | 每个插件运行在独立进程中 |
| 崩溃隔离 | 插件崩溃不影响核心与其他插件 |
| 通信 | 仅通过 UMP（stdio） |
| 生命周期 | 核心管理启动、停止、重启 |
| 资源限制 | v1 不强制（进程隔离已是边界）；心跳超时判定「失败」；CPU / 内存限制后置 |

### 3.4 版本兼容策略
核心接口版本变化时：① 提示用户该插件依赖旧协议版本；② 尝试运行；③ 无报错 → 正常使用；有报错 → 反馈用户 + 停止该插件进程，不影响核心与其他插件。

### 3.5 安全与信任边界
- 插件是用户自选安装、自行信任的代码；v1 不做权限沙箱。
- 协议面保证插件看不到世界内部（UMP 无世界字段）；插件不修改核心、不可写世界实例数据。
- 插件日志与收发记录进入核心日志，便于排查。

## 四、内建聊天窗口

- **逻辑归属**：核心进程的一部分；UI 由 Tauri 壳承载。
- **接入方式**：窗口以**通道客户端**身份连接核心（本地 WebSocket），走同一套 UMP —— 内建窗口是协议的第一个（参考）实现；与第三方插件功能地位相同、进程归属不同。
- **拆分预留**：架构上可改为插件形态；桌面端拆分后仅保留插件版本。
- **安卓端**：始终内建、独立维护、不随桌面端拆分（见 `ANDROID_SPEC.md`）。
- **能力**：完整能力集（多分段、状态提示），作为能力上限的参考实现。
- **功能范围**：会话界面、角色选择、世界切换、历史记录、世界时间显示、角色状态提示。世界时钟 / 时间线管理等数据面不经过通道协议（由相应模块的管理接口提供）。

## 五、壳与核心的接线（桌面端）

- 壳（Tauri）：窗口、拉起 Python 核心（sidecar）、下发端点与一次性令牌。
- 核心：会话、世界运行时、UMP 服务端。
- 其余管理接口（世界 / 时间线 / 设置）属对应模块的接口面，不在本文。

## 六、错误模型与可观测性

| 类别 | 例 | 处理 |
|---|---|---|
| 协议错误 | 版本不匹配、JSON 不可解析 | 断连 + 记录 + 提示（插件）；内建窗口自动重连 |
| 通道侧发送失败 | 外部平台拒绝、网络失败 | 通道上报 `error`（带 retryable）；核心记录，不无限重试 |
| 核心侧不可用 | 会话不存在、内部错误 | `error` 返回通道；不重试 |

- 所有 `error` 信封带：`code`、`message`、`retryable`、`ref`（相关信封 id）。
- 可观测性：插件 stderr → 核心统一日志；核心记录每通道的收发流水（供排查）。

## 七、实施分期（本模块）

- **阶段 0（与总设计对齐）**：UMP v1 + 内建聊天窗口链路（Tauri 壳 ↔ Python 核心）+ 心跳与错误模型。
- **后置（随外部通道需求启用）**：插件宿主（插件目录 / 进程管理 / 生命周期）、第三方开放交付物（协议规范、生命周期接口、消息收发接口、错误处理约定、版本兼容说明、示例插件）。QQ / Discord 等外部通道即这类插件的实例。
- **更后置**：附件 / 富媒体 / 流式表达；资源限制；插件分发渠道（v1 手工目录安装即可）。

## 八、与其它模块的接口

| 对方模块 | 接口面 |
|---|---|
| 会话核心层 | thread ↔ 会话绑定、消息路由；通道切换不改会话状态 |
| 世界运行层 | 无直接接口（世界对插件不可见） |
| 安卓端 | 内建实现遵循同一 UMP（见 `ANDROID_SPEC.md`） |
