# Writing Assistant 模块设计

> 状态：设计规范草案 v1.0，未实现声明。
> 定位：面向小说创作的上层叙事约束编排模块；GM 辅助是其一种应用方式。
> 依赖：[`../worldruntime/DESIGN.md`](../worldruntime/DESIGN.md)、[`../trpg-rules/TRPG_RULE_COMMON_MODULE_SPEC.md`](../trpg-rules/TRPG_RULE_COMMON_MODULE_SPEC.md)。
> 相关评价：[`../trpg-rules/TRPG_GM_USER_EVALUATION_DRAFT.md`](../trpg-rules/TRPG_GM_USER_EVALUATION_DRAFT.md)、[`../oc-story/USER_PERSPECTIVE_EVALUATION_DRAFT.md`](../oc-story/USER_PERSPECTIVE_EVALUATION_DRAFT.md)。

## 一、定位

Writing Assistant 是面向小说创作的上层叙事约束编排模块，负责把作者给定的故事大纲、创作意图和观察视角转换成可执行的叙事约束，并在 WorldRuntime 变化后返回符合视角的信息和候选表达。

GM 辅助不是它的首要设计目标，而是同一套“大纲约束 + 世界观察 + 候选编排”能力在 TRPG 主持场景中的一种应用方式。小说作者是默认用户；GM 使用时需要额外接入玩家视角、规则裁定和主持提交权限。


| 模式 | 用户 | 输入 | 输出 |
|---|---|---|---|
| GM 辅助 | GM | 故事大纲、场景安排、直接变化、主持要求 | 玩家观察到的情况、场景候选、待确认世界变化 |
| 小说写作辅助 | 作者 | 故事大纲、章节目标、人物安排、写作指令 | 可选情节推进、角色视角材料、场景草稿 |

两种模式共享大纲约束、世界观察和候选编排，但不共享提交权限：GM 可以在授权范围内提交主持声明；小说写作辅助默认只生成候选，不直接改写持续世界。

Writing Assistant 不是 WorldRuntime 的第二个事实层，也不是自动保证故事“按大纲发生”的强制引擎。它通过约束、偏离检测、候选提议和显式批准帮助故事靠近大纲；玩家选择、角色行为、规则裁定和世界后果仍可能导致偏离。

## 二、与三个相邻模块的关系

```text
OC 故事层
  -> 用户不提供故事大纲，消费角色合法视图并进行联络

TRPG 规则层
  -> 玩家提供行动，规则插件裁定，公共模块提交世界后果

Writing Assistant
  -> 创作者提供大纲和叙事约束，观察世界 / 场景结果，提出或提交下一步
```

Writing Assistant 与 OC 故事层都可能产生自然语言表达，但入口语义不同：OC 是“角色向用户表达已经存在的生活”；Writing Assistant 是“创作者编排故事目标并观察可行的推进”。不能用角色对话入口偷偷解释创作者指令。

## 三、大纲模型

大纲不是一串强制事件列表，而是分层约束：

| 层级 | 内容 | 默认强度 |
|---|---|---|
| 主题约束 | 作品关注的冲突、主题、情绪方向 | 软约束 |
| 必达节点 | 必须发生或必须被揭示的关键节点 | 硬约束 |
| 禁止事项 | 不得发生的事实、关系或结局 | 硬约束 |
| 角色弧线 | 角色需要面对的选择和变化方向 | 中约束 |
| 节奏目标 | 场景阶段、章节目标、悬念释放窗口 | 中约束 |
| 可变素材 | 地点、遭遇、对白、过场和实现方式 | 软约束 |

每条大纲条目都要有：

- 稳定标识；
- 约束类型和强度；
- 适用范围：世界、时间线、章节、场景或角色；
- 前置条件；
- 成功判据；
- 允许的替代路径；
- 当前状态：未开始、进行中、已达成、已偏离、已放弃。

“主角必须在第三章知道真相”是节点约束；“第三章必须在车站通过某句对白知道真相”是过度指定。系统优先守住叙事功能和因果，不强行复现某个表面场景。

## 四、故事状态与世界事实分离

Writing Assistant 维护的是大纲状态和候选，不拥有世界事实：

```text
故事大纲 / 创作者指令
  -> 约束状态与当前目标
  -> 读取 WorldRuntime 合法视图
  -> 检查达成、偏离、冲突和缺口
  -> 生成候选推进 / 观察材料
  -> 创作者确认
  -> 通过既有行动或 GM 声明路径提交 WorldRuntime
```

大纲说“守卫会离开”不等于守卫已经离开；大纲说“角色将失去信任”不等于关系已改变。只有明确提交并通过 WorldRuntime 校验的变化才会成为世界事实。

## 五、GM 辅助模式

### 5.1 GM 直接输入

GM 可以输入三种不同内容：

| 输入 | 处理 |
|---|---|
| 世界变化声明 | 转成 `source=gm_declaration` 的待提交后果 |
| 故事意图 | 生成候选行动 / 场景推进，不直接改世界 |
| 玩家观察请求 | 根据当前角色视角生成可见情况，不新增事实 |

例如“城门已被毁”是世界变化声明；“我希望这一章让玩家感到被追踪”是故事意图；“玩家现在看到什么”是观察请求。三者不可混为一条自由文本命令。

### 5.2 GM 输出

GM 辅助输出分为三层：

1. **玩家观察层**：玩家角色在当前视角下看到、听到、推断或不知道什么；
2. **主持依据层**：哪些世界事实、认知边界和大纲条目支持这个观察；
3. **下一步编排层**：候选场景、NPC 反应、可能推进和需要 GM 决定的分歧。

玩家观察层可直接用于主持；主持依据层默认只给 GM；下一步编排层必须标注候选，不得伪装成已发生。

### 5.3 GM 的控制点

- 接受或修改故事候选；
- 确认直接世界变化；
- 选择玩家观察视角；
- 调整大纲条目的软约束；
- 暂停推进并补充创作条件；
- 创建分支试演不同后果。

硬约束冲突时系统应阻止或明确要求 GM 选择“改大纲 / 改世界 / 接受偏离”，不能自动牺牲任一方并继续讲下去。

## 六、小说写作辅助模式

小说模式默认运行在草稿世界或只读投影中。作者可以：

- 输入章节目标、人物焦点和叙事视角；
- 查看角色按自身认知能观察到的素材；
- 让系统提出多条情节推进和冲突后果；
- 固定采用某条候选，形成章节草稿；
- 在提交前比较不同分支；
- 把确定的世界事件 / 角色经历提交到作品时间线。

小说模式生成的对白、场景描写和章节草稿是表达产物，不会自动成为世界事实。作者确认的“作品中采用”仍要区分：仅锁定文本，还是同时向作品世界提交事件和角色经历。

## 七、偏离检测

偏离检查分三类：

- **事实偏离**：候选或新提交与已固化世界事实冲突；
- **因果偏离**：结果缺少前置条件、跳过必要变化或破坏时间顺序；
- **大纲偏离**：未达成必达节点、触发禁止事项或角色弧线长期离轨。

偏离不是一律错误：创作者可以明确接受偏离并把大纲条目标记为替代路径、改写或放弃。系统要记录决定及其原因，不能静默把偏离重新解释成达成。

## 八、时间线与分支

Writing Assistant 的大纲状态绑定实例与时间线。试演候选优先在临时分支中运行；被接受后合并或转为当前线提交。生成文本草稿可以脱离世界分支存在，但引用的事实必须标注来源水位。

回滚世界不自动回滚作者已经导出的文本；文本回滚也不自动回滚世界。两者需要分别确认，避免“删掉一段草稿”意外改变持续世界。

## 九、与 TRPG 的结合

GM 辅助模式可以接在 TRPG 规则层外侧：

```text
玩家行动
  -> TRPG 规则独占转接插件
  -> TRPG 规则共用模块
  -> WorldRuntime 提交
  -> Writing Assistant 读取新状态
  -> 输出玩家观察与大纲偏离
```

GM 的直接变化则绕过具体骰点，但仍进入 TRPG 规则共用模块的结构化后果与 WorldRuntime 校验：

```text
GM 直接变化
  -> Writing Assistant 分类与结构化
  -> source=gm_declaration
  -> TRPG 规则共用模块
  -> WorldRuntime 提交
```

这样 GM 辅助不会与 OC 故事层重合：OC 消费角色表达；Writing Assistant 编排创作者目标并维护大纲；TRPG 规则层维护行动与裁定；WorldRuntime 统一拥有事实。

## 十、设计不变式

1. 大纲是约束和目标，不是已经发生的事实。
2. Writing Assistant 不拥有世界真值。
3. 玩家观察只能来自对应视角能获得的世界材料。
4. 候选、草稿和主持建议必须标明未提交状态。
5. GM 直接声明与规则裁定走不同来源，但共享结构化后果校验与 WorldRuntime 提交。
6. 大纲偏离可以被明确接受，不能被静默掩盖。
7. 试演优先走分支；接受、合并、回滚和文本导出分别确认。
8. 小说模式默认不直接修改持续世界。
9. OC 故事层不承担大纲维护，Writing Assistant 不承担普通角色联络。

## 十一、推荐分期

### W0：只读大纲与观察

建立大纲、绑定角色 / 时间线、读取合法视图、输出玩家观察和偏离提示。不提交世界变化。

### W1：GM 直接变化

支持结构化 GM 声明、WorldRuntime 校验、玩家视角观察和撤回前的待确认状态。覆盖事实冲突、认知隔离和版本冲突。

### W2：TRPG GM 辅助

接入规则共用模块，读取玩家行动结果，维护大纲状态，生成场景候选和主持依据。规则裁定与 GM 声明都保留来源。

### W3：小说写作辅助

加入草稿分支、章节目标、候选比较、文本锁定和世界提交分离。先做单作者，不做多人协作和自动出版。

## 十二、行为验收

- 大纲条目能区分硬约束、软约束、必达节点、禁止事项和可变素材。
- 大纲未达成时，系统能指出缺口而不凭空制造世界事实。
- GM 输入直接变化时，系统能区分声明、意图和观察请求。
- GM 确认结构化变化后，WorldRuntime 才固化世界后果。
- 输出给 GM 的玩家观察不泄露角色不应知道的事实。
- 玩家行动结果能更新大纲状态，但不能让模型把规则裁定改写成大纲已达成。
- 大纲冲突会阻止或要求明确选择，不自动吞掉冲突。
- 分支试演不会污染主线；文本导出和世界回滚彼此独立。
- 小说模式候选只读、不提交；作者明确确认后才能进入作品时间线。
