## 一、模块职责与范围

**职责**：世界包结构与双轨内容、共享生成器、角色装配、实例创建与锁定、多世界、整体导入导出。

**范围外**：运行与版本机制、对话生成、通道实现。用户修改已运行世界的事件路径见 `EVENT_ENGINE_SPEC.md` §八。

## 二、世界包

### 2.1 内容范围

世界包是可修改、可反复加载、仅保留最新版的**模板**，包含：

- 世界背景、公理、体裁与边界；
- 历法：纪元、日长、月 / 周体系、时段及可选季节；
- 环境事实（按题材可选）：可被角色感知的天气、光照、温度、声响或类似状态；每类声明单位、取值域、变化来源、适用区域与角色可观察条件；不默认引入气象或空间模拟；
- 地理与活动区域的叙事描述，不含几何 / 路网；
- 社会、文化、信仰、科技 / 魔法及命名语汇；
- 制度与职责：重要组织的职权、持续义务与有效条件，职位的延续、失效、空缺与承接规则；
- 文化惯例：重要惯例的适用群体、当前做法、形成依据与允许变化范围；
- 历史与当前局势的实情 / 公共叙事双轨；
- 史料（传本）：作品归属与传本标识、贡献者列表（著 / 编 / 校 / 整理 + 各自时期）、止笔与成书时刻、覆盖区间、体裁与立场；
- 种族与寿命：种族表声明寿命带（按历法年；特殊寿命以极长 / 无上界表达），个体可覆盖；角色与登记实体的出生 / 死亡由此确定；角色寿终后的行为由世界包声明（默认归档）；
- 信息渠道、来源与可接触条件；
- 世界事件源、支持的效果模板与**必填密度档**；
- 日常生活的世界级模板、角色类型与角色模板；
- 与用户双向联络的解释及限制；
- 初始事件、传闻、未解之谜与初始世界时刻。

包只含声明式数据，不携带可执行脚本、模型权重或需运行任意代码才能加载的对象。

### 2.2 双轨内容

| 层 | 内容与消费边界 |
|---|---|
| 实情层 | 创作者真值及世界公理，供运行与一致性校验；不得直接注入角色生成 |
| 公共叙事层 | 可被传播、观察或转述的版本集合，允许真实、片面或错误；每条仍有来源与认知条件 |

- 「公共」不等于所有角色皆可访问。认知接口按角色设定、经历、渠道及获知时间过滤。
- 亲历通过观察投影形成该角色可见片段；允许逐步发现秘密，但不能一次把幕后真相交给角色。
- 双轨的**初始设定快照锁定**；新事件与新说法作为运行状态演化，不回写模板或改写历史快照。
- 实情、说法、实体和渠道使用稳定引用；传闻可以指向一个被否定的命题，不要求每条说法都等于真相。
- **登记实体（名册）**：创作期声明，或创建期回填按规则生成的人物 / 组织 / 地点 / 物件；有稳定身份，不以显示名作主键。登记不代表它是可聊天角色，也不保证任何角色已知。
- **登记门槛按用途**：作为事实参与者、独立效果目标、角色背景 / 初态引用，或需跨条目稳定指涉的世界实在对象，必须在册；匿名但独立参与因果的人物同样在册，纯叙述泛称与标签不逐人建档。
- **制度状态附着于登记实体**：政令、资格、义务与职位延续按组织 / 职位声明，不随个人消失；空缺期间哪些事务继续、哪些暂停须可判定。组织仍是名册对象，不因此获得可聊天角色资格。
- **说法中的指称不等于事实实体**：传闻、神话、虚构指控或未能实体化的署名可被合法获知、返回与讨论，其文字与指涉随说法 / 传本固化；不因名字不在册而过滤整条说法，也不因反复出现就认定其真实存在。

### 2.3 文件形态与校验

- 单文件 JSON，不含二进制资源；可手编、可 diff，只保存当前确认版本。
- 修改只影响之后新建的实例；不自动迁移任何既有实例。
- 在生成完成、用户确认保存与实例创建前使用同一套校验：结构版本、必填字段、唯一标识、引用闭包、合法历法、双轨边界、史料引用与贡献者时期、种族与寿命参数、事件源与密度、角色模板兼容性。
- 校验失败指出**模板自身**的字段与原因；不能「尽量加载」后把无效日长、悬空渠道或未知事件效果交给运行期兜底。
- 文件规模、嵌套深度与文本长度应有加载限额；数值实现时标定，超限明确拒绝，不静默裁掉设定。
- 用户手动改包造成的语义错误与运行后果不在支持范围；这不免除结构、安全与引用校验，也不影响已经创建的实例。
- 校验分两步：模板 / 角色装配阶段查声明与已有引用；创建期回填后查完整产物、初态、角色知识与引用闭合。最低内容标准见附录 D，它**补充、不取代**本节的必需字段。

### 2.4 生成与修改方式

| 方式 | 行为 |
|---|---|
| 表单式 | 用户填字段，可按需让 AI 补全指定部分 |
| 对话式 | 用户描述意图，AI 生成或修改候选包，用户检查差异 |

两种方式可混合。初期是有限字段表单与文件编辑，不扩展成地图或完整可视化世界编辑器。

- 新建候选只需自身自洽，不必与别的世界包一致；修改现有包时才保持未授权变动部分及已有引用一致。
- AI 可以读取创作中的实情以保证一致性，但创作上下文不转用为角色对话上下文。
- 失败、取消或校验未通过不覆盖原文件；用户确认后原子替换最新版。候选可编辑、可重生成，不保留生成历史。
- **草稿态**：只保存当前候选包、候选角色卡与继续编辑所需进度；允许字段未填完但标记未通过校验。草稿与确认文件、可运行实例分开，不因自动保存成为正式包，也不另建生成历史库。关闭引导或中断任务保留草稿并可显式继续；「丢弃草稿」才删除候选。
- **用量预算**：需远程生成时先确认服务并说明必要文本将发送给供应商，再确认预计调用次数区间、token 量级与总调用上限（含重试）；达到上限暂停并保留进度；规模或计划实质变化时重新估算并确认，不靠无限重试扩支。

### 2.5 共享生成器

- 桌面 / 安卓共享 schema、模板、校验规则、生成与修订流程，而不是各写一套「差不多的」生成器。
- 共享保证**结构和约束一致**，不承诺两次独立 LLM 调用逐字相同；比较相同固化产物时，两端解释必须一致。
- 当前版本生成器产出并通过校验的包，须能被当前版本创建实例；未知必需能力必须在确认前报错。
- API 不可用时保留编辑中的候选并允许手编，不伪造生成成功。

## 三、世界包与世界实例

### 3.1 对象区分

| 对象 | 可变性与版本 |
|---|---|
| 世界包 / 创作中的角色卡 | 可修改，仅保留最终确认版本 |
| 实例的设定快照 | 创建时锁定，不可编辑，与源文件脱钩 |
| 实例的运行状态 | 公理下持续演化，支持时间线、提交与回滚 |
| 实例管理元数据 | 名称等可管理；不改变世界设定或故事事实 |

**设定锁死不等于运行状态冻结。** 实例是锁定设定与可演化运行状态的整体。

### 3.2 实例创建流程

1. 选择并校验世界包，确认原始世界包名称。
2. **装配角色卡**：自定义或 AI 生成 → 用户检查 → 与世界包联合校验；角色卡以独立内容对象保存。创建时至少装配一名角色，其余角色可在运行期通过**补卡**加入（§3.7）。
3. 生成候选实例名并交用户调整：本地全局唯一，重名从 `_2` 起追加序号。
4. 一次性固化世界包、角色卡、初始知识、初始时刻、世界种子与生成规则版本，形成自包含实例及初始时间线 / 提交。
5. 创建成功后默认冻结；由用户明确选择激活并进入对话。任何前置失败均不留下半个实例。

- 角色装配数量不属于设定锁定范围：创建时可装配一名或多名角色，运行期可继续补卡（§3.7）；文件与作用域按多角色设计。
- 同一包可以创建多个独立实例。新建可产生新的世界种子；整体导入则保留已有种子与历史，不重新抽取世界。
- 校验分两步（见 §2.3 与附录 D）：装配阶段查声明与引用；回填后查完整产物与初态。两步都通过才原子登记实例；不以「稍后补卡」绕过锁定。

### 3.3 无关联原则

- 实例不记录需要持续解析的源文件引用；后续修改、删除、移动世界包与角色卡文件都不影响它。
- 实例只保留内部快照与必要的来源元数据；「来源名称」不是运行依赖。
- 创作资产可以复制后复用，但不同实例不共享可变角色状态、记忆或世界历史。

### 3.4 设定锁死与世界修改

锁定内容包括世界公理、历法、初始双轨、**已装配角色卡（不可改、不可删）**、通讯规则；没有「非语义修改」后门。**角色集合属于可扩充项**：可在运行期通过补卡加入新角色（§3.7）。

- **改模板 / 公理 / 既有角色卡**：编辑创作文件，再创建新实例。
- **扩充角色集合**：补卡（§3.7）——放入新角色，不改变既有设定与历史。
- **在原有公理内改变局势**：显式引入合法世界事件，创建新时间线，不修改原线过去，见 `EVENT_ENGINE_SPEC.md` §八。
- **正常运行演化**：角色行动与世界规则持续产生事件，无需每件日常事件都分叉。

### 3.5 完全黑箱

- 实例内的事件、角色状态、性格数值、记忆与实情演化不可浏览或编辑。
- 允许对话、公开世界时钟、运行状态，以及实例 / 时间线 / 提交的必要管理元数据和操作。
- 提交标识、用户备注、来源关系可见；自动生成的剧情摘要、内部 diff、性格 / 记忆面板不可见。
- 显式引入事件的草案只能展示用户意图与可确认内容；不能借校验错误或近似方案泄密。
- 可以整体导出，不加密，接受用户在产品之外自行查看；**黑箱是产品接口约束，不是密码学防读取承诺**。普通日志也不复制内部正文。

### 3.6 创建期的历史回填

历史不只靠预写：创建实例时按「先约束、后补史、再锁定」补齐过去。

1. **约束输入**：已确认的历史、世界公理、当前局势与角色背景是硬约束；复用已有事件与说法引用，只在空白处补史，不随机覆盖已有锚点。
2. **骨架回填**：按本次创建固定的种子、生成规则版本与受支持的因果规则，分时代抽样生成合法骨架；独立预算，不占运行期每日密度；无合法候选则留白，不为凑量添加事实。确定性只保证复现，不能替代因果校验。
3. **一档文本**：按传本与卷批量编纂（暂按十年一卷、10–20 条一批），全量生成所选条目的「一句话」级文本并确定各传本的选载范围；文本生成受骨架约束，不由文本反向决定事实效果。
4. **联合校验与固化**：检查历史与当前局势相容、实体与因果引用有效、各传本来源与贡献者活动区间合法，并最终校验角色初始知识引用及范围；沿用实例创建的原子边界一起固化，失败不留下可运行的半个实例。必须改变已确认内容时返回创作阶段重新确认，不暗改世界包或角色卡。

历史后果及仍有效的影响须已纳入初始状态，运行自初始时刻继续。**回填记录不再次施加灾害、性格冲击或获知效果**；角色后来合法读到旧史料形成新的获知经历，不是历史事件重新发生。规则与确定性边界见 `EVENT_ENGINE_SPEC.md` §三。

编者实体化按**在世推断**：寿命模型能给出出生 / 死亡且与编纂 / 整理活动相容的编者，建成人物生平（可作为实体被引用、被事件影响、被对话问及）；给不出的只留署名。遗稿与后世整理由贡献者列表中的整理者及各自时期表达，不把成书时刻当作原编者仍在世的时刻。**校验义务不后置**：寿命相容属创建期联合校验，不因年代久远而豁免。

回填产物的具名对象按 §2.2 的名册门槛登记；缺寿命依据的署名只保留署名，不补造生死。回填走 §2.4 的用量确认与草稿 / 暂存规则：保留已确认输入、种子、规则版本、已采纳产物、进度与已用预算；继续时先查是否已完成，复用有效结果、只补未完成部分；变更输入后先判定失效范围再重新校验与确认。**未完成生成只保留可恢复状态，始终不是可运行实例。**

【初期口径（临时）】载体 1 部官修 + 1 部非官修；跨度当前纪年往前 2–4 个时代（百年级），刻意填不满；条目量 10² 量级，「一句 : 段」≈ 9 : 1。**以上均为起步口径，不冻结，预期在后续版本修改**；本层固定模型与约束，不固定规模，不承诺每卷填满或每件事都配齐相反说法。

### 3.7 补卡（角色加入）

已创建的实例可在运行期扩充角色集合。**补卡只增加角色：不修改、删除或替换任何既有角色卡，也不改写既有历史。**

**语义**：

- 新角色**一直存在于该世界**：世界初始时刻她已在该世界中生活，只是此前未与用户建立联络、也未被既有角色特别提及。补卡不产生「她凭空出现」的世界事实。
- 用户可在补卡时**自定义一个世界事件**，作为她与用户建立联络（或进入联络范围）的世界内解释；该事件走既有事件路径（前置条件、效果与校验）并登记为一个世界事件。未提供时不额外生成事件，联络由来由角色卡的「初见设定」承担。
- 允许在补卡时声明新角色与既有登记实体（含既有角色）的**已相识关系**（亲属、同事、旧识等）。该声明是背景事实，不产生角色间自主互动，也不开放角色间的对话或记忆可见性。

**装配与校验**（与创建期同一套规则，另有补卡特有项）：

1. **定义与成员资格分离**：新角色的不可变定义写入实例设定快照；每条时间线另写一条带加入提交、加入水位和退出 / 撤销状态的成员资格记录。角色选择、认知查询、会话创建和事件受影响范围都必须先检查当前提交可达的成员资格，不能因实例快照仍保留定义而在退出线重新暴露角色。
2. **目标线与加入事件**：补卡默认作用于用户明确选择的一条目标线，并在该线原子创建加入提交；不可静默写入所有兄弟线。若提供加入事件，首版只允许在补入提交水位立即生效；未来时刻的预约事件须走 `EVENT_ENGINE_SPEC.md` §八的待执行事件路径，不在补卡事务中提前施加效果。冻结线允许这一管理性补卡例外，但补入不激活、不推进其他状态。
3. **时间锚定**：新角色的初始状态锚定**补入时刻的世界时刻**——年龄、经历、位置与作息按当前世界时间推导，不回到实例初始时刻。角色必须在补入时刻已出生；“一直存在”指她在世界中存在，不要求她在实例初始时刻已经出生。
4. **个人史回填**：她活到现在的经历须与世界既定历史相容；复用创建期回填规则（确定性骨架、文本、联合校验），范围收窄为「与该角色相关、且不新增世界级事实」。回填先固化私人活动、接触对象、渠道和发生水位，再据此形成初始获知记录；仅有渠道资格而无实际接触依据的事件保持未知。
    - 不得与既有实情冲突（不能是已死之人，不能经历与既定历史相悖的事）；
    - 只允许此前未记录的**私人经历**，不得借回填补造世界级事件、他人死亡或公理变更；
    - 出生时刻与寿命依据合法，出生不晚于补入时刻。
5. **初始知识投影**：以「她一直在」为基准，但只对已固化私人活动、接触记录和合法渠道实际触达的内容跑认知过滤，形成她的初始知识；不手工挑拣、不越权，也不因职业或渠道自动获得全量历史。
6. **联合校验**：新卡、成员资格、私人史、初始知识、加入事件和目标线当前状态必须作为一个原子事务校验与发布；任何失败均不改变实例快照、目标线、事件、角色会话或用量状态。

**版本与生命周期**：

- 补卡在三处留痕：实例设定快照的角色定义、目标线的成员资格扩充，以及目标线的加入提交；定义是实例级不可变对象，成员资格是线内可回滚状态。
- 回滚跨越加入点时，该角色在本线退出（状态、对话、记忆随之一致撤销）；从加入后的提交分叉则继承她。
- 冻结线可在其冻结时刻补入（锚定冻结时刻），补入本身不激活该线。
- 新角色拥有自己的初见资格（按实例、时间线、角色三元组独立，见 `SESSION_CORE_SPEC.md` §5.5）。
- 隔离不变：她与既有角色各自与用户独立会话，互不可见、无角色间互动（阶段 5 的披露机制照旧）。
- 同一补卡请求带稳定请求标识；重试返回原子发布结果，不重复登记角色定义、成员资格、加入事件或初见资格。回滚后再次补入必须使用新的加入版本，不能复活被撤销的旧成员资格记录。

**成本**：个人史回填与初始知识投影纳入既有「用量预算」确认与草稿 / 暂存规则（§2.4）。

## 四、多世界与角色拓扑

- 支持多个独立实例；同一实例可有多个角色，每角色独立卡片与状态，运行时钟在同一时间线内共享。
- 角色选择只切换会话视图，不转移记忆，不让其他角色获得对话。
- 角色集合可在创建时装配，也可在运行期补卡扩充（§3.7）；补卡只增不减，不绕过设定锁定。
- 当前不做角色之间自主互动，不支持跨世界共享运行角色，不支持世界或时间线合并。
- 角色间披露机制按阶段 5 验收；补卡本身不等待该阶段（见 §九）。

## 五、用户位置与通讯方式

- 用户是世界外的观察者、联络者、对话者，不占据世界内位置，不直接作为事件参与者。
- 普通对话的影响路径为「用户 → 角色自主行动 → 世界规则与事件」；没有已执行行动时不能声称世界已改变。
- 管理面引入事件属于创作者操作，与角色聊天明确分开。
- 每角色有符合世界设定的双向联络方式，只连接其与用户；不自动成为世界内角色互相通报的渠道。
- 世界内信息渠道和跨世界联络是两种概念。硬约束角色可以没有世界内新闻渠道，但仍能从用户通讯获知用户所述信息。

## 六、跨端同步

- 无云同步、无后台自动上传或合并。跨端迁移由用户整体导出 / 导入完成。
- 导入始终创建新副本，不接管、覆盖或追赶另一端已有实例；两端随后独立演化，不能再合并。
- 「全局唯一名称」指每个安装端的本地实例库，不需要跨设备名称登记服务。
- 用户可自行管理旧副本是否冻结；系统不能远程停止另一端，也不暗示正在双向同步。
- 无云同步不等于无联网：语言生成与远程 embedding 的必要文本请求仍需在服务配置时说明，不把实例包整包发送给模型。

## 七、世界实例导入导出

### 7.1 导出内容与一致性

- 单一文件、不加密，容器格式实现时确定。
- 在每条线的完整提交边界捕获一致状态，包含冻结设定、**全部角色卡**、所有时间线及其所需提交闭包、种子 / 规则版本、事件、生活线、性格、认知、对话、披露、三层记忆与固化的生成结果。
- 导出包含尚未成为用户手动 / 自动提交点的当前完整状态，不能只打包最近一个旧提交而漏掉新对话。跨线捕获统一的现实切点，各线可以有不同世界时刻。
- 若正在补算，等待一个明确的完整水位或报告尚未就绪；不能导出「最新时钟 + 旧状态」。
- 未完成逻辑任务保存必要来源和处理状态；临时模型上下文、半截回复不当作完成结果。导入后不能凭旧投递任务自动向外发送。
- **不含任何本机激活状态**（包括历史元数据副本）、当前视图、现实钟继续运行锚点、待生效的本机倍率命令、通道绑定 / 凭据、投递回执、API Key、日志和设备路径。
- 保留每线世界时刻与有效倍率；向量缓存可选，源文本与引用不可缺。
- 导出到临时文件完成全部校验后再交付最终文件；中途失败不留下伪装为成功的包，也不破坏先前导出件。
- 同一一致水位与引用闭包规则供**本地滚动备份**复用：先写暂存、完整校验，再发布为成功备份，不直接复制正在写入的零散文件；向量等可重建缓存可省略。

### 7.2 世界包名称与实例名称

- 区分**原始世界包名称**与**实例显示名称**：前者提供创建 / 导入的默认命名依据，后者由用户管理且全局唯一。
- 原始名称在世界包首次通过系统确认时记录；全手工新包在首次接受时初始化。生成期仍未确认的名称属于草稿。
- 之后编辑普通名称字段不改原始名称；创建 / 导出把独立原始名称记录嵌入快照，导入优先读取该记录，不以文件名或可编辑显示名覆盖。
- 模板和导出件都是用户可访问的不加密数据；手动篡改整份系统元数据的真实性不能靠普通校验和证明。产品不提供此类修改通道，也不承诺防伪，不引入签名服务器来兑现不存在的防篡改能力。

### 7.3 导入流程

1. 在隔离暂存位置检查容器结构、大小、文件数、校验清单与数据版本。
2. 校验所有必要引用与历史闭包，拒绝缺记录、重复标识、损坏历史、非法历法与未知必需能力；不手动挑一部分导入。
3. 按兼容规则使用原件，或经用户确认对**副本**运行可信转换器；转换后重新完整校验。
4. 读取原始世界包名称，生成本地唯一实例候选名，交用户确认。
5. 原子创建新本地实例命名空间；保留包内逻辑身份 / 因果关系 / 种子，重新映射本地引用，禁止与现有库因同 ID 意外相连。
6. **所有导入线默认冻结**；用户选择激活时以当下现实时间重新锚定，从包内世界时刻开始。运输时间、导出端现实时间差和导出端激活状态均不触发补算。
7. 建立本地新会话路由后才能聊天；历史保留，但不恢复外部通道凭据、不重播旧消息。导入失败撤销全部暂存，不影响任何已有实例。

### 7.4 命名

- 候选名基于原始世界包名称；冲突追加 `_2`、`_3` 等，选最小可用序号。
- 用户确认的名称仍冲突则拒绝，不静默改成另一名称。创建 / 导入 / 重命名共用同一规范化规则与原子唯一约束。
- 名称去除首尾空白后不能为空；大小写及 Unicode 等价的比较规则实现时统一并跨端保持一致，不让 UI 与存储用不同判定。

### 7.5 版本兼容与安全

- **兼容性检查在导入和打开本机实例时执行**，导出只保证当前产物完整，不尝试适配未知目标版本。设定层负责读取格式版本、必需能力和可信转换器；运行层负责确认确定性规则版本可执行；桌面 / 安卓只展示结果与请求用户确认，不各自实现一套兼容判断。
- 比较数据格式版本与必需能力；项目显示版本不同不必然不兼容。同格式 / 能力可读时提示差异后允许导入，不兼容则拒绝。
- 已注册的可信转换器可自动发现，但执行转换需用户确认；无转换器则提示使用对应兼容版本，无强制导入或手动部分迁移。
- 重大不兼容变更发布时必须配转换器；转换失败保留原包，不修改已有实例。
- 拒绝绝对路径、路径穿越、符号链接逃逸、压缩炸弹与可执行载荷；不反序列化任意代码对象，不执行包中声称的转换脚本。
- 校验和用于损坏检测，不冒充来源认证。手编模板「后果自负」不免除应用的输入校验义务。

### 7.6 已打开实例的升级兼容

- 应用启动或打开实例时，先检查实例数据格式、锁定设定版本、确定性规则版本以及当前版本声明的必需能力；不能只比较应用版本号。
- 检查通过时沿实例记录的规则版本继续推进；当前版本拥有兼容实现但需要转换时，先在副本上执行可信转换，完整校验并原子发布，保留原实例可恢复副本。
- 无法执行原规则且没有可信转换器时，实例进入「兼容性阻断」：停止世界推进、后台派生任务、主动生成与新对话提交；允许读取管理元数据和最后完整历史，提示兼容版本或用户确认转换。
- 转换失败、写入失败或校验失败均保留原实例与最后完整水位，不以当前规则静默重算，不删除旧备份，不创建半迁移实例。用户确认转换后，转换产物必须获得新的数据 / 规则版本标记。
- 升级兼容检查不改变导入语义：导入仍创建独立新副本，升级打开的是本机原实例。
- 兼容检查输出固定结果：`compatible`（沿原版本运行）、`convertible`（用户确认后在副本转换）、`blocked`（只读 / 冻结，等待兼容版本或转换）。检查本身不得推进世界、生成文本、消费预算或改变实例版本。

### 7.7 对话体验与离线查看

导出包含内部真相，而对话只呈现角色局部认知，两者不同是设计使然。产品不提供包内浏览器、不解释秘密，也不把导入校验信息变成剧情检查面板。

## 九、实施分期（本模块）

- **阶段 1**：世界包与角色卡创作、联合校验、实例创建、初始快照、完整导入导出。

- **阶段 5**：角色间披露与多角色端到端隔离验收；既有实例的角色卡仍不解锁设定。

## 附录 B：导出容器与实例元数据（设计级）

- manifest 记录格式版本、项目版本、必需能力、导出时间与完整性清单。
- 设定快照包含世界包、原始名称及全部角色卡；运行部分包含每条线的完整可恢复状态和必要共享提交。
- 实例名称、来源、创建时间是管理元数据；激活集合 / 当前视图等本机控制信息单独存放，不进入便携包及其历史副本。
- 世界包模板与实例导出包是两类输入；导入入口明确区分，不能把解出的快照当成修改旧实例的后门。

## 附录 C：行为验收

1. 修改或删除源模板 / 角色卡后，既有实例内容不变；锁定实例不能改历法或改既有角色卡；补卡只扩充角色集合。
2. 新建与修订两种生成模式共用校验；失败 / 取消不覆盖确认版本；两端解释同一包一致。
3. 创建 / 导入 / 重命名并发时仍全局唯一；名称字段修改不取代原始名称记录。
4. 多线导出再导入能恢复全部对话、披露、记忆与引用；删除原实例也不影响新副本。
5. 导入全部冻结，无运输期间补算，不恢复插件 / Key / 绑定，不向旧通道补发消息。
6. 版本不兼容、转换失败、损坏或恶意容器均原子失败，已有实例不变。
7. 包中无激活状态及凭据；UI、普通日志与导入错误不泄露内部事件、性格与记忆。
8. 创作者改变公理须新建实例，合法改变局势须新建时间线；普通聊天不隐式触发任一操作。
9. 历史回填不推翻已确认的历史、公理与角色背景；无法满足约束时创建失败或保留合法留白；初始知识引用的史料条目不存在或范围越权时不能创建实例。
10. 名册与引用：事实参与者、效果目标或结构引用指向未登记对象时创建失败；纯署名的史料贡献者不被补造生平；含虚构名字的传闻仍可被合法获知；在册不等于角色已知。
11. 最低标准：只有一个事件族或无谜题的合法包不被题材配额拒绝；空壳史料、非法寿命依据或越权初始知识仍然失败。
12. 草稿与用量：无 API Key 可手编、保存草稿或导入；关闭引导后可续作，丢弃不损伤正式资产；达到确认的调用上限暂停，续作复用有效产物；模板与实例两类导入不混淆。
13. 未声明制度或文化扩展的合法题材不被新丰富度配额拒绝，也不隐式补造组织、习俗或个人目标；声明的制度与惯例若无法被一致解释，创建期即失败。
14. 补卡：新角色不凭空出现（默认「一直在」）；初始状态锚定补入时刻，个人史不与既定历史冲突；初始知识不越权；失败不改变实例。
15. 补卡可回滚：回滚跨过加入点后该角色在本线退出（成员资格、状态、对话、记忆一并撤销），实例级角色定义仍保留但不可在该线选择；从加入后提交分叉则继承；冻结线补入不激活该线。
16. 补入角色与既有角色默认隔离：各自独立会话、互不可见、无角色间互动；用户声明「已相识」不改变这一点。

## 附录 D：最小内容标准（设计级）

本表**补充、不取代** §2.3 与附录 A 的必需字段：模板 / 角色装配阶段查声明与已有引用；创建期回填后查完整产物、初态与角色知识，通过后才原子锁定；回填留白不必预写完，明确引用的对象不能永久悬空。

| 内容 | 最小（阻断条件） | 建议（内容丰富度，不阻断） |
|---|---|---|
| 公理与背景、历法、初始世界时刻 | 必填，历法有效，世界边界明确 | 按回填口径保留跨时代留白，不强凑跨度 |
| 命名语汇 | 对包内采用的实体类别有一致命名规则 | 按题材覆盖人 / 地 / 机构等类别 |
| 种族、寿命与实体引用 | 角色 / 登记人物的寿命依据合法，结构引用闭合 | 不为配额添加人口或组织 |
| 信息来源与双轨 | 说法有来源及获知条件，实情与说法分开；世界内新闻渠道可为空，实际采用的来源须合法 | 2–3 条差异化来源；有相应制度时才含官方来源 |
| 事件源与密度档 | 至少一类合法、受引擎支持的事件源；前置条件与效果有效，固定事件不超预算 | 适用时以 3–4 族、每族 3 个模板为生成起点；族数不作为创建门槛 |
| 初始事件 / 传闻 / 谜题 | 字段明确，可为空；已有内容须合法引用双轨，历史后果与初态一致 | 适用时以传闻 3 条、谜题 1 条为生成起点，不为凑数增内容 |
| 史料（传本） | 至少一部有效传本；来源、贡献者时期、覆盖范围与条目引用合法，不能用空壳计数 | 两部立场不同的史料；官修 / 非官修只是适用题材的起步组合 |
| 角色类型、模板与联络 | 至少一种可装配模板；创建时全部角色卡已确认、联合校验通过，双向联络合法 | 补卡角色按同一标准单独校验，不要求凑多角色 |
| 生活模板 | 世界时间窗与活动有效，覆盖声明的生活区间，睡眠 / 无睡眠明确 | 由职业与世界日长形成差异，不强套现实作息 |
| 制度与惯例（按题材） | 未声明即不适用，不因缺少制度 / 惯例条目拒绝合法题材 | 声明的制度与惯例须有职权、群体与允许变化范围，可被生成器与校验器一致解释 |
| 可探索入口 | 至少一名可联络角色能凭合法初始知识、亲历或允许渠道接触一项世界内容 | 线索互引、不同来源保留分歧；至少一处内容可被后续经历接回并补充先前片段 |

- 只缺建议项则提示，不阻断、不偷偷补造事实；满足最小标准也不承诺叙事质量已达标。
- **互释属建议级**：可检查「新片段能否解释旧片段」，但不要求每个秘密都可被拼完，也不因缺少谜题或互释条目拒绝合法题材。
- 丰富度数量与规模属标定起点；**必填、引用闭包、时间相容与认知边界不是调参项**，修改硬门槛须更新规范，不能实现时临时放宽或加严。
