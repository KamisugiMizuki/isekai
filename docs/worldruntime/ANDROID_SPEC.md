# 安卓端（ANDROID_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 安卓端能力与一致性规范
> 来源：2026-09-19 总设计与模块深化；本轮补齐恢复、跨端确定性、文件及服务配置边界。
> 状态：设计规范，尚未实现；**先桌面，安卓为阶段 7 可选评估，不在本轮确定技术路线**。 **2026-09-21 更正**：安卓工程本体仍为阶段 7 可选评估、未动工；但「同 UMP 语义的进程内传输」已落地 （`isekai_core/local_channel.py`，安卓侧可直接喂帧，不占回环端口），且「两端解释同一包一致」已在两条传输上验证。

## 一、模块职责与范围

- 安卓端提供与桌面同一世界 / 对话核心体验，不开放第三方插件。
- 冻结能力、协议、数据格式与运行语义；不把「两端文件能打开」当成完整兼容。
- 内建聊天独立维护，不随桌面聊天拆成插件而拆分；界面可以使用平台原生形态，不要求复制桌面托盘或窗口。

## 二、能力范围

| 能力 | 桌面端 | 安卓端 |
|---|---|---|
| 聊天 | 内建，可停用 / 拆为插件 | 始终内建 |
| 第三方通道 | 独立进程插件，后置 | 不提供安装、接入或启用入口 |
| 世界包创作 | 表单式 + 对话式 | 同能力，共享生成器 |
| 角色卡 | 创建前生成、联合校验、用户审定 | 同规则 |
| 世界实例 | 创建、对话、命名、删除 | 同规则 |
| 整体导入导出 | 创建独立新副本 | 同规则 |
| 时间线与版本 | 创建、激活 / 冻结、归档 / 删除、提交 / 回滚 | 同规则，包括多线激活 |
| 显式世界修改 | 引入事件草案并确认创建新线 | 同规则，不由聊天隐式触发 |
| 世界时钟 | 当前查看激活线时钟、倍率调整 | 同规则 |
| 倍率上限配置 | 仅开发者 | 仅开发者 |
| 主动消息 | 世界源、统一配额与投递状态 | 同一语义，平台呈现见 §四 |

- 黑箱规则一致：不得以手机调试或迁移为由新增事件 / 记忆 / 性格浏览面。
- 角色卡随实例锁定，不能在安卓端编辑卡后覆盖旧实例。

## 三、协议、格式与运行不变式

### 3.1 协议与生成器

- 遵循 `CHANNEL_PLUGIN_SPEC.md` 的 UMP 消息语义：稳定身份、幂等接受、固化结果、回执、显式重试与错误。
- 传输可适配进程内调用，不强制 WS 或插件进程；传输变化不能省掉消息去重、持久化和回滚失效。
- 共享世界包 schema、模板、生成 / 修改流程及校验器；同一固化包两端解释一致，独立 LLM 调用不保证逐字相同。
- 当前版本生成并校验通过的包必须在当前版本可创建实例；技术路线若无法复用同一生成器核心，不满足既定要求。

### 3.2 运行一致性

- 同一锁定设定、种子、规则版本、前序状态与固化输入，在两端得到相同历法、倍率边界、事件骨架与事实效果。
- 不使用平台时区、随机化 hash、线程调度顺序或新本地实例 ID 改变世界结果。
- 已固化事件 / 说法 / 计划文本不因换端重新生成；事实推进规则由运行层唯一规定。
- 若安卓选择重写核心，必须用同一套确定性输入样本逐项对照，不能只测 JSON 解析成功。

### 3.3 导入导出

- 使用 `WORLD_SETTING_SPEC.md` 的完整快照、引用闭包、安全校验、命名和原子失败契约。
- 兼容依据为数据格式与必需能力，不只看应用版本号。所有不兼容包均拒绝直接导入；可信转换器存在时经用户确认转换，转换后重新校验，无转换器提示兼容版本。
- 打开本机已有实例也必须先检查数据格式与运行规则能力；不兼容或转换失败时保留原数据并停止推进，不静默以当前版本规则补算。
- 导入始终创建本地独立新实例，所有线默认冻结；激活时从包内世界时刻重新锚定，**不补算文件运输期间**。
- 不导入源端激活集合、通道绑定、Key、设备路径或待发送外部消息；本机唯一命名不依赖另一端在线。
- 无云同步、自动覆盖或副本合并；用户自行管理各端副本。

## 四、平台生命周期与交互

### 4.1 持久化与恢复

- 系统挂起、终止进程或设备重启不等于用户冻结时间线；不依赖退出回调才写存档。
- 恢复时只补算本机中断前已激活的线，冻结线不推进；导入新副本另按 §3.3 处理。
- 补算按运行层共同水位分批，预算不改变事实；恢复期间明确显示追赶 / 失败状态，不以旧角色状态回答新时刻的问题。
- 手机后台无法保证持续执行和实时送达；必须保证**再次获得执行机会时恢复一致**，不能把逻辑持续运行描述成进程永不被杀。
- 若采用后台运行能力，具体系统集成在选型时评估；权限缺失不得损坏历史或改变世界推进规则。
- 安卓壳复用核心启动状态枚举：未达到 `ready` 时不提交新对话；`compatibility_blocked`、`persistence_blocked` 与追赶状态必须分别显示可执行的恢复入口或只读边界，不以通知权限或进程存活推断世界可用。

### 4.2 聊天与主动消息

- 持久聊天历史是真值，通知只是已固化消息的平台提醒，不生成第二份对话或重复消费主动额度。
- 通知权限被拒或后台受限时，消息仍可在应用历史中读取，不宣称已送达 / 已读。
- 应用回前台不逐日补发离线积累的主动消息；当前素材按共享时效规则处理。通知投递状态不得成为用户在线 / 情绪检测输入。
- 切换、回滚与重绑使旧历史游标和缓存失效；冻结线发新消息前明确激活。

### 4.3 文件与服务配置

- 用系统文件选择 / 保存流程取得文件访问授权，不假定桌面绝对路径存在或要求全盘存储权限。
- 导入先复制到应用私有暂存区并完整校验，成功后原子登记；取消、空间不足或转换失败不留下半实例。
- 导出先在私有暂存区形成完整容器，再复制到用户选择的位置；写出失败不得显示成功，不破坏已有备份。
- 运行中持久化失败、空间不足或权限失效时保留最后完整状态，停止不可持久化的新工作；恢复写入后从原水位继续，不自动删除旧备份。
- Android 受系统限制无法持续执行时，不改变世界规则；获得执行机会后按最后完整水位恢复。通知点击只打开其固化消息所属会话，目标失效时显示管理错误，不改投、不激活冻结线。
- 提供 LLM 与远程 embedding 的地址 / 模型 / Key 配置，读取打码；embedding 可独立配置，失败降级全文召回。不要求用户手改内部配置文件。
- 界面只显示必要管理数据、时钟和对话；诊断日志不泄密。触控、键盘 / 辅助功能、长历史与错误恢复按平台方式验收。

## 五、技术路线（待定）

- 候选继续并列：Chaquopy 嵌入 Python 核心；或原生核心适配共享生成器与协议。此处不是选型结论。
- 评估硬约束：共享生成器可复用、完整数据可恢复、确定性规则一致、依赖可打包、持久化可靠、文件权限可用、暂停 / 杀进程后能追赶。
- 不以桌面方案或其他项目的成功经验代替本项目实测；后台存活与恢复须真机验证，模拟器通过不代表系统限制下通过。
- 若某路线只能读包却不能兑现完整语义，判为未达标，不悄悄删掉版本、记忆或多线能力。

## 六、实施分期

- **阶段 7（可选）**：先做路线可行性验证，再实现本规范能力面。
- 验证使用桌面固化样本、故障 / 重启场景与来回导入导出；不得只用安卓自己生成又自己读取的样本证明跨端一致。

## 七、待模块设计项（残余）

- 运行时与 UI 技术路线、共享生成器运行方式。
- 后台执行 / 通知策略、系统文件授权和本地凭据保护实现。
- 包体、内存、补算单批预算及真机验收矩阵；这些是实现评估项，不提前搭平台插件框架。
- 初见、睡眠等待、备份 / 恢复与用量语义在阶段 7 复用同一数据与行为语义（触发受平台执行机会限制，不照搬桌面定时 / 退出回调）；不因此提前启动安卓实现。

## 八、行为验收

1. 桌面导出 → 安卓导入 → 再导出返回桌面：角色卡、全部时间线、对话、披露、记忆与来源均完整，无跨实例引用。
2. 跨端同一确定性样本得到同样历法、倍率边界与事件骨架；固化文本不重抽。
3. 挂起 / 杀进程 / 重启后仅本机激活线补算；冻结线不动，导入副本不追赶运输时间。
4. 文件授权取消、空间不足、损坏 / 恶意包与转换失败均不影响已有实例。
5. 通知被拒或后台停运不丢历史、不伪报已读、不集中补发过期消息。
6. 无第三方插件入口；仍有完整创建、对话、创作、版本与倍率能力，没有内部状态浏览面。
7. 远程服务错误不暴露 Key；向量服务不可用时全文召回可用，恢复中不读取半份状态。
8. 打开旧实例先做兼容检查；不兼容、空间不足或转换失败不覆盖原数据、不补算、不伪报成功。
9. 通知点击定位到固化消息所属会话；通知权限拒绝、进程被杀或目标失效不丢历史、不伪造已读、不改投其他角色。
