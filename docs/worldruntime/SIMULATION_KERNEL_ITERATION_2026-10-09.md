## 零、一页结论

**诊断**：本内核目前不是「耦合动力学世界模拟器」，而是**「确定性日历事件抽样器 + 认知（说法 / 实情）引擎 + 版本层」**。
四件事它做得比五作都深——**确定性复算、时间线分叉回滚、同一事实的多版本认知、用户不在线也推进**；
五作都有的那件事它缺——**世界状态之间的耦合**：没有关系、没有空间、没有资源、没有数值演化、没有跨域推导，
因此世界的变化是**「被抽样出来的」而不是「被状态推出来的」**【代码确证，见 §1.3】。

**本轮两个必须分开处理的问题**：

| 问题 | 性质 | 结论 |
|---|---|---|
| **A. 内核自身的成本、正确性与可复现性** | 优化，不改语义（11 项，均可立即拆分实施） | 5 项 P0 成本：单批成本随世界年龄增长（实测 **+0.017 ms/(世界日·世界日)**，1500 日约 23×），根因是**每世界日批对全部在位记忆逐行 UPDATE**、活跃后果集无界累积后全量扫描、`reaction` 全表重算、自动提交全量 dump、无界读取；另有确定性 2 项（多处 `hash()`/`secrets`、指纹缓存口径）、正确性/结构 4 项 |
| **B. 内核的模拟表达力** | 设计改动，需先裁决（9 项） | **1 项与现行规格明文冲突**（B-2 关系模型，须裁决 `MEMORY_SPEC.md:134`）、**6 项需修订措辞**（B-1/B-3/B-4/B-5/B-6/B-8）、**2 项为新增**（B-7 作用域生命周期、B-9 关注域分层与物化契约），**必须先裁决再改码** |

**五作给出的最重要一条**：RimWorld 的事件不是「按日历抽」的，是**由世界状态算出的压力标量加权的**（威胁点数由财富、人数、时长推导），
且全游戏**唯一**的效用评分只在战斗选目标——平时决策走的是**规则优先级树 + 谓词门**。
本内核已有密度预算与确定性抽样，只差把**候选权重接上世界状态**——这是投入产出比最高的一处模拟能力改动（§3.2 B-1）。
DF 与 BG3 从两个相反方向指向同一件事：**必须有「作用域生命周期」**——DF 靠抽象层 / 具体层的实例化与卸载，
BG3 靠「每关一个 goal，离开即 EXIT 清理」；本内核**什么都没退休**（§1.2 实测：所有状态表行数随世界年龄线性增长，无一被压缩）。

**Songs of Syx 给出的最重要一条（它改变了本轮对「抽象」的理解）**：被称作「真实模拟每个角色、不做省略」的游戏，
其**全细节个体模拟只覆盖玩家自己的首都**——界外是「各族人口计数 + 日增率 + 产出/税收/价值」这类标量，
移民来自 `potential immigrants` **抽象池**，AI 战争走 `auto-resolve`，开发者本人承认「**I patch up reality here and there**」。
它真正的结构是**双引擎 + 少量接口事件**：焦点域内微观自下而上（食物真的被个体从田里搬到嘴里），焦点域外宏观自上而下，
两者只在**移民生成 / 入侵生成 / 税收 / 收获日发货**这几个口子上耦合。
⇒ 五种作品各自把抽象画在**不同的轴上**（§2.7）：DF 画在**对象**上、Songs of Syx 画在**焦点域**上、
RimWorld 画在**节拍与全局层**上、Elin 画在**因果**上、BG3 画在**关卡/阶段**上。
**本内核该画在「作用域 + 节拍」上，绝不能画在「人」上**——它只有 2–10 个角色，没有匿名大众可抽象；
而「聚合量」与「个体」之间必须有显式、可追溯、确定性的**物化契约**（§3.2 B-9）。

**Elin 给出的最重要一条（推翻了 2026-09-19 的原判断）**：**「世界自主推进」与「不可逆性」可以彻底解耦**。
Elin 的世界只做固定节拍的重置与再分配（**振荡器**），**所有真正的不可逆都挂在玩家动词上**（肢解 / 驱逐 / 售出 / 发布地图 / 杀 Boss——**棘轮**），
而 NPC 死亡默认是 7 天可逆的、连炸掉首都也会「一两周后重建」。它靠这个结构撑起了数百小时持续感。
本内核恰好相反：**世界自己在动，但几乎没有「不可逆」**；且两类时间效应混在同一条补算路径上（§3.2 B-8）。

**本轮最意外、也最该先修的一条**：在默认运行路径下，**世界跑 1500 天只产出 8 句不同的文本**【实测】。
9147 条说法里只有 8 条不同文本——因为说法文本 = 事件模板摘要原文（`events.py:259`），
而把它「表述成人话」的渲染是**显式管理操作**（`event.render`），不在推进路径上。
结构上「同一世界不同角色知道不同的事」成立（两角色 claim 交集为 0），**内容上不成立**（同一句话）。
这直接决定 §3.2 B-6 与 §4 的体裁推荐。

**游戏方向推荐**：四个体裁候选里推荐**「情报向开放世界 RPG」（C1）**——唯一一个把本内核**独有且五作都没有**的能力
（说法 / 实情分离 + 可复算的世系与回溯）当作核心玩法而非附属功能的方向。
**并建议分两步走**：先做 **C1a（无化身的调查向推理层，只吃现有聊天面 + B-6）**——它不裁决任何原则、不动设定层，
却足以验证「同一件事的不同版本，用户能不能感觉到」；验证通过后再谈 **C1b（有化身、有空间）**。见 §4.3。

**明确不建议**：现在就把内核改造成「RimWorld 式需求 - 效用殖民地模拟」。那需要同时新建需求 / 效用、资源经济、空间三套系统，
其中两套与 `DESIGN.md` §2.2 的既有原则正面冲突，且会把 A 类欠债放大到无法偿还。
**Songs of Syx 把这条否证的代价量化了**：它用**一个开发者十一年**、自研 Java 引擎、单核极限压榨，才把「逐个体模拟」做到
「**一个首都**的深度」（界外仍是计数器）；照抄这条路线**起价 10 人年以上**。理由见 §五。

## 一、现状诊断：这个内核到底在模拟什么

### 1.1 世界状态的三个存储层次【代码确证】

| 层 | 载体 | 可变性 | 证据 |
|---|---|---|---|
| **设定层** | `instance.setting` = `{world_package, original_name, cards}` JSON | 创建即锁定，实例生命周期不可编辑 | `store.py:112-125` |
| **运行层** | SQLite 表：`event` / `claim` / `knowledge` / `effect_state` / `environment_state` / `institution_state` / `custom_state` / `life_plan` / `experience` / `reaction` / `unit` / `intent` / `memory` / `character_state` | 随提交 / 分叉 / 回滚版本化 | `store.py:226-810` |
| **版本层** | `commit_snapshot`（delta 链，`kind / base / body`） | 提交 / 分叉 / 回滚 / 压缩 | `versioning.py:178-181`、`store.py:3667-3847` |

> **关键事实**：**运行层没有实体表**——`grep entity` 于 `store.py` 零命中【代码确证】。
> 名册实体（`person` / `org` / `place` / `item`）只活在锁定的设定 JSON 里，运行期唯一能改的实体边是
> `institution_state.holder`。**世界在运行期不会「长出新实体」**，事件只能引用已登记身份【规格 `EVENT_ENGINE_SPEC.md:34`】。

### 1.2 推进链路与实测成本

**结构**（`service.advance`，`service.py:2736`）：

```
心跳 app.py:388 _clock_tick（5 s）→ app.py:412 catch_up_all（墙钟时间盒 1.0 s，按线平分）
└─ service.advance(instance, timeline, now_real)                      service.py:2736
   ├─ 冻结检查（timeline.state != active → 返回 frozen）              service.py:2752
   ├─ 结算到期倍率命令 + 计算目标世界时刻 target                       service.py:2755-2758
   ├─ processed > target → 记一致性错误、返回 inconsistent（不倒拨）    service.py:2760-2765
   ├─ **取一次全量活跃后果 active_effects**（整个 advance 共用）        service.py:2785
   └─ while 未追平 且 批数 < 硬闸 且 未超时间盒：                       service.py:2786
        每批 = 一个世界日（2787-2788），批内顺序：
        _collect_batch → _world_event_rows → _death_rows → _revise_intents
        → _institution_rows → _environment_rows → _propagate_and_clear
        → **唯一事务边界 store.apply_runtime_batch**（store.py:3265，单事务 :3297）
        → decay_memories / apply_due_pending_events 在**批事务之外**（service.py:2891-2892）
```

**推进批次内没有任何模型调用**【代码确证，且是结构性的】：`Service.advance` 是**同步函数**（`service.py:2736` `def advance`，非 `async def`），
语言层面就不可能 `await` 模型；全文件 8 处 `llm.chat` 分别属于 `draft_user_event`（`:460`）、`extract_memories`（`:1149`）、
`compact_backlog`（`:1459`）、`organize_memories`（`:1558`）、`first_contact`（`:3143`）、`_narrative_check`（`:3467`）、
`_speak_unit`（`:3502`）、`propose_intents`（`:4686`）——**没有一个是 advance 或其批内步骤**。
文本表述（`event.render`）、角色自主提案（`intent_propose`）、记忆提取都是**独立操作**。
因此下面测出的都是**纯计算成本**，不含模型延迟。

**实测 E（独立审计，配置不同、结论互补）**【实测，`.hermes/research-2026-10-09/kernel_advancement_audit.md`】

- **记忆衰减是更严重的一项**：`store.py:4704-4725` 每批把 `decay_world` 推到本批批界（`:4722`），
  下一批批界更大 ⇒ `decay_world < to_world` 对**全部在位记忆**再次成立 ⇒ **O(在位记忆 × 批数)**。
  实测 8000 条在位记忆：**每批 +45~56 ms**（无记忆 11.76 ms）；而 `DESIGN_EFFICIENCY_SCREEN_2026-10-08` 的「54 ms 已落实」只是**单批**数字。
  索引已修好（`ix_memory_timeline_decay`，"全表扫描"没了），**「每批 O(n)」没修**。
  ⚠️ 我的实测 A 中 `memory` 表为 0 行（记忆提取是会话侧独立操作，本轮未触发）⇒ **实测 A 是下限**。
- **自动提交是全量 dump**：`service.py:731-745` 触发条件含「新增事件 ≥ 50」⇒ 高倍率下基本每拍触发；
  路径 `commit → versioning.snapshot_of → store.runtime_dump`（把该线全部历史读成 Python 对象）
  → 再物化上一条快照做 delta。实测 **`runtime_dump` 25 ms、`commit()` 86.5 / 115.2 ms**，
  落库快照 **2.85 MB = 库总体的 52%**（`MAX_DELTA_CHAIN=8` 到期即物化全量）。
- **`effect_state` 无界累积**：默认 `expiry = until_cleared`（`events.py:209-211`）⇒ 未显式解除的后果永久留在候选集。
- **无界读取长在读路径上**：`history_read`（`service.py:2227-2230`）说法侧**无 LIMIT**，
  实测 `limit=50` 的请求说法侧返回 **882 条**；`_known_event_ids`（`:122-135`）无窗口，被 `character_snapshot:4343` 每个角色调用一次；
  `world/ops.py:1046`、`:2223` 为找一条说法把整表拉进 Python。
- **逐行 `execute`、无 `executemany`**：批内 SQL 条数数十到数百条，叠加 543 条 reaction 与 8000 条记忆 ⇒ 单批可上万次 execute。

**由此推出的阈值**【推断，由实测外推】：

- **时间盒排水**：10 年世界（3650 日）= 约 63 ms/世界日 ⇒ 1.0 s 时间盒只能排 **约 16 世界日/秒**；
  而默认 `rate_max = 2592000` 世界秒/现实秒 = **30 世界日/现实秒** ⇒ 默认上限在**约 5 年世界龄**不再可达。
  若叠加实测 E 的记忆成本（+50 ms/批量级），阈值再降到**约 3 年**。
- **节拍占空比**：核心每 5 秒一拍、时间盒 1.0 s ⇒ 20% 占空比 ⇒ 10 年世界的**有效**排水率 ≈ 3.2 世界日/现实秒。
- **口径不缺，缺的是实现与校验**：`DESIGN.md:220` 与 `WORLD_RUNTIME_SPEC.md:92` 已**明文要求**
  `rate_max = floor(安全系数 0.25 × 排水能力)`；但【代码确证】`config.py:117-131` 只有注释复述该要求，
  代码既不测量排水能力、也不校验 `rate_max` 与它的关系。
  **关键点是「排水能力」被当成了常数，而实测表明它随世界年龄与角色数下降**——
  这使得「配置自洽」只在 t=0 成立（见 §3.1 A-11）。
- **真实触发条件是**：高倍率加速、长时间离线后补算、同实例多角色、以及未来游戏层的高频读；
  `rate=1` 的日常运行每 5 秒只需推进约 0.0001 世界日，成本可忽略【推断】。

### 1.3 世界状态的表达力：能表示什么，不能表示什么

【代码确证，来自本轮独立审计 `.hermes/research-2026-10-09/kernel_state_model_audit.md`】

**有的**：角色（性格单元 = 四类驱动 + `[0,1]` 置信度）、生活线（时间窗 + 活动标识）、打算（对象 / 依据 / 强度 / 窗口 / 前置 / 单个效果）、
短期反应、事件（事实骨架 + 效果 + 有效期 + 说法集合 + 获知记录）、环境事实（声明式类型 / 离散取值域 / 观察条件）、
制度（职位 + 在任者 + 空缺政策）、惯例（做法形态）、记忆（三层域）、版本与时间线。

**没有的（20 项，节选最关键的 9 项）**：

| 能力 | 状态 | 后果 |
|---|---|---|
| 角色 ↔ 角色关系（亲疏 / 债务 / 仇恨 / 隶属） | **零字段**；最近似物是 `disclosure`（信息授权边）与 `reaction.tendency`（自由文本） | **社会拓扑是星形**——所有角色只与用户相连，角色之间没有边；关系不可计算、不可查询 |
| 空间坐标 / 距离 / 拓扑 / 路网 | **无**；`world.geography` 是自由文本，`regions` 显式声明「无几何 / 路网」 | 「路断了」只是叙事标签，推不出「谁到不了哪」 |
| 资源 / 库存 / 金钱 / 生产 / 交易 | **无**；`runtime/change.py:50` 明文拒绝 `resource_change` | 消耗、匮乏、交易不可表达，只能当说法叙述 |
| 组织规模 / 军力 / 财力 / 成员集合 | **无**；`org` 实体只有名字；`institution_state` 只有职位、在任者（`holder`）与空缺政策（`continues` / `suspended`），没有成员集合或可比较的规模量 | 势力强弱不可比较 |
| 数值型环境量 / 量间推导 | **半有**；`values[]` 是离散枚举、按日哈希换档（`environment.py:56-63`）、逐行独立无交叉读取 | 「人口 → 税收 → 军力」在代码里**没有任何落点** |
| 身体 / 健康 / 伤势程度 | **无**；只有 `activity_constraint` 效果 | 受伤没有程度、没有恢复曲线 |
| **事件致死 / 致伤** | **无**；效果闭集 8 项（`validate.py:678-687`）无一项能改生死或伤势 | **事件打不死人**——战斗、灾难、刺杀都无法落成世界事实 |
| 玩家化身 / 身体 / 位置 | **无**；玩家是「世界外的联络者」 | 玩家不是世界内实体，不可被其他角色看见 |
| 高频状态读取 | **弱**；`read_snapshot` 要求线已追平（`service.py:2009-2016`），`snapshot_id` 每次重算，payload 每次重扫**十余张表**（`SNAPSHOT_INCLUDES` 只覆盖其中 6 个键，另有直接查询的 `claim` 等） | 持续运行的线上实测返回 `not_ready`；游戏层没有可用接口 |

**四条会咬人的事实**：

1. **新增一类世界状态不会自动进快照**——必须手工改**四处**：`runtime_dump`（`store.py:3667`）、`runtime_load`（`:3849`，无通用回退）、
   **`timeline_clear_state` 的表清单（`:3140-3163`）**、TRPG 类还要 `TRPG_COLUMNS`（`:941-973`；
   自陈「本仓库踩过四次的老账」的注释在 `store.py:4004`）。
   漏第三处的后果不是「没恢复」，而是**回滚后脏数据残留**。
2. **`intent.strength` 写入但重议不读**：`intents.py:95-111` 的 `decide` 只消费 `stage / preconditions / effect / window`；
   「优先级」实际由**遍历顺序 + `MAX_LIVE_INTENTS = 3`** 隐式决定。**最省力的行为杠杆点**。
3. **多处 `hash()` / `secrets` 破坏「同设定 + 同前序 → 同结果」**（本轮独立复核，比审计报告列出的更多）：
   - **直接影响世界事实的三处**：`runtime/life.py:60`（生活线计划 id，`lp-{secrets.token_hex(6)}`）、
     `runtime/personality.py:146`（性格单元 id，`abs(hash((source_key, semantic)))`）、
     `runtime/service.py:1653`（披露派生记忆 id，`abs(hash(item['ref']))`）。字符串 `hash()` 受 `PYTHONHASHSEED` 进程随机化影响，
     而 `events.py:7` 明文承诺「禁止依赖进程随机化的语言内置 `hash()`」。
   - **标识符与缓存指纹四处**：`service.py:691`（提交 id）、`:763`（时间线 id）、`:4864`（待执行事件 id）、
     `:1828` / `:1839`（实例设定指纹，用作**进程级长期缓存**的键——与 `WORLD_RUNTIME_SPEC.md` §14「请求作用域内复用、不设跨请求长期缓存」的措辞相反）。
   - 确定性主体（blake2b 抽样、同刻定序、世界日对齐批）成立，但**字节级可复现性不成立**（跨进程导出的 id 与内容都不同）。
4. **一处静默逻辑漏项**：`service.py:2828` 是 `world_rows["effects"] + [dict(item) for item in []]`——
   空列表死代码，**打算行动的环境效果没有进 `_environment_rows`**，被静默丢弃。

### 1.4 定性小结：世界推进的七种范式与本内核的位置

| 范式 | 世界变化的来源 | 代表 | 本内核 |
|---|---|---|---|
| **① 日历抽样式** | 按时间预算从候选池抽样，前置条件把关 | 本内核现状 | ★ 就在这一档：密度档 0–5 件/历法日、固定哈希抽样、无合法候选则留白 |
| **② 压力加权抽样式** | 世界状态算出压力标量，压力决定候选权重与强度 | RimWorld（MTB 到达 + 威胁点数） | ✗ 候选权重不读世界状态 |
| **③ 规则 / 需求驱动的 agent 式** | agent 按优先级树与需求行动（**效用只用在个别环节**） | RimWorld（ThinkTree）、DF（facet → need → focus） | ✗ 无需求、无目标优先级；打算由模板 + 闭集提案决定 |
| **④ 批量生成 + 局部精算式** | 历史在创建期批量生成并冻结；运行期只精算局部 | DF（worldgen → fort → legends） | ★ 形态同构：创建期历史回填 + 运行期事件 + 认知出口 |
| **⑤ 手工编排 + 通用规则式** | 世界不自主推进，靠手工内容与规则闭集组合 | Baldur's Gate 3 | ✗ 不适用，但可借其**效果闭集 / 前置条件 / 作用域生命周期**的工程手法 |
| **⑥ 振荡器 + 动词棘轮式** | 世界只做固定节拍重置；**不可逆全部挂在玩家动词上** | Elin / Elona | ✗ 内核两种都有雏形（历法节庆 + 用户引入事件），但**混在一条补算路径上**（§3.2 B-8） |
| **⑦ 双引擎式（焦点域个体 + 域外账本）** | 焦点域内由**个体行为**自下而上驱动；域外由**宏观标量与聚合结算**驱动；两者只通过少量**接口事件**耦合 | Songs of Syx | ✗ 现状是单引擎（无域分层）；**B-3 + B-9 的提案正是引入这个范式**（§2.1b 的裁决） |

**本内核的真实定位**：**① 的推进方式 + ④ 的历史形态 + 一层五作都没有的认识论层**。
「说法 / 实情分离」不是本内核的一个功能，而是它唯一无法被五作复制的资产：
DF 有 legends 记录但没有 per-agent 信念；RimWorld 没有谣言传播；Elin 与 BG3 用 flag 代替认知。
**任何游戏化方向，如果不把这一层用在核心玩法上，就是在花最贵的成本做五作早就做完的事。**

### 1.5 一条被本轮实测推翻的隐含假设

设计上「说法集合」被当作碎片化叙事的载体。实测结果：

| 指标 | 第 1520 日实测 |
|---|---|
| `claim` 行数 / 不同文本数 | 9147 / **8** |
| 每个事件的 claim 数 / 其中不同文本数 | 3 / **1**（3048 个事件全是这个形态） |
| 两角色 `knowledge` 行数 | 各 3048（**交集 0**，claim id 与来源互不相同） |
| 两角色看到的文本 | **完全相同** |
| `knowledge.stance` 取值分布 | 6096 条全是 `recorded`（无差异） |

> **日期口径**：本表是**第 1520 日**的读数（1500 日连续推进的产物 + 那一次 cProfile 又推了 20 批）。
> 同一天的 §1.2 实测 B 是**第 1500 日**的读数（`claim` 9033 / `knowledge` 6020，即每角色 3010），两者不矛盾，差的就是那 20 日。
> 换句话说：**再推 20 天，说法从 9033 涨到 9147（+114），而不同文本数没有增加**——这本身就是本条结论的一部分。

**机制**：`events.py:259` 每个来源的 claim `text` 都取 `event.summary`（模板摘要原文）；
把骨架「表述成人话」的 `event.render`（`world/ops.py:2146`，写回 `store.event_render_save:4189`，
**支持按 source_id 分别写不同文本**）是**显式管理操作**，不在推进路径上。

⇒ 也就是：**「同一世界不同角色知道不同的事」在结构层成立（不同 claim、不同来源、不同渠道），在内容层不成立（同一句话）。**
这是 §3.2 B-6 的直接依据，也是 §4 体裁推荐的依据：如果内容层不差异化，用户换人、换时间也拼不出不同版本。

### 2.1b 「抽象画在哪」——五种画法，以及本内核该怎么画

这张表是本轮新增的核心判断。**五部作品都不是「模拟一切」或「不模拟」，而是各自把抽象画在了一个轴上**：

| 作品 | 抽象画在哪个轴上 | 具体做法 | 代价 / 风险 | 对本内核的启示 |
|---|---|---|---|---|
| **Dwarf Fortress** | **对象** | 只有 histfig / artifact 被显式追踪；其余人口按 `entity_population` 计数；进出即实例化 / 卸载 | 无名者的历史不可追 | 「命名脊柱 + 匿名血肉」；但血肉必须**可被按需点名**（B-9） |
| **Songs of Syx** | **焦点域（作用域）** | 玩家首都全细节（每个居民是实体，有传记与家谱）；世界地图 region 只到计数器 / 比率；移民来自 `potential immigrants` 抽象池；AI 战争 `auto-resolve` | 「真实感」只在可见范围内成立；界外是**开发者自陈「patch up reality」**的假数字 | **抽象边界画在作用域上、不画在「人」上**；域内外必须有**显式接口事件**（B-9） |
| **RimWorld** | **节拍 + 全局层** | 错峰 tick（1/10/50/100/1000）；世界地图用抽象威胁点数与派系近似 | 事件强度由**玩家可操控的财富曲线**决定，非世界自洽 | 分级节拍（A-6）可直接用；**压力旋钮不可用**（裁决原则 3） |
| **Elin** | **因果** | 世界只做定期重置（振荡器）；所有不可逆只挂在玩家动词上（棘轮） | 关系层空洞（`UpdateRelations()` 为空——昂贵的假象） | 振荡器 / 棘轮分层（B-8） |
| **Baldur's Gate 3** | **关卡 / 阶段** | 每个 level 一个 goal，离开即 `EXIT` 清理；跨 act 截断 | point of no return 丢历史 | 作用域生命周期（B-7） |
| **isekai 现状** | **还没画**（＝画在「全量保留」上） | 所有状态一律全量保留，什么都不退休 | 成本随世界年龄线性上升（§1.2 实测 23×） | 该画在**作用域 + 节拍**上，**绝不能画在「人」上**——它只有 2–10 个角色，没有匿名大众可抽象 |

> **裁决**：本内核的抽象边界应取 **Songs of Syx 的轴（焦点域）＋ RimWorld / DF 的轴（节拍）**，
> 而**不取 DF 的对象轴**——因为「对象轴」的前提是「有大量无名对象」，而本内核没有。
> 这直接决定了 §3.2 B-3（声明式聚合量）与 B-9（物化 / 归档契约）必须成对出现：
> **聚合量负责「域外」，物化契约负责「域内被点名时」**，两者之间只允许走**显式事件**。

### 2.2 Dwarf Fortress：三层结构与「抽象 / 具体」教义

**机制**（来源见调研报告 §1–§7；证据分级【文档】/【访谈】/【社区】）：

1. **三层不是三个程序**：worldgen（年步进批量生成前史）→ fortress（tick 级局部模拟 + world activation 续写）→
   **legends = 对同一份事件 / 实体表的只读视图 + 序列化**。legends 不是第二次生成，XML dump 只是投影的一个出口，且明确不完整（可达 1 GB）。
2. **时间与错峰更新**：worldgen 只在年末暂停；fort 1 tick = 72 游戏秒、1 天 = 1200 ticks。
   最可迁移的是**分级节拍表**：每 1 tick（流体 / 温度 / 单位行动）、10（季节 + 围城）、50（酒馆神庙 / 库存）、100（job 分配、strange mood、**世界地图军队移动**、腐烂）、1000（对象释放）。
3. **FPS death 归因**：>60% 时间在「单位执行回合」，**寻路不到 10%**；次杀手是温度、物品堆栈、污染物、洞穴层。要塞内**没有任何 LOD / 降级**，只能靠玩家减量。
4. **抽象 / 具体边界有官方教义**：多数人口按 `entity_population` 抽象计数，只有 histfig / artifact 被显式追踪；
   **探索时生成一切、离开时抹掉一切，除了 histfig / artifact 及其关联**；Army 是纯抽象结构、每 100 ticks 在世界地图走一步；商队 / 外交官 / 移民 / 野兽直接瞬移。
5. **系统耦合主链**（值得抄的一条完整链）：personality facet(0–100，差 >60/<40 生 grudge) → need 权重(1/2/5/10) → focus(技能 ±50%)
   → 产出质量（masterwork 概率上限 1/3，且 masterwork 记入 Legends 并把制作者**升格为 histfig**）→ 关系 / 记忆 → 反塑 facet。
6. **确定性硬警告**：同种子可复现地理与命名，但**事件会变**（Bug 6934）；改任意 worldgen token 会移位 PRNG 消耗。
   ⇒ 应存「种子 + 参数快照 + 事件日志」，**不靠重跑复现**。
7. **哲学（Toady 一手引文）**：worldgen 是「零玩家策略游戏 + 松散回合 + 差 AI + 上千智能体，历史只是记录」；
   DF 的「智能」主要是**对记录的 importance 排序与筛选**；Legends 是「我们的还没有书的模式」。
   **关键警告**：人为给无名者补写「未发生的过去」会「绕进死结、充满不一致」。

**可迁移 Top 5**：
① **命名脊柱 + 匿名血肉**（只有少数量被显式追踪，其余按聚合计数）→ 本内核缺的正是这一层（§3.2 B-3）；
② **单一日志 + 多投影**（真相只有一份结构化表，文本永远是受门控的投影）→ 本内核已有（事件日志 + 认知接口），**本轮实测证明它是对的**（§1.5 的 8 句话是投影层的问题，不是日志层的问题）；
③ **分级节拍数据化**（cadence 写进数据，而非所有系统同频）→ 直接可用的成本优化（§3.1 A-2）；
④ **抽象 ↔ 具体实例化 / 卸载协议**（含「卸载后状态不愈合」这类反面教材）→ §3.2 B-7；
⑤ **写入时 importance 评分 + Top-K 检索**（筛选归引擎、润色归 LLM）→ 直接服务「世界越老，读路径越贵」的问题（§3.1 A-5）。

**陷阱三条**：① 全量 per-tick + 无 LOD；② 具体层物理保真 + 完整内部货币经济（Dwarven economy 已在 v53 移除）；
③ 让 LLM 反事实补写过去 / 把导出文本当权威存储。

### 2.3 RimWorld：导演 + 规则驱动的模拟

**机制**（来源见调研报告 §1–§7，证据分级【文档】/【自述】/【共识】/【推断】）：

1. **时间**：60 ticks/现实秒（1×）、2500 ticks/游戏小时、60,000 ticks/天。三档 tick 间隔（Normal 60 Hz / Rare 250 tick / Long 2000 tick），
   用 `HashOffset` 错相防止所有单位在同一 tick 齐步。**1.6 引入 VTR**（按状态与玩家视角降频，最低 4 Hz）并把寻路改为多线程 + Unity Burst——
   **官方自己承认全量 60 Hz 不可持续**。
2. **导演与模拟分离**：`Storyteller` 是**纯 AI 导演，没有实体**，只管「何时发生何类别」。
   真实口径：Cassandra `onDays 4.6 / offDays 6.0 / minSpacingDays 1.9 / minDaysPassed 11`，重大威胁 8.5 次/年；Phoebe 8/8；
   Randy 无周期无冷却、`mtbDays 1.35`、`maxThreatBigIntervalDays 13`、`randomPointsFactorRange 0.5–1.5`，
   类别权重 `Misc 3.5 / ThreatBig 1.4 / FactionArrival 2.4`。
   **触发语义是 MTB（均值 N 天的指数分布），不是「每 N tick 掷概率」**——这是与 isekai「每日硬预算」最本质的差别。
   自适应旋钮：`PopulationIntent`（按驻留天数 × 人口查曲线）与 `AdaptationFactor`（初始 0.8、30 天宽限、每 12 小时结算、`[-60,100] → 0.4–1.47`、跨地图共享）。
3. **威胁点数**（≈ 事件强度 / 规模的推导量）：约 1 点 = 1 战斗点，范围 35–10,000，
   `= f(财富点 + 人口点) × 威胁规模 × 起始因子 × 适配因子`，上限后再乘 Randy 的 0.5–1.5 或任务星级。
   财富 ≤14k 为 0、400k 为 2400、≥1M 封顶 4200；每人 15→140 点，奴隶 0.75 / 冬眠 0.3 / 婴儿 0 / 囚犯 0。**财富是玩家可操控的难度旋钮。**
4. **Agent 决策是规则驱动，不是效用驱动**：需求（Food / Rest / Recreation / Beauty / Comfort / Outdoors…）+ 心情双轨
   （Target 即时变，Mood 以 +12/−8 每小时追赶，睡眠时暂停崩溃风险）；崩溃阈值 35/20/5% 用 MTB 4 / 0.8 / 0.5 天，恢复给 +40 Catharsis（负反馈自稳）。
   决策结构是**规则优先级树**（`ThinkNode_Priority` 短路 + `Conditional` 谓词门 + `JobGiver` + `Subtree`，`insertTag` 是官方插桩点）
   + `JobDriver` 的 Toil 序列；群体用 `Lord/LordToil/StateGraph/Trigger` + `PawnDuty`。
   **全游戏唯一的效用评分只在战斗选目标**——这是本轮最重要的单条事实。
5. **数据组织**：Def XML 是**只读模板**，运行期是实例（`ThingWithComps` + `ThingComp` / `CompProperties`）；
   `DefPatch` / Harmony 做非破坏修改；`Tale` 是结构化叙事记录；历史界面 = 财富 / 人口 / 心情三曲线 + 事件色点。
6. **确定性是反面教材**：`Verse.Rand` 是**单一全局可变流**——多抽一次就全局漂移，且**症状远离病因**；
   帧态（`DrawPos`）曾被用作弹道原点；mod 改调用序列即破坏确定性。存档是**全状态快照**，
   **无回滚 / 分叉 / 重演，也无离线补算**。
7. **性能天花板**：热点是 `TickList.Tick ⊃ Pawn.Tick`（ThinkTree / WorkGiver / 寻路）；社区共识 **12–20 殖民者为设计区间、50+ 敌人必掉 TPS**；
   tick 超预算会**自动降 TPS 保 FPS**（这是保护阀，不是 bug）。失效是架构性的，只能靠 LOD / 降频 / 事件驱动缓解。

**可迁移 Top 5**：
① **MTB 调度语义 + 类别权重分层抽取**（保留每日硬预算做上限闸）→ §3.2 B-1；
② **on-off 周期 + 确定性自适应标量** → §3.2 B-1（密度档从常数升级为节律函数）；
③ **规则优先级树 + 谓词门 + 短路**（**不要**效用打分）→ §3.1 A-9（让 `intent.strength` 进决策）+ §3.2 B-2 的关系轴；
④ **Def 式只读模板 + 运行期实例 + 可打补丁（含官方插桩点）** → 与本内核「世界包声明 + 实例锁死」同构，可借其**插桩点**设计；
⑤ **随机流隔离 + 每批固定抽取次数 + 批内快照** → §3.1 A-8。

**不可迁移三条**：
① **「每 tick 全量更新」架构本身**——本内核的「墙钟时间盒 + 每世界日整批原子」在这一点上**优于**它，不要倒退引入固定步长 tick 循环；
② **威胁点数 / 财富曲线 / 面向玩家的难度自适应**——在 RimWorld 是合理产品设计，在本项目等于**为让用户好过而篡改世界因果**，
   违反 `EVENT_ENGINE_SPEC.md` §3.1#5 与本文裁决原则 3：**压力标量只能由世界状态推导，不能由用户行为 / 体验指标推导**；
③ **「存档 = 全状态快照 + 单一全局 RNG」的确定性方案**——RimWorld 不支持回滚 / 分叉 / 重演，而本内核恰恰需要；
   它的价值是反面教材：**进程态不入档、帧态漏进模拟、mod 改调用序列这三件事必须显式防御**。

### 2.4 Elin（与 Elona 谱系）：振荡器 + 挂在动词上的棘轮

**本轮调研推翻了 2026-09-19 的原判断**，并给出一个可直接改造内核的框架。

**「世界几乎不动」核验**（逐条证据见调研报告 §3）：

| 原判断的支柱 | 核验结果 |
|---|---|
| 「NPC 死了就是死了」 | **错（对 Elin）**。默认**可逆**：居民 / 宠物被击败后**7 天定时重生**（有护理爱好则 1 天）。不可逆只发生在**玩家主动的三类处置**上：肢解（`Slaughter`）、驱逐（`Banishment`）、贴售签卖给访客——这三条是**永久删除**，酒保与护理都无法恢复 |
| 城镇会被摧毁 | **会，但会自己修好**。Elona 里花 12,000GP 买核弹炸掉 Palmia，代价是 −200 karma，而「**Palmia 会在一两周后重建**」。**连「炸掉首都」都被写成插曲而非状态**——因为世界必须保持可用 |
| 任务有时限 | 是，硬时限 + 不可取消（上限 5 件，只能弃单并计失败）；演奏类限时 3 小时；**任务地图不可二次进入** ⇒ 掉落物结构性不可回收 |
| 玩家行为留痕 | **是，这是本作真正的「世界记忆」层**：死亡点的骷髅标记与掉落金钱（除非地图重生成）、`Palmia Times` **报纸会登记玩家的婚姻（伴侣 / 时间 / 地点）**、被肢解 / 驱逐 / 售出的居民、**被击败的 Boss 不复活**、发布的地图**不可撤回**、以太病症状**强度永久固定**（只能按 LIFO 移除最新症状） |

**修正后的准确表述**（调研报告 §3.5 的判断，本文压缩转述）：

> **世界本身不做状态演化，它做的是「固定节拍的重置与再分配」**（天气队列推进、冒险者复活并随机改派城镇、随机地城重掷、每小时刷新全球地图上的强盗 / 商人、每天 5 点的包裹流、每年重复的节庆日历）。
> **所有真正的「不可逆」都挂在玩家动词上。世界不会因为时间流逝而变得不同；它只会因为你做过什么而变得不同。**

**系统动力学（调研报告 §8）**：

- **振荡器（oscillators，无状态累积）**：天气队列（10–34 小时一换）、节庆日历、每月税单 / 薪水、每小时全球地图刷新、每天 5 点发货、每 90 天解锁死亡惩罚、**每两个月**圣井充能、每年许愿计数 −1、每约 2000 回合以太病程 +1。
  **它们都在「回到同一个值」的循环里运动。世界是一台振荡器，不是一台积分器。**
- **棘轮（ratchets，只增不减）**：**几乎全部锚定在「玩家做过什么」而非「时间过了多久」**——NPC 处置、Boss 击杀、主线选择、地图发布、Permadeath、以太病症状、报纸上的婚姻记录；物质侧是土地肥力、育种 +值、炉石等级（**危险度随之上升，自带负反馈**）。
- **正反馈回路**（滚雪球，主要驱动力）与**负反馈限速器**并存：肥力消耗、炉石等级↑⇒危险度↑、人口超限每人 −20% 效率、**税收随名声上升（成功本身产生成本）**、兴趣度消耗后需离场恢复、委托槽上限、重复买地契价格翻倍。
- **一句话总结**：**Elin 的世界是一个「振荡器 + 一组挂在玩家动词上的棘轮」。** 故事量完全由动词互锁提供。

**玩法动词集与互锁（调研报告 §4，本项目最关心的一节）**：

- **规模**：约 **70+ 个机制族**（wiki `Mechanics` 索引页列出约 67 条）、**50+ 个 NPC 可执行动作**（`AI__*` 反编译清单）、**60+ 种任务类型**、**2716 个类**；每族内还有若干具体动作（仅 Crafting 一族就有 13 种工作台）。
- **互锁的形态是「一个动词的产出正好是另一个动词的必需输入」**，调研报告 §4.3 给出 **11 条**有 wiki 文本支撑的链条（§4.4 另有动词的不可逆代价汇总），典型如：
  `战斗 → 怪物种族决定肉/蛋特性 → 烹饪 → 属性成长 → 战斗`（**打怪不是为了经验，是为了食材的属性配方**）；
  `怪物等级 → 奶的 +值 → 幼体技能 → 战力 → 更深地城`（闭合正反馈环）；
  `Nefia → 强化种子 → 农业 → 更好产出 → 更强队伍 → 更深 Nefia`（地城深度与农业技能双向约束）；
  `装修 → 旅游价值 / 传家宝 → 家庭排名前 125 → 月薪 → 更多装修`；
  以及两条极端的：**信仰直接改写其他动词的成功率**；**香水 / 气味消耗品直接调整全球地图的袭击事件发生率**。
- **好感度 ↔ 几乎所有系统**（招募、婚姻、居民效率、宠物 feat 点数、共生 / 骑乘经验）。

**共享世界与离线**（调研报告 §5，两处结论都很硬）：

- **「共享世界」= 地图快照托管，不是联机模拟**：把自家地图发布到托管池，别人通过门传送过来参观；数据**单向**（访客只能带走画作 / 同人书等**作品**，不能改变对方任何状态），**发布后不可删除**；没有共享时钟、没有共享事件、没有跨玩家因果。
- **离线时世界不推进（代码级证明）**：全部时间推进入口是 `GameDate.AdvanceSec/AdvanceMin/...`，唯一驱动是游戏主循环 `GameUpdater.Update()`；世界级状态（`World.date` / `weather` / `season` / `dayData` / `ether`）全部序列化进存档，**没有任何时间戳字段用于追赶，也不存在 `CatchUp(hours)` 一类方法**。
  ⇒ 这是与 isekai 内核**最本质的分歧**（内核 `§2.2#4` 要求离线补算）。
- ⚠️ **一个反直觉但极重要的推论**：**因为世界不推进，Elin 才敢把那么多东西做成「定时重置」**（7 天复活居民、8 天消失的随机 Nefia、每小时刷新的强盗）。**若把这些定时器搬到会离线推进的内核上，它们会在玩家不在场时把内容消耗掉，玩家回来只看到一地被烧过的定时器。**

**可迁移 Top 5**（调研报告 §9）：
① **「按世界日的确定性再分配」而不是「按世界日的状态演化」**——Elin 的 `AdvanceDay()` 每天只做 O(1) 的事（掷当日种子、10% 概率复活并改派冒险者、按历法硬日期发信发礼），**天然满足内核的确定性要求**；
② **`World.ModEther` 式的「世界状态写入点挂钩」**——这是全篇唯一一处「角色状态自动回写世界状态」，实现方式只有 3 行（带阈值的累加器：`ether += a; if (ether >= 100) { ether = 0; weather.SetCondition(Ether, 24); }`）。
   **可迁移的是挂钩点的选择：不要建模因果，只在世界状态机的写入点上挂一个带阈值的累加器**；
③ **不可逆性挂在动词上，而不是挂在时间上**——直接降低补算成本：补算只需重放振荡器，棘轮由输入驱动、天然不需要追赶；
④ **玩家痕迹进入「世界介质」（报纸 / 排名 / 骷髅标记）**——`Palmia Times` 会登记玩家的婚姻。**「报纸」就是一个渠道，上面登的是「说法」**：这给内核一个高价值的具体用法（把玩家重大行为作为渠道事件发布，让 NPC 能读到它，同时保留失真可能）；
⑤ **「发布快照」式的异步共享，而非联机模拟**——冻结快照 + 单向只读访问 + 少量可带走的实体，就足以产生「别人的世界存在」的感觉，**完全不需要共享时钟或并发一致性**。

**不可迁移三条**（调研报告 §10）：
① **不要照搬「世界不推进、离线冻结」**——内核的立场恰好相反；正确借鉴是**分层**（可补算的振荡器 vs 输入驱动的棘轮）；
② **不要用「每 N 回合掷一次骰子」冒充世界演化——那是空函数**。决定性证据：`RelationManager.UpdateRelations()` 被 `AdvanceDay()` 每天调用，**方法体是空的**；「NPC 迁移」是瞬移；势力效果只作用于玩家势力。
   这解释了为什么 Elin 的世界**读起来**是活的（报纸、排行榜、迁移的冒险者），但**住进去**会发现 NPC 之间的关系从未改变——**这是一个昂贵的假象**。**要么真的建模关系，要么明确声明关系层不建模，不要留一个空函数。**
③ **不要接受「读档重掷随机世界状态」**——Elin 明确允许存读档重掷该层的神龛 / 雕像类型。**陷阱**：一旦某个世界状态由「时间 + 随机」产生且**未绑定到已提交事件**，用户就能通过回滚反复重掷它，**「确定性」在用户可见层面就失效了**。正确做法（内核已有语汇）：**把随机结果固化进已提交事件**，使重掷的代价等于重掷整条因果链。

### 2.5 Songs of Syx：「一个首都的深度」，以及被营销话术掩盖的抽象边界

**基本情况**【文档/媒体】：Gamatron AB（瑞典独立工作室，**单人主导**，主导开发者 **Jakob de Laval**，社区多称 Jake）；
2015 年起开发（Steam 自述），**2020-09-21 起抢先体验**，至今未 1.0；Java + **自研引擎 Snake2d** + LWJGL 3.x，**不是** Unity/Unreal/MonoGame；
低奇幻、随机生成世界、单人；**常被媒体与 RimWorld / Civilization / Total War 相比**【媒体：GameStar 2020-01 / 2025-12，德文 Wikipedia 亦如此概括】；Steam 约 **95% 好评**【媒体：GameStar 2025-12】。

**「真实模拟每个角色、不省略」的核实结论：部分成立，且边界是官方设计。**

- **成立的部分（仅限玩家自己的首都）**：每个 citizen / slave / noble / child / soldier 都是独立实体，带
  姓名与肖像、personality 与 traits、**出身标签**（native / immigrant / former slave / ex-convict）、
  **七类 fulfillment 需求**、工作班次与优先级（45 秒「取料 → 产出」循环）、装备与负重、
  健康 / 医院 / 疾病、士兵经验与近战 / 远程训练 / 击杀 / 溃逃、信仰与改信、
  **退休年龄 = 预期寿命的一半**、自然死亡与死因统计、
  **V71 起怀孕 / 婴儿 / 儿童 + 家谱**（最多 100 万条，**满树**约 **6 MB**）、V67 起传记。
  **未观察到配偶 / 婚姻机制**（调研报告列为「未能确证」，证据倾向没有——本文不写成「确定没有」）。
- **不成立的部分（界外一律是抽象）**：

| 层 | 形态 | 处理方式 |
|---|---|---|
| 玩家首都内 subjects | **真个体** | 逐个体字段 + 状态机 + 移动 + 需求 + 工作班次 |
| 首都的「未来人口」 | **抽象池** | `potential immigrants` 计数 + 按幸福度概率生成，**落地才成为个体** |
| 世界地图 region 的人口 | **各族计数 + 日增率 + 等级阈值** | 公式增长，非个体 |
| region 经济 | `production / knowledge / worth / prospects`、税收、关税 | **宏观标量直接参与结算** |
| 其它派系 | 关系标量（opinion / rivalry / trust）+ 军队对象 + 财富值 | 谈判 / 宣战 / AI 战争走 **`auto-resolve` 聚合结算** |
| AI 兵源 | **`conscript pool`（再生资源）** | 从池里「生成」军队，不是征召真人 |
| 掠夺者 / 商队 / 游客 / 使节 | 预生成或按事件生成的**少量实体** | 有限集、有名字与位置、可被杀死 |
| 世界地图产出 / 税收 | 由区域标量直接产生，经车队 / 收获日流入你城 | 数值驱动 + 少量实体运输表现 |

- **最赤裸的两处「假数字」**：V68「net worth includes **worth of your population as slaves**（每个 pop = 养育时长 × 最便宜食物 × 2）」；
  V68「**Excess world workforce generates denari**」（世界劳动力盈余直接生钱）。
- **V71 之前繁殖甚至是一条配方**：Garthimi 至今仍是「1 个孩子 = 2 天工时 + 2 肉」。

**设计哲学原话（逐字，含 URL）**【自述/文档】：

> 官网：「Its uniqueness comes from having huge populations, while still **simulating each individual in great detail** and providing big maps with 1:1 scale buildings.」
> Steam 商店页：「Watch tens of thousands of **individually simulated** citizens and slaves interact: each with their own life, religion, fears and desires.」
> Steam 商店页：「**Each soldier is simulated** and will require supplies produced by the industrial might of your great state.」
> **Jake（2026-01-20 dev log，最诚实的一句）**：「I always try to keep it real, but **in order to do so fully, we'd need an in-game day to be a real day**, and that is a problem in itself. So **I patch up reality here and there** to give us all a more fun experience.」
> **Jake（关于生产 tooltip）**：「**what's stated in the tooltip does not represent reality. Reality is based on the individual workers working their shifts, commuting and fetching input.**」
> **Jake（关于产业平衡）**：「…**make all industries fundamentally equal in profitability, at the cost of reality**.」
> **Jake（关于家谱）**：「A completely useless feature, but puts some fluff on the future child rearing and immersion. **Meat on the bones**, so to speak.」
> V71 公告：「A family tree holds up to a million entries… **so each subject finally has their own story to tell.**」

**结构判定：它是双引擎，不是「无省略」**【自述 + 文档 + 推断】——
**焦点域内微观自下而上**（食物真的被个体从田里搬运到仓库 / 餐厅 / 嘴里；tooltip 上的数字只是**估计值**），
**焦点域外宏观自上而下**（计数器 / 比率 / `auto-resolve`），
两者靠**少量接口事件**耦合：移民生成、入侵生成、税收 / 贡赋、收获日发货、车队 / 商队。

**⚠️ 一条必须写下来的核实**：**【未能证实的说法】「官方声称不做 LOD / 不省略」没有来源支撑。**
商店页的「individually simulated」是**营销文案**，不是工程承诺；工程上它更可能是**按需驱动**（没有工人就没有寻路、战斗只在接触时结算、需求与生育按「天」推进），
而**没有证据**表明存在「屏幕外居民降级为统计量」的经典 LOD。**不要把营销话术写进设计目标**（§五 5.2）。

**技术实现（决定它能否被抄）**【文档/推断，工程细节见调研报告】：
Java + 自研引擎 + 自研容器 + **单线程**（开发者：性能「主要取决于单个 CPU 核心」，「多线程 = 重写整个游戏」；玩家实测单核跑满、其余核约 5%）；
**零分配纪律**（开发者原话：「我是以一种不产生垃圾的方式编程的」）、`SerialGC`、`byte` 位域、整数索引查全局属性表；
**战斗逐单位结算**（官方宣称至多 5 万单位），编队只给数值加成、不承担结算抽象；
存档是**稀疏二进制**（默认值不落库）；**大版本更新必定破坏旧存档**（V71 公告直言「Your saves will break」），
同 seed 只「more or less the same」、**save-scum 有效**。
实测瓶颈排序：**单核 > 寻路 > 工作分配 > 渲染 > GC**；`i9-14900K` 级机器约 **6k 居民**开始降速（有玩家 5k–10k 无事，主观差异大），玩家实测约 **16,000 触顶**。

**可迁移 Top 5**：
① **关注域分层 + 显式晋升 / 降级契约**：`world_ledger`（域外计数器与比率）＋ 常驻 agent（域内焦点）；
   **当角色与账本交互或账本跨阈值时，用确定性物化函数「点名」出一个个体**，交互结束可收回归档 → §3.2 B-9；
② **个体 = 统一浅状态机 + 数据驱动计划**（用数值优先级表 + 班次推进驱动叙事，而不是每回合自由生成）→ 与 A-9 的「规则树 + 谓词门」同向；
③ **派生细节按需物化**（名字 / 传记 / 家谱 = 账本为骨、文档为肉；6 字节/条的量化证明）→ §3.2 B-6 的「渲染」与 §4.1 的**角色传记视图**；
④ **宏观量显式成账本 + 只允许通过事件与微观耦合**（移民 / 入侵 / 贸易 / 征税是**唯一**允许「个体 ⇄ 计数」互换的口子）→ B-3 + B-9；
⑤ **「可见的东西与不可见的推算是同一套原语」**：SoS 的真实感来自「tooltip 是估计、现实是个体行为」——对本内核的对应纪律是
   **对外文本一律从账本 / 事件渲染，宁可少说不可说错**。

**不可迁移三条**：
① **实时 tick + 逐 agent 主循环 + 时间压缩**：与本内核「离线确定性补算 + 每世界日整批原子」正面冲突；引入它会同时失去确定性与性能（B-8 已把它列为禁止项）；
② **自研引擎 / 自研容器 / GC 调优 / 单核垂直压榨**：这是**一人十一年**的产物，收益只有「单核多塞几千居民」；在 Python + SQLite 里是负收益。
   **可迁移的只有原则**（紧凑编码、整数时间戳、索引化），不是实现；
③ **「为体验抹平现实」与「让 UI 数字与模拟脱钩」**：在单人图形游戏里可接受（玩家只看结果），
   在**以 LLM 文本为表达层**的内核里是毒药——叙述层一旦与账本不一致，LLM 会放大矛盾并编造历史。

> **成本警告（必须写进决策记录）**：Songs of Syx 证明的是「**一个顶级工程师愿意花十一年手工压榨单核**」可行，
> **不是「某种架构可以让你也做到」**。任何「照抄 SoS 路线」的估算，**起价 10 人年以上**的引擎与模拟内核投入，
> 且它至今未到 1.0。**把它当作「逐个体模拟确实可行」的存在性证明 + 三条原则来源，不要当作可复制的架构模板。**

### 2.6 Baldur's Gate 3：手工编排 + 通用规则引擎（已证实，且比预期更硬）

**机制**（来源见调研报告 §1–§7，含 40 条 URL）：

1. **没有自主模拟，而且是公开选择**：2020-03 Larian 官方宣布 BG3 **不做昼夜循环、不做模拟世界**（NPC 不响应时间、不循日程），
   理由是「重点是讲故事而非模拟世界」。**时间只在结算面有语义**（长休结算营地事件队列 + 少数脚本化 deadline + 跨 act 截断）。
   数据挖掘到的反证：若提夫林全灭，Act 3 会在**原位**生成行为如常的僵尸版本——位置是场景摆设，出场者由 flag 决定。
2. **系统交互 = 闭集原语 × 正交规则的乘积**：surface 之间按元素互相转化（水+电→电水、冰+火→水、酒+火→火、油被点燃→爆炸）、
   status 与 surface 正交、高度 / 重量参与规则（调研报告 §2；该报告未给出 surface 的精确种类数，本文不填数）。
   开发者原话：「我们放这些系统进去就是为了让你滥用」。**不驱动任何 NPC 动机**，成本在规则表的正交性，不在算力。
3. **状态与脚本**：Osiris 是官方文档确证的声明式层，操作「唯一一张、游戏范围的数据库」，
   规则仅 `IF event AND query THEN call`（**无 OR**，析取靠命名查询），879 个 API 撬动效果组合。
   **关键结构：每个 level 一个 goal，进入时构建、`EXIT` 时清理以缩小存档**；mod 用「版本号 DB + 载入时 `SysClear` 重建」做迁移。
4. **规模的真实成因**：17,000 种结局变化 = **共享尾声文本 × 条件门的组合**，靠一张「一行又一行」的电子表格人工核对。
5. **确定性与存档**：d20 + 显式百分比；Karmic Dice 默认开启，per-faction 债务、对话检定单独记账，`p^(1-Debt)` 概率自动成功，
   官方定性为「一个友善的 DM」。存档是扁平事实表，**可被玩家直接编辑**。

**可迁移 Top 5**（按收益 / 成本排序）：
① **扁平谓词事实表**（让「说法 / 实情」天然成为同一表上的两个视图，而不是两套数据）；
② **作用域 goal 生命周期 + schema 版本迁移**（进入构建 / 结束回收 / 载入迁移）——**直接对应本内核「什么都不退休」的缺口**；
③ **效果与条件的闭集组合律**（任意两原语相遇必须有一条合成规则；LLM 只选组合与表达，不发明效果）；
④ **对话 / 叙事 DAG + flag 前置 + 组合矩阵自动审计**（同一内容多入口；用工程手段而非直觉控制分支爆炸）；
⑤ **业力账本**（可关闭、按主体 / 域分账、长期分布不失真）——把「叙事不可用性」压到可接受区间的廉价手段。

**明确不能抄三条**：
N1 **不能抄「无时间语义的世界」**（可抄其形态：时间推进做成离散事件队列 + 到期结算，而不是逐 NPC tick）；
N2 **不能抄 236 小时配音 + 逐结局人工核对的表达层**（可抄结构，不可抄资产）；
N3 **不能抄 point-of-no-return 式丢弃历史 + 可被玩家直接编辑的权威存档**（可抄阶段化冻结 / 归档，不可抄丢历史与无校验存储）。

**反例价值**：BG3 证明了「手工编排 + 通用规则引擎」的反应深度上限极高，
同时证明了它的成本结构（巨型写作团队 + 配音 + 逐结局人工核对）**无法支撑无人运行的世界**。
原话——Vincke：「我们一直把它当作**古怪的 DM** 来处理：玩家会找到一切，我们只能预先设想所有玩家想做什么——当然这不可能」。
**这就是 BG3 架构的墓志铭：它的上限由「人预先设想」决定；持续世界内核的立身之本恰恰是取消这个上限。**

### 2.7 五作交叉后落下的六条结论

| # | 结论 | 来源 | 对本内核的动作 |
|---|---|---|---|
| 1 | **代价必须随「离玩家 / 离当下的距离」衰减**：DF 只精算看得见的地方，其余按聚合计数；BG3 只在当前 level 建规则库；**Songs of Syx 只在自家首都**全细节 | DF §4、BG3 §3.2、SoS §2 | 新增**作用域生命周期 + 分级节拍 + 退休契约**（§3.2 B-7、§3.1 A-2/A-4） |

| 6 | **抽象必须画在一个轴上，并显式声明域外是什么**：五作各画在对象 / 焦点域 / 节拍 / 因果 / 关卡上；**没有一部是「模拟一切」** | §2.1b（DF / SoS / RimWorld / Elin / BG3） | 本内核该画在**作用域 + 节拍**上；域外由**声明式聚合量**承担，域内被点名时由**确定性物化函数**产出，两者之间**只允许走显式事件**（§3.2 B-3 + B-9） |

**五作都没有、本内核独有的三件事**：① per-agent 的**说法 / 实情分离**（含传播到达时刻与主观确信）；
② **可复算的时间线分叉 / 回滚**；③ **用户不在线也推进的确定性补算**（Elin 与 RimWorld 都明确没有，DF 的 worldgen 事件甚至同种子不可复现）。
这三件事是 §4 体裁推荐的唯一依据。

## 三、设计改动提案

### 3.0 分级与三条裁决原则

- **A 类（优化与纠错）**：不改世界语义、不改对角色 / 用户可见的行为，只改成本、可复现性与正确性。**可立即拆分实施**。
- **B 类（模拟能力扩展）**：新增世界状态维度或改变世界变化的驱动方式，**须先裁决原则再改码**。

任何一条改动都必须过这三道闸，过不了就砍掉（不写「预留」）：

| # | 原则 | 检验问法 |
|---|---|---|
| 1 | **可复算**（`DESIGN.md` §2.2#14） | 同一锁定设定 + 种子 + 前序状态 + 固化输入 + 规则版本，是否仍得同一答案？是否引入进程随机化 / 帧态 / 调用顺序依赖？ |
| 2 | **认知边界**（`DESIGN.md` §2.2#5/#6） | 是否让实情层越层泄漏？是否让「可能听到」变成「已经听到」？ |
| 3 | **不篡改因果**（`EVENT_ENGINE_SPEC.md` §3.1#5「没有合法依据时保留后果，不为凑故事强行续发」） | 是否引入「为让用户好过 / 为让故事好看而改变世界因果」的旋钮？ |

> 第 3 条是**从 RimWorld 的反面教训里反推出来的**：威胁点数 / 财富曲线 / 面向玩家的难度自适应，
> 在 RimWorld 里是合理的产品设计，在「世界为主体、用户在世界外」的本项目里等于**篡改世界因果**。
> 因此 §3.2 B-1 的压力标量**只能由世界状态推导，不能由用户行为 / 体验指标推导**。

### 3.1 A 类：优化与纠错（不改语义）

**统一验收口径**（全部 A 类共用）：在同一实例上，
**第 10 世界日与第 1500 世界日的「每世界日推进耗时」之比 ≤ 1.2×**，
且**在实测 E 的 8000 条在位记忆条件下，每批额外耗时 ≤ 2 ms**。当前基线分别为 23×（实测 A）与 +45~56 ms（实测 E）。

| # | 问题（证据） | 机制 | 落点 | 验收 |

### 3.2 B 类：模拟能力扩展（须先裁决）

每条给出：**问题 → 提案机制 → 落点 → 与现行规格的关系 → 验收**。成本评级沿用状态审计 §9 的口径。

#### B-1 状态耦合的最小动力学：压力标量 → 候选权重与到达语义【借 RimWorld】

- **问题**：世界级事件的候选权重不读世界状态（`EVENT_ENGINE_SPEC.md` §四 只规定密度档与固定权重；附录 A 的抽样输入只有种子 / 日期 / 密度 / 槽序）。
  世界因此**不会因为「局势紧张」而更容易出事**，也不会因为「稳定繁荣」而平静——变化与状态解耦。
- **提案机制**（三步，都为确定性纯函数）：
  1. **声明式压力量**：世界包新增段 `pressures[]`：`{id, name, 取值域（档位或整数）, 初始值, 来源（自然变化 / 事件效果 / 推导式）, 作用域（全局 / 区域 / 组织）}`。
     它不是新的事实类型，而是**在既有 `effect_state` + 环境事实范式上加一层可被引用的量**。
  2. **候选权重函数**：事件模板声明 `weight_expr`——对压力量的**单调、可解释、纯函数**表达式（如 `base × (1 + k × pressure)`）。
     **禁止**由用户行为 / 体验指标 / 现实时间推导（违反裁决原则 3）。
  3. **到达语义（借 RimWorld 的 MTB，但保留每日硬预算）**：把「先定当日数量、再等概率选候选」
     升级为「按权重算出**到达强度** → 采样到达时刻 → 由**每日硬预算封顶**」。
     这样既保留「不得只做独立概率抽样却宣称严格上限」的现有义务，又让**发生与否**由状态决定；
     同时把 `on-off 周期`（RimWorld 的 `onDays/offDays`）作为密度档的可选形态引入——
     世界包可以声明「每 30 日中有 4.6 日偏动、6.0 日偏静」，而不是一个常数。
- **落点**：`world/package.py` 骨架（新段）、`world/validate.py`（分派 + 校验 + `_all_ids` 引用闭包）、
  `runtime/events.py:99-116`（`_templates` / `draw_slot` 权重）、`:160-190`（`plan_day` 到达与预算）、
  `service.py:3906`（`_world_event_rows`）、`EVENT_ENGINE_SPEC.md` §四 + 附录 A。
- **与现行规格的关系**：**修订**（§四 与附录 A 需改写；「密度档 = 目标区间」改为「到达强度 + 硬预算上界」）。
  可复算义务不变：压力量、权重函数、抽样输入全部确定性。
- **配套的决策形态（借 RimWorld 的 ThinkTree，附其调研报告的一手结论）**：RimWorld 的 agent 决策是
  **规则驱动的优先级树 + 谓词门 + 短路**，「无效用函数、无市场竞价、无成本收益权衡——规则驱动 + 玩家手动配置」，
  **唯一**的效用式评分只在战斗目标选择。因此本内核的角色决策应走**声明式规则树**
  （`Priority`（顺序试、首个有效即短路）→ `Conditional`（谓词门）→ `意图` → 步骤序列，**只做状态转移、不进 tick**），
  **不要在规则树上加效用打分**：文本世界里的「她为什么选这个」必须**可解释、可审计**，而不是分数比大小。
  这同时给了 `intent.strength`（§3.1 A-9）一个正当去处分——**作为谓词门的比较输入，而不是总效用**。
- **验收**：① 同设定 + 种子 + 前序 → 同到达序列；② 人为提高某压力量，候选权重与发生频次**单调变化且可解释**；
  ③ 每日硬预算仍是不可越过的上界；④ 无合法候选时仍留白（不得为了压力高就凭空造事件）；⑤ 压力量本身不得由用户行为推导（裁决原则 3 的回归测试）。

#### B-2 关系模型：角色 ↔ 角色 / 角色 ↔ 组织

- **问题**：角色间关系**零字段**。最近似物是 `disclosure`（信息授权边，不是社会关系）与 `reaction.tendency`（自由文本，不可查询不可比较）。
  **社会拓扑是星形**：所有角色只与用户相连，角色之间没有边——而「世界为主体」要求角色生活在**同一个社会**里。
- **提案机制**：新增**闭集关系轴 + 强度标量 + 来源依据**的状态域，完全复用 `institutions` 已有的三闸范式
  （包校验声明 → 模板效果校验 → 运行期再判一次，不允许就 `continue` 不落状态）：
  - 关系轴闭集（首版建议）：`亲属 / 同僚 / 恩情 / 债务 / 宿怨 / 隶属`；
  - 每条关系记录 `{from, to, axis, strength∈[0,1], basis(来源事件 / 说法 id), from_world, updated_world}`；
  - **强度只沿已有依据变化**（与性格单元同一纪律：不允许无来源的数值漂移）；
  - 关系变化必须走事件效果（新增 `relation_change` 闭集项），并**只对已获知该事件的角色生效**（认知边界）。
- **落点**：世界包新段 `relations`（声明哪些轴在本题材启用）、`world/validate.py`、新表 `relation_state`、
  **A-7 的状态域注册表**（否则又是四处手工改动）、`runtime/events.py` 效果闭集、`runtime/cognition.py`（关系是否可见要按获知过滤）。
- **与现行规格的关系**：**冲突**——`MEMORY_SPEC.md:134`「不引入用户模型 / 关系模型」、
  `WORLD_RUNTIME_INTERFACE_SPEC.md:566`「资源量与关系变化在闭集里没有对应项，如实 `rejected`」。
  **必须先裁决这条规格**：建议改为「不引入**用户对世界**的好感 / 信任数值」，而**允许世界内角色之间的关系**——
  两者不是一回事（前者是用户模型，后者是世界状态）。
- **验收**：① 关系只能由合法事件 + 已获知依据改变；② 回滚 / 分叉 / 导入导出一致；③ 认知接口按获知过滤，
  未获知的关系不出现在任何角色的视图里；④ 新增一个关系轴不需要改四处代码。
- **成本**：中（关系轴闭集）／高（若要做势力对抗）。

#### B-3 聚合量：人口 / 财力 / 人力档 + 声明式推导

- **问题**：`org` 实体只有名字；`institution_state` 只有 `holder`；环境事实是**离散枚举且逐行独立、无交叉读取**
  ⇒「人口 → 税收 → 军力」在代码里没有任何落点。
- **提案机制**（借 DF 的「命名脊柱 + 匿名血肉」）：
  1. **聚合量**：区域 / 组织可带**声明式数值档**（不是精确人口，而是档位或整数），取值域、单位、初始值、变化来源全部由世界包声明；
  2. **推导规则**：世界包声明少量**纯函数推导式**（如 `税收 = f(人口档) × 税率`），**只允许声明式、可静态检查、无副作用**；
  3. **匿名血肉**：聚合量不生成具名角色——只有被事件 / 角色行动**指涉**时才登记为具名实体（DF 的 histfig 教义）；
  4. **挂钩点而非因果模型**（借 Elin 的 `World.ModEther`，全篇唯一一处「角色状态自动回写世界状态」，只有 3 行）：
     在**世界状态机的写入点**上挂一个**带阈值的累加器**（`ether += a; if (ether >= 100) { ether = 0; → 触发某环境状态 }`），
     而不是去建模「角色处境 → 世界后果」的因果链。角色的处境（污染、声望、疾病、压力）因此能真的改变世界，**且不需要模拟**。
     落点即环境事实状态的「自然来源按世界日确定推进」——**把累加器与阈值也纳入声明式取值域**；
  5. **边界写清**：**角色身体层不做数值系统**（沿用「不默认建立健康值、饥饿值」），
     **世界聚合层才做**——两者不在一个层，不构成冲突。
- **落点**：世界包新段 `aggregates` + `derivations`、新表 `aggregate_state`、`world/validate.py`、A-7 注册表、效果闭集新增 `aggregate_change`。
- **与现行规格的关系**：**修订**——`WORLD_SETTING_SPEC.md`「不为配额添加人口或组织」的表述需限定为「不为叙事配额添加」；
  `runtime/change.py:50` 拒绝 `resource_change` 的口径需按「聚合量 vs 角色身体量」重述。
- **验收**：① 推导式可静态检查、无副作用、同输入同输出；② 聚合量变化只由声明来源产生；
  ③ 指涉到具体角色时才登记实体，且登记走既有名册门槛；④ 认知投影给出的是观察档位，不是精确数值。
- **与 B-9 的关系（重要）**：B-3 定义**域外的量**，但它单独存在会退化成「没来源的漂移数字」——
  正是 Songs of Syx 被其开发者自陈「patch up reality」的那种假数字。
  因此 **B-3 必须与 B-9 成对实施**：聚合量的每一次变化要么来自**声明的自然变化函数**，要么来自**显式接口事件**；
  任何「直接插值」都必须写进世界包并在创建期校验。
- **成本**：中（只做量与声明式推导）／高（若要做量间动态反馈）。

#### B-4 空间的最小形态：拓扑而非坐标

- **问题**：`regions` 显式声明「无几何 / 路网」，`route_blocked` 效果打在区域或渠道标识上——
  **「路断了」推不出「谁因此到不了哪」**。传播延迟与事件影响范围也因此只能靠叙事标签硬编码。
- **提案机制**（保住「无坐标」原则的折中）：
  1. 给 `regions` / `place` 实体加**邻接表 + 通行代价档**（相邻 / 可通行 / 受阻 + 1–3 档代价），**不给坐标**；
  2. 用途**只限三处**：① 说法传播延迟（渠道到某区域的到达时刻）；② 事件影响范围的计算；
     ③ 生活线活动的可达性判定（「去某地」变成「在可达集合内换活动」）；
  3. **明确不做**：寻路、渲染、连续距离、通行模拟。消费者侧的渲染地图仍按总纲附录 A 由种子程序化推导。
- **落点**：世界包新段（区域邻接）、`world/validate.py`（引用闭包 + 连通性校验）、
  `runtime/environment.py` / `runtime/life.py` 的可达判定、传播延迟计算（`events.claim_rows` 的 `earliest_world`）。
- **与现行规格的关系**：**修订**——`WORLD_RUNTIME_SPEC.md:235`「不引入坐标、路网或通行模拟」需限定为「不引入坐标与通行模拟」；
  `EVENT_ENGINE_SPEC.md:30`「不是坐标或路网系统」需改为「是拓扑，不是坐标」。
- **验收**：① 拓扑是引用闭集（悬空即创建前失败）；② 传播延迟随拓扑可解释；
  ③ 核心里**没有任何**坐标 / 距离 / 寻路符号（结构断言）；④ 同一拓扑下分批补算的到达时刻一致。
- **成本**：中（走拓扑路线）／高（若走坐标 + 寻路）。

#### B-5 致死与致伤进闭集

- **问题**：效果闭集 8 项**没有任何一项能改生死或伤势**——**事件打不死人**。
  致死只有寿命带或卡片 `identity.died`。战斗、灾难、刺杀、瘟疫都无法落成世界事实。
- **提案机制**：新增 `casualty` 效果（**程度档 + 恢复条件 + 失效方式**，不是健康值系统）：
  - 程度档：`轻伤 / 重伤 / 失能 / 死亡`（沿用 `activity_constraint` 的效果范式，不引入 HP）；
  - 与归档状态同批置位（沿用 `character_state.archived` 的既有义务 `DESIGN.md` §5.2）；
  - **规则细节仍归 TRPG 规则插件**（`WORLD_RUNTIME_INTERFACE_SPEC.md:44-53` 的边界不变）：
    核心只提供「可被裁定结果声明的后果」，不提供伤害公式、属性、回合。
- **落点**：`world/validate.py:678-687`（`SUPPORTED_EFFECTS`）、`runtime/events.py:32-41`（`EFFECT_PRIORITY`）、
  `runtime/change.py:38-47`、`runtime/service.py:3990-4056`（死亡路径复用）。
- **与现行规格的关系**：**修订**——`EVENT_ENGINE_SPEC.md:125`「身体类效果只按题材选择受支持的闭集（例如受伤、疾病或疲劳）」
  **规格本来就允许受伤**，是实现漏了；`casualty` 应补进闭集并给出失效方式。
- **验收**：① 受支持的 `casualty` 效果能改变伤势档并可被解除 / 自然恢复；② 死亡与归档态同批原子；
  ③ 未声明的效果仍被拒绝；④ 未引入任何通用数值（无 HP / 无健康值 / 无饥饿值）。
- **成本**：中（只做宣告）／高（若要在核心里做战斗结算——**不建议**）。

#### B-6 说法层的内容差异化（本轮实测直接催生）

- **问题**：**实测 1500 世界日、9147 条说法只有 8 条不同文本**（§1.5）：每个事件给三个来源发的说法文本完全相同，
  两角色 claim 交集为 0（结构分离成立）但**看到的文本完全一样**（内容分离不成立）。
  原因是 `events.py:259` 取 `event.summary`，而把骨架表述成人话的 `event.render` 是**显式管理操作**、不在推进路径上。
- **提案机制**（三选一或组合，须裁决）：
  1. **包里声明多版本说法**：每个事件模板的来源可各自携带说法骨架（含讹传 / 改写 / 残本），创建前校验互异性——
     最便宜，且与「世界包声明、引擎只执行」的纪律一致；
  2. **渲染进推进路径**：把 `event.render` 按**有界预算 + 可退化**接入推进（渲染失败退回模板，不改事实），
     使「文本一次固化」在默认路径上真的发生；
  3. **说法派生记录**：允许同一事件的多个来源各自产生**派生说法**（含明确标注的立场改写），
     沿用既有的「派生记录不改原记录」纪律（`store.py:4206-4214` 的 `claim_derived` 已有此形态）。
- **配套：把「玩家 / 用户痕迹」发布到世界介质**（借 Elin 的 `Palmia Times`——报纸会登记玩家的婚姻、时间与地点）。
  「报纸」在本内核里**就是一个渠道**，上面登的是**说法**：因此可以零新机制地把用户的重大管理操作
  （引入事件、写助手的显式批准、跑团的裁定结果）作为**渠道事件**发布出去，让角色能「读到」它，
  同时天然保留失真可能（`EVENT_ENGINE_SPEC.md` §二「说法可为真或假」）。
  落点：`CHANNEL_PLUGIN_SPEC.md` / `CHANNEL_PROTOCOL_APPENDIX.md` 已有渠道与传播到达时刻——
  建议补一个**「世界介质」渠道插件样例**，作为「用户留痕」与「说法失真」两个设计目标的最小实现。
- **落点**：`runtime/events.py:233-266`（`claim_rows`）、`world/ops.py:2146`（`_render_event`）与预算 `runtime/budget.py:31`、
  `world/validate.py`（包校验新增「多来源说法互异性 / 分歧声明」）、`EVENT_ENGINE_SPEC.md` §二 / §3.2 / §四。
- **与现行规格的关系**：**修订**——`EVENT_ENGINE_SPEC.md:32` 已把「同源异文 / 立场改写」列为**合法形态**，
  但只是「允许」；需升级为**可验收的义务**（至少要求同一事件不同来源的说法在文本上可区分）。
- **验收**：① 同一事件的两个来源说法文本必须不同（或有显式的「同文」声明）；
  ② 同一事实不得以两份相同文本的不同 claim 进入同一角色的认知；③ **换角色能观察到对同一事件的不同表述**——
  这是「碎片化是结构保证」的唯一有效检验；④ 渲染预算耗尽时退回模板且不改事实。
- **成本**：中（方案 1）／中高（方案 2，涉及预算与退化路径）。

#### B-7 作用域生命周期与退休契约【DF + BG3 的共同教训】

- **问题**：**本内核什么都不退休**——实测所有状态表行数随世界年龄线性增长（§1.2 实测 B），
  `effect_state` 默认 `until_cleared` 永久有效，`reaction` 全量重算，提交物化全量。
  BG3 用「每关一个 goal，离开即 `EXIT` 清理」控制存档与规则搜索空间；DF 用「探索时生成、离开时抹掉，只保留 histfig / artifact」控制模拟规模。
  **本内核缺的是同一个东西：作用域边界上没有回收点。**
- **提案机制**：
  1. **作用域维度**：给运行状态加一个 `scope`（全局 / 区域 / 事件弧 / 纪元），世界包声明作用域的开启与结束条件；
  2. **退休契约**：作用域结束时，其内部状态**只保留**「被具名引用 / 被效果引用 / 被认知引用」的部分
     （对应 DF 的 histfig / artifact 例外），其余归档为**可复算的摘要**（不是删除事实，而是从热路径移出）；
  3. **schema 迁移入口**：借 BG3 的「版本号 DB + 载入时重建」，内置 `schema_version` 与载入期迁移钩子，
     让内核长期演进时不腐化旧实例；
  4. 与 A-6 的分级节拍、A-4 的增量快照是同一条路线的三面：**热路径只保留当下的作用域**。
- **落点**：`runtime/versioning.py`、A-7 的状态域注册表（作用域是域的一个字段）、
  新增 `runtime/scope.py`、`WORLD_RUNTIME_SPEC.md`（新增一节）、`WORLD_SETTING_SPEC.md`（作用域声明与校验）。
- **与现行规格的关系**：**新增**——不与任何现有原则冲突，但与「实例内部黑箱」的表述需要对齐（归档不是删除，仍可被追溯读取）。
- **验收**：① 作用域结束后的热状态规模**有界**（不随世界年龄增长）；② 归档后仍可被合法追溯读取（历史不被删除）；
  ③ 被引用的实体不被回收（DF 的例外规则）；④ 回滚跨作用域边界时行为可判定；
  ⑤ `schema_version` 迁移前后同一提交物化出的可观察状态等价。
- **成本**：高（跨版本层与读路径），但**是唯一能同时解决成本欠债与长期演进的一条**。

#### B-8 振荡器 / 棘轮分层 + 「每日确定性再分配」pass【借 Elin】

- **问题**：内核把两类完全不同的时间效应混在一条补算路径上：**① 循环型（天气、节庆、计时器、定期重算）**与
  **② 累积型（玩家 / 用户输入造成的不可逆后果）**。代价是：补算必须覆盖前者（贵），而后者本该由输入驱动（不该被补算）。
  Elin 的对照证明了这种分层是可行的，而且**世界不需要「状态演化」也能有持续感**。
- **提案机制**：
  1. **振荡器**（可补算、幂等、状态回到同一值）：历法节庆、天气队列、定期重分配、到期复活 / 信件 / 纪念物。
     它们 O(1) per day，且**天然满足确定性**（同锁定设定 + 前序 → 同答案）。
  2. **棘轮**（只增不减，由**已固化输入**推进）：用户引入事件、角色行动的不可逆后果、死亡与归档、被判定的伤亡。
     补算**只重放振荡器**，棘轮由输入驱动，不需要追赶。
  3. **新增「每日确定性再分配 pass」**：按世界日做 O(1) 的再分配——候选池重掷、到期信件 / 纪念物、
     被声明为「可复活」的实体按历法硬日期回归、地区归属的确定性变更。
     **它与「状态演化」的区别是：不产生持久差异，只重置与再分配**——代价接近零，却给出「世界活着」的观感。
  4. ⚠️ **硬约束**：再分配 pass **不得消耗一次性内容**。Elin 敢做「7 天复活居民 / 8 天消失的随机地城 / 每小时刷新的强盗」，
     是因为**它的世界离线冻结**；本内核离线会补算，这些定时器会在玩家不在场时把内容烧掉。
     因此再分配 pass 必须是**幂等且与「用户是否在场」无关**的。
  5. **与 B-9 的归档入口统一**：B-7 的「作用域结束时回收」与 B-9 的「个体被点名后收回」是**同一条归档语义的两个触发条件**，
     必须共用同一个归档位（复用 `character_state.archived`）与同一套回滚规则；否则会出现两个「不在热层」的标记互相打架（§3.2 B-9 第 5 条）。
- **落点**：`WORLD_RUNTIME_SPEC.md` §2.6（补算口径：明确区分振荡器与棘轮）、
  `EVENT_ENGINE_SPEC.md` §四（每日密度预算旁的再分配 pass）、`service.advance` 批内顺序、
  世界包声明（哪些实体 / 状态是「可再分配」的）。
- **与现行规格的关系**：**修订**——`DESIGN.md` §2.2#4「世界不依赖用户在线……按确定性规则追赶」**保持**，
  但需补一句「追赶的对象是振荡器；棘轮只由已固化输入推进」。
- **验收**：① 长期离线后补算，振荡器结果与逐日在线推进**完全一致**；② 再分配 pass 幂等（重复推进同一水位不重复分配）；
  ③ 一次性内容不被离线补算消耗（构造「离线 N 天」测试，断言候选池规模不塌陷）；
  ④ 棘轮状态只能由已固化输入改变（回滚一并回滚其下游）。
- **成本**：中（分层是规范口径 + 一个 pass），但**收益是同时降低补算成本与提高「世界活着」的观感**。

#### B-9 关注域分层与惰性物化契约【借 Songs of Syx】

- **问题**：本内核**没有画抽象边界**（§2.1b 最后一行）：所有状态一律全量保留。
  但「没有匿名大众」并不意味着不需要边界——**它意味着边界必须画在别处**：
  世界有区域、组织、制度、人口规模这些东西，而内核既不能逐个模拟它们，也不能让它们变成「没来源的漂移数字」。
  Songs of Syx 给出的答案是：**域外是账本、域内是个体，两者靠少量显式事件耦合**。
- **提案机制**（与 B-3 成对：B-3 定义域外的量，B-9 定义「点名」的规则）：
  1. **`world_ledger`（域外账本）**：区域 / 组织 / 制度的**计数器与比率**
     （全族人口、日 / 年增长率、产出、worth、prospects、关系标量…）。它不参与角色认知，只参与世界推进与推导。
     **它作为一种状态域登记进 A-7 的状态域注册表**，快照 / 清线 / 导入导出全部由注册表派生——
     **不要在这里另开一条手工入快照的路径**（那正是 A-7 要消灭的「漏一处 → 回滚脏数据」）。
  2. **物化（点名）契约**：当（a）角色与世界某计数器交互、或（b）计数器跨过声明阈值、或（c）叙事需要具名对象时，
     由**确定性物化函数**从账本派生一个个体并落库：`materialize(ledger_row, seed, world_second) → 实体`。
     **同 seed + 同年份 + 同账本身 → 同一人**（这是「未观察时是什么」的唯一正确答案）。
  3. **归档（降级）契约**：交互结束后，个体可按契约**收回归档**（状态摘要回写账本），
     **归档不是删除**：其 id、出生 / 死亡、与既有实体的关联必须留档，回滚跨边界时行为可判定。
  4. **接口事件是唯一的口子**：个体 ⇄ 计数之间**只允许**通过显式事件互换（移民、征召、税收、收获、灾害）；
     禁止任何一方「悄悄」改动另一方。这与 B-1 的压力、A-2 的后果集、B-7 的作用域生命周期是同一条纪律的不同侧面。
  5. **归档入口与 B-7 统一（一条，不是两条）**：B-7 管「**作用域结束**时的回收」，B-9 管「**个体被点名后收回**」，
     两者**共用同一个归档位与同一套回滚规则**——复用 `character_state.archived`（它已经是版本化角色状态的一部分，
     并有「归档与死亡同批置位」的既有义务），**不新开第二个「不在热层」的标记**；
     「已物化实体」的归档态同样登记进 A-7 注册表。
- **落点**：新表 `world_ledger` + `materialized_entities`（或**直接复用 `character_state` 的归档位**）、
  新模块 `runtime/ledger.py`（物化 / 归档纯函数）、A-7 的注册表、`WORLD_SETTING_SPEC.md`（账本字段、阈值、`hot_scope_entity_limit` 的声明）、
  `WORLD_RUNTIME_SPEC.md`（新一节，与 B-7 的归档语义放在同一处）、`EVENT_ENGINE_SPEC.md` §八（用户引入事件是接口事件之一）。
- **与现行规格的关系**：**修订**——`WORLD_SETTING_SPEC.md`「不为配额添加人口或组织」需限定为「不为叙事配额添加」；
  名册门槛（`§2.2`）需补一条「物化产出的实体按同一门槛登记」。
- **验收**：① **「未观察时是什么」有定义**：任意 `(账本行, seed, 世界秒)` → 确定性物化结果，两次相同；
  ② 物化 / 归档往返不产生矛盾（同一实体两次被点名，细节一致）；
  ③ 个体与账本之间的改动**只能**通过显式事件（回归测试：直接改一方的路径不存在）；
  ④ 归档后回滚跨边界不产生脏数据、不复活被撤销的实体，且**与 B-7 的作用域回收共用同一归档位与回滚规则**；
  ⑤ **规模上界可判定**：账本行数 ≤ `区域数 + 组织数 + 制度数`（与时间无关）；热层内已物化实体数 ≤ 世界包声明的 `hot_scope_entity_limit`。
- **成本**：中–高（新状态域 + 契约 + 注册表），但它是**同时解决 §1.2 成本欠债与「世界是真的」的唯一结构**。

### 3.4 改动总览：原状 → 优化 → 副作用（决策视图）

> 本节把 §3.1 / §3.2 的全部改动压成一张**决策视图**，并补上原提案缺失的一栏：**副作用**。
> 分三档的依据是「会不会改变同一锁定设定 + 种子 + 前序状态下的世界结果」——
> **第一档不改，第二档改（小改动但改语义），第三档改（扩展能力）**。
> 第二、三档都**必须走规则版本 + 兼容性阻断**（`WORLD_RUNTIME_SPEC.md` §十二「规则实现不可用时必须先进入兼容性阻断」），
> 否则用户会看到「升级之后，同一个世界走上了不同的路」。

**五条最危险的副作用（按后果排序）**

1. **B-7 的误退休** —— 把仍在起作用的后果当历史归档 ⇒ 世界因果断裂，而且是**沉默的**（不会报错）。
2. **A-9b 修死代码** —— 被静默丢弃的效果开始生效 ⇒ 既有实例出现新事实；最容易被当成「顺手修」而跳过规则版本。
3. **A-2 的活跃集合** —— 从「慢但正确」变成「快但可能静默丢后果」；这类改动的安全性**完全依赖一致性断言**。
4. **B-1 的调参** —— 权重写错的症状是「世界长期平静」或「事件爆炸」，都要很久才被察觉。
5. **A-4 的异步提交** —— 崩溃丢失范围变大 + 回滚粒度变粗；这是**用户可感知**的语义变化，不只是性能。

**顺序上的两条硬约束**

- **A-7 必须先行**：B-3 / B-7 / B-9 都要新增状态域；没有注册表就会把「四处手工」的老账复制三遍。
- **A-1~A-6 必须早于 B 类**：B 类都会放大每批成本，欠债不还会把新机制的收益抵消掉。

## 四、若基于该内核开发一款游戏：缺口与体裁推荐

### 4.1 分层缺口表

| 层 | 现状 | 缺口 | 归属 |
|---|---|---|---|
| **世界推进层** | 世界秒 + 倍率 + 每世界日整批原子 + 离线补算 | 高倍率排水能力不足（§1.2）；无「退休契约」；读路径不可高频 | **A 类修完即可用**，不需要新机制 |

**一条重要判断**：交互层与表现层加起来是**游戏层**，本内核的对外契约（稳定指涉 + 事件日志 + 闭集效果 + 认知投影）
恰好是游戏层要读的东西——**总纲附录 A 的这条判断在本轮实测后依然成立**，但要补一条：
**读契约目前不可用**（`read_snapshot` 在持续运行的线上返回 `not_ready`，payload 每次重扫十余张表），
所以 A-10（读路径）不是「优化」，而是**游戏化的前置条件**。

| 内核的不可替代性 | **极高**：五作都做不出「同一件事有几个版本，且都能被追溯」 | 高 | 低：RimWorld / DF **/ Songs of Syx** 已封顶 | 低：BG3 已封顶 |
| 最小可玩验证难度 | 中（一个地点 + 三个角色 + 一条可拼图的迷） | 低（但没有「玩」的部分） | 高（系统太少不成立） | 中低 |
| **评级** | **推荐** | 产品升级，不是游戏 | 不建议（现在） | 可选支线 |

### 4.3 推荐：C1 情报向开放世界 RPG

**理由（按重要性排序）**：

1. **只有它把内核唯一不可复制的资产变成玩法本体。** 五作都有「世界」，都没有「同一世界不同版本的认知」。
   C1 的核心动词——**打听、比对、判断谁在说谎、决定相信谁的版本**——直接消费 `claim` / `knowledge` / `stance` / `earliest_world` 这套结构。
   其他三个候选里，这套结构最多是调味料。
2. **它刻意避开内核最贵的三个缺口。** 不做需求 / 效用（角色动机仍走打算 + 谓词门）、不做经济（聚合量够用）、
   不做战斗数值（`casualty` 只做宣告）。这三样正是 C3 的地基，而 C3 需要同时新建三套系统、其中两套与既有原则冲突；
   **而且 C3 这条赛道已经被占满**——RimWorld / DF 之外，Songs of Syx 用**一个开发者十一年**才把「逐个体模拟」做到
   「一个首都的深度」（§2.5）。
3. **它所需的内核扩展都落在有降本路线的项上**：空间拓扑（B-4，走拓扑不走坐标 → 中）、
   高频读（A-10 → 中）、玩家化身（高，但它是唯一的「高」，且只跨四层、不动确定性核心）。
   **并且它的「世界规模」可以用 B-3 + B-9 的账本 + 物化契约来承担**，不需要逐个体模拟一片大陆（§2.1b 的裁决）。
4. **可验证性好**：一个地点 + 三个角色 + 一条有多个版本说法的谜题，就能验证「换人 → 换版本 → 拼出真相」这个核心循环，
   不需要内容规模，也不需要平衡。
5. **它的动词集天然带不可逆代价，而这正是 Elin 证明过的乘数**（Elin §8.2）：打听会暴露自己在打听、
   说谎会被其他角色的说法记住、把某人的版本传出去就收不回来。「不可逆」在本内核里已有表达力
   （`EVENT_ENGINE_SPEC.md` §二「后果须声明失效方式」+「错误说法可以导致真实措施」），
   而**用户不能靠读档撤销它**——这恰好是五作都做不到的一条：**把「不可撤回的信息行为」做成核心玩法**。

**把 C1 拆成两步，是这条推荐最关键的工程决定**（避免一上来就付「玩家化身」这笔最贵的账）：

| 阶段 | 形态 | 用户是谁 | 需要的内核改动 | 依赖成本 |
|---|---|---|---|---|
| **C1a 调查向推理层**（推荐先做） | 仍用**现有聊天面**：用户同时联络多个角色，靠**说法差异**做推理（谁的版本可信、谁在隐瞒、两件事对不上） | 仍**在世界外**（不违反 `DESIGN.md` §2.2#3） | **只要 B-6** + A-5/A-10 的读路径（把「跨角色比对」做成可用的读接口） | **低**（不动设定层、不动披露层、无空间） |
| **C1b 开放世界 RPG** | 用户**在世界内**：有身体、会移动、要去打听 | **在世界内**（须裁决 §2.2#3 的适用范围） | C1a 全部 + B-4 空间拓扑 + 玩家化身（高）+ 地图表现 | 中–高 |

**C1a 的独立价值**：它**不需要裁决任何原则**、不需要新状态维度、不需要改设定层，就能验证整条推荐的前提——
**「同一件事的不同版本，用户能不能感觉到、并且想为此继续问下去」**。
如果 C1a 验证不出来，C1b 就不必开始；如果验证出来了，C1a 本身就已经是一个可交付的产品形态（现产品的自然升级），
而不是一个「过渡原型」。（§4.3 阶段 1 即指 C1a。）

**C1b 的玩家循环，以及它消费的内核接口**（把推荐落到「按哪个键、内核给什么」）：

| 玩家动作 | 消费的内核能力 | 现状可用性 | 需要先做 |
|---|---|---|---|
| 前往某地 / 打听路线 | 空间拓扑、可达性 | **无** | B-4 |
| 问某人「你知道什么」 | `runtime.cognition.project`（认知投影） | **已有**（软约束 + 硬约束 + 主题优先） | — |
| 比对两人的说法、找矛盾 | `claim` / `knowledge` / `stance` / `earliest_world`（同一事实的多来源） | 结构**已有**，**内容未差异化**（§1.5：8 句话） | **B-6** |
| 判断谁在说谎 | 动机与关系线索（谁欠谁、谁与谁有怨） | **无** | B-2 |
| 把自己的版本传出去 / 承诺 / 指控 | 角色行动事件 + 后果持续（失效方式三类） | **已有** | — |
| 离开几天再回来，发现局势已变 | 离线确定性补算 + 压力驱动的世界变化 | 补算**已有**（A 类修完才可持续运行）；状态耦合变化**无** | A-1~A-5、A-11、B-1 |
| 停下来观察世界怎么动 | 高频读 / 增量订阅 | **弱**（`read_snapshot` 在持续运行的线上返回 `not_ready`） | A-10 |

> ⚠️ **C1 有一条必须先裁决的设计张力**：**允许读档，会摧毁 C1 的核心循环**。
> C1 的玩法本体是「不可撤回的信息行为」，而 Elin 的教训（§2.4 陷阱 3）说明：只要随机 / 世界状态能被读档重掷，
> 用户就会重掷，「确定性」在用户可见层面失效。本内核的版本层比 Elin 强（回滚是显式的、可追溯的），
> 因此 C1 有三条互斥路线，必须在体裁设计阶段就选一条：
> ① **提交即事实**：信息行为落成已提交事件，回滚只能整条时间线回滚（用户为「重来」付出全局代价）；
> ② **无读档**：像 Permadeath 一样，把「不能撤销」写进玩法契约；
> ③ **可读档但世界不配合**：回滚后世界的响应**不由随机决定**，而是由状态耦合推导（B-1）——同样的处境必得同样的后果，
> 重掷无收益。**③ 与本内核的确定性原则最契合，也正是 B-1 的另一个理由。**

**推荐的最小可玩验证（vertical slice）路径**：

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 0 | 先修 A-1~A-5、A-8、A-9：让世界能跑 10 年不越跑越慢、且逐字节可复现 | 无 |
| 1 | B-6：让说法层真的差异化（8 句 → 每个事件多版本），并在聊天界面里验证「换角色听到不同版本」 | 无（可在现产品里验证） |
| 2 | A-10 + 最小地图表现：把认知投影渲染成「雾状地图 + 传闻面板」 | A-10 |
| 3 | B-4 + 玩家化身：玩家作为世界内实体移动、打听 | B-4 |
| 4 | B-5：让世界能死人（否则开放世界的后果没有重量） | B-5 |
| 5 | B-8 + B-7 + B-1：让世界自己动起来、且不越跑越慢（分层补算 → 退休契约 → 压力驱动） | B-8 / B-7 / B-1 |

> 阶段 1 是本推荐里**最先该做、也最便宜**的一步：它不需要任何内核新机制，只需要把已经存在的渲染能力接进默认路径或包声明，
> 就能把「碎片化」从结构承诺变成可观察体验。**如果阶段 1 验证不出「同一件事的不同版本能被用户感觉到」，C1 的前提就不成立，应回头重估体裁。**

### 4.4 明确不建议

| 路线 | 为什么不做 |
|---|---|
| 把内核改造成需求 - 效用殖民地模拟（C3） | 需同时新建需求 / 效用、资源经济、空间三套系统；前两套与 `DESIGN.md` §2.2 原则冲突；会把 §1.2 的成本欠债放大到无法偿还 |
| **照抄「无省略的逐个体模拟」**（Songs of Syx 的路线） | 它的全细节也只覆盖**一个首都**，界外是计数器与 `auto-resolve`（§2.5）；其实现依赖**一人十一年 + 自研 Java 引擎 + 单核极限压榨**，照抄起价 10 人年以上，且它至今未到 1.0。**可迁移的是原则（B-9 的域分层），不是规模** |
| 用难度自适应 / 财富曲线调节世界（RimWorld 的做法） | 等于为让用户好过而篡改世界因果，违反 `EVENT_ENGINE_SPEC.md` §3.1#5 与本文裁决原则 3 |
| **让「UI / 叙述数字」与账本脱钩**（Songs of Syx 的 tooltip 哲学） | 在图形游戏里可接受（玩家只看结果），在**以 LLM 文本为表达层**的内核里会让叙述层放大矛盾并编造历史——必须反过来：**所有对外文本从账本 / 事件渲染** |
| 让 LLM 反事实补写过去 | Toady 的明确警告（会绕进死结）；也与本项目既有纪律冲突（`EVENT_ENGINE_SPEC.md` §3.4「只展开既定内容」） |
| 把内核做成实时物理 / `tick` 级局部模拟（DF 要塞层） | DF 的 FPS death 是架构性的（>60% 时间在单位回合，要塞内无任何 LOD）；本内核的「墙钟时间盒 + 每世界日整批原子」在这点上**优于**它，不应倒退 |
| **照搬「大版本破坏存档」与 save-scum 可用的存档策略**（Songs of Syx） | 本内核的核心资产恰恰是**可复算 + 版本化回滚 + 兼容性阻断**；放弃它等于换掉立身之本 |
| 现在就把「世界合并 / 多人同世界」做进内核 | 现有版本层不支持世界线合并；且会把「黑箱」与「认知隔离」两条不变式同时推到未裁决区 |

## 五、反模式与风险

### 5.1 从五作反推的九条「不要做」

| 反模式 | 出处 | 本内核的对应防线 |
|---|---|---|
| 全量 per-tick 更新且无 LOD | DF FPS death；RimWorld 靠自动降 TPS 兜底 | 分级节拍（A-6）+ 退休契约（B-7） |
| 玩家可控的难度旋钮（财富 / 威胁点 / 自适配因子）影响世界事件 | RimWorld | 裁决原则 3：压力只能由世界状态推导 |
| 单一全局可变随机流 + 帧态 / 进程态混入模拟 | RimWorld（`Verse.Rand`、`DrawPos` 进弹道） | A-8 随机流隔离；`hash()` 全清 |
| 手工编排撑起表达层（配音 + 逐结局人工核对） | BG3（236 h 配音 / 电子表格核对 17,000 结局） | 表达全部由 LLM 按需生成；但见 5.2 的代价 |
| **空函数式的「伪演化」**（每 N 回合掷骰、关系层方法体为空） | Elin（`UpdateRelations()` 为空） | **要么真建模（B-2），要么明确声明不建模**；禁止无收益的随机 pass |
| **把定时重置型内容放到会离线推进的世界里** | Elin（7 天复活居民 / 8 天消失的随机地城，之所以可行是因为它离线冻结） | B-8 的硬约束：再分配 pass 必须幂等且与「用户是否在场」无关 |
| **把营销话术当设计目标**（「每个个体都详细模拟」） | Songs of Syx：全细节只覆盖自家首都，界外是计数器 / 抽象池 / `auto-resolve` | **把「未观察时是什么」显式建模**（B-9 的物化契约），而不是留给实现临时决定；对外只宣称已定义的边界 |
| **让对外数字与模拟脱钩**（tooltip 不代表现实） | Songs of Syx：开发者自陈「make all industries equal… at the cost of reality」 | **单一事实源**：所有对外文本从账本 / 事件渲染，宁可少说不可说错（LLM 会放大矛盾） |
| **牺牲可复算与存档兼容换取单机性能** | Songs of Syx：save-scum 有效、同 seed 只「more or less the same」、大版本必破存档 | 本内核的 A-8 + 版本层 + 兼容性阻断是其反面；不得为性能放弃 |

### 5.2 五条会在游戏化过程中被违反的原则（都是真实压力，不是假想）

1. **为玩法方便在核心内建通用数值系统**（HP / 精力 / 好感值 / 等级）。一旦开了口子，
   「性格 = 可解释单元」「不设通用情绪数值」「不引入用户模型」这三条同时失守。**B-2 / B-3 / B-5 的边界必须写在规格里，而不是靠实现自觉。**
2. **为内容量放宽效果闭集**。BG3 的反面证明是「手工编排的上限」，正面结论是「规则闭集的上限**更高**」——
   一旦允许模板声明任意效果，确定性与可审计性同时消失。**闭集可以扩（B-5），不能开放。**
3. **把「渲染文本」当成事实来源**。`EVENT_ENGINE_SPEC.md` §3.2 已定：「文本写了 ≠ 世界已经发生」。
   B-6 让渲染进推进路径时，这是最容易破的一条。
4. **让「时间 + 随机」产生的世界状态留在已提交事件之外**。Elin 允许读档重掷该层神龛 / 雕像类型；
   在内核里同样的做法会让用户通过回滚反复重掷，**「确定性」在用户可见层面失效**。
   防线：随机结果必须**固化进已提交事件**，使重掷的代价等于重掷整条因果链（A-8 的验收项）。
5. **用「以后再优化」掩盖未定义的抽象边界**。Songs of Syx 的教训是：**界外是什么必须现在就说清楚**
   （它是账本、是抽象池、还是根本不建模）——一旦「未观察时是什么」没有定义，
   同一对象两次被观察就可能互相矛盾，而**LLM 会把这种矛盾放大成编造的历史**（B-9 的验收 ①）。

### 5.3 五条具体风险

| 风险 | 触发条件 | 影响 | 应对 |
|---|---|---|---|
| **成本欠债在游戏化后被放大** | 游戏层高频读 + 多角色 + 高倍率同时出现 | 排水能力崩溃，离线补算长期停留在「追赶受限」 | A-1~A-5、A-11 先做；A-10 的缓存键必须含水位 |
| **内容层不差异化，核心卖点失效** | 世界包只声明 3 个模板、渲染不进默认路径 | 世界跑一年只有 8 句话；用户换人换时间拼不出不同版本（§1.5 实测） | B-6 作为**核心卖点验收项**，而不是内容优化项 |
| **长期运行腐化** | 世界寿命以年计，`effect_state` / `reaction` / `memory` 只增不减 | 第 10 年每世界日耗时 >300 ms；快照体积持续膨胀 | B-7 退休契约 + A-7 注册表 + schema 迁移入口 |
| **补算烧掉一次性内容** | 照搬「定时重置」类机制 + 离线补算 | 用户离线回来只看到一地被烧过的定时器 | B-8 的幂等硬约束 + 「离线 N 天」验收测试 |
| **未观察态未定义 → 自我矛盾** | 域外是计数、域内按需物化，但物化函数不是确定性的 | 同一实体两次被点名细节不一致；LLM 会把它放大成编造的历史 | B-9 的验收 ①（`(账本行, seed, 世界秒)` → 同结果）与 ②（物化 / 归档往返一致） |

|---|---|---|

**两轮实测数值的口径**：实测 A（本文件 §1.2）是 2 角色、密度「常规」、`memory` 为 0 的**下限曲线**；
实测 E（内核推进审计）是 3 角色、密度「稀疏」、180 日，含 8000 条在位记忆的**对照实验**。两者配置不同，**互补而非冲突**。

**已知限制**（结论不要越过这些限制）：
1. 全部实测用 `FakeLLM`，**不含模型延迟**；真实部署的墙钟成本还要加上「渲染 / 提案 / 提取」三条独立 LLM 路径。
2. 实测 A/C 的世界 `memory` 为 0（记忆提取是会话侧操作，本轮未触发）⇒ **成本是下限**；实测 E 的 8000 条记忆是构造的对照实验条件，不是真实增长曲线。
3. 单机、单进程、无并发写者；未测多实例并发与备份 / 恢复路径的开销。
4. **拟合外推**（不是实测）：§1.2 中「10 年世界龄」的每世界日耗时、默认 `rate_max` 的失效时点、以及 §1.2 实测 C 里由角色数放大年龄斜率得到的结论。
