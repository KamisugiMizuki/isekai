## 1. v1 现状

| 落点 | 内容 |
|---|---|
| `store.world_ledger` | `(实例, 线, 作用域类, 作用域, 键) → 整数 + 单位 + 更新时间`；`ledger_list` / `ledger_put` / `ledger_init`（**只补不覆盖**） |
| `runtime/service.py` | `advance` 接上**写入方**（按声明补齐缺失键，幂等） |
| `world/validate.py` | `ledger[]` 声明校验：作用域类闭集、键与初始值必填整数、**键白名单**（多一个 `expr` 即拒绝） |

**v1 的守卫**：`ledger_init` 只补不覆盖 ⇒ 账本数字只能经 `ledger_put` 变更（单一事实源）。

## 2. 问题：v1 的数字只能被「说明」，不能被「算出来」

v1 的 `initial` 是死值，推进过程不改它，也不允许任何关系式。于是「税收 = 人口 × 税率」这类
**结构的**量只能靠作者手写常量，世界规模一变就对不上。

## 3. 裁决：**只做声明式纯函数**，且**推导值不落库**

### 3.1 形态（严格限定的四种算子，**没有表达式语言**）

```json
{"derived": [
  {"id": "d-税收", "scope_kind": "region", "scope_id": "pl-1", "unit": "石",
   "op": "产品", "a": "人口", "b": "税率", "scale": 1000}
]}
```

| 键 | 约束 |
|---|---|
| `id` | 推导键标识（在**同一作用域内**唯一；**不得与已存储的键重名**——否则「哪个是真的」不可解释） |
| `scope_kind` / `scope_id` | 与 v1 同：作用域类闭集（`region` / `org` / `institution`） |
| `op` | **闭集，只有四种**：`和`（a+b）、`差`（a−b）、`积`（a×b//scale）、`比`（a×1000//b，scale 忽略） |
| `a` / `b` | **必须是已声明的账本键**（存储键或**更早声明的**推导键） |
| `scale` | **积**专用：整数千分比分母（缺省 1000）；其余算子忽略 |
| `unit` | 可选，仅用于展示 |
| **其余键** | **一律拒绝**（`expr` / `formula` / `sql` / `λ` / `callback` …） |

**为什么只给四种算子**：可自由编写的表达式 = 在核心里开一个脚本引擎入口（与「不做 HP 系统」
「不给 `weight_expr`」「不引入坐标」是同一条纪律）。四种算子是**可枚举、可校验、可审计**的。

### 3.2 推导值**不落库**、**不进快照**、**不参与热查询**

| 决定 | 理由 |
|---|---|
| `ledger_derived(...)` 在**读时**算出，不写 `world_ledger` | **单一事实源**：账本数字只能经 `ledger_put` 变更；把推导值落库会制造第二份可被写坏的事实 |
| 不进快照 / 不登记状态域 | 它不是状态——它是**已存储键的纯函数**。快照恢复存储键后，推导值自动一致 |
| 不允许对推导键 `ledger_put` | 否则「推导值」与「存储值」会打架；写入被拒（校验在前，运行期再兜一层） |
| 求值顺序 | 只允许 `a`/`b` 引用**存储键**或**在它之前声明的推导键** ⇒ **无环、单趟、确定性** |

### 3.3 除零与夹取

`比` 的分母为 0 ⇒ 该推导键返回 **0**（不抛错：账本要能被稳定读取，且 0 是「无意义值」的保守表达）。
不设额外夹取（账本是域外计数器，允许为负——例如「净流入」）。

## 4. 兼容性与规则版本

| 情形 | 行为 |
|---|---|
| 未声明 `ledger` / 未声明 `derived` 的包 | **逐字节不变**（不建行、不读表、不参与任何查询） |
| 声明了 `ledger` 但没有 `derived` 的包 | **逐字节不变** |
| 声明了 `derived` 的新包 | 只是**多了一组可查询的纯函数值**；不改变世界演化（推导值不写库、不被推进读取） |

⇒ **不需要规则版本递增**：本项**不改变任何世界事实的演化路径**，只新增一个**只读派生视图**。
（这与 B-1 v2 的判据一致：现有包与现有实例行为逐字节不变。）

## 5. 必须同时改的地方

1. `runtime/ledger.py`（新模块）：四种算子的**纯函数**实现 + `evaluate`（单趟、确定性、除零回 0）；
2. `store.py`：`ledger_derived`（读存储键 → 交给 `ledger.evaluate`）；
3. `world/validate.py`：`derived[]` 校验（算子闭集、操作数必须是已声明键、**不得与存储键重名**、
   **不得引用更晚声明的推导键**、多余键即拒、`scale` 必须为正整数）；
4. **不需要** A-7 登记（没有新表、没有新状态域）；
5. **不需要**快照/回滚改动（不落库 ⇒ 无可回滚状态）。

## 6. 验收（可反证）

| # | 断言 |
|---|---|
| ① | 四种算子逐一对拍手算值（含整数除法语义） |
| ② | 未声明 `derived` ⇒ `ledger_derived` 返回空（既有包零影响） |
| ③ | **单一事实源**：推导值**不出现在** `world_ledger` 里；`ledger_put` 写推导键被拒 |
| ④ | 除零回 0（不抛错） |
| ⑤ | 确定性：同输入同输出；多次调用一致 |
| ⑥ | 校验：算子非法 / 操作数未声明 / 与存储键重名 / 引用更晚声明的推导键 / 多余键（`expr`）⇒ 全部拒绝 |
| ⑦ | 链式推导（`d1` 用存储键，`d2` 用 `d1`）单趟可求值 |

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 推导式被当成「算世界」的入口 | 它**只读**、**不落库**、**不被推进消费**；算子闭集；操作数必须已声明 |
| 第二事实源 | 显式禁止对推导键写入 + 测试断言它不在 `world_ledger` 里 |
| 除零 / 负数导致读数抖动 | 除零固定回 0；无额外夹取（域外账本允许负值） |
| 循环引用 | 只允许引用更早声明的推导键 ⇒ 结构上无环 |
