# 题材适配硬验收：只准声明，不准改内核

**状态**：**草案，待人类确认**（2026-10-10）。
**来源**：本会话人类裁定——把「适配新题材不得修改内核」这句话写成硬验收。
**性质**：这是**开发期验收闸**，不是运行期功能。它**不改任何现存 SPEC 义务**，也不替代三档发布纪律（`KERNEL_OPTIMIZATION_TASKS_2026-10-10.md:99-105`）——它是那道纪律**前面**的一道前置闸。

---

## 一、硬验收条款（原文，不可调参）

> **适配一个新题材时，只允许新增 `examples/` 与 `tests/` 下的文件；不允许修改 `isekai_core/` 下任何既有文件——尤其不得往共享闭集常量上手工添行。**

判据：

> **如果导入一个世界包适配不了，那不是世界包的问题，是内核缺少一个槽位。**

**效力范围**：只约束「为适配某个题材而做」的改动。常规功能开发与缺陷修复不受本闸限制（它们仍受三档发布纪律与各 SPEC 约束）。

---

## 二、这条为什么是硬验收，而不是一句口号

三件事同时成立才算「硬」：

1. **可机械判定**：判定发生在 diff 级别，不依赖评价者的尺度（§四）。
2. **失败时没有「就地改常量」这个出口**：失败只允许产出「槽位缺口」这一种结果（§五）。
3. **唯一的代码通路被写死并需登记**：例外只有一种，且条件、登记方式、反面判据全部写明（§三、§六）。

---

## 三、允许 / 禁止 / 例外

### 3.1 禁止（diff 状态为 `M` / `D` / `R`）

`isekai_core/` 下**任何既有文件**的修改。以下六处是**最容易顺手改、因此必须点名**的反例清单——它们正是「新增一个效果种类要同步改 6 处」的全部落点：

| 位置 | 为什么最容易被顺手改 |
|---|---|
| `isekai_core/world/validate.py:861` `SUPPORTED_EFFECTS` | 加一个效果种类 |
| `isekai_core/runtime/events.py:32` `EFFECT_PRIORITY` | 同上：每加一个 kind 要补一行 |
| `isekai_core/store.py:30` `SETTING_EFFECT_KINDS` | 同上：设值型效果的退休判定 |
| `isekai_core/runtime/change.py:38-54` `EFFECT_BY_KIND` / `STATE_KIND_BY_TARGET` / `REFUSED` | 让新 kind 能翻成世界事实 |
| `isekai_core/runtime/rule_common.py:35,50` `CONSEQUENCE_KINDS` / `WORLD_EFFECTS` | 同上：派生副本 |
| `isekai_core/runtime/service.py`（物化绑定） | 「声明了要有消费路径」 |

另外两条同类禁止：

- **不得为单个题材递增 `RULES_VERSION`**（`isekai_core/version.py:20`）。递增的判据是三档纪律（是否改变「同一设定 + 种子 + 前序状态」下的世界结果），不是「某个题材需要」。
- **不得为单个题材修改状态域登记**（`isekai_core/store_state_domains.py`）。新增状态域必须登记，但登记的理由是「它是世界状态」，不是「某个题材需要它」。

### 3.2 允许（diff 状态为 `A`）

- `examples/**`：新题材的样例世界包、机制使用示例。
- `tests/**`：该题材的拟合验收测试。
- `docs/**`：规格与裁决记录。
- `config/**`：仅当需要该题材的推荐配置，且不得改变既有默认值语义。

### 3.3 例外：唯一的一条代码通路

**新增**一个隔离机制模块（`isekai_core/` 下的**新文件**），且**必须同时**满足五条：

1. **不修改任何既有文件的语义**——尤其是 §3.1 的六处共享常量；
2. **经注册接口接入**，且「未启用它的世界包行为逐字节不变」（沿用既有的「声明即启用」纪律：`world.regions` / `events.hop_delay_seconds` / `relations` / `pressures` / `ledger` 都是这个先例）；
3. **自带版本标识**，并写明它与 `RULES_VERSION` 的关系：是否改变世界结果、是否需要兼容性阻断；
4. **自带不变式断言与测试**，且**声明与消费同批**（防 A-9b 那类「声明了没人消费、被静默丢弃」）；
5. **经人类裁决并登记**在 §六。

并且**不得**以「通过验收」为名引入：表达式语言、脚本载荷、万能 `custom_effect`。
依据：世界包明文禁带脚本（`WORLD_SETTING_SPEC.md:35`）、账本推导只给四算子且没有表达式入口（`isekai_core/runtime/ledger.py:21`）、规则插件侧同一条红线（`TRPG_RULE_COMMON_MODULE_SPEC.md:269`）。这三条都是**故意**的，本闸不得成为绕开它们的理由。

## 四、机械判定（可复跑）

```powershell
# 1. 内核是否被改：期望空输出
git diff --name-status <base>..<head> -- isekai_core

# 2. 全量改动清单：isekai_core 下只允许出现 A（新增机制模块），且它必须已在 §六 登记
git diff --name-status <base>..<head>
```

- 出现 `M` / `D` / `R` 于 `isekai_core/` ⇒ **判定失败**，走 §五。
- 出现 `A` 于 `isekai_core/` 但未在 §六 登记 ⇒ **判定失败**（未登记的例外不算例外）。
- 全量 `pytest -q` 必须全绿（它是既有基线，不是本闸的加分项）。

**能力级判定**另见 §七：用「一个题材从零到跑通」的可复跑场景来判，而不是只看 diff。

## 五、失败时怎么办（这一节是闸门能不能立住的关键）

1. **判定失败 = 登记一条「槽位缺口」，不是改常量。**
2. 缺口进入既有的三档排序：第一档（不改语义）可直接合入；第二、三档**先裁决原则与规格，再改码**。
3. 一个槽位立项的正当理由是「它覆盖**一整类题材**」，不是「它能让**某个题材**过关」。
4. 明确禁止的四种绕过：
   - ① 往共享常量添行（§3.1）；
   - ② 用 `custom_state` 或自由文本塞值逃避闭集；
   - ③ 引入表达式 / 脚本；
   - ④ 把题材机制塞进规则插件的 `opaque_state` 冒充世界事实——**规则私有状态自由，但世界看不到它**：不进认知投影、不进补算、不进世界一致性，换不来贴合度。

## 七、首批验收对象（可执行的拟合场景）

| 场景 | 位置 | 验收问句 | 已知前置 |
|---|---|---|---|
| 循环 / 重置类 | `examples/theme_loop/` + `tests/test_theme_loop_fidelity.py` | ① 同一件事是否十个人各有版本？② 跨轮是否记得自己是谁？ | 「轮次派生量」与「包内多版本说法」两个槽位 |
| 认知扭曲类 | `examples/theme_distortion/` + `tests/test_theme_distortion_fidelity.py` | ① 共享的假象能否被所有观测者一致看到？② 同一个事实能否对一个角色是 A、对另一个是 B？ | 无（两条都用环境事实 + 定向说法，零内核改动） |

**通过标准**：整个适配过程**只新增** `examples/` 与 `tests/` 下的文件。

**明确不做**：个体幻觉（「她的知觉被篡改」）。它看似缺状态维度，实质是给某个角色注入未发生的观察片段，同时撞「没有来源的标签不进入状态」（`WORLD_RUNTIME_SPEC.md:268`）与「实情层不直接注入角色生成上下文」（`:319`）两条红线。替代路径已在现有原语内：共享扭曲 → 环境事实；个体错误认知 → 一条只发给她的说法（渠道 + 受众条件已支持）。

## 九、与既有纪律的关系

- 三档发布纪律不变，本闸是它**前面**的闸：先过本闸（证明「这一个不需要改内核」），过不了才立项槽位；立项后仍走三档与兼容性阻断。
- 「声明即启用、未声明逐字节不变」是本闸的既有先例，不是本闸新造的规则。
- `docs/trpg-client/TRPG_CLIENT_SPEC.md:72`「不应反向扩展 WorldRuntime 的题材字段」与本闸同向。
- 本文件**不改任何 SPEC 义务**，也不改 §3.1 的任何常量。
