> 状态：审阅修订稿，尚未并入 SPEC、尚未实现；以下为拟补充规则，不提前替代现行规范。内容并入 SPEC 后删除本文件。
> 来源：2026-09-19 总纲筛查（对照 14 条原则 / 6 个跨模块机制 / 8 个阶段 / 指标表）；七条缺项经用户确认后补写。

## 一、新实例的第一次接触

**问题**：世界源主动消息要求“已经历 / 已获知”的素材且阶段 3 起启用；新实例需要一个有明确来源的初次联络，而不是凭空编一次世界事件。

- 角色卡新增**初见设定**：角色与用户建立联络时的姿态与意向，不是逐字台词，也不暗含已经发生的共同经历。创建前审定并随卡锁定；未填写时只作不新增事实的身份 / 联络确认，不擅自编造过往关系。
- **触发**：用户第一次在有效绑定的会话视图中打开该角色，登记一次开场请求；只有时间线已激活、状态已追赶到一致水位且角色未归档时才允许生成。打开冻结线只读历史，不暗中激活；激活后视图仍打开或再次打开，才继续未完成的初见请求。
- 打开信号由**受信管理入口**提供，后台分页、重连与绑定本身不算打开。独立开场只投向触发视图的 thread，并捕获其绑定令牌；不广播、不改长期主动目标。没有打开信号的通道不伪造打开，由首条入站承接初见。
- **一次性与失败**：同一（实例、时间线、角色）共用一份初见状态，多窗口不能各发一条。开场或承接初见的首轮普通回复**成功固化时**才消费资格；独立开场生成失败由管理面显式重试，已并入用户轮次则沿普通回复的重试规则。已经固化但投递失败，只能恢复原消息，不重新生成。
- **与用户抢先发言的边界**：以“独立开场尚未固化”为准，而不是“尚未送达”。开场与普通输入共用会话串行顺序；此时已有入站被接受，就取消独立开场候选，把初见意向并入首轮回复，`reply_to` 正常关联入站。若独立开场已固化，则保留原历史，用户输入按普通轮次处理。
- **事实与时间**：初见设定只提供联络动机，事实来自当轮认知过滤后的一致快照，包含合法初始知识与其后已获知内容；不整包读取背景，不把初态活动冒充当前活动。消息按实际固化时刻写入，不倒填进实例初始提交；提交前仍须检查事实是否过期。并入普通回复不限制该轮使用后来合法获得的知识。
- **回滚与继承**：开场正文、对话经历及派生记忆正常随线回滚；同会话的“初见已完成”防重发记号不随回滚倒退，也不能把被撤销正文重新注入认知。分叉按来源提交继承联络历史；导入保留包内联络历史——已有联络的继承会话不再初见，无联络历史的新会话才有首次资格。重连、换通道与改名不是新会话。
- **睡眠边界**：无用户输入的独立开场不绕过睡眠禁发，初见请求可留待清醒且视图再次可用时处理；用户先发言则并入第七节的睡眠回复。冻结、回滚、删除、角色归档或触发 thread 重绑使旧候选失效，不改投其他窗口。
- 独立开场使用 `reply_to = null`，是**初次联络的单次例外**，不占世界源主动配额、不消费事件素材；不因此放开其他无来源主动消息。随真实实例 / 角色卡在阶段 1 接入，此阶段仅消费经校验的初始知识与初态，不伪造时间进展；阶段 2 起接入当前生活线与认知水位。阶段 0 的占位会话不声称具备这套世界行为。

【保留决定】触发仍为“首次打开”，不是“激活即发”；这里只保证向触发视图提供开场，不把投递成功称为用户已读。

## 二、实体名册门槛

**问题**：“不能凭空添加实体”还需要登记边界；但**可在说法中提及、作为世界实在对象登记、参与状态变化**不是同一件事。

- **登记实体**：创作期声明，或创建期回填按规则生成的人物 / 组织 / 地点 / 物件；有稳定身份，不以显示名作主键。登记不代表它是可聊天角色，也不保证任何角色已知。
- **门槛按用途，不只看具名**：作为事实参与者、独立效果目标、角色真实背景 / 初态引用，或需跨条目稳定指涉的世界实在对象，必须在册。叙事地理中被这些结构引用的地点与重要物件同样适用；匿名但独立参与因果的人物也不能因为无名而免登记。
- **集合与标签**：纯叙述中的“街上的人”等泛称不逐人建档。事件可沿现有规范使用已声明的受影响标签 / 范围；实际效果仍须落到合法状态对象，不把自由文本当效果目标，也不为一个范围标签创建整个人口名册。
- **署名例外保留**：史料贡献者必须有署名、职责与各自时期；仅在寿命模型可给出相容生平时登记为人物，否则只保留署名，不为过名册门槛补造生死。按本人编纂 / 整理时期校验，不把后世成书时刻当作原作者仍在世的证明（沿用 `WORLD_SETTING_SPEC.md` §3.6）。
- **说法中的指称不等于事实实体**：传闻、神话、虚构指控或未能实体化的署名仍可被合法获知、返回与讨论，其文字与指涉随说法 / 传本固化；不能因名字不在册就过滤整条说法，也不能因它反复出现就自动认定此人 / 物真实存在。不在册对象不能因此取得事实参与或状态效果资格。
- **按引用种类校验**：实体参与者与实体目标查名册 / 角色，受影响范围查声明的标签及受支持效果；说法来源按实际类型查渠道、传本条目、观察或用户通讯记录。渠道、史料来源与世界外用户不必一律变成人物实体。正式引用必须闭合，纯署名不能伪装为实体引用。
- **时间与认知另行校验**：人物登记须带种族、出生与合法寿命依据；已发生的死亡有对应时刻，尚在世或无上界寿命不强填一条“已经死亡”的事实。后世史料可以提及已故者，但实际行动时期须与生平相容。组织 / 地点 / 物件不套人物寿命模型。在册只证明可指涉，不授予角色获知权限。
- 本稿不新增运行期实体创生机制；普通对话、说法修辞与惰性展开不得偷偷扩充事实名册。后续若增加创生规则，仍须经事件与世界规则确认，而不是靠 LLM 写出一个名字。

【参数待标定】回填期“要点人物”的挑选与体量；登记、说法与认知的区分不属于可随意调参的部分。

## 三、世界包最小内容标准

**问题**：密度档约束事件产出，不能证明世界可被探索。最低标准应保证结构有效与内容可达，不把某种题材偏好误作所有世界的硬门槛。

本表**补充、不取代** `WORLD_SETTING_SPEC.md` §2.3 与附录 A 的必需字段。校验分两步：模板 / 角色装配时查声明与已有引用，创建期回填后查完整产物、初态与角色知识，再原子锁定；允许回填的留白不必预写完，明确引用的对象则不能永久悬空。

| 内容 | 最小（阻断条件） | 建议（内容丰富度，不阻断） |
|---|---|---|
| 公理与背景、历法、初始世界时刻 | 必填，历法有效，世界边界明确 | 按既有历史回填口径保留跨时代留白，不强凑跨度 |
| 命名语汇 | 对包内采用的实体类别有一致命名规则 | 按题材覆盖人 / 地 / 机构等类别 |
| 种族、寿命与实体引用 | 角色 / 登记人物的寿命依据合法，结构引用闭合 | 不为配额添加人口或组织 |
| 信息来源与双轨 | 说法有来源及获知条件，实情与说法分开；世界内新闻渠道可为空，但初始自知 / 亲历等实际采用的来源须合法 | 2–3 条差异化来源；有相应制度时可含官方来源，不强制所有体裁设官方 |
| 事件源与密度档 | 至少一类合法、受引擎支持的事件源；明确密度，前置条件与效果有效，固定事件不超预算 | 适用时以 3–4 族、每族 3 个模板为生成起点；族数不作为创建门槛 |
| 初始事件 / 传闻 / 谜题 | 字段明确，可为空；已有内容须合法引用双轨，历史后果与初态一致 | 适用时以传闻 3 条、谜题 1 条为生成起点，不为凑数增加不合题材的内容 |
| 史料（传本） | 至少一部有效传本；来源、贡献者时期、覆盖范围及条目引用合法，不能用空壳计数 | 两部立场不同的史料；官修 / 非官修仅为适用题材的起步组合 |
| 角色类型、模板与联络 | 至少一种可装配模板；创建时全部角色卡已确认、联合校验通过，双向联络合法 | 多角色属阶段 5，首版不要求凑多角色 |
| 生活模板 | 世界时间窗与活动有效，覆盖声明的生活区间，明确睡眠 / 无睡眠，不能靠散文补空档 | 由角色职业与世界日长形成差异，不强套现实作息 |
| 可探索入口 | 最终至少一名可联络角色能从合法初始知识、亲历或允许渠道接触一项世界内容；不能只有角色永远读不到的设定 | 线索互引、不同来源保留分歧 |

- 不达最小标准时指出模板 / 创建材料的字段与原因；只缺建议项则提示，不阻断、不偷偷补造事实。满足最小标准也不承诺叙事质量已达标。
- 丰富度数量与规模属于标定起点；**必填、引用闭包、时间相容与认知边界不是调参项**。修改硬门槛须更新规范，不能实现时临时放宽或加严。

## 四、冷启动路径

**问题**：首次启动没有包——从哪进生成器、要不要样例、走到一半放弃之后是什么状态。

- 首次引导保留三个入口：**AI 生成**（对话式，一段描述起手）/ **表单式** / **导入已有包**。导入须先区分**世界包模板**与**世界实例导出件**：前者进入创作与角色装配，后者走完整实例导入，不重新生成角色或回填历史。
- 需要远程生成时先配置 / 检查服务并说明必要文本将发送给供应商，再按第六节确认用量预算；没有 API Key 仍可手编、保存草稿或导入，不伪造 AI 生成成功。
- **草稿态**：只保存当前候选世界包、候选角色卡与继续编辑所需进度；允许字段尚未填完，但明确标记未通过校验。草稿与最终确认文件、可运行实例分开，不因自动保存而成为正式包，也不另建生成历史库。
- **暂停 / 失败与丢弃分开**：关闭引导或中断任务保留当前草稿，返回后可显式继续；“丢弃草稿”才删除该候选。任一路径都不覆盖先前确认的模板。创建期回填的暂存与续作规则见第六节。
- 角色卡走同一路径，并在创建前全部装配、联合审定；回填后再做最终联合校验。完成校验后才原子登记实例，默认冻结，用户明确激活后才能对话。不以“稍后补卡”绕过锁定。

【待定】是否随应用发行一部样例世界包（首次体验更直观 vs 内容维护成本与"这是别人的世界"的混淆）。

## 五、本地数据保护

**问题**：世界与对话长期保存在本机；回滚点不是独立备份，手动导出也不能承担自动保护。

- **备份对象**：本地实例库、其完整历史闭包，以及应用管理的已确认创作资产、当前草稿和非敏感配置。用户选择过的外部模板文件不等于授权备份其整个目录；只有已纳入应用管理的副本进入备份。向量等可重建缓存可省略，源文本与引用不可缺。
- **滚动快照**：参数起点为每现实 24 小时一次、保留最近 7 份成功的自动备份，存于独立目录。首次有正式数据后建立首份；后续按**距上次成功自动备份的间隔**判断到期，有数据变化才新增，不混用“同日去重”。
- **触发与失败**：运行期间定时检查，启动完成恢复后及显式退出前补做一次到期检查；程序关闭时不承诺定时备份。失败不更新成功时间、不删除旧备份；有界等待后报告非剧情性错误，退出不无限等待。新备份完整校验成功后才轮转，手动“立即备份”不受间隔限制，手动保留件不被自动轮转删除。
- **一致性**：复用 `WORLD_SETTING_SPEC.md` §7.1 的一致水位与引用闭包，不直接复制正在写入的零散文件。先写暂存、完整校验，再发布为成功备份；未完成生成只保留可恢复状态，不伪装成已完成结果。
- **恢复不是导入**：普通实例导入仍创建独立新副本；本地灾难恢复则经用户确认，恢复所选备份中的**整套受管数据**，保留原逻辑身份、不与现有库拼接。先在隔离暂存区检查格式、完整性与可恢复性，通过后才切换；失败不覆盖现有数据，原数据保留为隔离副本。确认时说明备份点后的进展会丢失。
- **恢复后的运行边界**：全部时间线先冻结；用户激活时从备份内世界时刻重新锚定，不自动补算备份日至今的间隔。旧进程 / 任务失效，不恢复待生效倍率命令、通道绑定或待发送队列，不自动重播旧消息；需要重新确认通道绑定。普通崩溃重启仍遵循原有离线补算规则，不能与备份恢复混同。
- **损坏处理**：启动时发现完整性损坏，停止写入与自动轮转，不静默重建 / 覆盖；提供校验可用的恢复点或另建数据目录的入口，保留损坏原件。恢复件不兼容时沿用可信转换与拒绝强制加载的规则。
- **凭据不入快照**：API Key、通道 / 插件令牌等全部排除，恢复后重新配置；备份默认也不含普通日志。备份本身含私人对话与内部世界内容，不加密且不自动上传；同盘备份不能防磁盘损坏，应允许用户选择另一存储位置。
- 设置面提供“立即备份”“恢复备份”“打开备份目录”，以及目录、间隔、保留数配置；只显示时间、完整性、成功 / 失败等管理信息，不开放备份内的世界数据浏览器。

【参数待标定】频率、保留数、磁盘预算与压缩策略；备份 / 恢复由核心负责，桌面壳只提供入口。安卓若启用，复用数据语义，触发受平台执行机会限制，不照搬退出回调。

## 六、生成成本预估

**问题**：创作与历史回填可能产生集中用量；需要让用户在开始前知道规模，并能暂停。条目数不等于调用数，不能在没有实测时断言“数百到上千次调用”。

- **按阶段预估**：创作生成与创建期回填分别在开始前确认。根据实际计划的角色数、史料条目 / 传本、批量尺寸、上下文与输出预算、有界校验重试，给出预计远程调用次数区间与 token 量级，并标明估算依据 / 不确定性。确定性骨架计算不算 LLM 调用；历史按卷批量编纂，不能按跨度乘运行期日密度估算。
- **预估不是无限授权**：任务同时给出包含重试的总远程调用上限，用户可调整后确认；达到上限就暂停，保留进度。规模或计划实质变化时重新估算并确认，不靠无限重试偷偷扩支。token 估计不是金额承诺；若包含远程向量化，单列其用量。
- **可中断**：停止派发新请求，等待在途请求在有限时间内结束；供应商已经受理的请求不保证撤销或免计费。已完成且校验通过的产物保留在草稿 / 创建暂存中，未完成内容保持未完成；整个创建仍只在最终联合校验通过后原子进入实例库。
- **续作不重抽**：保留本次创建的已确认输入、种子、规则版本、已采纳产物、进度与已用预算。用户显式继续时先检查是否已完成，复用有效结果，只补未完成部分，不借暂停 / 重启清零额度；变更输入后先判定哪些产物失效，重新校验与确认预算，不把两套世界拼在一起。暂存可丢弃，始终不是可运行实例。
- **真实用量与未知分开**：按服务 / 模型记录实际请求尝试、成功 / 失败 / 在途状态及供应商返回的用量；已消耗预算的重试和失败请求不能漏记。token 只把供应商已回报部分称为实测，超时、取消或未回报部分标“未知”，不能记成 0；字符推算若提供，单独标为估算。
- 完成 / 中断时给本次任务摘要并保存本地用量记录；不写入世界历史、不随实例导出。记录只含任务、阶段、模型与用量等运维信息，不复制 prompt、世界秘密、对话正文或凭据；常规运行中的对话 / 惰性展开不混进本次创建用量。
- 不猜价格、不做费用面板与账户绑定；调用与预算状态在任务界面可见，两端共用统计口径。

## 七、睡眠期回复

**问题**：睡眠中的角色不应与清醒时具有相同响应节奏。用户已定：仍回，但半梦半醒 + 延迟；判断依据是她的世界生活线，不是用户现实中的深夜。

- **触发与等待**：输入持久接收后，在一致水位读取角色生活线；处于睡眠块才设置现实延迟，参数起点 30–120 秒。等待截止点以核心首次接受该批输入的现实时间为基准，一次确定并持久化；后续输入不重置、不按条数叠加。取快照 / 排队已耗去的时间计入等待，世界推进不被暂停。
- **合并只改变回复组织，不吞输入**：仅合并同一会话、同一已认证通道 / thread、同一绑定版本与运行世代内的一段连续入站，按全会话接受顺序串行处理，不跨通道合并或广播。各输入保留自己的原文、标识、顺序与接受状态；截止点到达、开始生成、达到容量或遇其他来源输入，任一发生即封口，后来输入属于下一批。
- 合并批次共享一份固化回复及处理结果，`reply_to` 关联批内最后一条入站；核心保留该回复覆盖的全部输入关联。查询或重试任一批内输入都返回同一批状态 / 同一 `message_id`，不再逐条补发、不重复提取同一来源。失败与取消也同步结算到各输入，不能让前面的消息永久“排队”。这项多入一回语义须同步写入 UMP，不能只靠前端拼文本。
- **到期按真实状态表达**：到期取当前一致快照再生成，提交前沿用事实过期检查。仍睡眠时作短暂朦胧应答，不声称起身做事；已自然醒来则按清醒状态回复，可回顾“刚才睡着”，不得为了套睡意口吻否认世界推进。30–120 秒是人为等待预算，不承诺网络 / 排队后的总送达时长。
- **只保持生活安排不变**：这次应答本身不截断睡眠块、不改次日计划，也不伪造清醒活动；但对话原文、合法获知、记忆与其他允许的对话增量照常保存。所谓“被吵醒”是短暂应答的表达，不是把所有状态写入禁掉。世界事件确实改变生活线时，以新事实为准。
- **恢复与作废**：普通断线保留等待任务；冻结、回滚、删除、角色归档或来源 thread 重绑使旧任务失效。进程中断沿既有“标记中断 → 显式重试”恢复，先检查是否已有固化结果；不重抽等待、不重新等待完整节拍，不绕过后续轮次与运行世代检查。导入 / 备份恢复不自动恢复旧发送任务。
- 后续主动消息只看生活线中的**下一次实际醒来**，不假定现实次日；还须有合法已发生素材、分享价值、额度与唯一目标，不新增必发的“醒来补偿”。睡眠期一般主动消息仍禁发。
- 非睡眠时段不额外设置睡眠等待，同会话仍守既有处理顺序；无睡眠角色不适用。生活线不可读则按已有未就绪 / 错误语义处理，不凭现实钟猜她在睡。

【参数待标定】延迟分布、单批容量与已有队列上限；超限明确拒收 / 背压，不裁掉已接受消息。机制随生活线在阶段 2 接入，不把等待状态作为内部睡眠面板展示。
