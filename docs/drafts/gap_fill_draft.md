## 一、新实例的第一次接触

**问题**：主动消息要求"已经历 / 已获知"的素材且阶段 3 起启用；在此之前，新建实例是一间空屋子。

- 角色卡新增**初见设定**：角色与用户建立联络时的姿态与意向（不是逐字台词；表达时按世界状态与认知生成，校验同回复链路）。
- **触发**：实例激活后，该角色会话**第一次被打开**时发出一次开场消息；每会话一次性、幂等，重开不重发，回滚不复活。
- 开场是会话层消息（`reply_to = null`），但**不占主动配额、不来自后续素材**——它属于初始状态的一部分。
- 生成约束：只用角色初始知识与初始状态（认知过滤），不得引用尚未发生的世界事件。
- 若用户在开场发出前已发言，开场**并入该轮回复**，不补发第二条。

【判断点】触发时机取"首次打开"（确保用户能看到）；若以后想要"激活即发"另行修订。

## 二、实体名册门槛

**问题**：现在只有"不能凭空添加实体"，没有"谁该被登记"；寿命建模、编者门槛、事件参与者与指涉复全都压在它上面。

- **登记实体**：创作期声明、或回填期按要点规则生成的人物 / 组织 / 地点 / 物件；带稳定标识，可被引用、可被事件参与、可被对话提及。
- **门槛**：事件中出现的**具名**人物 / 地点 / 组织、史料贡献者、角色背景引用的对象、初始状态条目指向的对象，必须在册；集合与泛称不要求在册。
- **不在册**的名字只能作为说法文本里的字串：不参与因果、不产生获知记录、不被认知接口返回。
- **校验**：事件参与者、效果目标、说法来源必须指向在册实体或角色；悬空引用在创作期与创建期校验报错。
- 人物类登记实体带出生 / 死亡（寿命模型）；组织 / 地点 / 物件不适用。

【缺口】回填期"要点人物"的挑选规则与体量属标定项（已登记于 `WORLD_SETTING_SPEC.md` 残余）。

## 三、世界包最小内容标准

**问题**：密度档解决了"每天出事多少"，没解决"一个包要有什么才算够"；这是生成器的目标函数，也是校验器的依据。

| 内容 | 最小（否则不能创建实例） | 建议（撑得起可探索的世界） |
|---|---|---|
| 公理与背景、历法、初始世界时刻 | 必填、历法合法 | 留白 ≥ 2 个时代 |
| 命名语汇 | 必填 | ≥ 3 类（人 / 地 / 机构） |
| 信息渠道 | ≥ 1 | 2–3，含至少一条官方来源 |
| 事件源与密度档 | ≥ 2 族可用 | 3–4 族、每族 ≥ 3 个模板 |
| 初始事件 / 传闻 / 谜题 | 各 ≥ 1 | 传闻 ≥ 3、谜题 ≥ 1 |
| 史料（传本） | ≥ 1 部 | 2 部（1 官修 + 1 非官修） |
| 角色类型与模板 | ≥ 1 | — |
| 生活模板 | 必填、可被历法解释 | 覆盖包内日长 |

- 达不到"最小"→ 校验失败并指出字段（沿用 §2.3）；达不到"建议"→ 提示但不阻断。
- 【缺口】数字均为**参数起点**，实现时标定。

## 四、冷启动路径

**问题**：首次启动没有包——从哪进生成器、要不要样例、走到一半放弃之后是什么状态。

- 首次引导三入口：**AI 生成**（对话式，一段描述起手）/ **表单式** / **导入已有包**。
- **草稿态**：候选世界包与候选角色卡在确认前保存为本地草稿（可继续、可丢弃、不进入实例库）；取消或失败不产生半包。
- 生成中断：保留草稿与已填字段，再次进入引导可继续。
- 角色卡走同一路径；与世界包在实例创建前联合审定。

【待定】是否随应用发行一部样例世界包（首次体验更直观 vs 内容维护成本与"这是别人的世界"的混淆）。

## 五、本地数据保护

**问题**：长跑的世界只有一个本地库；回滚 ≠ 备份，导出是手动的。

- **滚动快照**：默认每现实 24 小时一次、保留 7 份，独立目录；快照取一致水位（沿用导出的闭包规则，向量缓存可裁剪）。
- **触发**：应用运行期间定时 + 显式退出前一次（同日去重）。
- **损坏恢复**：启动时校验数据完整性；损坏则拒绝静默重建，提示从快照恢复或新建。
- **凭据不入快照**：恢复后需重新填写 API Key（与"凭据不进入导出件"一致）。
- 设置面提供"立即备份"与"打开备份目录"。

【判断点】默认排除凭据；【缺口】频率、保留数与压缩策略为参数起点。

## 六、生成成本预估

**问题**：生成世界包 + 回填是一次数百到上千次调用的大额支出，而设置面只有地址与 Key。

- 生成 / 回填开始前给出**预估**：预计调用次数区间与 token 量级（按世界规模与跨度参数），用户确认后执行。
- 执行中可**中断**：已产出内容留在草稿 / 未锁定状态，按"不留下半个实例"规则不进入实例库。
- 完成或中断后报**实际用量**（调用数、token 量级），存本地用量记录；不进世界数据、不随实例导出。
- 不猜价格、不做费用面板与账户绑定：只报次数与 token 量级。

## 七、睡眠期回复

**问题**：生成链路对睡眠无涉，深夜发消息她秒回。用户已定：回，但半梦半醒 + 延迟。

- 生成前读该角色当前生活线：处于睡眠块 → 按**被吵醒**处理。
- **延迟**：回复延迟一个有界节拍（**现实时间**，参数起点 30–120 秒，不随消息条数叠加）；期间同一会话的连续入站**合并为一次回复**。
- **表达**：带睡意口吻（表达层约束，不改变事实与认知边界）；不得声称"已经醒了去做事"——她仍在睡。
- **状态不变**：该回复不作为清醒活动写入生活线；次日醒来可有一条主动消息（沿用既有素材规则）。
- 非睡眠时段不受影响；无睡眠角色不适用。

【缺口】延迟节拍与合并窗口为参数起点。
