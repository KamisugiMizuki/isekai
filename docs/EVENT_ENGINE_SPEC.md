# 世界事件引擎（EVENT_ENGINE_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「世界事件引擎」子系统设计文档
> 来源：2026-09-19 深化轮（决策：事件密度 = 世界包**必填**体裁属性；事件带**公共说法层**，误解可传播）。
> 定位：世界运行层的子系统——产出写入事件日志（见 `WORLD_RUNTIME_SPEC.md` §十二）。

## 一、职责与范围

**职责**：世界侧事件的生成、固化与流转——事件模型、确定性生成、事件族与预算、可见性（认知范围）、与生活线互动、主动发言素材、用户引入事件（世界修改路径）。

**范围外**：认知过滤的执行（运行层认知接口）、主动发言的发送决策（会话层）、生活线本身（运行层）。

## 二、事件模型

| 字段组 | 内容 | 说明 |
|---|---|---|
| 身份 | 事件 id、来源 | 来源：引擎生成 / 用户引入 / 生活线派生 |
| 时间 | 世界时间（历法时刻） | 挂世界钟 |
| 主体 | 世界 ｜ 角色 | 世界级事件 / 角色经历 |
| 类型（族） | 政治 / 灾害 / 节庆 / 风闻（世界级）；经历（角色级） | 见 §四 |
| 内容 | **实情**（真相描述）＋ **说法[]**（流传版本，0..n） | 说法可与实情相反（承双轨决策） |
| 认知范围 | 谁可能知道（标签：公开 / 本地 / 宫廷 / 传闻 / 远方……） | 供认知接口过滤 |
| 素材标记 | 是否值得她提起 | 主动发言筛选依据（见 §七） |

## 三、生成（骨架确定性 + 文本一次固化）

- **骨架**：由「世界种子 + 历法日 + 密度档」经**确定性函数**生成——是否发生、类型族、规模档、参与方基调。同一世界、同一历法日，任何消费者得到同答案。
- **文本**：实情与说法由 LLM 生成**一次**，随即固化进入该时间线状态（此后不再变化）；生成失败 → 模板兜底。
- **推导约束**：事件必须从世界包（双轨内容 / 事件源 / 既有事件）推导——**不凭空**；阶段 6 的「世界自演化」即该推导链加深：新设定从旧设定长出。
- 写入即固化：随提交快照与回滚（见 `WORLD_RUNTIME_SPEC.md`）。

## 四、事件族与预算

**密度 = 世界包必填**：事件密度是体裁属性（王都 vs 荒野不同），由世界包声明密度档；引擎按档抽样。

| 档（建议值，实现后标定） | 每历法日世界级事件预算 |
|---|---|
| 稀疏 | 0–1 件 |
| 常规 | 1–3 件 |
| 丰盛 | 2–5 件 |

世界级四族（v1）：

| 族 | 题材示例 | 典型认知范围 |
|---|---|---|
| 政治 | 政令、贵族动向、边患 | 公开 / 宫廷 / 传闻 |
| 灾害 | 天灾、事故、封路（叙事面） | 本地 / 公开 |
| 节庆 | 节日、集市、典礼 | 公开 |
| 风闻 | 传闻、谣言、异象 | 传闻（**天然带说法层**） |

**角色经历**（角色级）：由生活线执行与世界事件派生（例：节庆 → 她去看了集市）；按生活线节奏产生，与世界级事件分别预算。

## 五、可见性与跨角色

- 每事件带**认知范围**；认知接口按角色（经历 / 信息渠道 / 设定）过滤后返回（见 `WORLD_RUNTIME_SPEC.md` §十三）。
- 实情层不直接外泄；角色能说出的是**说法层**（可与实情相反；「误解」是设计素材）。
- 多角色共享时：事件是**公共事实源**（同一世界、同一历法日，各角色面对同一事件骨架）；谁知晓什么由各自认知面决定。

## 六、与生活线的互动

- 世界事件可**覆盖**当日剩余活动块（简单覆盖语义）：与角色相关的事件（发生地 / 波及范围）触发覆盖或标记。
- 覆盖只调整当日计划，不走回滚语义。

## 七、主动发言素材

- 事件生成时评估「**值得她提起**」并打素材标记；被标记的事件进入主动发言候选（会话层按她的世界节律择时筛选）。
- 素材 ≠ 发送决策：发送时机与节流在会话层（见 `SESSION_CORE_SPEC.md` §五）。

## 八、用户引入事件（世界修改路径）

（承总设计原则 9：世界设定初始确定，后续修改通过引入世界事件 + 创建时间线进行。）

1. 用户描述修改意图（自然语言）；
2. 系统结构化为事件草案（类型 / 时间 / 内容 / 认知范围）；
3. **一致性校验**：对照世界包（含双轨）与既有事件——不允许与实情层冲突的引入；冲突 → 提示并给出可行的近似（或由用户改写）；
4. 用户确认；
5. **创建新时间线**：从修改点（指定提交点或当前）分叉，注入该事件；原时间线保留（创建语义，非回滚）；
6. 事件随新时间线固化。

设计含义：世界修改永远走「新时间线」——已创建的过去不被改写；这是「世界事件驱动修改」的实现路径。

## 九、与其它模块的接口

| 对方模块 | 接口面 |
|---|---|
| 世界运行层 | 事件日志（写入 / 检索）、生活线覆盖、提交 / 回滚 |
| 会话核心层 | 主动发言素材（素材标记事件）；认知接口经其暴露给生成链路 |
| 世界设定层 | 世界包提供：事件源 / 密度档（必填）/ 双轨内容（推导依据） |
| 角色卡 | 角色级事件的主体（她的经历落点） |

## 十、实施分期

- **阶段 3**：事件日志 + 世界级四族 + 角色经历派生 + 素材标记。
- **阶段 4**（时间线机制就绪后）：用户引入事件。
- **阶段 6**：世界自演化（推导链加深）。

## 十一、待模块设计项（残余）

- 种子函数的实现细节（哈希输入与骨架映射）。
- 事件文本生成的提示词与兜底模板库。
- 事件族模板库与规模档数值。
- 密度档的具体参数标定。
