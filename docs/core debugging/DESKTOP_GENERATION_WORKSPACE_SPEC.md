# 生成工作区设计草案（世界包 / 角色卡）

> 状态：**已定稿 v1.0（2026-09-21）**。与 `DESKTOP_SPEC.md` 并列的界面设计篇（DESKTOP_SPEC 管义务与验收，本篇管排布与交互）；职责边界：全局配置归设置页，世界 / 角色的操作归管理页。
> 起因：管理页里的「世界包」「角色卡」目前各只有两个文本框（一段话 + 名称）+ 一个生成按钮，调节自由度与可见性都不够；
> 用户提出把生成改成「按钮 → 进入可交互的生成界面」，并问世界包 / 角色卡两个生成界面该怎么排。

> 后续正式桌面入口与结构化表单按 [统一界面设计 §5](../user-interface/USER_INTERFACE_DESIGN.md) 执行；本文保留生成参数、分段编辑、锁定和现有实现依据。正式入口改为“世界与素材”，不再复制一套管理页生成器。新交互尚未实施。

## 一、结论先行（三条）

1. **入口归属不变**：世界包的一切操作留在管理页的「世界」区（页面标题即「世界」），角色卡同理；设置页只放全局配置。
2. **形态（已拍板 2026-09-21）：主窗口内的「生成工作区」**，不是新的 OS 窗口。理由：`DESKTOP_SPEC` §2 定的是**单窗口侧栏**；工作区自带未保存状态、草稿续作、长调用进度，独立窗口要额外背一套窗口生命周期与状态同步，收益不抵成本。若以后确实要真独立窗口，单独改 §2 再说（本草案不铺）。
3. **后端基本齐了**：分段补全 `world.package.fill`、指令修订 `world.package.revise`、草稿 `world.draft.*`、校验 `world.package.validate`、落盘 `world.package.save`、卡的生成与确认 `world.card.generate` / `world.card.confirm` 都已存在；UI 只需接上，**本方案不新增后端 op**（唯一可选项：把「生成进度」做成轮询，见 §六）。

## 二、管理页的入口改造（世界包 / 角色卡两组）

```
管理（世界）
├── 世界包
│   ├── [导入世界包…]         ← 新增：原生文件选择 → 字节限额 + 结构校验 → 通过才落盘
│   ├── [新建世界包]          ← 原「新建骨架」
│   ├── [AI 生成世界包]        ← 原两个文本框 + 按钮，改成**一个按钮**，进工作区
│   └── 列表：选包 / [校验] / 详情
├── 角色卡
│   ├── [导入角色卡…]         ← 新增：需先选归属世界包（渠道与史料引用依赖包）
│   ├── [新建角色卡]
│   ├── [AI 生成角色卡]        ← 同样改成按钮，进工作区
│   └── 列表：选卡 / [确认卡片] / 选包做联合校验
├── 草稿（未完成的创作）
└── 世界实例
```

要点：**导入与生成并列**，都是「把一个包/卡弄进来」的两条路；「AI 生成」按钮只负责**进入工作区**，不再在管理页里塞输入框。

> 落地进度（2026-09-21）：导入路线已开工——核心侧 `world.package.import` / `world.card.import` 已实现（读取前字节限额 → 结构 / 联合校验 → 校验不过不落盘；同名要显式确认才覆盖），壳侧两个导入按钮与实例组的「不兼容 → 转换」入口正在接线；生成工作区本体按 §七 P1 走。

## 三、世界包生成工作区

### 3.0 先把「能调节的东西」数清楚

世界包真实字段面（以 `world/example.py` 的样例包为准，15 个顶层键）：

| 段 | 顶层键 | 可调的是什么 |
|---|---|---|
| ① 结构 | `meta`、`calendar` | 名称 / 纪元 / 历法（年长、月数、日长、季节） |
| ② 世界细节 | `world.axioms`、`world.geography`、`world.society`、`world.lexicon`、`world.institutions`、`world.customs`、`environment`、`races`、`roles`、`comms` | 公理、地理、社会形态、用词表、制度（含职位）、惯例、环境类型、种族与寿命、角色位、称谓 |
| ③ 历史与说法 | `sources`、`canon`、`narratives`、`historiography`、`entities`、`events`（含 `density` / `families` / 节庆）、`life`、`initial_state` | 传本、实情条目、说法条目、史学口径、实体、事件族与节庆、生活模板、初始态 |

**自由度 = 两层**：`参数层`（要多少、什么调性）和 `条目层`（具体每一条长什么样，且改动不被重生成覆盖）。只做参数层就是现在的两个文本框放大版，所以这版设计两层都做。

### 3.2 参数层：旋钮清单（13 个计数 + 9 个取向）

| 组 | 旋钮 | 取值 | 落到哪 |
|---|---|---|---|
| 取向 | 体裁 / 基调 / 超自然在场度 / 技术水位 / 命名风格 / 冲突主线 / 纪元起点 / 当前年 / 史料深度 | 下拉或短文本 | 提示词的「调性段」 |
| 规模 | 公理 / 区域 / 制度(含职位) / 惯例 / 环境类型 / 种族 / 角色位 / 用词表 / 传本 / 实情条目 / 说法条目 / 实体 / 生活模板 / 事件族 / 节庆 | 数字（0 = 不生成该段） | 提示词的「只产出 N 个 X」 |
| 内容指定 | 必含清单 / 禁忌清单 / 参考致敬 | 多行文本，一行一条 | 提示词的「必须出现 / 禁止出现」 |

**一句诚实的话**：旋钮全部只影响提示词；`validate_package` 才是硬闸（比如「区域 0 且地理段为空」会被校验拦下），界面上把校验错误摆在 ③ 列就是为了这个。

### 3.3 条目层：编辑、加、锁（这版的重点）

- 每段可展开成**条目表**：一行一条 `id · 摘要 · 来源(AI/你/锁定) · [编辑][复制][删除][锁定]`；段头有 **[＋加一条]**（从该段的字段模板起手）与 **[重跑这段]**。
- **锁定 = 重生成不覆盖**。重跑某段时，锁定条目原样带进提示词，明确「以下条目已定稿，不要改动」；未锁定条目允许模型重写。锁定集合随草稿一起存。
- 从空骨架长：`[新建骨架]` 的产物可以直接丢进工作区（每段都是空表），用户自己写几条、锁上，再让 AI 只补其余。
- 条目字段表单按段的真实结构生成（公理 = 一句话；制度 = mandate/scope/succession/职位；事件模板 = summary/preconditions/effects(闭集)/expiry…），不做自由 JSON 编辑框当唯一入口。

### 3.4 可见性

- **[看这次给模型的提示词 ▾]**：把拼好的提示词折叠展示（只读）。用户能看见「我填的旋钮变成了哪句话」，旋钮才不是玄学。
- 每个条目行显示来源，AI 给的内容不冒充用户写的。
- 摘要卡片记住本次旋钮取值（「上次：区域3/实体8/基调冷硬」），方便复现。

```
└────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 与世界包工作区的三处不同

1. **必须先有包**：归属世界包是**必填**，渠道选项、史料 scope、寿命带全部从包里读；没有包就只给「先建/导入一个包」的引导，不给生成按钮。
2. **字段级而非段级**：卡是十几个短字段（身份职业 / 背景 / 性格与口吻 / 初始处境 / 渠道（多选包内 source）/ 史料引用（scope）/ 寿命与生死 / 初始意向 / 初始知识（渠道 + 史料两条来源各选一遍）），按字段给「AI 给的 / 你改的」并标来源，字段可 [锁定]（重跑不覆盖），粒度是「这个字段」或「整卡」。
3. **确认是硬闸**：`world.card.confirm` 才是最终版；未确认的卡进不了实例（`validate_assembly` 的既有行为）。所以工作区右下角的主按钮是 **[确认卡片]**，不是 [保存]；`[存为草稿]` 保留中间态。

## 五、两个工作区的公共件（写一次，两处用）

| 件 | 说明 |
|---|---|
| 顶栏与返回 | `管理 ▸ 世界包/角色卡 ▸ 生成`，[返回] 回管理页对应组；离开前未保存提示 |
| 状态条 | 模型名 · 本次调用次数 / 预算上限 · 最近一次错误 · 草稿保存时间 |
| 错误清单 | 统一渲染 `validate_*` 的 error 列表；每条可点，跳段（包）或跳字段（卡） |
| 长调用 | 生成期间按钮转「生成中…」+ 可取消（取消 = 丢弃本次结果，不动已有段落/字段） |
| 草稿续作 | 进入工作区时若该名下有草稿，先问「继续上次 / 重新开始」 |

## 六、可选增强（P3，先不做）

- **进度可见**：现在生成是一次长调用，界面只能转圈。要显示「正在生成第 2 段」需要后端分段回调或轮询（`call_ledger` 已有记账）。**P3，先说清楚代价**：加这个要动生成器的调用切分，不是纯 UI。
- **并排对比**：同一 brief 生成两份取其一（多花一次预算）。
- **从空骨架长**：把「新建骨架」的产物直接丢进工作区，用 [重跑这段] 逐段填充（对「先写结构、再让 AI 填」的用法很顺）。
