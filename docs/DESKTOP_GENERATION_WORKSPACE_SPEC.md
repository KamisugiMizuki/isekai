# 生成工作区设计草案（世界包 / 角色卡）

> 状态：**草案 v0.1（2026-09-21），未定稿**。定稿后并入 `DESKTOP_SPEC.md`；本文件只写设计与验收，不写代码条目。
> 起因：管理页里的「世界包」「角色卡」目前各只有两个文本框（一段话 + 名称）+ 一个生成按钮，调节自由度与可见性都不够；
> 用户提出把生成改成「按钮 → 进入可交互的生成界面」，并问世界包 / 角色卡两个生成界面该怎么排。

## 一、结论先行（三条）

1. **入口归属不变**：世界包的一切操作留在管理页的「世界」区（页面标题即「世界」），角色卡同理；设置页只放全局配置。
2. **形态：主窗口内的「生成工作区」**，不是新的 OS 窗口。理由：`DESKTOP_SPEC` §2 定的是**单窗口侧栏**；工作区自带未保存状态、草稿续作、长调用进度，独立窗口要额外背一套窗口生命周期与状态同步，收益不抵成本。若以后确实要真独立窗口，单独改 §2 再说（本草案不铺）。
3. **后端基本齐了**：分段补全 `world.package.fill`、指令修订 `world.package.revise`、草稿 `world.draft.*`、校验 `world.package.validate`、落盘 `world.package.save`、卡的生成与确认 `world.card.generate` / `world.card.confirm` 都已存在；UI 只需接上，**本方案不新增后端 op**（唯一可选项：把「生成进度」做成轮询，见 §六）。

## 二、管理页的入口改造（世界包 / 角色卡两组）

```
管理（世界）
├── 世界包
│   ├── [导入世界包…]         ← 新增：原生文件选择 → 字节限额 + 结构校验 → 通过才落盘
│   ├── [新建世界包]          ← 原「新建骨架」
│   ├── [AI 生成世界包]        ← 原两个文本框 + 按钮，改成**一个按钮**，进工作区
│   └── 列表：选包 / [校验] / 详情
├── 角色卡
│   ├── [导入角色卡…]         ← 新增：需先选归属世界包（渠道与史料引用依赖包）
│   ├── [新建角色卡]
│   ├── [AI 生成角色卡]        ← 同样改成按钮，进工作区
│   └── 列表：选卡 / [确认卡片] / 选包做联合校验
├── 草稿（未完成的创作）
└── 世界实例
```

要点：**导入与生成并列**，都是「把一个包/卡弄进来」的两条路；「AI 生成」按钮只负责**进入工作区**，不再在管理页里塞输入框。

## 三、世界包生成工作区

### 3.1 布局（三列 + 顶栏 + 底栏）

```
┌ 管理 ▸ 世界包 ▸ 生成 ─────────────────────────────────────────────────────────── [返回] ┐
│ ┌─ ① 意图与约束 ────────┐ ┌─ ② 分段生成与校对 ──────────┐ ┌─ ③ 预览与落盘 ───────┐ │
│ │ 世界名   [________]   │ │ 段 1 结构（meta/历法/公理）  │ │ 摘要                 │ │
│ │ 一段话   [________]   │ │  待生成 ▸ 生成中 ▸ 已通过    │ │  名称 / 纪元 / 区域  │ │
│ │         [________]    │ │  校验错误 n 条  [重跑这段]   │ │  条目数 / 校验状态   │ │
│ │ 体裁与基调 [下拉]      │ │ 段 2 世界细节（区域/制度…）  │ │                      │ │
│ │ 规模：区域[3] 实体[8] │ │  同上                        │ │ [存为草稿]           │ │
│ │      实情[20] 说法[30]│ │ 段 3 历史与说法（canon/…）   │ │ [保存为世界包]       │ │
│ │ 细节度：[简/中/详]    │ │  同上                        │ │                      │ │
│ │ 事件密度：[低/中/高]  │ │ ─────────────────────────    │ │ 错误清单（按段分组） │ │
│ │ 必含 / 禁忌 [自由文本]│ │ 修订：改一句 → [按指令修订]  │ │  点一条 → 跳到该段   │ │
│ └───────────────────────┘ └─────────────────────────────┘ └──────────────────────┘ │
│ 状态条：模型 deepseek-* · 本次调用 3/6 · 最近错误：… · 草稿已存 2 分钟前            │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 三列各管什么

| 列 | 内容 | 落到的既有机制 |
|---|---|---|
| ① 意图与约束 | 世界名、一段话描述、体裁基调、**规模四个旋钮**（区域 / 实体 / 实情条目 / 说法条数）、细节度、事件密度、必含与禁忌自由文本 | `world.package.generate {brief, name, max_calls}`；旋钮进 brief 的**结构化前缀**（拼进提示词），不改后端签名 |
| ② 分段生成与校对 | 三段分别是「结构（meta/历法/公理）」「世界细节（区域/制度/惯例/环境）」「历史与说法（canon/narratives/生活模板/事件族）」；每段一张卡：状态、校验错误数、耗时、**[重跑这段]** | `world.package.fill {package, section}`（分段重跑）· `world.package.revise {instruction}`（按指令改）· `validate_package` 的错误按顶层键归段 |
| ③ 预览与落盘 | 包摘要、[存为草稿]、[保存为世界包]、错误清单（点一条跳到对应段） | `world.draft.save` · `world.package.save`（**校验不过不落盘**，校验器是唯一闸门） |

### 3.3 三个必须做对的细节

- **旋钮只是提示词的结构化前缀**，不是后端的硬约束：生成结果仍以校验器为准。旋钮值显示在摘要里，方便用户复现（「上次是按 区域3/实体8 生成的」）。
- **段与校验错误的对应**：`validate_package` 的错误首字段就是顶层键（`world.axioms:` / `calendar:` / `narratives:`…），按这个归段即可，不另造映射表。
- **未保存保护**：工作区里任何离开动作（返回、切栏、关窗）在「有未落盘的改动」时先提示；草稿是默认兜底（[存为草稿] 随时可按，续作从草稿列表进）。

## 四、角色卡生成工作区

### 4.1 布局

```
┌ 管理 ▸ 角色卡 ▸ 生成 ────────────────────────────────────────────────────────── [返回] ┐
│ ┌─ ① 卡的设定 ──────────┐ ┌─ ② 生成与校对 ──────────────┐ ┌─ ③ 预览与确认 ───────┐ │
│ │ 归属世界包 [下拉 ▾]   │ │ 字段 1 身份与职业            │ │ 公开面（实例可见）   │ │
│ │ 角色名  [________]    │ │  AI 给：…  [采用] [自己改]   │ │  名字 / 职业 / 意向  │ │
│ │ 身份职业[________]    │ │ 字段 2 性格与说话方式        │ │                      │ │
│ │ 背景一段[________]    │ │ 字段 3 初始处境（地/关系）   │ │ 联合校验             │ │
│ │        [________]     │ │ 字段 4 渠道（包内 source）   │ │  对包：✔ 渠道 src-1  │ │
│ │ 性格/口吻[________]   │ │ 字段 5 史料引用（scope）     │ │  对时刻：✔ 活动区间  │ │
│ │ 渠道 [多选 ▾]         │ │ 字段 6 寿命与生死（可选）    │ │                      │ │
│ │ 史料 [多选 ▾]         │ │ ───────────────────────────  │ │ [存为草稿]           │ │
│ │ 寿命/生死 [可选]      │ │ 错误清单（点一条 → 跳字段）  │ │ [确认卡片]           │ │
│ └───────────────────────┘ └──────────────────────────────┘ └──────────────────────┘ │
│ 状态条：包 = greytide.json · 卡片未确认（确认后才可进实例）· 本次调用 1/2            │
└────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 与世界包工作区的三处不同

1. **必须先有包**：归属世界包是**必填**，渠道选项、史料 scope、寿命带全部从包里读；没有包就只给「先建/导入一个包」的引导，不给生成按钮。
2. **字段级而非段级**：卡是十几个短字段，按字段给「AI 给的 / 你改的」并标来源，重跑粒度是「这个字段」或「整卡」，不引段概念。
3. **确认是硬闸**：`world.card.confirm` 才是最终版；未确认的卡进不了实例（`validate_assembly` 的既有行为）。所以工作区右下角的主按钮是 **[确认卡片]**，不是 [保存]；`[存为草稿]` 保留中间态。

## 五、两个工作区的公共件（写一次，两处用）

| 件 | 说明 |
|---|---|
| 顶栏与返回 | `管理 ▸ 世界包/角色卡 ▸ 生成`，[返回] 回管理页对应组；离开前未保存提示 |
| 状态条 | 模型名 · 本次调用次数 / 预算上限 · 最近一次错误 · 草稿保存时间 |
| 错误清单 | 统一渲染 `validate_*` 的 error 列表；每条可点，跳段（包）或跳字段（卡） |
| 长调用 | 生成期间按钮转「生成中…」+ 可取消（取消 = 丢弃本次结果，不动已有段落/字段） |
| 草稿续作 | 进入工作区时若该名下有草稿，先问「继续上次 / 重新开始」 |

## 六、可选增强（P3，先不做）

- **进度可见**：现在生成是一次长调用，界面只能转圈。要显示「正在生成第 2 段」需要后端分段回调或轮询（`call_ledger` 已有记账）。**P3，先说清楚代价**：加这个要动生成器的调用切分，不是纯 UI。
- **并排对比**：同一 brief 生成两份取其一（多花一次预算）。
- **从空骨架长**：把「新建骨架」的产物直接丢进工作区，用 [重跑这段] 逐段填充（对「先写结构、再让 AI 填」的用法很顺）。

## 七、分期与验收

| 期 | 内容 | 验收（行为级，CDP 驱动真壳） |
|---|---|---|
| **P1** | 管理页两组改成入口按钮 + 工作区骨架（三列布局、顶栏返回、状态条、错误清单、草稿续作） | 按 [AI 生成世界包] → 工作区出现且管理页不再有内联输入框；填表 → 生成（FakeLLM）→ 三段各显示状态；保存后包出现在管理页列表；未保存时返回有提示 |
| **P2** | 接上分段重跑与指令修订（包）· 字段级重跑与联合校验（卡） | 改一段后 [重跑这段]，其他段内容逐字段不变；非法产物被 `validate_package` 拦住且不落盘；卡未确认时 [进实例] 不可点 |
| **P3** | 进度可见 / 并排对比 / 从骨架长 | 见 §六，届时另定判据 |

**不做**：真独立 OS 窗口、多标签工作区、生成历史的版本树（草稿本身就是中间态，够了）。
