# 会话核心层（SESSION_CORE_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 会话核心层
> 来源：2026-09-19 模块深化；本轮统一会话身份、事务边界、披露与主动投递。
> 状态：设计规范，尚未实现；角色记忆细则见 `MEMORY_SPEC.md`。

## 一、模块职责与范围

**职责**：会话与路由、对话隔离、回复生成全链路、披露、世界源主动发言、记忆编排。

- 世界运行层持有世界与角色状态，本层通过其一致性边界读取与回写，不另建一套真值。
- 不带入用户中心机制：关系 / 好感 / 依恋数值、用户情绪感知、想念 / 牵挂驱力、用户权重、屏幕视觉注意力、用户模型与文风学习。
- 普通聊天中，用户是世界外联络者；影响路径为「用户 → 角色自主行动 → 世界」。显式管理面引入事件是另一条已授权路径，不由聊天文本隐式触发。

## 二、会话与绑定

### 2.1 身份定义

- **会话**：固定绑定（世界实例、时间线、角色）的持久对话身份；同一三元组复用同一会话，不因新开窗口而形成第二套记忆。
- **窗口 / 当前视图**：用户此刻选择看哪一个会话，不持有另一份历史。
- **通道 thread**：外部平台或内建客户端的对话载体；路由键为已认证通道实例身份与 thread 标识。
- 一个会话可绑定多个通道 thread；一个 thread 在某一绑定版本下只指向一个会话。绑定只由受信管理面修改，插件不能自选世界标识越权绑定。

### 2.2 切换语义

| 操作 | 语义 |
|---|---|
| 切换世界 / 角色 / 时间线 | 选择目标三元组对应的会话，创建或恢复其视图；不修改原会话身份 |
| 更换通道 | 新 thread 绑定到已有会话，沿用其历史与角色状态 |
| 重绑已有 thread | 原绑定版本失效，改为指向目标会话；旧历史留在原会话，不迁移 |
| 激活 / 冻结时间线 | 世界运行操作；与选择窗口分开，不随视图切换暗中执行 |

同一时间线内角色共享世界时钟但不共享对话。可以同时打开绑定不同线的会话；冻结线仅可查阅既有对话，发新消息前须明确激活，不能以对话偷偷推进冻结世界。

### 2.3 消息路由

- 入站：认证通道 → 核验发送时取得的不透明绑定令牌 → thread 绑定 → 固定会话 → 对应时间线，不读取 UI 的全局「当前激活线」。令牌过期的未接收消息也拒绝，不以当前绑定重新解释旧输入。
- 普通回复只回来源 thread，不广播到所有绑定。同会话其他视图不实时同步推送，但再次加载历史时须看到同一份持久数据。
- 通道断线不删除会话。路由、连接状态与凭据属于本机控制数据，不随世界回滚或跨端导入恢复。
- 未绑定、失效或指向已删除对象的 thread 返回明确错误，不能自动选默认角色。
- 指向已归档角色的会话转为**只读**：既有历史与记忆可查阅，入站消息明确拒绝（不静默丢弃、不自动改投默认角色），不为其生成新回复。

## 三、对话上下文与时间线

- 历史与角色记忆按实例、时间线、角色隔离；不同线分叉前的共同过去可继承，分叉后的对话互不可见。
- 回滚恢复目标提交的对话、披露与记忆版本，不能仅删新增消息而保留后来整理的摘要或强化状态。
- 切换只读取目标会话自己的历史，不跨线拼接。界面始终标识当前实例 / 角色 / 时间线。
- 分页历史接口只返回用户与角色的往来原文及处理 / 投递状态，不返回内部记忆、提示词或事件日志。
- 分页游标和客户端缓存绑定历史版本；回滚 / 删除 / 重绑后失效并重载，不能继续显示被撤销的本地缓存。
- 同一三元组来自不同 thread 的轮次按核心接受顺序串行处理；不同线可独立运行，避免同角色并发回复相互覆盖。
- **持久化不依赖自动提交开关**。自动提交决定可选历史回滚点，不决定聊天和世界状态是否能跨重启恢复。

## 四、生成链路（Agent 层）

### 4.1 定位

把用户消息与角色可见世界上下文变成最终角色文本；通道只看到接受回执、操作状态、最终回复或错误，不接触中间推理。

### 4.2 处理顺序

1. **接收**：按 UMP 去重与校验；记录输入、处理状态、固定绑定、绑定版本和运行世代，持久化后才确认接收。相同请求重试查询既有处理结果，不再次生成。
2. **取快照**：捕获输入所需世界水位，待运行层完成后读取该线的一致快照；时间、生活线、认知与记忆来自同一可读边界。
3. **组装**：已过滤的角色扮演定义、性格表达、同一水位的世界时刻、实际活动、仍有效的相关后果、认知可见子集、当前角色记忆简报和最近对话。地点、在场者、环境或身体状态只有在该水位存在合法来源时加入；不得整包注入世界设定或带秘密的角色创作背景，也不得把计划当经历。
- 组装中的当前处境按固定顺序合并：世界时刻与活动 → 有效事件 / 身体 / 环境效果 → 角色实际经历与认知投影 → 规范记忆 → 最近对话。来源冲突按水位、角色可知范围和状态有效期裁决，不能由模型自行选择幕后真相。
4. **生成**：有界调用 LLM，失败保留用户输入与失败状态；不把空回复、截断协议或内部分析当成成功文本。
5. **校验**：检查输出完整性、认知边界、当前事实表述与来源；允许有来源的错误传闻，不以幕后真相强行纠正角色的合法误解。失败有界重试，仍不合格则返回不越界的回应或明确生成失败。
6. **提交**：再次核对绑定版本、运行世代、来源有效性；将最终回复、明确披露的效果、合法角色增量与后续提取任务依据一致持久化。
7. **投递**：向来源 thread 发送固化回复，适配分段；成功 / 失败 / 未知回执更新投递状态。发送重试只重发已有产物，不重新生成或重复写记忆。
8. **派生任务**：记忆提取、向量化等可异步完成，必须携带同一作用域与来源版本；失效结果不可回写。

### 4.3 时间与并发规则

- **生成不阻塞世界时钟**；世界可在 LLM 等待期间继续推进，本轮只写自己的增量，不能整份旧快照覆盖新世界状态。
- 正常时间推进不自动取消本轮，但会使「我现在正在……」类表述过期；提交前检查所依赖的活动 / 事件，必要时改为有时间依据的回顾或重新生成一次。持续高速变化时明确失败，不无限追赶或冒充当前事实。
- 回滚、冻结、删除或来源 thread 重绑会使未完成轮次失效；迟到结果不写入、不投向新绑定。已经固化的历史不因普通断线消失。
- 崩溃后已完成轮次恢复原产物；尚未完成者标记中断并通过显式重试恢复处理，先检查旧结果是否已经提交，不能静默漏单或执行两次。
- 生成重试不得向已完成的后续轮次之前插入新角色回复：只在该会话尚无后续成功轮次、绑定与世代仍有效时恢复原轮次；否则提示用户作为当前新消息重新发送。世界已推进时重新取一致快照，动作不得倒填进过去。
- 生成与状态校验错误只给可理解的原因，不含实情、内部字段、prompt、记忆简报或供应商敏感响应。

### 4.4 角色行动与世界影响

- 普通对话可以促成角色自主行动，但「她说要做」不等于「已经做了」。
- 行动候选须有来源输入、角色、目标时刻及受支持效果，经运行层 / 事件引擎校验后才形成事件并影响生活线。
- 不允许对话生成器直接覆盖世界事实、计划或公理；不支持的行动只保留为意愿，不能伪报执行成功。
- 首版只复用已有事件效果，不另建通用任务执行器或无限制规划器。事实效果与 LLM 表述边界见 `EVENT_ENGINE_SPEC.md`。
- **打算跨轮延续**：角色自己的打算（含并非由用户提出的）在话题切换与应用重启后仍可延续；运行层在相关世界事件、生活线节点、阻碍或目标时间窗到来时触发重议。无用户输入也可以重议，但只有受支持行动经运行层 / 事件引擎校验后才产生世界效果；放弃、延期与改主意都合法，且须有角色可知的依据。
- 用户建议不是命令：角色可接受、保留或拒绝；不引入用户任务清单、完成奖励或进度播报。

### 4.5 睡眠期等待与合并（多入一回）

- **触发与等待**：输入持久接收后，在一致水位读取该角色生活线；仅当处于睡眠块时设置现实延迟（参数起点 30–120 秒）。截止点以核心首次接受该批输入的现实时间为基准，一次确定并持久化；后续输入不重置、不按条数叠加。取快照与排队已耗去的时间计入等待，世界推进不被暂停。
- **合并只改变回复组织，不吞输入**：只合并同一会话、同一已认证通道 / thread、同一绑定版本与运行世代内的一段连续入站，按全会话接受顺序串行处理；不跨通道合并或广播。各输入保留自己的原文、标识、顺序与接受状态；截止点到达、开始生成、达到容量或遇其他来源输入，任一发生即封口，后来输入属于下一批。
- 合并批次共享一份固化回复与处理结果；`reply_to` 关联批内最后一条入站，核心保留该回复覆盖的全部输入关联。查询或重试批内任一输入返回同一批状态与同一 `message_id`，不逐条补发、不重复提取同一来源；失败与取消同样结算到批内各输入。该语义须在 UMP 层表达，不能靠前端拼接文本。
- **到期按真实状态表达**：到期取当前一致快照再生成，提交前沿用事实过期检查。仍睡眠时作短暂朦胧应答，不声称起身做事；已自然醒来则按清醒状态回复（可回顾「刚才睡着」），不为套睡意口吻否认世界推进。等待预算不承诺网络与排队后的总送达时长。
- **只保持生活安排不变**：应答本身不截断睡眠块、不改次日计划、不伪造清醒活动；对话原文、合法获知、记忆与其他允许的对话增量照常保存。世界事件确实改变生活线时以新事实为准。
- **恢复与作废**：普通断线保留等待任务；冻结、回滚、删除、角色归档或来源 thread 重绑使旧任务失效。进程中断沿既有「标记中断 → 显式重试」恢复，先检查是否已有固化结果；不重抽等待、不重新等待完整节拍。导入 / 备份恢复不自动恢复旧发送任务。
- 非睡眠时段不额外设置等待，同会话仍守既有处理顺序；无睡眠角色不适用；生活线不可读按未就绪 / 错误语义处理，不凭现实钟猜她在睡。

## 五、主动发言（世界源）

### 5.1 来源与认知

- 仅来自角色**已经历 / 已获知**且有分享价值的世界事件或角色经历。
- 不使用用户在线状态、情绪、作息或屏幕信号触发；通道能否投递只是技术状态，不决定角色有没有分享动机。
- 全局事件标记不能绕过角色认知；无合法素材不生成，秘密原文不作为素材直送模型。
- **表达取舍属角色**：在合法认知范围内可完整讲述、只讲部分、暂缓或拒绝，依据价值倾向、处境、已有承诺与具体经历并保持跨轮连续；不按提问次数解锁秘密，不以反复吊胃口维持对话。
- 分享价值可以来自它改变了旧话题的意义，不只来自事件规模或新鲜程度；不要求用户继续追问，不产生待完成事项或剧情催办。

### 5.2 节律、配额与积压

- 按她的世界生活节律择时，睡眠期不主动发送；无睡眠角色不强行套现实夜间。
- 默认起点为**每角色、每时间线、每世界日最多 2 条**，可调；所有窗口 / thread 共用额度与素材消费记录。
- 同一素材不因重启、重试或换通道重复消费。配额按最终消息固化计数，投递失败不重新生成一条来绕过额度。
- 离线补算不补造过去每个发送时机的消息。既有经历保留供问答，恢复后只从仍有时效的素材生成当前消息，过期问候不补发。
- 高倍率也不能把历史天数额度瞬间变成发送洪峰；投递队列有现实时间背压和容量上限，限的是技术发送，不根据用户在线状态择人投递。
- 角色归档后不再产生主动消息、不再消费素材；历史中的既有消息保留，未投递任务按过期规则处理，不补发。

### 5.3 唯一目标与投递

- 会话保存一个明确的主动投递目标；首次绑定默认使用该 thread，多个绑定时由管理面选择。普通入站不暗中更换目标，不广播、不在线追踪改投。
- 消息先固化到会话历史，协议用 `reply_to = null` 表示主动消息，自带稳定标识；同一会话无论几个窗口都只有一份。
- 无目标或目标离线时保留历史与未投递状态，不臆造发送成功。恢复连接只按有界策略处理仍有效的未投递消息，过期消息留在历史而不作为新通知补发。
- 区分已生成、通道 / 平台接受、结果未知与用户已读；默认没有已读证据，不写成「用户已知道」。
- 回滚 / 导入使旧投递任务失效。外部平台已显示的消息不能保证撤销，世界经历也不因发送失败消失。
- 桌面提醒若由平台支持，只能引用已固化的主动消息，并携带实例 / 时间线 / 角色 / 会话定位信息。点击由受信管理面解析当前有效绑定；绑定失效时显示非剧情错误，不自动激活冻结线、不改主动目标、不生成用户已在线信号。提醒不可用时，历史仍是唯一真值。

### 5.4 自然开场素材

- 对无明确查询主题的开场（例如「今天怎么样」），先从当前活动和近期已发生且该角色已知的经历中取得有限候选，再按角色表达取舍决定是否使用。
- 若只有角色未知的世界事件，不得把该事件作为开场素材；没有合法素材时可以平淡回答或说明没有特别想说的事，不补造趣事。
- 验收同时覆盖有近期已知经历、只有未获知事件、以及无可用素材三种情况；开场不改变事实、获知或主动配额。

- 候选优先级为：当前实际活动与刚完成经历 > 仍有效且已获知的后果 > 近期未闭合打算 > 较旧但具有共同指涉的经历。每类候选都必须通过角色表达取舍和认知校验；候选为空时不调用模型编造“最近发生的事”。

### 5.5 分期

阶段 3 起随事件引擎启用；阶段 0–2 没有世界源素材，不提供无来源的替代主动消息。

### 5.6 初见（初次联络）

- 角色卡「初见设定」只提供联络动机，不提供台词，也不暗含已发生的共同经历。
- **触发**：用户第一次在有效绑定的会话视图中打开该角色时登记一次开场请求；只有时间线已激活、状态已追赶到一致水位且角色未归档时才允许生成。打开冻结线只读历史，不暗中激活。打开信号由受信管理入口提供；后台分页、重连与绑定本身不算打开。
- 独立开场只投向触发视图的 thread 并捕获其绑定令牌；不广播、不改长期主动目标；没有打开信号的通道不伪造打开，由首条入站承接初见。
- **一次性与失败**：同一（实例、时间线、角色）共用一份初见状态，多窗口不能各发一条；开场或承接它的首轮普通回复**成功固化时**才消费资格。生成失败由管理面显式重试；已固化但投递失败只恢复原消息，不重新生成。
- **与用户抢先发言**：以「独立开场尚未固化」为准，而不是「尚未送达」。开场与普通输入共用会话串行顺序；已有入站被接受即取消独立开场候选，把初见意向并入首轮回复（`reply_to` 正常关联入站）。独立开场已固化则保留原历史，用户输入按普通轮次处理。
- **事实与时间**：事实来自当轮认知过滤后的一致快照（含合法初始知识与其后已获知内容）；不整包读取背景，不把初态活动冒充当前活动。消息按实际固化时刻写入，不倒填进实例初始提交。
- **回滚与继承**：开场正文、对话经历与派生记忆随线回滚；「初见已完成」记号属控制状态，不随回滚倒退（见 `WORLD_RUNTIME_SPEC.md` §5.1）；分叉继承共同过去，导入保留包内联络历史——继承会话不再初见，无联络历史的新会话才有首次资格。重连、换通道与改名不是新会话。
- **睡眠边界**：无用户输入的独立开场不绕过睡眠禁发（见 §4.5）；用户先发言则并入睡眠期回复。
- 独立开场 `reply_to = null`，是**初次联络的单次例外**：不占世界源主动配额、不消费事件素材，也不放开其他无来源主动消息。
- 补入角色（`WORLD_SETTING_SPEC.md` §3.7）拥有自己的初见资格：初见按（实例、时间线、角色）独立成立，补卡不继承其他角色的联络历史。
- **分期**：随真实实例 / 角色卡在阶段 1 接入（只消费经校验的初始知识与初态，不伪造时间进展）；阶段 2 起接入当前生活线与认知水位；阶段 0 的占位会话不声称具备该行为，也不改变 §5.4 的主动消息分期。

### 5.7 角色寿终后的联络收束

- 运行层在寿终事件与归档状态同一提交内通知会话核心；核心先使未完成生成、等待任务、主动候选和未投递任务失效，再处理用户可见的收束消息。
- 若寿终前存在一条已经固化但尚未投递的合法角色回复，按普通投递恢复规则处理；不得为了“最后一句”倒填新的生前回复。未固化回复直接标记为因归档失效。
- 可选的最后联络必须来自寿终前已发生、已获知且有分享资格的内容，或来自世界包声明的合法传递机制。寿终事件不能赋予角色临终预知、死后亲历或对未知责任 / 死因的知识。
- 单角色会话可以产生一条独立的归档说明，但它必须标记为联络系统 / 管理机制的角色化说明，不能伪装成死者新回复；说明只陈述用户有权知道的归档事实，不泄露角色未知的死因、责任人或幕后实情。
- 多角色世界中，其他角色只有在自己通过合法渠道获知死讯后，才可能在各自会话中表达；不能因用户正在查看死者会话而自动替其他角色传话。
- 归档说明只生成一次，写入原会话历史并遵守投递状态；投递失败不重生成，不改变角色已知状态。回滚跨过寿终提交时，归档状态、终止记录和说明一并撤销，后续重新推进按原规则重新判定。
- 归档会话保留历史和记忆供只读查看；入站消息返回明确的归档错误，不自动改投其他角色、不激活冻结线、不把用户点击或重试作为角色已知信号。

## 六、角色记忆（子系统）

- 主语是角色，用户对话是一类经历，不设用户特权权重。
- 三层：对话原文、已发生经历、规范记忆；混合召回、衰减、整理与冲突规则见 [`MEMORY_SPEC.md`](MEMORY_SPEC.md)。
- 本层只负责何时触发写入 / 召回，记忆子系统负责候选和检索，世界运行层统一存储与版本边界；避免三方重复写同一份经历。
- 所有路径都带实例 / 时间线 / 角色。检索不足不得跨角色放宽，角色台词不能反向自证成世界事件。

## 七、披露机制（多角色对话可见性）

### 7.1 默认隔离与显式授权

- 同实例同时间线内，角色 A 的私聊默认不对 B 可见；角色不会互相转告与用户的对话。
- 用户可明确向指定角色披露指定消息 / 片段；授权记录接收角色、来源、范围与生效时刻，随时间线版本化。
- **用户转述不等于读取授权**。说「A 提过某事」首先只是 B 本次收到的用户陈述；只有明确可确定的披露范围才开放对应历史。
- 范围不明确时询问确认或只记录本次转述，不自动检索整段私聊、隐含记忆或实情。授权不自动传递给第三个角色。
- 跨实例 / 跨线的用户叙述仍是当前会话中的转述，不触发跨域数据库查询。
- 披露改变 B 可访问的认知，不改变世界真值，也不把 A 的经历变成 B 的亲历。

### 7.2 撤回

- 无单独撤回某条披露的功能；须将当前线回滚至披露前的提交，连同之后的全部进展一起恢复。
- 也可从披露前提交创建新线，但这**不会撤销原线**中的披露；两条路径不能混为一谈。
- 恢复须同时撤销授权、接收者的派生记忆、摘要及相关任务，不能只删授权记录后留下已复制内容。
- 已发到外部平台的文字及用户已经读过的信息不保证消除，确认回滚时明确说明。

## 八、与其它模块的接口

| 对方模块 | 契约 |
|---|---|
| 通道插件层 | 持久通道身份 / thread 路由、幂等接受、固化回复、投递回执 |
| 世界运行层 | 固定作用域的一致快照、原子增量、运行世代、冻结 / 回滚失效 |
| 事件引擎 | 认知可见素材与合法角色行动；显式管理事件入口独立 |
| 角色卡 | 过滤后的扮演定义、性格倾向、认知与通讯边界 |
| 世界设定层 | 创建 / 删除 / 导入的会话历史与本地路由分离 |
| 平台管理面 | 会话选择、历史分页、主动目标、必要错误状态；不开放内部记忆 |

## 九、实施分期（本模块）

- **阶段 0**：最小持久会话、身份 / 路由 / 去重、基础生成与错误模型；无世界记忆引擎。
- **阶段 1**：随真实实例创建 / 导入管理历史，不恢复源端路由。
- **阶段 2–3**：认知、记忆、合法角色行动与世界源主动发言。
- **阶段 4**：完整多线切换、回滚与异步任务失效。
- **阶段 5**：多角色披露及端到端隔离。

## 十、待模块设计项（残余）

- LLM 服务与参数、输出结构、上下文预算和有界重试数。
- 披露范围的 UI 选择 / 自然语言确认细节。
- 主动素材时效、技术背压与队列参数；跨通道订阅式广播 v1 不做。
- 睡眠等待的延迟分布、单批容量与队列上限；超限明确拒收 / 背压，不裁掉已接受消息。
- 表达取舍的依据与稳定性、旧话题回接的相关性与复述抑制；打算的保留范围与重议触发条件。
- 自然开场候选的具体时间窗、去重和长度参数；候选来源、优先级、越权禁止和无素材降级已确定。

## 附录 A：主动发言参数（设计级）

每日额度以世界历法日划分；默认最多 2 条 / 角色 / 时间线。睡眠静默只看角色生活线；素材按分享价值与时效排序。配置属于会话策略，额度与消费记录是可恢复的线内状态。

## 附录 B：行为验收

1. 切换世界 / 角色 / 时间线或更换通道后，历史不迁移、不串读；同三元组新窗口复用同一历史。
2. 同请求重试、投递失败重发与核心崩溃恢复不重复生成、写记忆或消费素材。
3. 慢生成期间正常世界推进不被旧快照覆盖；冻结、回滚、删除或重绑后迟到结果不能写入或错投。
4. 生成上下文不含不可见实情；有依据的传闻与明确推测不会被强行改成全知真相。
5. 对话促成的行动只有经规则校验才产生世界效果；普通文本不会创建管理性时间线。
6. 多 thread 共享主动配额且只向选定目标投递；离线与高倍率不补发历史洪峰。
7. 披露严格限于明确来源与接收角色；回滚撤销派生认知，而从旧提交分叉不假称原线已撤回。
8. 关闭自动提交后重启仍能恢复历史；回滚后的旧分页游标与客户端缓存不继续展示已撤销内容。
- 角色归档后：历史可查阅；未固化任务失效；最多一次合法最后联络或归档说明；入站消息明确拒绝，不再产生新回复或主动消息。
10. 初见：多窗口只生成一次；用户抢先输入不双发；生成失败可重试；已固化未送达不重生成；回滚不复活；继承旧联络的会话不重新初见。
11. 睡眠等待：连续输入不延长等待；不同 thread 不合并或错投；批内每条输入都能查到同批结果；等待中自然醒来不说仍睡；冻结 / 回滚 / 归档后迟到任务不写入。
12. 角色不愿讲的已知内容在反复追问下保持既有取舍：不按次数解锁、不泄漏未知实情、不临场编造掩饰事实。
13. 相关新经历与早先对话具有合法共同指涉时可自然回接；用户换话题后不出现任务催办、进度或补偿性线索。
14. 角色自己的打算在话题切换与重启后延续；未实际执行前不产生「已做过」的表述。
15. 生成上下文能同时带入实际活动、有效后果、合法环境投影和角色可知经历；计划、未获知事件与实情不会进入上下文。
16. 自然开场在有近期合法素材时可以自然回接，在只有角色未知事件或没有素材时不会泄漏或补造事件。
17. 一条跨水位的角色故事单元能表达目标、阻碍、选择、代价与达成 / 失败 / 持续中等局部终态；终态不关闭世界、不泄漏角色未知真相。
