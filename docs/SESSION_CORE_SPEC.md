# 会话核心层（SESSION_CORE_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「会话核心层」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分；同日模块深化（参考 veranima 会话部分：排除用户中心机制；含生成全链路；主动发言 = 世界源；记忆以角色经历为中心、分期实现）。

## 一、模块职责与范围

**职责**：会话管理、消息路由、绑定关系（世界实例 / 角色 / 时间线）、对话上下文隔离、披露管理、**角色回复的生成全链路（Agent 层）**、**主动发言（世界源）**、**角色记忆子系统**（契约在本模块；存储与版本化随世界运行层）。

**范围外**：通道实现（`CHANNEL_PLUGIN_SPEC.md`）、世界运行机制（`WORLD_RUNTIME_SPEC.md`）、世界包与实例（`WORLD_SETTING_SPEC.md`）。

**设计基线（参考 veranima 的取舍）**：
- **排除（用户中心，不带入）**：① 关系状态 / 好感 / 依恋数值；② 用户情绪感知；③ 以用户为中心的主动消息（想你 / 牵挂类）；④ 共同经历类的用户权重；⑤ 观察用户屏幕的视觉注意力。
- **保留并改造**：会话与绑定、生成链路、记忆（以角色经历为中心）、披露与隔离。
- **不变式：用户是观测者**——用户不占据世界内位置、不直接改变世界；影响路径只有「用户 → 角色 → 世界」。

## 二、会话与绑定

### 2.1 会话定义
- 会话 = 用户与一个角色、在一个世界实例、一条时间线上的持续交谈窗口。
- 绑定：会话 ↔（世界实例、角色、时间线）固定三元组；通道 thread 经路由映射到会话（一个会话可挂多个 thread / 通道）。

### 2.2 切换语义
| 切换类型 | 影响 |
|---|---|
| 切换世界 | 会话切换到新世界的角色；世界时钟独立；状态独立 |
| 同一世界切换角色 | 会话切换到同一世界内另一角色；世界时钟共享；认知隔离 |

### 2.3 时间线与会话
- 一个会话绑定一条时间线。
- 用户可同时开启多个会话，分别绑定不同时间线。
- 用户可在同一时间线内切换角色（若该时间线所属世界包含多角色）。
- 用户可切换某会话所绑定的时间线。

### 2.4 消息路由
- 入站：通道（UMP）→ thread 解析 → 会话 → 生成链路。
- 出站：回复发回**消息来源的 thread**；同一会话的其他在线连接默认不同步（避免重复发送）——订阅式分发记入待定项（§十）。
- 会话状态（历史、绑定）与通道无关；通道上下线不影响会话。

## 三、对话上下文与时间线

#### 隔离原则

- 一个会话绑定一条时间线。
- 对话上下文随时间线隔离。
- 不同时间线的对话历史互不可见。
- 对话上下文属于该时间线状态的一部分：**时间线回滚（覆盖语义）将其截断到回滚点**——与披露撤回同一机制。
- 同一时间线内，多角色时角色间对话历史按披露机制处理。

#### 切换时间线时的上下文

用户切换会话所绑定的时间线时：

- 原时间线的对话上下文保留在原时间线。
- 新时间线的对话上下文从该时间线已有历史继续。
- 不跨时间线拼接上下文。
- 界面显式标注当前时间线。

#### 设计意图

对话上下文是时间线体验的一部分。用户在时间线 A 与角色讨论过的事，在时间线 B 中不应自动成为共同记忆。这保证了时间线的独立性，也保证了角色认知的一致性。

## 四、生成链路（Agent 层）

### 4.1 定位
把「用户消息 + 世界上下文」变成「角色回复」的完整链路；对通道只暴露最终回复文本（通道不感知生成过程）。

### 4.2 链路阶段
1. **接收**：校验、去重（UMP 信封 id）；用户消息写入会话历史。
2. **上下文装载**：世界实例快照（当前激活时间线的世界时钟）、该角色状态（性格单元 / 最近经历）、记忆召回（时间线作用域）、披露状态（多角色时）。
3. **组装**：角色卡扮演定义 + 认知可见子集（世界运行层「认知接口」）+ 记忆简报 + 最近对话。
4. **生成**：LLM 调用（模型与参数属实现层）；生成失败按错误模型上报，不静默。
5. **解析与回写**：回复文本 → 分段（按通道能力）；抽取记忆候选；写入会话历史与角色记忆（策略见 §六）。
6. **发送**：经来源 thread 交回通道层。

### 4.3 原则
- **生成不阻塞世界时钟**：世界推进与生成解耦。
- 认知注入的边界由角色卡（软 / 硬约束）与认知接口共同决定（见 `CHARACTER_CARD_SPEC.md`）。
- 生成过程（提示词、中间状态）永不外泄到通道或用户。

## 五、主动发言（世界源）

### 5.1 定位
角色在世界中经历值得分享的事时，可主动经会话绑定的通道发送一条消息。触发**全部来自世界侧**，与用户状态无关。

### 5.2 触发源
- **世界事件**（事件日志中与她相关、值得提起的）；
- **角色经历**（她做过的事、遇到的人与物——由事件与角色行为产成）。
- **不含**任何用户侧信号（在线状态、情绪、日程等）。

### 5.3 时机与节流
- 按她的世界时间节律择时（如清醒时段）；静默期 = 她的睡眠时段（世界侧）；
- 频率上限（每日上限；数值实现后标定）；
- 不做用户在线检测——消息可异步阅读（与「世界不依赖用户在线」一致）。

### 5.4 生成与投递
- 主动消息走生成链路（§四），触发素材作为上下文的一部分；
- 消息先写入会话历史，再经通道发送；发送失败由通道层按错误模型处理（不重试风暴）。

### 5.5 分期
依赖世界事件引擎（阶段 3+）；阶段 0–2 只预留架构位（触发源为空）。

## 六、角色记忆（子系统）

### 6.1 定位
记忆的主语是**角色**；组织中心是**角色经历**；用户对话是其中的一类经历（「与联络者的交谈」）。

### 6.2 参考 veranima 的取舍
| veranima 机制 | 本项目处置 |
|---|---|
| 原始消息 / 规范记忆分层 | 参考：对话原文 + 角色经历记录 |
| 候选记忆与写入策略（什么值得记） | 参考，重心改为角色经历（她的事、世界事件） |
| 去重 / 冲突 / 版本链 | 参考（后期） |
| 召回流水线（查询规划 → 候选 → 排序 → 简报） | 参考（服务 §四 生成链路） |
| 强度衰减与整理（Curator 类） | 参考，分期 |
| 用户文风学习、用户模型 / 关系模型 | 排除（用户中心） |
| 牵挂账本 / 驱力池等内心闭环 | 排除用户中心部分；角色自身的连续感由性格单元引擎承担 |
| 主动引擎的多维评分（用户行为 / 社交资本维度） | 排除用户维度；保留素材与节律维度（见 §五） |

### 6.3 作用域与归属
- 记忆是**角色状态的一部分**：按世界实例与时间线隔离，随 diff 复制、随提交快照、随回滚截断（存储与版本化随世界运行层）。
- 本模块定义记忆的**写入与召回契约**（何时写、写什么、召回什么进入生成）。

### 6.4 分期
1. 基础：对话历史 + 经历记录 + 简单召回；
2. 衰减、强化与压缩；
3. 深度整合（可选；待表现评估）。

### 6.5 待深化
记忆子系统的数据结构与召回算法细则；复杂度超出本模块时可拆为独立 SPEC。

## 七、披露机制（多角色对话可见性）

### 7.1 多角色与对话历史可见性

#### 实现分期

多角色能力在阶段 5 落地；此前按单角色运行，架构始终预留多角色扩展点。

#### 多角色时的对话历史规则

当同一世界包含多个角色时：

| 规则 | 说明 |
|---|---|
| 默认隔离 | 用户与角色 A 的对话历史，角色 B 默认不可见 |
| 用户主动披露 | 用户主动向角色 B 说明后，相关历史对 B 可见 |
| 角色不主动表露 | 角色之间不会主动向对方透露自己与用户的对话 |
| 披露粒度 | 按用户说明的范围披露，不自动扩散 |

#### 披露机制的含义

- 用户是对话历史的唯一授权者。
- 角色没有“互相通报”的动机或能力。
- 披露是单向的、显式的、由用户发起的。
- 披露后，角色 B 的认知中新增这部分信息。

#### 设计意图

这一机制保证了：

- 用户对多角色关系有完全控制权。
- 角色之间不会形成“信息串联”破坏沉浸感。
- 用户可以选择让角色间“知道彼此”，也可以保持隔离。

### 7.2 披露撤回机制

#### 机制

披露撤回**通过将时间线回滚到某个提交来实现**（不引入独立机制）。

#### 规则

- 披露信息一旦发生，即成为该时间线状态的一部分。
- 不存在“单独撤回某条披露”的操作。
- 如需撤回，用户将时间线回滚到披露发生之前的提交。
- 回滚后，从该提交创建新时间线，或继续推进。

#### 设计含义

- 披露是世界状态的一部分，不是独立可撤销的对象。
- 撤回披露 = 世界回滚。
- 这与版本管理机制统一，不引入额外机制。
- 用户需理解：撤回披露的代价是丢失该提交之后的所有进展。

#### 操作路径

1. 用户找到披露发生之前的提交。
2. 将当前时间线回滚到该提交，或从该提交创建新时间线。
3. 披露信息不再存在于新状态中。

## 八、与其它模块的接口

| 对方模块 | 接口面 |
|---|---|
| 通道插件层 | UMP thread ↔ 会话映射；回复按通道能力裁剪 |
| 世界运行层 | 角色状态读写、认知接口、世界时钟、事件日志（主动发言素材）、提交 / 回滚 |
| 角色卡 | 扮演定义、认知边界（软 / 硬约束）、初始性格单元集合 |
| 世界设定层 | 实例与时间线生命周期（创建 / 导入 / 回滚）对会话的影响 |

## 九、实施分期（本模块）

- **阶段 0**：最小会话核心——会话 / 绑定 / 路由 + 生成链路基础（单角色、单时间线；对话历史内存档，无记忆引擎）。
- **阶段 2–3**：记忆子系统按 §6.4 分期承接；主动发言随事件引擎启用（阶段 3+）。
- **阶段 5**：多角色与披露全面生效。

## 十、待模块设计项（残余）

- 记忆子系统的数据结构与召回细则（见 §6.5）。
- 主动发言的事件筛选规则与频率参数（实现后标定）。
- 同会话多通道的订阅式分发（可选；v1 不做）。
- 生成链路的模型选择与失败重试策略（实现层）。
