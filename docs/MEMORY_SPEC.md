# 角色记忆（MEMORY_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 角色记忆子系统
> 来源：2026-09-19 模块深化；本轮补齐角色隔离、来源与冲突、异步回写、索引和跨端契约。
> 状态：设计规范，尚未实现。会话层负责编排，存储与版本化纳入世界运行层的一致性边界。 **2026-09-21 更正**：记忆子系统已实现（三层各守本分、有界提取、来源校验、幂等与冲突、迟到衰减、混合召回与简报、引强化），审计 `scripts/_audit2_mem.py` 35 项 35 PASS / 0 FAIL。

## 一、定位与中心

- 记忆的主语是**角色**，中心是**角色经历**。用户对话只是「与联络者交谈」的一类经历，无特殊用户权重。
- 目标是让角色记得自己经历、获知和说过的事，而不是复制世界实情库。
- 遗忘、低确信和模糊回想合法；来源缺失或越权读取不是拟真，不能以「软约束」放行。
- 用户不可浏览或直接编辑记忆；内部简报、置信数值和整理过程均不对外展示。

## 二、数据域（三层）

| 域 | 内容 | 写入时机 |
|---|---|---|
| 对话原文 | 当前角色与用户已接受的输入及已固化的回复，带角色与时间线作用域 | 接收输入 / 提交回复时 |
| 经历 | 已发生的活动、事件参与、观察与信息获知，带世界时刻和来源引用 | 世界侧推进及角色获知时 |
| 规范记忆 | 从前两者提取的短条目，带类型、来源、强度、置信与状态 | 有界的轮后 / 经历后提取 |

原文是对话事实，经历是角色视角的事件记录，规范记忆是派生表达。三者不能互相冒充：**角色说了某事不等于该事真实发生**。

- 合并回复（多入一回，见 `SESSION_CORE_SPEC.md` §4.5）：多条入站共享一份固化回复时，对话原文按各输入分别保留，批内不重复提取同一来源。

## 三、规范记忆条目模型

| 字段组 | 保证 |
|---|---|
| 身份 | 稳定条目标识、版本与被替代关系 |
| 作用域 | **世界实例 + 时间线 + 角色**；同一线不同角色也隔离 |
| 文本 / 类型 | 一到两句话；事实、片段、承诺或印象；「事实」仍须标明是谁的陈述或观察 |
| 来源 | 对话消息、事件、经历或说法引用；来源角色与获知途径可追溯 |
| 时间 | 发生时间、该角色获知时间、记录时间；以世界秒为准，不混成一个时间戳 |
| 强度 | `[0,1]`，决定易被想起程度；不代表真伪 |
| 置信 | `[0,1]`，角色对内容的主观确信；不等于客观正确性 |
| 状态 | 活跃、衰减中、归档；来源可达性另行硬过滤 |

- 说法层包含可信公告、亲历投影和传闻，不一律低置信。未核实传闻保留「听说」来源；误信也可高确信，但不能升级为世界真值。
- 初始知识来自锁定角色卡与其可见设定，不由运行期检索全世界秘密补齐。

## 四、写入（什么值得记）

### 4.1 来源与提取

- 对话轮后提取有分量的来往、承诺、观点与角色决定；世界推进只为该角色已经历 / 已获知的内容产候选。
- 不从未过滤的世界实情直接提取。来自其他角色对话的材料先通过披露授权，不能因为底层存于同一库就读取。
- 回复中的自述只有在世界事件或经历有来源时才记作亲历；否则最多记录「她曾这样说 / 打算这样做」，不能反向伪造事件。
- 提取判断点可用低成本 LLM + 保守规则兜底。失败时先保留原文 / 经历和待处理标记，不拿不完整 JSON 或猜测填入规范记忆。
- 提取不阻断已固化回复的投递；后续任务绑定来源、角色、时间线与运行世代。回滚、删除或来源失效后，迟到结果不可写回。
- 相同来源的提取任务幂等；重试不重复记忆、不重复强化；批内多条输入共享一份回复时按来源分别结算，不重复提取。
- 提取任务记录来源版本与语义生效水位。延迟完成时按来源发生 / 获知时刻结算应有的衰减起点，再以当前可达来源重新做去重、冲突和替代关系校验；不能用迟到结果覆盖期间已经固化的纠正。
- **打算与未竟之事**按「角色决定 / 打算」类条目记录，保留对象、依据与改变原因；不因记下打算而执行任何世界效果，也不把每句随口愿望升级为必须追踪的义务。

### 4.2 粒度、去重与冲突

- 条目入库前蒸馏为一到两句话；长度压缩不能丢掉时间、否定、说法来源与不确定性。
- 去重仅在同角色、同线可达视图内进行。相同事实多来源可合并来源集合；单凭向量相似不能合并相反陈述。
- **最小冲突规则首版即有**：新旧说法并存并保留来源；明确纠正建立替代关系。查询当前认知取有效版本，问历史时可按当时水位读取旧版本。
- 自动深度归并可以后置，但不能在此之前把矛盾记忆静默覆写成「最新就是客观真相」。
- 用户给出的外界信息只记为用户所述。披露另一角色的话不把它转换成接收角色的亲历。
- **采信独立于来源版本**：来源更正与角色接受纠正分别处理，角色可以保留旧判断、暂缓或只修正部分观点；召回与复述不自动提高采信，同源重复不计作独立佐证。新证据推翻一个解释时，不自动补出尚未知晓的细节。

## 五、召回（混合）

### 5.1 流程

1. **限定可访问集合**：实例、时间线可达历史、当前角色、查询水位、有效披露与来源状态。任何召回路径必须先满足同一隔离规则。
2. **查询构造**：当前话题与会话上下文，带世界时间锚点；涉及明确旧时刻时不能被一律「越新越好」覆盖。
- **旧话题回接**：召回须能按共同指涉物回到角色自己曾谈过的片段，使其可被补充或重新解释；不额外扩大作用域，也不把其他角色的私聊或未获知内容纳入。
3. **候选**：全文与向量并行。检索不足不能跨角色 / 跨线放宽权限。
4. **排序**：先把全文与向量分数归一或做秩融合，再结合相关性、强度与适当的时间权重；不能直接相乘不同量纲的原始分数。同分用稳定标识排序。
5. **简报**：按有限预算、角色视角打包，保留来源与确信线索；只进生成上下文，不展示给用户。

### 5.2 向量服务与降级

- 向量化走**远程 embedding API**；不打包本地模型。其地址、模型、凭据有独立配置，可显式复用 LLM 凭据，但不能假定聊天服务一定支持 embeddings。
- 缺少配置、请求失败或单条未嵌入时使用全文召回；不能让整个对话或世界推进阻塞在向量 API 上。
- 未完成任务进入有界重试队列；只发送该任务需要的文本，不上传整库、完整实例包或无关角色材料。
- 向量记录关联源文本版本与模型指纹（模型 / 维度及必要归一化约定）。模型改变后旧向量不可混算，后台重建期间全文检索仍可用。
- 首次配置远程服务时说明会发送所需文本用于生成 / 向量化；「无云同步」不等于「不访问远程 API」。
- embedding 任务受运行层共享调用预算约束；预算耗尽时保留待嵌入状态并立即使用全文召回，不阻断世界推进或已接受回复。模型 / 维度变化时旧向量停止参与混合召回，重建从源文本开始，重建期间全文召回保持可用。

### 5.3 召回后的状态变化

- 低置信记忆带保留说法，归档唤起带模糊表达；归档不是权限豁免。
- 只有实际进入一轮成功采纳上下文的条目才按规则强化；候选扫描、查询失败与请求重试不重复加权。
- 强化只改变易被想起的程度，**不默认提高采信程度**；重复引用同一来源不构成独立佐证。
- 同一轮的强化与引用记录幂等，随时间线版本化。技术诊断不消费或强化记忆。

## 六、衰减与整理

- 强度按**世界时长**衰减；小步与批量补算结果等价，冻结期间不衰减。
- 低于阈值归档，不进入普通召回；强相关检索可唤起，但仍需相同作用域和来源过滤。
- 整理挂角色作息节律，如睡眠时段；无睡眠角色按世界日界触发，不要求每个世界都有现实夜晚。
- 整理只调整组织、强度与表达长度，**不创造事实、不合并相互矛盾的来源**；结果固化并版本化，补算不重复调用生成器改写同一段过去。
- 语义遗忘不等于物理压缩。原文 / 经历的保留不使其自动重新进入规范召回，但它们仍须满足已有提交恢复与来源引用完整性。
- 归档清理若以后启用，必须处理被记忆、披露与历史提交引用的来源；不能破坏已保留历史。

## 七、作用域与版本

- 记忆随角色状态提交、diff、分叉与回滚。分叉继承来源点的共同过去，之后各线独立；不共享可变对象。
- 角色 B 的召回只看到自己的经历，以及用户明确向 B 披露的部分；授权不把 A 的整库复制给 B。
- 对话原文、经历、规范记忆、冲突替代关系、已完成提取与待处理标记均纳入一致快照。
- `system_notice`、平台错误和管理诊断不是角色发言或角色经历来源；它们可以进入用户可见历史，但不得触发角色亲历、获知或规范记忆提取。
- 全文索引、向量缓存和简报缓存是派生视图：可以重建，不能成为越过时间线可达性 / 角色权限的旁路。回滚后即使旧向量仍物理存在，也不能被命中返回。
- 索引重建完成前只读已校验的子集或降级查询；不得暂时查询未过滤的全库。
- 整体导出包含三层内容及必要引用；向量缓存可选。导入时检查模型指纹，不兼容则从已导入的文本重建，不能要求部分手动迁移记忆。
- 删除实例 / 时间线由其生命周期统一处理任务与缓存；用户界面不额外提供记忆浏览、逐条编辑或单独撤回披露的入口。

## 八、实施分期

- **阶段 0**：持久化对话原文，确保聊天重启可恢复；尚无规范记忆引擎。
- **阶段 2–3**：经历、简单提取、首版隔离 / 冲突规则、全文召回、向量接入与简报注入。
- **阶段 4**：完整版本操作及索引生命周期；衰减、强化、归档、整理。
- **阶段 5**：披露后的跨角色授权召回验收。
- 深度语义归并与其他整合可选，依据实际表现评估，不引入用户模型 / 关系模型。

## 九、与其它模块的接口

| 对方模块 | 契约 |
|---|---|
| 会话核心层 | 轮后提取、成功上下文的强化、披露授权、唯一回复记录 |
| 世界运行层 | 角色作用域、来源水位、原子回写与任务失效、分叉 / 回滚 |
| 世界事件引擎 | 已获知说法与已发生经历，不传原始全量实情 |
| 世界设定层 | 一致导出、完整来源闭包、跨端向量模型变化 |
| 平台设置面 | embedding 配置和非内容性服务错误；不开放记忆明细 |

## 十、待模块设计项（残余）

- 存储 schema、索引布局、全文分词与向量相似度实现。
- 提取提示词、排序融合参数、简报预算与衰减阈值。
- 整理频率和重试预算；这些参数不能改变隔离与来源规则。
- 采信变化的判定范围与独立佐证的认定方式；打算类条目的保留范围与容量策略。
- 具体预算配额由运行层统一决定，本层只实现预占、失败释放未用额度、待处理状态与全文降级，不建立独立预算账本。

## 十一、行为验收

1. 同一实例同一线的两个角色默认无法召回彼此的对话或规范记忆；不同实例、不同线亦不串读。
2. 分叉继承共同过去但不继承来源线后续记忆；回滚后旧向量、摘要缓存与迟到提取均不能复活未来内容。
3. 角色随口说出的无依据往事不会变成亲历；传闻不变真相，高确信错误说法仍保留其来源。
4. 相似但矛盾的陈述不会被去重吞掉；纠正保留替代链，查询过去与当前能区分版本。
5. embedding 不可用、维度改变或导入缺缓存时仍可全文召回；不阻断世界推进。
6. 同一源重复提取、同一轮重复召回和中断补算不重复写入或强化。
7. 高倍率衰减、冻结恢复、无睡眠角色整理均遵守世界时间；归档唤起仍执行认知权限。
8. 导出后导入能恢复原文、经历、记忆及引用；不含 API Key，不存在用户可见的记忆明细入口。
9. 合并批次的回复不导致重复提取或重复强化；睡眠等待中的消息在恢复后不重复写记忆，回滚 / 冻结 / 归档后迟到任务不写入。
10. 来源更正后角色可以保留旧判断或部分修正；召回与重复引用不提高采信，也不自动补出未获知的细节。
11. 角色自己的打算跨重启保留，未实际执行前不产生亲历；随口愿望不被升级为必须完成的任务。
12. 相关新经历可接回角色此前谈过的片段，回接仍受实例 / 时间线 / 角色隔离与披露规则限制。
13. 共享预算耗尽时，已固化对话不被记忆提取阻塞；向量任务可待处理，全文召回可用，重复重试不绕过预算或重复强化。
14. 同一提取结果立即提交或延迟数个世界日提交，在相同当前水位下具有等价的来源、冲突关系和按世界时间结算后的强度；期间已固化的纠正不会被旧提取覆盖。
