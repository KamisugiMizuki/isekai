# 角色卡（CHARACTER_CARD_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 角色卡模块
> 来源：2026-09-19 总设计及模块深化；本轮明确创建前装配、初始认知、锚点与生活模板约束。
> 状态：设计规范，尚未实现；不沿用其他项目可运行时换卡的语义。

## 一、模块职责与范围

**职责**：角色创作数据、生成与审定、初始性格单元、初始知识、世界绑定、认知边界、生活线模板。

**范围外**：性格演化、运行生活线与认知过滤分别归 `WORLD_RUNTIME_SPEC.md`；实例生命周期归 `WORLD_SETTING_SPEC.md`。

角色卡定义「她起初是谁」，不是持续改写运行状态的配置开关。

## 二、角色卡结构（字段设计）

| 字段组 | 内容与消费方 |
|---|---|
| 身份与背景 | 稳定角色标识、姓名、种族与出生时刻（年龄为推导值）、性别（按世界适用）、职业、自我认同与背景；供表达与世界校验 |
| 创作者背景 / 自知背景 | 区分幕后设定与角色自己知道的经历；前者不能整段进入扮演上下文 |
| 生活区域 | 叙事描述或世界内区域标签，无几何 / 路网；供认知与事件范围匹配 |
| 信息渠道 | 引用世界包已定义的来源，注明可接触条件；不靠散文假定她能看到全世界 |
| 初始知识 | 角色初始掌握的说法、可知历史与自身经历及来源；不等于世界包全部公共叙事 |
| 通讯方式 | 世界设定允许的对用户双向联络方式与限制；不能扩大世界级限制 |
| 初始性格单元 | 稳定标识、语义、驱动依据与初始置信度，含锚点子集 |
| 认知边界 | 默认 soft；可声明 hard 及允许的信息来源，说明与世界规则一致 |
| 生活线模板 | 世界时间窗、活动标识 / 允许变化范围、睡眠或无睡眠声明、职业与作息习惯 |
| 可选外貌 | 文字描述；不依赖立绘、媒体资产或模型权重 |

- 字段是声明式数据，不携带脚本、工具调用权限或可覆盖系统隔离规则的指令。
- 实现级 JSON schema 后续冻结；稳定引用、初始知识和生活时间窗属于首版必需契约，不可只留自然语言占位。

## 三、角色与世界的绑定

- **创作阶段**：角色卡是可修改、可单独审定的内容对象；创作资产可复制用于另一世界，但必须重新校验。
- **实例创建**：装配最终角色卡，与世界包联合校验后一起固化；此后角色卡属于该实例且锁死。
- 不支持给既有实例增、删、替换或修改角色卡。需要不同角色集合时创建新实例，不能让运行期管理入口绕过锁定。
- 不同实例不共享运行角色；同一实例不同角色也不共享可变状态。
- 分叉复制来源提交中各角色的状态，包括已形成的记忆与锚点；不是每次创建时间线都回到卡片初始值。
- 修改外部创作文件不追溯实例；角色间自主互动当前不做。

## 四、多角色角色卡

- 每角色一张独立卡，角色标识在实例内唯一；姓名只用于呈现，不作为状态隔离键。
- 同一实例同一时间线共享世界时钟与事件真值，各自持有性格、认知、经历与记忆。
- 多角色在阶段 5 启用；此前只接受单角色创建。架构预留不等于升级后能修改已锁定的旧实例。
- 同一世界出现反差角色不应触发引擎分叉：差异写在卡片，公共机制保持体裁与人格无关。

## 五、角色卡生成

### 5.1 两种方式

| 方式 | 流程 |
|---|---|
| 用户自定义 | 手工填写 / 编辑卡片，经同一校验后确认 |
| AI 根据描述生成 | 用户描述 → 候选 → 校验 → 用户修改与确认 |

输入包括用户意图、目标世界包、可选角色模板。**创作校验器可使用实情层**以保证背景自洽，但必须把自知信息与幕后信息分开存放，不能把创作上下文直接当角色 prompt。

### 5.2 联合校验与确认

确认前检查：

- 身份、职业、背景与世界公理无冲突；引用的区域、渠道、说法、活动真实存在或作为创作修改一并得到确认。
- 通讯方式在世界包允许范围内；硬约束来源与卡片经历不自相矛盾。
- 初始知识有合法来源，不凭角色职业自动赋予全量秘密；初始自述经历不能暗含尚未发生的事件。
- 初始知识引用史料时：条目须存在于对应传本，获知时间不晚于初始时刻，并明确所掌握的条目或范围；不能由职业或渠道资格自动获得整部史料。
- 种族、出生时刻与个体寿命覆盖与世界包种族表相容；年龄由出生与世界时刻推导，不手填数字。
- 性格单元语义与置信合法，存在可辨识的初始锚点；重复语义不靠不同名字重复计权。
- 时间窗按目标世界历法解释，非现实钟；睡眠跨日、夜班或无睡眠均有明确表示，活动不重叠且覆盖声明的生活区间。

只有用户确认的最终版本进入实例；不保留 AI 生成历史。失败 / 取消不替换已确认版本。公开审定的是最终卡片，不要求暴露模型中间推理。

## 六、认知约束

### 6.1 软约束（默认）

知识来自角色设定、初始知识、真实经历、已接触渠道、自己的对话与显式披露。

允许知道一部分、听说未确认、推测、不知道和主观解释；不允许无来源的全知。

**软的是解释，不是数据权限**：不能因为 soft 就向生成器提供实情全集、其他角色私聊或未来事件。推测须以猜测表达，不自动写成世界真值或亲历。

### 6.2 硬约束例外

与外界无通常信息交流的角色可显式声明 hard，例如与世隔绝的囚徒或封闭舱内居民；不是仅凭「宇航员」等职业标签自动启用。

允许来源限于卡片明确规定的自身经历、小环境观察和与用户通讯。世界内公共新闻必须确有渠道才能进入；用户转述仍是用户所述，不成为亲历。

世界包定义可用来源与约束，角色卡选择和收窄；卡片不能自行给封闭世界开一个全知通道。

### 6.3 执行入口

- 卡片声明，运行层认知接口过滤，会话层只拿过滤后的切片。
- 错误传闻应有已接触的说法来源；未获知内容可以回答不知道。
- 生成后的一致性检查不能替代生成前隔离；角色背景中的秘密同样必须过滤，不因在卡片内而豁免。

## 七、初始锚点与可辨识性

- 初始锚点来自 `initial_units` 的 anchor 子集，可覆盖行事风格、价值倾向、说话句式与口癖；AI 提出命名与语义，用户审定。
- 初始置信度必须在运行层规定的对应生成区间内；锚点 **0.75–0.99** 是校验范围，不只是可忽略的建议。
- 锚点数量由生成与审定决定，不设统一固定数量；不能用空锚点集合宣称满足角色辨识保障。
- 各线共享同一份**不可变初始定义**，不共享可变置信度。分叉继承共同过去，此后锚点演化独立，不向兄弟线转移。
- 锚点不归档，新增与渐进迁移见 `WORLD_RUNTIME_SPEC.md` §十；卡片不再另设一套竞争的人格核心模型。

## 八、与其它模块的接口

| 对方模块 | 契约 |
|---|---|
| 世界设定层 | 创建前装配、联合校验、最终卡快照与锁定 |
| 世界运行层 | 初始单元 / 知识、活动模板、角色渠道与约束 |
| 事件引擎 | 主体身份、受影响范围、获知来源；不是创建第二套角色历史 |
| 会话核心层 | 已过滤的扮演信息、表达倾向与通讯限制 |
| 记忆子系统 | 初始自知与后续经历的来源边界，角色作用域 |
| 桌面 / 安卓 | 同一生成和审定规则；既有实例内仅选择角色，不编辑卡片 |

## 九、实施分期（本模块）

- **阶段 1**：卡结构、自定义 / AI 生成、联合校验与实例创建前确认。
- **阶段 2–3**：初始知识、性格与生活模板由运行层实际消费。
- **阶段 5**：多角色创建与隔离验收。

## 十、待模块设计项（残余）

- 实现级 schema、稳定标识与模板引用的具体编码。
- AI 创作提示词、表单交互、联合校验错误的呈现。
- 不预设兼容旧项目卡格式；若移植资产，须显式转换并经当前规范校验。

## 附录 A：字段与初始单元约束（设计级）

- 身份、知识、渠道、单元与活动都有独立标识，不以可变显示名作为引用键。
- `initial_units` 至少能表达语义、驱动与置信；初始区间不是后续演化的硬下限，具体见运行层。
- `cognition` 表达 soft / hard 和来源范围，不能只写一个 mode 而省掉过滤依据。
- `life_template` 须有机器可检查的世界时间窗与活动集合；「作息惯例」文本可以辅助描述，不能替代结构。
- 身份以「种族 + 出生时刻」表达，年龄为推导值；个体寿命覆盖不得与世界包种族表冲突。
- 字段示意不再用互斥枚举拼成一个值，或用 0.0 作为不合法锚点置信度，避免实现者照抄错误示例。

## 附录 B：行为验收

1. 卡片未确认、渠道悬空、初始知识越权（含史料引用与种族 / 出生不合法）或日程非法时，实例创建失败且不留半个角色。
2. 实例创建后修改 / 删除源卡不改变实例；增卡、换卡、改卡被锁定边界拒绝。
3. 角色背景含幕后秘密时，创作校验可读，实际对话上下文不可读。
4. 同世界不同角色初始认知不同；硬约束角色不因公开事件标签获得不存在的渠道。
5. 分叉继承当时状态，不重置到卡片初值；兄弟线之后的锚点与记忆不互传。
6. 非现实日长、跨日睡眠和无睡眠模板可被一致解释；生成重试不偷偷修改已确认版本。
