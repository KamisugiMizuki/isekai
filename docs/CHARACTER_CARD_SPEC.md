# 角色卡（CHARACTER_CARD_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「角色卡」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分；同日模块深化（结构字段级落位；与生活线 / 认知接口对齐）。

## 一、模块职责与范围

**职责**：角色卡结构、生成流程、初始性格单元集合（含锚点）、角色与世界的绑定、认知边界、生活线模板。

**范围外**：性格单元引擎（`WORLD_RUNTIME_SPEC.md` §十）、生活线的运行机制（`WORLD_RUNTIME_SPEC.md` §十一）、世界包与实例（`WORLD_SETTING_SPEC.md`）。

## 二、角色卡结构（字段设计）

角色不是全局角色，而是「某个世界中的角色」。角色卡字段：

| 字段组 | 内容 | 说明 |
|---|---|---|
| 身份与背景 | 姓名、年龄 / 性别、职业、来历与背景故事 | 自我认同与他人称呼的基础 |
| 生活区域 | 活动范围的叙事描述（**无几何、无路网**） | 供表达与认知；与生活线模板配套 |
| 信息渠道 | 她能接触到的信息来源（通讯设备、报纸、传闻、魔法通讯……） | 认知接口的过滤依据之一 |
| 通讯方式 | 与用户联络的解释（由世界设定定义） | 仅连接用户与角色，不连接世界内其他存在 |
| 初始性格单元集合 | 一组性格单元 + 初始置信度 | 其中**锚点驱动子集**（行事风格 / 说话句式 / 口癖等可辨识特征）作为跨时间线识别起点 |
| 认知边界 | 软约束（默认）/ 硬约束声明 | 与外界无信息交流的角色启用硬约束 |
| 生活线模板 | 职业与作息习惯 | 供运行层生成每日活动序列（「日界」取自作息惯例） |
| （可选）外貌与形象 | 文字描述 | 供表达与描写；不依赖立绘等资源 |

> 具体字段与格式在实现时冻结（JSON schema）；本表为设计级字段面。

## 三、角色与世界的绑定

- 角色绑定世界：角色卡属于**世界实例**，创建后锁死（承总设计：实例设定锁死）。
- 不同角色的角色卡互不共享；不同角色的角色状态独立演化。
- 跨世界角色共享：不支持（角色随世界走）。

与时间线的关系：

- 每条时间线持有每个角色各自的状态。
- 创建时间线时，各角色状态分别复制（通过 diff）。
- 同一时间线内，各角色状态独立演化。
- 角色间交互（未来）将基于各自状态进行。

## 四、多角色角色卡

- 同一世界多角色时，**不同角色间应有不同的角色卡**。
- 每个角色一张独立角色卡；规则同上（属于实例、创建后锁死、互不共享）。
- 实现分期：阶段 5 落地；此前单角色运行（架构始终预留）。

## 五、角色卡生成

#### 两种生成方式

| 方式 | 说明 |
|---|---|
| 用户自定义 | 用户直接定义角色卡各项内容 |
| AI 根据描述生成 | 用户给出自然语言描述，AI 生成角色卡 |

#### 生成输入

- 用户的自然语言描述；
- （可选）世界包提供的角色类型与模板；
- 世界背景（公共叙事层的风格与语汇——保证角色与世界同调）。

#### AI 生成后的检查

- AI 生成角色卡后，必须经过用户检查。
- 用户可修改、补充、删除生成内容。
- 用户确认后，角色卡才生效。
- **仅保留最终确认版本，不保留生成历史。**
- 未经确认的角色卡不进入世界实例。

设计含义：生成历史不保留，避免冗余；用户确认版本即最终版本；与黑箱设计一致——内部生成过程不对外暴露。

## 六、认知约束

#### 认知软约束

默认采用软约束。角色知道什么，由以下因素共同决定：

- 角色自身设定
- 角色在世界中的处境与经历（生活线执行 + 事件参与）
- 角色能接触到的信息渠道
- 角色与用户的历史对话

角色可以：

- 知道一部分
- 听说过但不确认
- 推测
- 完全不知道
- 给出带主观色彩的解释

角色不应：

- 无理由知道全局设定
- 说出角色不可能接触到的信息
- 以全知视角描述世界

#### 硬约束例外

当角色被设定为“与外界无信息交流”时，启用硬约束。例如：

- 独自在太空舱中的宇航员
- 与世隔绝的囚徒
- 封闭实验对象

此类角色只能知道：

- 自身直接经历
- 自身所处小环境内的信息
- 与用户通讯中获得的信息

硬约束是世界包中的显式设定，不是默认行为。

#### 执行入口

- 角色卡**声明**认知边界；过滤由运行层的**认知接口**执行（见 `WORLD_RUNTIME_SPEC.md` §十三）。
- 角色未接触到的内容 →「不知道 / 没注意」是合法状态；错误说法必须来自公共叙事层，不得现编。

## 七、初始锚点与可辨识性

- 角色卡包含**初始锚点驱动单元集合**（含初始置信度），跨时间线共享，作为角色识别起点。
- 锚点驱动单元覆盖：行事风格、说话句式、口癖等可辨识特征。
- 各时间线中演化出的锚点驱动单元、极慢衰减与驱动迁移共同保证可辨识性（见 `WORLD_RUNTIME_SPEC.md` §十）。

## 八、与其它模块的接口

| 对方模块 | 接口面 |
|---|---|
| 世界运行层 | 初始性格单元集合（引擎起点）、生活线模板、认知边界声明 |
| 会话核心层 | 扮演定义（生成链路组装）、认知边界与披露状态 |
| 世界设定层 | 角色卡属于实例（创建后锁死）；世界包提供角色类型与模板 |
| 安卓端 | 角色卡生成与检查（两端同能力） |

## 九、实施分期（本模块）

- **阶段 1**：角色卡结构 + 生成（随世界实例创建登场）。
- **阶段 5**：多角色角色卡生效。
