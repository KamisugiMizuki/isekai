# 世界运行层（WORLD_RUNTIME_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「世界运行层」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分及模块深化；本轮按总纲修订时间、版本、性格与认知契约。
> 状态：设计规范，尚未实现；本文的验收项是实现门槛，不代表测试已通过。

## 一、模块职责与范围

**职责**：世界时钟（时间基元、历法、倍率）、时间线、版本管理（提交 / diff / 回滚 / 压缩）、角色状态（性格单元 / 生活线 / 记忆载体）、事件日志、认知接口。

- 本层是**世界运行状态的唯一持有者**。会话层编排对话，记忆子系统定义写入与召回；两者经本层的时间线一致性边界提交变化，不各自维护另一份世界状态。
- 范围外：通道、世界包编辑、角色卡创作、语言表达。相应契约见各自 SPEC。
- 下文的「同一世界」涉及运行状态时均指**同一世界实例的同一时间线**；模板相同不代表实例状态共享。

## 二、世界时钟与流速倍率

### 2.1 时间基元与历法

- **世界秒**是唯一时间基元；日期、月份、时段均为显示与查询视图，不作状态排序主键。
- 世界包定义纪元、日长、月份及天数、周制与可选季节、昼夜时段；不假设现实的日长、月份或时区。
- 世界秒与历法时刻换算为确定性纯函数；相同历法快照、相同时刻，所有消费者得到相同结果。
- 历法日界由纪元和日长决定；角色入睡只是**生活计划的生成触发点**，不能重新定义世界日界。
- 倍率改变世界秒流速，不改变历法规则。持久化精度与边界舍入规则须统一，不能因 tick 频率或浮点累加误差改变事件归属。
- 同一史料链上区分若干时点：事件实际发生、传本止笔 / 成书 / 可传播、角色获知、记录固化。后台何时生成文本不冒充事件发生或角色阅读的时刻。
- 史料自称的年代属于说法，可记错，但不覆盖权威事件时间；相对年代（如「三百年前」）绑定该句的叙述时点，角色转述时按当前世界时刻换算，不随查询日期改写原文。

### 2.2 倍率定义与状态

- `rate` 为正整数，默认 1，允许范围 `[1, rate_max]`。
- `rate_max` 默认 **2592000**，全局统一、仅开发者可配置，不随时间线版本化。此值是世界秒 / 现实秒，不代表任意世界历法的「30 天」。
- 冻结通过时间线状态表达，不使用倍率 0。

| 状态 | 作用 |
|---|---|
| 基准现实时间 / 基准世界时间 | 当前倍率段的起点 |
| 当前倍率 | 本时间线独立的流速 |
| 待生效倍率、输入时刻、生效整秒、请求顺序 | 可跨重启恢复的倍率变更 |
| 已处理世界时刻 | 事件、生活线与角色状态完成推进的共同水位 |
| 运行世代 | 回滚、删除等使旧异步任务失效的控制标记；不随回滚倒退 |

当前倍率段的目标时刻：

```text
目标世界时间 = 基准世界时间 + (当前现实时间 - 基准现实时间) × 当前倍率
```

- 有倍率变更时按分段累计，不能以最新倍率乘整个离线区间。
- 现实时间统一使用 UTC；设备时区变化只影响现实时间的显示。自然整秒以该时间基准划分。
- 系统时钟倒拨不允许世界倒退或重复执行：保留现实时间高水位，在时钟追平前不增加世界时间，并给出非剧情性时钟异常提示。主动回到过去只能走回滚。
- 系统时钟大幅前跳与长时间离线均走补算，不把异常间隔直接当作状态已完成。

### 2.3 倍率调整

1. 管理操作到达核心并通过权限与范围校验时，记录权威**输入时刻**及请求顺序；客户端显示时间与通道信封时间戳不参与裁决。
2. 生效点为**严格晚于输入时刻的第一个自然整秒**；恰在整秒输入也属于下一整秒。
3. 同一生效点多次调整，以最后一个有效请求为准；重试同一请求不产生第二次变更。接收属于更晚生效点的新请求前，须先结算已有到期变更；不能用单个 pending 字段覆盖尚未处理的前一倍率段。
4. 生效时先按旧倍率结算至该整秒，再更新基准与倍率；时钟连续，无跳跃、重复或空档。
5. 若调度器迟到，仍在原定整秒切分，之后的区间按新倍率补算，不以回调实际执行时刻替代生效点。
6. 待生效请求须先持久化才确认成功；重启按原定时刻恢复。冻结前结算已生效段，取消尚未生效的请求并返回明确结果；冻结线不接受倍率调整。

### 2.4 倍率的作用范围

- 每条激活时间线独立持有倍率；调整不影响其他时间线。
- 未激活线冻结，重新激活以**当前现实时间**重新锚定，不补算冻结期间。
- 倍率上限降低或导入端上限较低时，不静默改写历史倍率：该线保持冻结，提示在激活操作中确认一个合法倍率，再按确认值开始推进。

### 2.5 倍率与各机制的关系

| 机制 | 时间依据 |
|---|---|
| 时钟、事件、生活线、时间驱动性格、记忆衰减 | 世界时间 |
| 自动提交时间间隔、网络超时、投递背压 | 现实时间 |
| 对话顺序 | 接收顺序及所在时间线的一致快照 |
| 会话 / 通道 | 不自行计算倍率；使用核心提供的时刻与状态 |

### 2.6 持续运行与离线补算

- **激活不等于进程正在运行**：应用退出、崩溃或被系统挂起，不自动冻结已激活线。恢复后只对中断前激活的线补算。
- 从最后持久化的共同水位推进到目标时刻，按确定的时间与因果顺序执行事件、生活线、认知获得、性格与记忆变化；每批原子记录进度，重复启动不重复产生经历。
- 在线、高倍率与离线使用同一套推进规则。固定输入下，分批执行与连续执行的**事实状态**必须等价。
- 补算预算限制单批工作量与语言生成量，**不允许以摘要代替未执行的状态转移**。可使用经等价性验证的批量计算；暂不支持的区间必须继续分批处理并显示追赶中，不能跳过。
- 未生成的表述可使用确定性模板，已有表述不重生成。LLM 不决定补算次数、发生时间或事实效果；离线时也不要求逐日调用 LLM。
- 对话、提交、导出必须读取同一已完成水位。对话接收时捕获目标水位，待推进到该水位后取快照；不能边读目标时钟边读旧角色状态。超过等待预算则报告追赶中，不无限等候或混用新旧状态。
- 恢复时不逐条补发离线期间本可发送的主动消息；素材保留供回忆，当前主动候选重新按时效筛选，见 `SESSION_CORE_SPEC.md` §五。
- 补算不重写已固化历史：回填、展开与获知分别沿用稳定身份与幂等规则，重启不重抽、不重复消费。
- **备份恢复与本层补算分开**：本地灾难恢复后全部时间线先冻结，激活时从备份内世界时刻重新锚定，不补算备份日至今的间隔，不恢复待生效倍率命令、通道绑定与待发送队列；普通崩溃重启仍走补算规则。

## 三、世界时钟可见性

- 区分**激活集合**与**当前查看线**：前者可以有多条，后者是当前会话 / 管理视图选择的一条。
- 只展示当前查看且已激活线的时钟；其他激活线可后台推进，但不并排暴露其时钟。
- 查看冻结线仅显示「已冻结」与管理元数据，不继续跳时，也不自动激活。
- 切换查看不改变激活集合。追赶期间显示运行状态，不能把尚未追上的目标时刻伪装成已可对话的状态。

## 四、时间线模型

- 时间线是可独立激活的平行世界线，不是只能检出一条的 Git 分支。
- **仅激活时间线推进**；冻结线不产生新事件或角色变化，只能查阅已有对话。冻结先结算到操作水位，再使未完成生成 / 状态回写失效；重新激活不接收旧世代结果。允许同时激活多条，可配置激活数量上限。
- 创建时继承指定来源提交的完整状态；**创建本身不等于激活**。创建流程可由用户明确同时激活，只有确认激活后才从新的现实基准推进。
- 创建方式：手动从提交分叉；用户引入事件后分叉；从历史提交重置为新线。原线均保留，线间不合并。
- 可命名、描述、归档、删除；列表只含名称、状态、来源提交与创建关系等管理元数据，不显示世界内部内容。
- 归档先冻结，不删除数据。删除需确认并停止该线任务、解绑其通道；若其他线引用它的历史提交，保留被引用的不可变数据，不连带删除后代。
- 分叉前已发生的历史是共同过去；分叉后的变化互不可见。「跨线隔离」不是把继承的历史清空。

## 五、版本管理

### 5.1 作用域与一致快照

版本管理只作用于**世界运行状态**，不修改实例锁定的设定或可编辑世界包。

| 纳入同一提交的内容 | 保证 |
|---|---|
| 世界时刻、倍率、事件及其固化文本、推进水位 | 从同一时点恢复，无未来事件混入 |
| 所有角色的性格、生活线、认知、经历、规范记忆 | 不是只快照当前聊天角色 |
| 该线的对话原文、披露授权、已确定的提取结果 | 回滚后不会从对话 / 摘要 / 向量旁路找回未来 |
| 主动素材消费记录及已生成消息的逻辑状态 | 不因重启重复生成或重复计数 |
| 时间线语义元数据、确定性规则版本与必要输入 | 来源、种子与因果引用可恢复 |

**不随回滚恢复的控制状态**：本机激活集合、视图选择、待生效的本机倍率命令、通道绑定与凭据、实际投递回执、去重作废记录、初见防重发记号、运行世代、全局设置。它们不是世界历史；恢复历史不能重新启用插件或重新发送已撤销的消息。

- 提交在一致性边界取快照：已接受输入及其待处理状态可纳入，但不能把半份记忆写入当成完成。
- 自动提交默认起点：**现实时间 1 小时或新增事件数 50**，任一到达即触发；全局参数可配置、可关闭。手动提交不受开关限制。
- 日常状态持久化独立于自动提交：关闭自动提交只是不再自动创建用户可选回滚点，不能关闭写盘或崩溃恢复。
- 提交是回滚点与分叉点；列表只显示标识、时间、用户备注与来源关系，不生成泄漏剧情的状态摘要。
- 世界包只保留最新版；实例内锁定快照不依赖原文件。

## 六、角色状态与 diff 复制

- 逻辑语义始终是完整快照；全量快照与 diff 是等价的存储方式，不是两套产品行为。
- diff 可用于角色状态、事件、对话、披露等版本化数据；世界时钟按线独立持有。
- 新线指向**不可变的来源提交**，不是来源线的可变头部。读取时仅合成该提交及本线差异，绝不读取来源线后来发生的变化。
- 差异包含新增、替换与删除标记，不能因祖先层仍有旧值而复活已撤销数据。
- 所谓「diff 合并」是祖先基线与差异的**状态物化**，不是时间线合并。阶段 4 前可用全量快照验证相同语义。
- 共享祖先数据只读；任一线的更新、回滚、压缩或删除不能更改其他线的可读状态。
- 角色状态含种族、出生时刻与死亡时刻（若已发生）；年龄为推导值，不单独存储。登记实体的出生 / 死亡随事件记录与快照同样版本化；寿终判定与对应事件在同一提交内一致。寿终后角色转入**归档**：不再推进生活线、不再产生经历与素材，既有记忆、披露与对话历史保留；归档状态随该线版本化，可经回滚撤销。

## 七、回滚语义

- 回滚保持当前时间线身份，把其有效历史覆盖至所选的可达提交；不自动保存「回滚前时间线」。
- 该点后的事件、角色变化、对话、披露、记忆、主动素材与未完成任务均退出当前线；索引与缓存同步失效。
- 原子切换前停止该线写入并提升运行世代；旧 LLM 回复、记忆提取和投递任务即使晚到，也不能写回或继续发送。
- 恢复世界时刻与倍率后，**以回滚完成时的现实时间重新锚定**。不把历史提交日至今的现实间隔立刻补算回去。
- 本机激活 / 冻结状态不从历史提交恢复；原来激活则由回滚点继续，原来冻结则停在该点。历史中的待生效倍率请求不作为现时控制命令重发。
- 回滚为破坏性操作。若要保留回滚前进展，先从当前提交**创建保留时间线或整体导出**；只做手动提交不等于有独立备份。
- 被截去的未来不再是当前线可访问历史；为其他线仍保留的共享数据不因此删除。
- 披露撤回走同一机制，不单独撤回。外部平台已收到的消息及用户已经读到的内容无法抹除；回滚只保证核心历史与此后的生成 / 投递一致。
- 初次联络的正文、对话经历与派生记忆正常随回滚撤销；「初见已完成」记号属控制状态不倒退（见 §5.1），被撤销的正文不得重新注入认知。

## 八、压缩策略

- 自动压缩减少 diff 链长度、合并物理存储，不改变可观察状态、历史提交可恢复性或分叉来源。
- 压缩前后，同一提交物化出的事件、记忆、披露、性格与时刻应等价；被其他线引用的祖先必须继续可读。
- **物理压缩不等于语义遗忘**：不得顺便删除锚点单元、有效经历或记忆。归档整理是显式的版本化状态变化，由对应子系统控制。
- 触发阈值、分块、缓存和存储算法实现时标定；崩溃恢复必须能保留压缩前或压缩后的一份完整可读状态。

## 九、多角色共享世界时钟

- 同一实例同一时间线的所有角色处于同一个世界时刻，事件真值共享，性格、经历、认知与记忆分别持有。
- 不同线独立计时；不同角色查询同一已完成水位不能获得不同的事件事实。
- 角色间交互当前不做；共享世界事件不等于共享彼此与用户的对话。

## 十、性格单元引擎

### 10.1 单元与四种驱动

单元有稳定标识、语义、置信度、来源依据与活跃 / 归档状态。AI 负责命名与有依据的语义候选；数值变化与归档由确定性规则执行。候选一旦采纳即固化，重放不再次询问 LLM。

| 驱动 | 强度来源 | 初始置信度区间 | 变化速度 | 衰减速度 |
|---|---|---|---|---|
| 锚点 | 核心辨识特征 | 0.75–0.99 | 极慢 | 极慢 |
| 事件 | 角色亲历或获知的事件影响 | 0.40–0.95 | 快 | 慢 |
| 对话 | 与联络者交谈的情感 / 语义强度 | 0.15–0.70 | 中 | 中 |
| 时间 | 世界时间跨度 | 0.05–0.50 | 慢 | 快 |

- 初始区间保持**锚点 > 事件 > 对话 > 时间**的阈值顺序；这是**生成区间，不是终身硬下限**。
- 驱动强度在 `[0,1]`；方向明确区分强化与削弱。不能只用非负增量声称支持反向影响。
- 普通单元更新限制在 `[0,1]`，允许低于初始区间并最终归档；不得每次更新都夹回生成下限，否则「低于 0.05 归档」永远不可达。
- 后来的弱驱动不能把已有高置信单元直接裁剪到该次驱动的生成上限。变化速度与保护程度取决于单元累积状态，变化必须连续。

### 10.2 迁移与锚点

- 驱动迁移由累积证据、稳定时长及强化 / 衰退结果隐式形成；**不另设可见的迁移事件或迁移日志**。必要的来源、稳定性依据随状态保存，不能只凭一次置信度越界判为锚点。
- 事件 / 对话 / 时间影响长期稳定后可以固化为锚点；普通单元的影响消退时可逐渐降低稳定程度，不瞬间跳值。
- **锚点不归档**；保有锚点保护下限并极慢变化，不能以压缩、整理、迁移为名删除或绕过保护。
- 锚点可新增、数量由 AI 在已有依据下提出，不设任意数量硬配额；重复语义可共用标识与来源，不靠删除既有锚点控量。
- 初始锚点来自实例锁定的角色卡；分叉继承来源点已存在的锚点，此后新增锚点不跨线传播。各线不共享可变单元对象。

### 10.3 消失、归档与可复算

- **非锚点**置信度 `c < 0.05` 时归档：不参与平时表达，但保留依据，后续相关驱动可从归档阈值附近渐进唤醒。
- 时间衰减按世界时长结算；在线小步、离线大步应等价，不能按 tick 次数扣值。
- 同一来源驱动只消费一次；重试、补算或重新载入不能重复强化。归档清理若后续启用，须显式版本化且不破坏既有提交。
- 相互矛盾的单元允许共存，由置信度与当前语境决定表达，不强制归并成单一标签。
- 步长、稳定期与衰减函数实现时校准；附录 A 仅提供起点参数，不宣称其长期表现已验证。

## 十一、角色生活线

- 生活线是回答「她在做什么」的轻量真值序列，只有**世界时间窗 + 活动**；不引入坐标、路网或通行模拟。
- 模板来自世界包日常结构与角色卡职业 / 作息，使用可检查的时间窗、活动标识与允许变化范围，而不只是交给模型的一段散文。
- 当前日首次需要时初始化；之后在入睡时准备下一历法日。跨午夜睡眠按世界秒展开；无睡眠角色按世界日界生成。每个角色、每个世界日只形成一份有效计划。
- **计划不等于经历**：未来活动块不可当作已经发生。推进到活动实际开始 / 完成时才产生对应事实与经历。
- 模板确定活动骨架，LLM 仅细化表述；失败用模板。已生成计划固化，读取、重启不重抽。
- 世界事件只覆盖生效时刻以后的活动块：当前块可在该点截断，过去片段不改；受影响范围来自叙事标签，不暗中加入空间系统。
- 用户普通对话不能直接写计划。角色自主采纳建议时，先形成经世界规则校验的角色行动，再由事件路径影响计划；没有该能力的阶段只回应，不声称建议已改变世界。
- 生命周期、事件覆盖和经历产成都随时间线提交 / 分叉 / 回滚。
- 睡眠期的短暂应答（见 `SESSION_CORE_SPEC.md` §4.5）不截断睡眠块、不改次日计划；后续主动消息只看生活线中**下一次实际醒来**，不假定现实次日。

## 十二、事件日志

- 唯一事件模型由 [`EVENT_ENGINE_SPEC.md`](EVENT_ENGINE_SPEC.md) §二定义；本层负责持久化、时序和版本化，不维护第二套简化模型。
- 同一已发生事件同时供认知、经历、记忆与主动素材使用；各消费方不得分别生成事件文本或另造事实。
- 确定性针对「锁定设定 + 种子 + 前序状态 + 已固化输入 + 规则版本」。同一天的抽样候选可以相同，已经分化的时间线不必发生相同结果。
- 写入事件、应用事实效果、更新相关生活线及推进水位必须一致提交。失败重试沿用事件身份，不重复结算。
- 历史条目与运行事件同表，靠来源标记区分视图；统一经认知接口按角色过滤，不设第二条读取路径。

## 十三、认知接口

### 13.1 语义与输入

输入必须包含**实例、时间线、角色、查询主题、查询水位**；输出该角色截至该水位已可接触的信息子集，含来源、获知时间、说法版本与主观确信度。

依据：角色初始知识、已发生经历、已接触的信息渠道、该角色自己的对话与显式披露。不能把「可能听到」直接当作「已经听到」。

### 13.2 双轨与观察

- 实情层仅供世界运行与一致性校验，**不直接注入角色生成上下文**。
- 公共叙事 / 说法层是可被角色获知的版本集合，**不表示全体角色公开可见**；每条说法仍需来源、受众条件和获知时点。
- 亲历也走观察投影：从事实中形成该角色能感知的片段并记录来源，不能借亲历把整条幕后真相塞给角色。某秘密可以通过合法经历被逐步发现，不要求「永远不可知」。
- 说法可以真实，也可以错误；确信程度不等于客观真伪。事实尚未发生、渠道尚未传播或披露尚未授权时均不可返回。

### 13.3 软 / 硬约束与表达

- **可访问数据边界始终严格过滤**。软约束意味着允许角色在已有信息上猜测、犹豫和主观解释，不意味着能检索未授权的真相。
- 硬约束角色只接受卡片明确允许的直接经历、小环境与用户通讯来源；不因事件被标为公开而绕过渠道限制。
- 「不知道」合法；推测必须以推测表达，不回写为世界事实。可确定的错误传闻应来自已接触的说法；用户的新说法只记为用户所述，不能成为事实真值。
- 生成后做一致性检查：不合格时有界重试，仍失败则给不越界的回应或明确生成错误，不输出内部检查内容。

### 13.4 史料与获知

- 时点序：对本稿已成书的传本，止笔 → 成书 → 相应渠道可传播 → 角色获知 → 查询水位须依序不倒退（允许同刻）；覆盖区间须能按锁定历法解释。
- 「成书不晚于获知」只是必要条件：还须有合法渠道与实际接触依据。未接触来源者不可获知；初始知识引用必须存在于对应传本、获知时间不晚于初始时刻，并明确所掌握的条目或范围。
- 物化不等于获知：系统生成或展开文本不虚构读书经历，只能返回角色原本掌握范围内的展开；不因追问自动解锁整部史料。

## 十五、实施分期（本模块）

- **阶段 0**：单实例占位、单线身份及持久化边界，只服务最小聊天；不宣称世界模拟可用。
- **阶段 1**：真实实例初始全量快照、导入导出所需恢复边界。
- **阶段 2**：时钟 / 历法 / 倍率 / 激活冻结 / 补算，性格、生活线与最小认知。
- **阶段 3**：事件日志、世界事件引擎与经历产成。
- **阶段 4**：多线完整管理、提交 / 回滚 / diff / 压缩；此前全量快照不得与本规范最终语义冲突。
- **阶段 5**：多角色与披露整体验收；**阶段 6**深化世界自演化。

## 十六、待模块设计项（残余）

- diff 物化、压缩、索引重建的存储算法与性能阈值。
- 性格强度、稳定度、衰减参数标定；归档清理是否确有必要。
- 补算单批预算与等价批量计算优化。预算不得改动事实语义。
- 日历可支持的具体扩展（如闰年）由 schema 显式声明；不支持的包在创建前拒绝，不能静默近似。

## 附录 A：历法、生活线与参数起点

- 日序号：`day_index = floor(t / day_seconds)`；纪元对应世界秒 0。日长与各月天数须为正，周制及分段引用须有效。
- 年 / 月 / 日依锁定月表累计换算；v1 无闰年时明确固定年长，禁止把任意历法交给现实日期库猜测。
- 生活线生成：模板展开 → LLM 表述细化或模板兜底 → 校验时间窗、活动允许集与清醒 / 睡眠覆盖 → 固化。事件覆盖另行版本化。

| 驱动 | 变化步长起点 | 每世界日衰减起点 |
|---|---|---|
| 锚点 | 0.01 | 0.001 |
| 事件 | 0.10 | 0.02 |
| 对话 | 0.06 | 0.05 |
| 时间 | 0.03 | 0.08 |

这些数值是标定输入，不是无条件线性扣减公式；正式函数需满足锚点保护、普通单元可归档与分批等价。

## 附录 B：行为验收

1. 整秒前、整秒上、同秒多次调整、调度迟到与待生效时重启：倍率只在规定边界改变，世界时刻连续。
2. 多线同时激活、只切换查看、冻结后再激活：各线独立；冻结间隔不被补算。
3. 同一固定输入连续推进与中途退出后分批补算：事实状态、经历与数值一致；中断重试无重复事件。
4. 回滚到历史提交后不会瞬间追赶回原进度；被撤销消息的晚到生成、提取、重试均不能复活未来。
5. 来源线继续推进、回滚或删除后，已分叉线的共同过去不改变；压缩前后每个保留提交可恢复等价状态。
6. 普通单元可衰减到归档；锚点经弱驱动或压缩仍受保护；时间小步 / 大步结算等价。
7. 夜班、跨日睡眠与无睡眠角色共用一个世界日界；计划中的未来活动不能被当作既有经历。
8. 同一事件对不同角色返回不同可见说法；尚未获知的秘密、未来事件与其他角色未披露的对话无法进入生成上下文；未接触史料来源者不能获知，后台展开不自动扩大任何角色的已知范围。
9. 回滚与重启：回到获知之前，展开缓存、引用记录与派生记忆都不能让角色继续引用后来读到的内容；迟到任务不能恢复已撤销的获知。
10. 历史不重演：启动、重启、导入与批量补算不重复执行历史效果，不给角色批量补发旧事件。
11. 错记年代与相对年代不改变事件实际时刻，也不随查询日期悄悄改写原文。
12. 年龄由出生时刻与世界时刻推导；分叉 / 回滚不改变已固化的出生与死亡；寿终事件与状态在同一提交内一致。
13. 睡眠等待的任务在断线后保留、在冻结 / 回滚 / 归档 / 重绑后失效；恢复不重抽等待、不重复生成。
14. 备份恢复：全部线先冻结、重新锚定、不补算旧间隔、不重发消息；普通崩溃重启仍按补算规则执行。
