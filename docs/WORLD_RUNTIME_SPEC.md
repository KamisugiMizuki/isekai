# 世界运行层（WORLD_RUNTIME_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「世界运行层」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分；同日模块深化（决策：世界时钟机制内置历法——世界包定义日长与月份；角色生活线 = 轻量活动序列，无空间 / 路网）。

## 一、模块职责与范围

**职责**：世界时钟（时间基元 + 历法 + 倍率）、时间线、版本管理（提交 / diff / 回滚 / 压缩）、角色状态（性格单元引擎 / 生活线 / 记忆载体）、事件日志、认知接口。

- 本层是**世界运行状态的唯一持有者**；记忆的写入与召回契约在会话层（`SESSION_CORE_SPEC.md`），存储与版本化在本层。
- 范围外：通道（`CHANNEL_PLUGIN_SPEC.md`）、会话与生成（`SESSION_CORE_SPEC.md`）、世界包与实例（`WORLD_SETTING_SPEC.md`）、角色卡内容（`CHARACTER_CARD_SPEC.md`）。

## 二、世界时钟与流速倍率

### 2.1 时间基元与历法

- **时间基元：世界秒。** 世界时间以世界秒连续推进，是唯一原子量。
- **历法由世界包定义**（见 `WORLD_SETTING_SPEC.md`）：纪元、**日长**（一日 = 多少世界秒；不假设 24 小时）、月 / 周体系（数量、长度、名称）、可选季节结构。
- 世界秒 ↔ 历法时刻（日期 / 时段）的换算为**确定性纯函数**：同一世界、同一时刻，任何消费者得到同一答案。
- **机制不假设现实历法**：日长、月份、周制全部来自世界包；引擎只保证换算一致。
- 昼夜 / 时段由世界包定义（默认按日均分，包可覆盖）；角色表述使用世界历法词汇。
- 倍率作用于世界秒的**流速**；历法只改变呈现，不影响倍率语义。

### 2.2 倍率定义与状态

- 世界时钟与现实时间存在可调倍率关系。
- 倍率 `rate` 为正整数。
- 含义：现实时间每推进 1 秒，世界时间推进 `rate` 秒。
- `rate = 1` 为默认值。
- 默认上限为 2592000（30 天）。
- **上限为全局配置，不随时间线走。**
- **上限仅开发者可配置，用户不可配置。**
- 用户可在 `[1, 上限]` 范围内自由调整倍率。

用途：

- 调试：快速流逝时间，检测时间驱动性格单元、事件生成、世界演化。
- 正式：用户可调整世界节奏，适应不同世界的叙事密度。

世界时钟状态：

| 字段 | 说明 |
|---|---|
| `base_real_time` | 基准现实时间 |
| `base_world_time` | 基准世界时间 |
| `rate` | 当前倍率，正整数 `[1, 上限]` |
| `pending_rate` | 待生效倍率 |
| `pending_rate_input_time` | 待生效倍率的输入时刻 |

全局配置项：

| 配置项 | 说明 |
|---|---|
| `rate_max` | 倍率上限，默认 2592000，仅开发者可配置 |

当前世界时间计算：

```
current_world_time = base_world_time + (now_real - base_real_time) × rate
```

### 2.3 倍率调整

倍率更新在自然整秒时生效，倍率归属以用户输入时刻为准。

调整流程：

1. 用户输入新倍率，记录输入时刻 `pending_rate_input_time`。
2. 新倍率存入 `pending_rate`。
3. 系统确定该输入归属的自然整秒：
   - 若输入发生在整秒 `T` 之前（即 `T` 尚未到达），则归属整秒 `T`。
   - 若输入发生在整秒 `T` 之后（即 `T` 已过），则归属整秒 `T+1`。
   - 若输入时刻恰为整秒 `T`，则归属整秒 `T+1`。
4. 在归属的整秒时刻：
   - 计算当前世界时间。
   - 更新 `base_world_time` 为当前世界时间。
   - 更新 `base_real_time` 为该整秒时刻。
   - 将 `pending_rate` 赋给 `rate`。
   - 清空 `pending_rate` 与 `pending_rate_input_time`。

### 2.4 倍率的作用范围

- 倍率为每条激活时间线独立配置。
- 不同激活时间线可拥有不同倍率。
- 修改某条时间线的倍率不影响其他时间线。
- 未激活时间线冻结，倍率不生效。
- **倍率上限为全局配置，所有时间线共享同一上限。**

### 2.5 倍率与各机制的关系

| 机制 | 与倍率的关系 |
|---|---|
| 世界时钟 | 直接受倍率影响 |
| 时间驱动性格单元 | 受倍率影响 |
| 角色生活线 | 受倍率影响（她的「日」随世界时间推进） |
| 事件生成 | 受倍率影响 |
| 自动提交 | 按现实时间间隔触发，不受倍率影响 |
| 手动提交 | 用户触发，不受倍率影响 |
| 会话核心 | 不感知倍率 |
| 对话上下文 | 不受倍率影响 |
| 插件层 | 不感知倍率 |

## 三、世界时钟可见性

- 世界时钟作为公开信息展示（含历法换算后的世界日期）。
- **仅展示当前激活时间线的时间。**
- 不展示其他时间线的时间。
- 用户切换激活时间线时，展示的时间随之切换。
- 世界运行状态正常提示同样仅针对当前激活时间线。

## 四、时间线模型

#### 模型语义

这里使用的“分支”更接近**平行时间线**，而非 Git 的独占式分支。关键差异：

| Git 分支 | 本项目时间线 |
|---|---|
| 同时只有一个检出 | 可同时激活多条 |
| 未检出分支不推进 | 未激活时间线冻结，激活时间线推进 |
| 分支用于开发隔离 | 时间线用于世界演化隔离 |

#### 推进规则

- **仅激活时间线推进。** 未激活时间线冻结在世界时间上，不产生新事件，不消耗模拟资源。
- **允许同时激活多条时间线。** 多条激活时间线各自独立推进，互不干扰。
- **每条激活时间线拥有独立世界时钟。** 不同时间线的世界时间可以不同。
- **时间线从创建时刻开始推进。** 创建时继承来源时间线的状态快照，此后独立演化。

#### 时间线的创建

时间线通过以下方式创建：

1. **引入世界事件。** 用户提出修改意图，系统创建新时间线，从修改点起引入事件。
2. **手动创建。** 用户从任意提交点创建新时间线。
3. **重置。** 从某个历史提交创建全新时间线。

#### 时间线的管理

- 命名、描述、归档、删除。
- 查看所有时间线及其状态。
- 查看时间线之间的关系（来源提交、创建时间）。
- 时间线不合并。

## 五、版本管理

#### 作用域

版本管理**仅作用于世界运行状态**。世界包仅保留最新一版。

| 对象 | 是否版本管理 | 说明 |
|---|---|---|
| 世界运行状态 | ✅ | 世界时钟、角色状态、事件日志、认知状态 |
| 世界包 | ❌ | 仅保留最新版，用户可自行导出备份 |
| 时间线元数据 | ✅ | 时间线的创建、来源、状态 |

#### 世界包的处理

- 世界包不参与版本管理：仅保留最新版，用户可自行导出备份。
- 世界包与世界实例**无关联**（见 `WORLD_SETTING_SPEC.md`）：实例创建后其设定锁死并自包含。
- 实例内的时间线始终在该实例锁定的设定下运行；世界包的修改只影响此后新建的世界实例。

这意味着：世界包是“世界的模板”，世界实例是“模板的一次实例化”；模板的修改不追溯任何已创建的实例。

#### 提交机制

提交对象：**世界运行状态快照**。内容包含：

- 世界时钟
- 角色状态
- 事件日志
- 认知状态
- 所属时间线元数据

提交方式：

| 方式 | 说明 |
|---|---|
| 自动提交 | 按时间间隔或事件数量阈值自动快照 |
| 手动提交 | 用户主动创建快照 |

- 自动提交默认参数（实现后标定）：**现实时间间隔 1 小时、事件数阈值 50**。
- 自动提交参数全局统一、可配置；用户可关闭自动提交。
- 手动提交不受全局配置限制。

#### 提交的作用

- 作为回滚点。
- 作为时间线创建点。
- 作为世界重置的锚点。
- 作为状态恢复的基线。

#### 与类 Git 的对应

| Git 概念 | 本项目 |
|---|---|
| 仓库 | 一个世界 |
| 提交 | 世界运行状态快照 |
| 分支 | 时间线（可多条同时激活） |
| 检出 | 激活 / 冻结时间线 |
| 标签 | 里程碑事件标记 |
| 回滚 | 回到某个提交 |
| 合并 | 不支持 |

## 六、角色状态与 diff 复制

**角色状态内容**：性格单元集合（含置信度）、记忆（载体在本层，契约在会话层）、经历、生活线、认知状态。

#### 模型概述

角色状态复制通过**类似 Git 的 diff 方式**实现。

#### diff 模型

- 角色状态以增量形式存储。
- 创建时间线时，新时间线从来源时间线的状态快照开始。
- 新时间线的角色状态只记录与来源时间线的差异。
- 状态读取时，沿时间线祖先链回溯，合并 diff 得到完整状态。

#### 适用对象

| 对象 | 是否 diff |
|---|---|
| 角色状态（性格单元、记忆、经历、生活线、认知状态） | ✅ |
| 事件日志 | ✅ |
| 世界时钟 | ❌（每时间线独立计时） |
| 世界包 | ❌（不参与版本管理） |

#### 设计含义

- 存储效率提高，多时间线共享祖先状态。
- 状态读取需要回溯合并，实现复杂度上升。
- 与版本管理的提交机制统一：提交即快照，时间线即 diff 链。
- 回滚是沿 diff 链回退，不是恢复全量快照。

#### 风险

- diff 链过长时，状态读取性能下降。
- 需要定期做“压缩提交”（类似 Git 的 squash 或 gc）。
- 压缩策略需在具体设计中确定。

## 七、回滚语义

#### 语义

回滚为**覆盖语义**：回滚点之后的状态被覆盖，原时间线不保留。

#### 规则

- 时间线回滚到某个提交时，该提交之后的状态被覆盖。
- 原时间线不保留为独立时间线。
- 回滚是破坏性操作。
- 回滚后，时间线从该提交继续推进。

#### 与创建时间线的区别

| 操作 | 语义 |
|---|---|
| 创建时间线 | 从某提交分叉出新时间线，原时间线保留 |
| 回滚 | 当前时间线回到某提交，之后状态被覆盖 |

#### 设计含义

- 回滚前建议用户手动提交，以便未来参考。
- 回滚是不可逆的，除非用户之前导出过备份。
- 界面需明确提示回滚的破坏性。

#### 披露撤回的统一

- 披露撤回通过回滚实现。
- 回滚覆盖披露之后的进展。

## 八、压缩策略

- 采用**自动压缩**。
- 压缩策略在实现后根据实际表现进行相应处理。
- 总设计层面只确定：自动压缩是 diff 链的必然配套机制。
- 具体压缩触发条件、压缩粒度、压缩算法留待实现阶段确定。

## 九、多角色共享世界时钟

#### 规则

- 同一世界内的多个角色**共享同一世界时钟**。
- 世界时钟按时间线独立推进。
- 同一时间线下，所有角色处于同一世界时间。
- 不同时间线的世界时钟独立。

#### 设计含义

- 角色间的时间一致性由世界时钟保证。
- 用户在同一时间线下与不同角色对话时，世界时间是统一的。
- 角色状态随时间线隔离，但共享该时间线的时间基准。
- 未来角色间交互时，共享世界时钟是基础。

## 十、性格单元引擎

#### 四种驱动方式

| 驱动类型 | 强度来源 | 生成下限 | 生成上限 | 变化速率 | 衰减速率 |
|---|---|---|---|---|---|
| **锚点驱动** | 角色核心辨识特征 | 0.75 | 0.99 | 极慢 | 极慢 |
| **事件驱动** | 事件的重要程度 | 0.40 | 0.95 | 快 | 慢 |
| **对话驱动** | 对话的情感强度 | 0.15 | 0.70 | 中 | 中 |
| **时间驱动** | 时间跨度的长度 | 0.05 | 0.50 | 慢 | 快 |

**关键规则：**

- 锚点驱动的置信度上下限阈值最高，衰减最慢。
- 事件驱动次之，对话驱动再次，时间驱动最低。
- 阈值顺序：锚点 > 事件 > 对话 > 时间。

#### 强度计算

- 驱动强度 `s` 为 `[0, 1]` 连续值。
- 每类驱动有各自的强度计算方式，具体算法在实现阶段确定。
- 强度参与置信度更新公式：`c_new = clamp(c_old + Δ × s, 下限, 上限)`。

#### 生成规则

- 当某个性格单元首次被触发时，根据触发它的驱动类型，赋予一个初始置信度。
- 初始置信度落在该驱动类型的生成阈值范围内。
- 事件驱动生成的单元初始置信度更高，对话驱动次之，时间驱动最低。

#### 更新规则

每次驱动事件发生时，相关单元的置信度按以下公式更新：

```
c_new = clamp(c_old + Δ × 驱动强度, 该驱动类型的下限, 该驱动类型的上限)
```

其中：

- `Δ` 为变化步长，由驱动类型的“变化速率”决定。
- `驱动强度` 为 `[0, 1]` 的连续值，表示该次驱动的强弱。
- `clamp` 将结果限制在该驱动类型的阈值范围内。

**方向性：**

- 同向驱动（强化已有单元）：置信度上升。
- 反向驱动（削弱已有单元）：置信度下降，下降幅度由“衰减速率”决定。

#### 驱动迁移

- 驱动迁移**隐式存在**，不显式记录。
- 迁移是置信度范围变化的结果，不作为独立事件记录。
- 迁移**不对用户可见**。用户无法看到“某个性格单元从对话驱动固化为锚点驱动”。
- 用户仅通过角色表达感受角色的变化，不通过界面查看迁移过程。

#### 驱动方式之间的转化

性格单元可以在驱动方式之间迁移：

| 迁移方向 | 触发条件 | 效果 |
|---|---|---|
| 事件 → 锚点 | 长期稳定、反复强化 | 阈值范围上移至锚点级 |
| 对话 → 锚点 | 长期稳定、反复强化 | 阈值范围上移至锚点级 |
| 时间 → 锚点 | 极长时间跨度 | 阈值范围上移至锚点级 |
| 事件 → 对话 | 事件影响减弱 | 阈值范围下移 |
| 对话 → 时间 | 对话影响消退 | 阈值范围下移 |

**迁移是渐进的，不是突变的。** 一个性格单元可以从事件驱动开始，经过长期稳定，最终固化为锚点驱动。

#### 锚点驱动的特性

- 不进入归档。
- 可新增，不跨时间线转移。
- 数量由 AI 决定。
- 依附时间线。
- 跨时间线起点由角色卡决定。

#### 角色可辨识性的保证

- 角色卡中的初始锚点驱动单元集合（跨时间线共享，作为识别起点）。
- 各时间线中演化出的锚点驱动单元（可能不同，但演化有连续性）。
- 锚点驱动单元的极慢衰减。
- 性格单元的驱动迁移（长期稳定的单元固化为锚点）。

#### 命名

- 性格单元的命名与语义由 AI 自动生成。
- 锚点驱动的单元同样由 AI 自动生成。
- 不区分两套命名机制。

#### 消失与归档

| 驱动类型 | 是否可归档 |
|---|---|
| 锚点驱动 | ❌ 不可归档 |
| 事件驱动 | ✅ 可归档 |
| 对话驱动 | ✅ 可归档 |
| 时间驱动 | ✅ 可归档 |

规则：

- 当 `c < 0.05` 时，该单元进入**归档状态**。
- 归档单元不再参与性格表达，但保留在状态中。
- 归档单元可被后续驱动重新激活，重新激活时从归档阈值开始上升。
- 长期未被激活的归档单元可被压缩提交清理（策略实现后确定）。

#### 设计含义

- 性格变化是连续漂移，不是离散切换。
- 事件对性格的影响最深，对话次之，时间最浅。
- 角色可以同时持有相互矛盾的性格单元，置信度决定主导权。
- 性格单元集合随时间线独立演化。

#### 待实现后调整的部分

- 具体变化步长 `Δ` 的数值。
- 驱动强度的计算方式。
- 归档清理策略。
- 压缩提交的触发条件与粒度。

## 十一、角色生活线

#### 定位

角色每日活动的**轻量真值序列**：回答「她在做什么」，并为对话、主动发言、事件提供素材。

#### 边界（与 veranima 虚拟日程的差异）

- **无空间**：不含地点、坐标、路网、通行时间（不引入虚拟空间体系）。
- 只有「时间窗 + 活动」两个维度。

#### 结构

- 一日 = 有序活动块序列：`{时间窗（历法时刻或世界秒区间）, 活动（短语，如「做早饭」「去集市」「巡夜」）}`。
- 模板来源：世界包（世界层面的日常结构）+ 角色卡（她的职业与习惯）。
- 作息惯例（入睡 / 醒来时段）属于模板的一部分，定义「日界」。

#### 生成

- 每日一次：在她入睡后生成次日计划（参考 veranima 的生成时机）。
- 模板骨架定结构，LLM 用于细化；产物落为角色状态的一部分（随提交 / diff / 回滚）。
- 生成一次即固化，不逐秒随机。

#### 更新

- 世界事件可**覆盖**当日剩余块（简单覆盖语义）。
- 生活线只由世界侧更新——用户对话不改变它（影响路径：用户 → 角色 → 世界）。

#### 用途

- 对话真值（认知接口返回当前活动）；
- 经历产成（生活线执行产生角色经历事件）；
- 主动发言素材。

#### 分期

阶段 2–3（与世界时钟、事件日志同期落地）。

## 十二、事件日志

#### 定位

世界侧发生过的可检索事实流；认知接口、主动发言、记忆的共同数据源。

#### 事件模型

`{世界时间（历法时刻）, 主体（角色 / 世界）, 类型, 标题, 描述, 认知范围, 素材标记}`

- **类型**：世界事件（政治 / 灾害 / 节庆 / 风闻）｜ 角色经历（她做过、遇到、遭遇的事）。
- **认知范围**：谁知道这件事（供认知接口过滤；默认按经历与信息渠道）。
- **素材标记**：是否值得她提起（主动发言筛选依据）。

#### 生成纪律（确定性）

- 事件生成 = **确定性种子函数**（同一世界、同一历法日，任何消费者同答案——沿用「纯函数」纪律）。
- 角色经历由生活线执行与世界事件派生。

#### 写入即固化

- 事件进入该时间线状态，随提交快照与回滚。

#### 分期与规模

- 世界事件引擎（事件族、种子设计）属独立子系统，**另立一轮深化**；
- 角色经历自生活线落地（阶段 2–3）起逐步产生。

## 十三、认知接口

#### 语义

输入（角色，查询主题）→ 输出该角色**应该知道**的世界信息子集（结构化）。

#### 决定因素（承角色卡）

① 角色设定与知识范围；② 经历（生活线执行 + 事件参与）；③ 信息渠道（世界包定义）；④ 对话历史（与联络者的交谈，经记忆召回）。

#### 纪律

- 生成侧不得越出子集（注入 + 后验一致性检查，实现层）。
- **认知子集是碎片化叙事的结构性保证**——不是提示词伪装。

#### 分期

阶段 2（最小版：设定 + 经历）。

## 十四、与其它模块的接口

| 对方模块 | 接口面 |
|---|---|
| 会话核心层 | 角色状态读写、认知接口、世界时钟（含历法换算）、事件日志（主动发言素材）、提交 / 回滚 |
| 世界设定层 | 世界包定义（历法 / 信息渠道 / 世界事件源）、实例创建与导入导出对运行状态的影响 |
| 角色卡 | 性格单元初始集合、认知边界、生活线模板（职业与习惯） |
| 通道插件层 | 无直接接口 |

## 十五、实施分期（本模块）

- **阶段 0**：世界时钟基元 + 倍率 + 时间线骨架（最小提交 / 激活 / 冻结）。
- **阶段 2**：历法换算、角色状态（性格单元 + 生活线）、认知接口最小版、时钟可见性。
- **阶段 3**：事件日志与世界事件引擎、生活线经历产成、主动发言素材。
- **阶段 4**：diff 存储、自动压缩、回滚全面生效（此前可用全量快照过渡）。

## 十六、待模块设计项（残余）

- diff 合并与压缩的具体算法。
- 性格单元置信度更新的具体公式与参数（步长 `Δ`、驱动强度计算）。
- 归档清理策略。
- 历法换算的实现细节（纪元起点、月份边界的惯例处理）。
- 生活线的生成提示词与检查方式。
- **世界事件引擎**（事件族、种子函数、可见性）——另立一轮深化。
