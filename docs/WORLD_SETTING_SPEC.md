# 世界设定层（WORLD_SETTING_SPEC）

> 上游总设计：[`DESIGN.md`](DESIGN.md)（总纲） · 本文为「世界设定层」模块设计文档
> 来源：2026-09-19 总设计对话整理拆分；同日模块深化（决策：世界包内容分「实情 / 公共叙事」双轨；世界包保持单文件、可手编）。

## 一、模块职责与范围

**职责**：世界包（结构 / 双轨内容 / 生成）、世界实例（创建、锁死、黑箱）、多世界与角色拓扑、用户位置与通讯方式、导入导出与跨端同步。

**范围外**：运行侧机制（`WORLD_RUNTIME_SPEC.md`）、会话与生成（`SESSION_CORE_SPEC.md`）、通道（`CHANNEL_PLUGIN_SPEC.md`）。

## 二、世界包

### 2.1 内容范围

一个世界包描述一个完整世界，包括但不限于：

- 世界背景与基本规则
- 时间体系：**历法**（纪元 / 日长 / 月周体系）——供世界时钟换算（见 `WORLD_RUNTIME_SPEC.md` §2.1）
- 地理范围与活动区域（叙事描述；**无几何、无路网**）
- 社会结构、文化、信仰、科技 / 魔法水平
- 重要历史与当前局势（**双轨**：实情层 / 公共叙事层，见 §2.2）
- 信息渠道（角色认知可及的信息来源——供认知接口）
- 世界事件源（供事件系统）
- 可出现的角色类型与角色模板
- 角色与用户之间的通讯方式及其限制
- 初始事件、传闻、未解之谜
- （可选）命名与语汇规范——供生成一致性

**世界包是结构化、可修改（仅保留最新版）、可被反复加载的模板。**

### 2.2 双轨内容

世界包中的「历史与事实」类内容分两层记录：

| 层 | 内容 | 用途 |
|---|---|---|
| **实情层** | 世界的真相（创作者真值） | 一致性校验与运行；**不越层泄漏给角色** |
| **公共叙事层** | 民间说法、信仰、分歧、流传版本 | 角色的表述从此层出；**允许与实情相反** |

- 角色能接触到哪一层、哪一部分，由认知接口按其设定 / 经历 / 信息渠道过滤（见 `WORLD_RUNTIME_SPEC.md` §十三）。
- **误解是设计素材**：同一件事的两种说法都可以是「她真诚相信的」。
- 双轨随世界实例一起锁死（见 §3.4）。

### 2.3 文件形态

- **单文件**（承总设计：世界包作为某一个文件保存在本地）。
- 格式：JSON——可手编、可 diff；不含二进制资源。
- 用户可自由修改；修改只影响此后**新建的世界实例**（见 §3.3）。

### 2.4 生成方式

| 方式 | 说明 | 适用场景 |
|---|---|---|
| **表单式生成** | 用户按结构化字段填写世界设定 | 用户已有明确构想 |
| **对话式生成** | 用户用自然语言描述，AI 生成候选世界包 | 用户只有模糊想法 |

两种方式可混合：用户可先对话式生成，再表单式修改。

**生成原则**：

- 生成结果必须可编辑，不是黑箱。
- 生成结果需与已有世界包内容保持一致。
- 世界包修改只影响此后新建的世界实例；已创建的世界实例与其时间线不受影响（无关联原则，见 §3.3）。

### 2.5 生成器

- **桌面端与安卓端共享同一生成器**（承总设计），两端生成结果一致。
- 结构（字段骨架、双轨框架、历法结构）由代码 / 模板定；文本由 LLM 产一次（可重试），不通过则手编。
- 生成结果需**用户审定**后生效：可查看、可修改、可重生成。
- 命名与语汇（人名 / 地名 / 组织 / 月名）随生成产出，用户可改。

## 三、世界包与世界实例

### 3.1 对象区分与生命周期

- **世界包是本地文件**：可修改，仅保留最新一版，作为模板存在、可被反复加载。
- **世界实例创建后，设定被完全锁死。**
- 锁死的是**世界实例**，不是世界包文件。

| 对象 | 可变性 | 版本 | 说明 |
|---|---|---|---|
| **世界包文件** | ✅ 可修改 | 仅保留最新版 | 本地文件，作为模板 |
| **世界实例** | ❌ 创建后完全锁死 | 不适用 | 从世界包加载后冻结 |
| **世界运行状态** | ✅ 可变 | 版本管理 | 时钟、角色状态、事件日志 |

```
世界包文件（本地，可修改）
        │
        │ 用户选择加载
        ▼
世界实例（创建后设定完全锁死）
        │
        │ 时间线推进
        ▼
世界运行状态（版本管理，可提交、可回滚）
```

### 3.2 实例创建流程

1. 用户选择本地世界包文件；
2. 校验（结构 / 引用完整性 / 双轨完整性）；失败 → 提示并停止；
3. 生成候选实例名（基于世界包名称），交用户调整——**命名规则与导入一致**：全局唯一、重名自动追加 `_2` 等序号；
4. 创建实例：世界包快照 + 设定锁死 + 与世界包文件**脱钩**（无关联）；
5. 进入运行：可创建时间线并推进（时间线从创建时刻开始）。

- 同一世界包文件可被多次加载，得到互相独立的多个实例。

### 3.3 无关联原则

- 世界包文件与世界实例之间**无关联**。
- 修改 / 删除世界包文件，不影响任何已创建的世界实例。
- 世界实例不记录其来源世界包文件的引用。
- 世界实例创建后，其设定完全自包含，不依赖外部文件。

设计含义：

- 世界包文件是“模板”，用完即弃；世界实例是“成品”，自包含、自洽、锁死。
- 用户可自由修改、删除、替换世界包文件，不影响已有世界。
- 如需基于修改后的世界包创建新世界，直接加载即可。

### 3.4 设定锁死

- 世界包加载并创建实例后，设定被**完全锁死**，不允许任何修改，包括：
  - 世界背景；地理范围；社会结构；文化信仰；科技 / 魔法水平
  - **历法与双轨内容**
  - 角色卡；通讯方式
- 没有任何例外，没有“非语义修改”通道。
- 修改世界设定的唯一路径：**创建新世界实例**（使用修改后的世界包）。

设定与运行状态的区别：设定是“世界的公理”（锁死）；运行状态是“公理下的历史”（通过时间线演化）。

### 3.5 完全黑箱

- 世界实例创建后，其内部数据**完全黑箱**（含实情层在实例内的演化）。
- 用户不可直接查看、不可编辑世界实例的内部数据（不提供查看 / 编辑接口）。
- 世界实例可作为**整体导出 / 导入**（封装包；不加密，接受用户解压查看，项目不提供支持与解释）。
- 用户与世界实例的交互仅通过对话、版本管理操作与整体导入导出进行。

| 操作 | 是否允许 |
|---|---|
| 与角色对话 | ✅ |
| 提交（自动/手动） | ✅ |
| 回滚 | ✅ |
| 创建时间线 | ✅ |
| 切换时间线 | ✅ |
| 激活/冻结时间线 | ✅ |
| 查看世界实例内部数据 | ❌ |
| 编辑世界实例内部数据 | ❌ |
| 修改世界实例设定 | ❌ |
| 整体导出 / 导入世界实例 | ✅（见 §六 世界实例导入导出） |

设计含义：世界实例是自包含、不可窥探的整体；用户通过对话“体验”世界，而非“检查”世界；黑箱强化“世界是真实的”这一体验。

## 四、多世界与角色拓扑

| 层级 | 支持 | 说明 |
|---|---|---|
| 多世界 | ✅ | 用户可拥有多个世界，各自独立 |
| 同一世界多角色 | ✅ | 同一世界可包含多个角色 |
| 同一世界角色切换 | ✅ | 用户可在同一世界内切换对话角色 |
| 同一世界角色间交互 | ❌（当前） | 未来开放世界方向再设计 |
| 跨世界角色共享 | ❌ | 角色绑定世界，不跨世界 |

实现分期：

- 阶段 5 之前按**单角色**运行（简化实现起步）；多角色能力在阶段 5 落地。
- 架构始终按多角色设计，预留：世界与角色的一对多关系、角色切换时的会话隔离、未来角色间交互的扩展点。

## 五、用户位置与通讯方式

#### 用户在世界外

用户不是世界内居民。用户不占据世界中的地理位置，不直接参与世界事件。用户是：

- 观察者
- 联络者
- 对话者

用户可以通过角色间接影响世界，但影响路径是“用户 → 角色 → 世界”，而不是“用户 → 世界”。

#### 特殊双向联络

角色拥有某种“仅能与用户双向联络”的特殊通讯方式。该通讯方式由世界设定定义，例如：

- 宇航员的量子通讯终端
- 王都居民的魔法传讯石
- 货车司机的某个神秘聊天软件
- 其他符合世界观的解释

通讯方式的特点：

- 仅连接用户与角色
- 不连接世界内其他存在
- 其存在本身可以是世界设定的一部分
- 其限制可以影响角色认知

## 六、跨端同步

#### 无云同步

- 项目**不提供云同步服务**。
- 不依赖任何云端存储。
- 不自动同步任何数据。

#### 手动同步

- 所有跨端同步由**用户手动完成**。
- 同步方式：通过世界实例的导出与导入。
- 用户在桌面端导出世界实例，在安卓端导入；反之亦然。
- 同步是用户主动行为，系统不介入。

设计含义：项目保持本地优先；用户完全掌控数据迁移；与黑箱设计一致（导出的是封装包）。

## 七、世界实例导入导出

#### 导出包格式

- 单一文件。
- 不加密。
- 具体格式由实现决定。
- 接受用户可能通过解压等方式查看内部数据。
- 封装世界实例的完整状态，包括世界包快照、世界运行状态、时间线、提交历史、角色状态。

#### 世界包名称存储

- 世界包名称嵌入世界包快照中。
- **系统以世界包快照中的原始名称为准。**
- **用户对世界包文件中名称的任何修改，系统视为未发生。**
- 导入时读取的是系统记录的原始名称，而非用户修改后的名称。

#### 导出内容范围

- 仅包含世界实例本身。
- 不包含激活状态信息；导入后激活状态由导入端设置。

#### 导入语义

- 导入始终创建一个新的世界实例。
- 导入不修改、不覆盖、不影响任何已有世界实例。
- 新实例与原有实例完全独立；各副本此后独立演化，互不影响。
- 不支持世界合并。

#### 导入实例命名

- 从导出包的世界包快照中读取**原始世界包名称**，自动生成候选名称。
- **全局不允许同名世界实例**（不区分世界）。
- 与已有实例同名时自动追加序号：`名称_2`、`名称_3`，依此类推。
- 名称生成后交用户调整、决定；用户确认后创建。
- 用户改后的名称仍同名 → 系统拒绝并提示（需提供全局唯一名称）。

#### 版本兼容检查

- 仅在导入时检查；导出时不检查。
- 导入时把导入包声明的版本与当前版本比对；有差异时提示导出时版本、当前版本、可能受影响的方面。

#### 版本不兼容的处理

- 版本差异极大且无转换工具 → 拒绝导入，提示使用对应兼容版本运行。
- 不提供强制导入选项；不允许手动部分迁移。
- 有转换工具时：自动检测并提示用户确认后转换。

#### 导出包与对话体验的关系

- 导出包包含世界实例的内部真相；对话体验是用户通过角色认知接口获得的局部视图。
- 两者存在差异是设计使然，不是 bug；不需要提示，不需要干预。

#### 世界包文件修改责任

- 用户可对导出世界包文件进行修改；项目不提供任何支持，后果自负。
- 已创建的世界实例与导出世界包文件无关联；修改不影响任何已创建实例。
- **世界包名称以系统记录的原始值为准，用户修改不生效。**

## 八、与其它模块的接口

| 对方模块 | 接口面 |
|---|---|
| 世界运行层 | 世界包快照（历法 / 信息渠道 / 事件源 / 双轨内容）供运行时消费；导入导出搬运运行状态 |
| 会话核心层 | 实例 / 时间线生命周期（创建、导入、回滚）对会话的影响 |
| 角色卡 | 世界包提供角色类型与模板；角色卡是其实例（见 `CHARACTER_CARD_SPEC.md`） |
| 安卓端 | 共享生成器；跨端导入导出（见 `ANDROID_SPEC.md`） |
| 通道插件层 | 无直接接口 |

## 九、实施分期（本模块）

- **阶段 1（承总设计）**：世界包结构（含双轨与历法）+ 生成器（表单 + 对话）+ 实例创建 + 导入导出。
- 多角色拓扑随阶段 5 生效（此前单角色）。
- 跨版本转换工具按需随版本发布提供。
