## 一、项目定位与背景

### 1.1 背景与问题定义

#### 现有基础

你已有的 Veranima Companion 已经实现了相当完整的角色陪伴能力：QQ 私聊主通讯、长期记忆（SQLite + FTS5 + 向量检索）、虚拟日程与昼夜节律、有限虚拟空间与地点池、角色卡 V3、PAD 人格与关系状态。这意味着**角色层**已经基本可用。

#### 核心问题

现有系统缺少的是**角色所生活的那个世界**。角色有日程、有地点、有记忆，但这些记忆和日程的**背景**——这个世界的历史是什么、有哪些重要事件发生过、社会结构如何、文化特征是什么——没有独立的、可被探索的载体。

用户在对话中问“你们那里最近有什么大事吗”，角色无法给出一个有世界观纵深的回答，因为世界本身没有被建模。

#### 问题的本质

这不是一个“角色缺少设定”的问题，而是一个**世界观缺少独立运行机制**的问题。现有的世界信息如果只是写在 prompt 里，它是静态的、被动的、不可探索的。你要做的是一个**世界模型**，角色生活其中，用户通过角色对话进入其中，碎片化地发现其中内容。

### 1.2 愿景与总体目标

#### 愿景

创建一个**自洽的、持续运行的、可被碎片化发现的异世界**。这个世界不依赖用户在线而存在。用户每次与角色对话，都是在“探访”一个一直在运转的世界，而不是“启动”一个对话场景。

#### 总体目标

| 层级 | 目标 |
|---|---|
| **短期（MVP）** | 世界时钟与系统时间同步运行；角色在世界中的行为产生事件；事件被记录并可被对话引用 |
| **中期** | 世界拥有一套最小可用的“历史-人文-事件”设定层，用户可通过多轮对话逐步拼凑出这些设定 |
| **长期** | 世界具备自演化能力：世界状态因角色行动和内部逻辑而持续变化，新设定从已有设定中“长出来”，而非预写 |

### 1.3 项目定位

**项目代号：Veranima World（暂名）**

这是一个**独立于 veranima-companion 的新项目**，包含自己的聊天功能，不以原项目为运行依赖。原项目作为设计参考、资产来源和理念基础，但新项目独立仓库、独立部署、独立演进。

核心定位：

> 一个支持多世界设定、可由用户修改、可由 AI 根据描述自动生成世界包的虚拟世界对话系统。用户作为世界外存在，通过角色特有的双向联络方式，与生活在不同世界中的虚拟角色持续对话，并通过碎片化叙事逐步拼凑出该世界的历史、人文与重要事件。

关键词：

- 独立项目
- 内建聊天功能
- 世界设定可插拔、可修改
- AI 辅助生成世界设定
- 现实时间与世界时间可调倍率同步（默认 1:1）
- 角色认知软约束
- 用户位于世界外
- 碎片化叙事

### 1.4 独立项目策略

#### 与原项目的关系

- 新项目独立仓库、独立部署、独立演进。
- 原项目作为设计参考与资产来源。
- 可选择性移植或重写：角色卡、记忆、PAD、关系状态、日程等。
- 不直接依赖原项目运行。

#### 新项目包含

- 内建聊天功能
- 世界设定模块
- AI 世界包生成
- 世界时钟
- 角色认知接口
- 事件日志
- 碎片化叙事分发

#### 新项目不包含

- 图形化世界地图（总设计层面不包含）
- 多用户共享世界
- 完整世界编辑器 UI（初期可用文件/配置编辑）
- 重写原项目全部功能
- 追求世界规模

### 1.5 设计理念：碎片化叙事的结构性保证

#### 碎片化叙事的结构性保证

碎片化叙事的核心不是“把信息拆成碎片”，而是**信息在时空中的自然分布**。在你的场景中，这意味着：

- 角色知道的世界信息，取决于角色**在世界中的位置和经历**。
- 同一世界的不同角色，可能知道不同的事。
- 角色对世界的认知是**局部的、有视角的**，而非全知的。
- 用户通过**与不同角色对话、在不同时间对话、询问不同话题**，逐步拼凑出世界的完整图景。

这需要世界层提供一个**角色认知接口**：给定角色 ID 和查询主题，返回该角色“应该知道”的世界信息子集。认知范围由角色在世界中的经历（去过哪里、见过谁、经历过什么事件）决定。

## 二、核心设计原则（最终版）

### 2.1 总设计收敛声明

本版是总设计的**收敛版本**。总设计层面不再新增待确认项；后续细化一律进入模块设计阶段（见 §四 模块与文档地图）。已收敛的关键结论收录于下方设计原则与各模块 SPEC 文档。

### 2.2 核心设计原则

1. 项目独立。
2. 聊天通道与内容生成解耦，通道为插件式适配器。
3. 世界包文件可修改，仅保留最新版；世界实例创建后设定完全锁死。
4. AI 生成，用户审定。
5. 用户在世界外。
6. 角色与世界高耦合。
7. 认知软约束为默认。
8. 时间同步是基础设施；世界时钟与现实时间存在可调倍率关系。
9. 世界设定初始确定，后续修改通过引入世界事件 + 创建时间线进行。
10. 版本管理作用于世界运行状态层面。
11. 仅激活时间线推进；允许同时激活多条时间线。
12. 角色性格由性格单元构成，置信度控制生成、变化、消失。
13. 性格单元有四种驱动方式：事件、对话、时间、锚点。
14. 锚点驱动是性格单元的一种驱动方式，不再有独立的锚点模型。
15. 对话上下文随时间线隔离。
16. 通道插件开放第三方开发，第三方插件作为独立进程运行（仅桌面端）。
17. 披露撤回通过时间线回滚实现。
18. 内建聊天窗口作为核心进程的一部分，遵循统一消息协议；拆分后仅保留插件版本。
19. 世界实例内部数据完全黑箱；世界时钟作为公开信息展示，仅展示当前激活时间线的时间。
20. 支持世界实例导入导出；导出包不加密，接受用户可能查看内部数据。
21. 安卓端不开放插件；安卓端支持世界实例创建、对话与世界包文件修改；支持表单式与对话式两种方式。
22. 项目不提供云同步服务，所有跨端同步由用户手动完成。
23. 驱动迁移隐式存在，不显式记录，不对用户可见。
24. 角色卡初始支持用户自定义或 AI 根据描述生成，AI 生成后需用户检查，仅保留最终确认版本。
25. 导入始终创建新世界实例，不修改或覆盖任何已有实例。
26. 内建聊天窗口拆分后，安卓端始终使用内建聊天实现，与桌面端插件版本并行；安卓端内建实现遵循统一消息协议；保持独立。
27. 不支持世界合并。
28. 世界时钟倍率在每一自然整秒时更新生效；倍率归属以用户输入时刻为准；若输入时刻恰为整秒，归属下一个整秒。
29. 安卓端与桌面端共享世界包生成器；当前版本生成的世界包保证在当前版本可运行；两端版本不同时按各自版本规则处理；跨大版本不兼容时先找转换器，无转换器则提示使用对应兼容版本运行。
30. 导出包包含世界包名称信息；导入实例名称基于此自动生成。
31. 倍率上限可扩展；默认上限 2592000；全局配置；仅开发者可配置。
32. 世界包名称嵌入世界包快照中；系统以原始名称为准，用户修改不生效。
33. 全局不允许同名世界实例，不区分世界。
34. 用户对导出世界包文件的修改，项目不提供任何支持，后果由用户自行承担；已创建的世界实例与世界包文件无关联。

## 五、跨模块机制概览

（各节为速览，机制细则见对应 SPEC。）

### 5.1 世界与实例
- 世界包 = 本地模板文件（可修改，仅保留最新版）；世界实例 = 模板的一次实例化（创建后**设定锁死**、**内部黑箱**、与世界包**无关联**）。
- 支持多世界；世界实例支持整体导入导出；**不支持世界合并**；全局不允许同名实例（不区分世界）。
- 详见 `WORLD_SETTING_SPEC.md`。

### 5.2 角色与性格单元
- 角色绑定世界；每个角色一张独立角色卡（含初始性格单元集合、认知边界、通讯方式）。
- 性格由「性格单元 + 置信度」构成；置信度控制生成、变化、消失；四种驱动方式：**锚点 > 事件 > 对话 > 时间**。
- 锚点驱动保证跨时间线的角色可辨识性；驱动迁移隐式存在、不对用户可见。
- 详见 `CHARACTER_CARD_SPEC.md`、`WORLD_RUNTIME_SPEC.md`（性格单元引擎）。

### 5.3 时间与版本
- 世界时钟独立推进：`当前世界时间 = 基准世界时间 + (现实流逝) × 倍率`；倍率按时间线独立、自然整秒生效、上限全局配置。
- 时间线 = 平行世界线（与 Git 分支的差异见 SPEC）；**仅激活时间线推进**；版本管理只作用于世界运行状态。
- 提交 / 回滚（覆盖语义）/ diff 存储 / 自动压缩；对话上下文随时间线隔离；披露撤回 = 回滚。
- 详见 `WORLD_RUNTIME_SPEC.md`、`SESSION_CORE_SPEC.md`。

### 5.4 通道与平台
- 通道与内容生成解耦；所有通道遵循统一消息协议；第三方插件独立进程（仅桌面端）。
- 内建聊天窗口属于核心进程、遵循同一协议、可拆分；安卓端始终内建、独立维护、**不开放插件**。
- 详见 `CHANNEL_PLUGIN_SPEC.md`、`ANDROID_SPEC.md`。

### 5.5 认知与碎片化叙事
- 认知为**软约束**：角色知道什么由设定、位置、经历、信息渠道、对话历史共同决定；与外界无信息交流的角色可声明硬约束。
- 世界层提供**角色认知接口**：按角色返回信息子集——碎片化是结构性的，不靠提示词伪装。
- 详见 `CHARACTER_CARD_SPEC.md`（约束规则）、`WORLD_RUNTIME_SPEC.md`（认知接口）。

## 六、实施路径

### 6.1 阶段路线图

#### 阶段 0：独立项目骨架 + 核心进程 + 内建聊天窗口

- 新建独立项目
- 定义统一消息协议
- 核心进程内实现内建聊天窗口（遵循统一消息协议）
- 定义第三方插件接口与文档
- 实现第三方插件进程隔离机制（仅桌面端）
- 实现最小会话核心

验证：内建聊天窗口通过统一消息协议对话；第三方插件可独立进程运行；插件崩溃不影响核心。

#### 阶段 1：世界包 + AI 生成 + 多世界 + 角色卡 + 导入导出

- 世界包文件结构定义
- 世界包生成器（表单式 + 对话式）
- 世界包文件可修改，仅保留最新版
- 世界包名称嵌入世界包快照，原始名称独立记录
- 从世界包文件创建世界实例
- 世界实例设定完全锁死，与世界包文件无关联
- 世界实例内部黑箱，世界时钟公开
- 世界实例导入导出（单一文件，不加密；导入时版本检查；不兼容拒绝导入；转换工具自动检测 + 用户确认；导入创建新实例；名称基于原始世界包名称自动生成 + 用户调整；全局不允许同名；重名自动追加 `_2` 等序号）
- 多世界支持
- 角色卡独立，支持用户自定义或 AI 生成 + 用户检查，仅保留最终确认版本

验证：修改世界包文件 → 创建新世界实例 → 旧世界实例不受影响；导入创建新实例且不影响原有实例；版本不兼容时拒绝导入；全局同名被拒绝；自动追加序号从 `_2` 起始；用户修改世界包名称不生效。

#### 阶段 2：世界时钟 + 倍率 + 角色认知 + 性格单元

- 世界时钟与系统时间同步，仅展示当前激活时间线时间
- 世界时钟倍率实现，每时间线独立，默认 1
- 倍率上限全局配置，默认 2592000，仅开发者可配置
- 倍率在自然整秒时更新生效，归属以输入时刻为准，整秒瞬间输入归属下一整秒
- 同一世界多角色共享世界时钟
- 角色状态存入世界运行层
- 性格单元置信度模型实现（四种驱动方式）
- 驱动迁移隐式存在，不对用户可见
- 认知接口按角色设定返回信息子集

验证：角色不会无理由知道全局设定；性格单元随四种驱动漂移；锚点驱动不归档；驱动迁移不可见；倍率在整秒生效且归属正确；倍率上限仅开发者可配置。

#### 阶段 3：事件日志 + 碎片化叙事

- 角色行动产生事件
- 事件写入日志
- 对话中按认知范围检索事件与设定

验证：用户通过 ≥ 5 轮对话获取 ≥ 3 条需拼凑的世界设定。

#### 阶段 4：版本管理 + 时间线 + diff 存储

- 提交机制（全局统一自动 + 手动）
- 时间线创建、激活、冻结
- 多条时间线同时激活
- 角色状态 diff 存储与合并（含四种驱动的性格单元）
- 自动压缩（策略实现后确定）
- 回滚（覆盖语义）
- 对话上下文随时间线隔离

验证：创建多条时间线并同时激活；diff 合并正确；回滚覆盖原状态；对话上下文隔离；自动压缩生效；倍率随时间线独立。

#### 阶段 5：多角色 + 披露机制

- 同一世界多角色，每角色独立角色卡，共享世界时钟
- 对话历史隔离
- 用户主动披露
- 角色不主动表露
- 披露撤回通过回滚实现

验证：角色间默认隔离；披露后可见；回滚后披露消失。

#### 阶段 6：世界自演化

- 世界规则驱动事件生成
- 新设定从已有设定中推导
- 世界在无用户互动时也持续变化

验证：运行一周后，世界状态有自洽变化。

#### 阶段 7（可选）：安卓移植评估

- 评估跨平台方案
- 安卓端不开放插件，始终使用内建聊天实现，遵循统一消息协议，独立维护
- 安卓端与桌面端共享世界包生成器
- 安卓端支持世界实例创建、对话、世界包修改（表单式 + 对话式）、导入导出、倍率调整
- 评估运行时方案
- 跨大版本不兼容时先查找转换器；无转换器则提示使用兼容版本
- 无云同步，跨端同步手动完成

验证：核心功能在安卓端可运行；世界包修改可用；世界包生成器共享；倍率调整可用；导入导出可用；无插件接入入口；跨版本处理符合规则。

## 七、成功指标

### 7.1 验收要点

| 维度 | 指标 |
|---|---|
| 独立性 | 新项目不依赖原项目即可运行 |
| 通道插件化 | 内建聊天可停用；可接入第三方插件；独立进程（桌面端） |
| 插件隔离 | 插件崩溃不影响核心 |
| 插件兼容 | 接口版本变化时提示用户；报错则反馈并停止 |
| 插件文档 | 提供接口文档与参考实现 |
| 内建聊天 | 桌面端核心进程的一部分，遵循统一消息协议，可拆为插件；拆分后仅保留插件版本；安卓端始终内建、遵循协议、独立维护 |
| 世界包文件 | 可修改，仅保留最新版，与世界实例无关联；用户修改后果自负 |
| 世界包名称 | 嵌入世界包快照，原始名称独立记录；用户修改不生效 |
| 世界包生成器 | 桌面端与安卓端共享；当前版本生成包当前版本可运行；版本不同按各自规则；跨大版本不兼容先转换，无转换器提示用兼容版本 |
| 世界实例 | 设定锁死，内部黑箱，可导入导出 |
| 导出包 | 单一文件，不加密，接受用户查看，含世界包原始名称 |
| 导出内容 | 仅世界实例本身，不含激活状态 |
| 导入语义 | 始终创建新实例，不影响已有实例 |
| 导入命名 | 基于原始世界包名称自动生成 + 用户调整；全局不允许同名；重名自动追加 `_2` 等序号 |
| 版本兼容 | 仅导入时检查；不兼容拒绝导入；无转换器仅提示用兼容版本；不允许手动部分迁移 |
| 世界时钟 | 公开，仅展示当前激活时间线时间 |
| 世界时钟倍率 | 每时间线独立，默认 1；自然整秒更新生效；归属以输入时刻为准；整秒瞬间输入归属下一整秒 |
| 倍率上限 | 全局配置，默认 2592000，仅开发者可配置 |
| 多世界 | 同一核心可运行 ≥ 3 个差异极大的世界包 |
| 多角色 | 同一世界可包含 ≥ 2 个角色，各角色独立角色卡，共享世界时钟 |
| AI 生成 | 表单式 + 对话式均可生成可编辑世界包 |
| 角色卡生成 | 用户自定义或 AI 生成 + 用户检查；仅保留最终确认版本 |
| 性格单元 | 四种驱动方式；置信度 0-1 连续值；AI 自动命名 |
| 驱动阈值 | 锚点 > 事件 > 对话 > 时间 |
| 锚点驱动 | 不归档；可新增；不跨时间线转移；数量 AI 决定 |
| 驱动迁移 | 隐式存在；不对用户可见 |
| diff 存储 | 角色状态通过 diff 复制与合并；自动压缩 |
| 时间同步 | 激活时间线世界时间与系统时间按倍率对应 |
| 软认知 | 角色默认不会无理由知道全局设定 |
| 碎片化 | 用户可通过多轮对话拼凑世界设定 |
| 版本管理 | 世界运行状态支持提交、回滚 |
| 多时间线 | 可同时激活 ≥ 2 条时间线；未激活时间线冻结 |
| 回滚语义 | 回滚覆盖原时间线 |
| 对话上下文隔离 | 不同时间线对话历史互不可见 |
| 披露机制 | 默认隔离；用户披露后可见；角色不主动表露 |
| 披露撤回 | 通过回滚实现 |
| 跨端同步 | 无云同步；用户手动导入导出 |
| 世界合并 | ❌ 不支持 |
| 实例同名 | ❌ 全局不允许，不区分世界 |
| 安卓端 | 不开放插件；始终内建聊天；遵循统一消息协议；独立维护；与桌面端共享世界包生成器；支持世界实例创建、对话、世界包修改（两种方式）、导入导出、倍率调整 |

## 八、主要风险与应对

### 8.1 风险清单

| 风险 | 应对 |
|---|---|
| 性格单元置信度模型不稳定 | 阈值与步长可配置；人工抽检；实现后调参 |
| 驱动迁移规则导致性格突变 | 迁移渐进；隐式存在；人工抽检 |
| 锚点驱动单元不足以保证可辨识性 | 角色卡初始集合 + 演化连续性共同保证 |
| 锚点驱动单元无上限导致膨胀 | AI 自行判断；压缩提交时评估保留必要性 |
| diff 链过长导致状态读取性能下降 | 自动压缩；压缩策略实现后确定 |
| diff 合并实现复杂 | 阶段 4 前先用全量快照验证机制，再引入 diff |
| 极高倍率下世界状态快速膨胀 | 默认上限 2592000；仅开发者可配置；用户需注意；可通过版本管理回退 |
| 倍率归属边界不明确 | 以输入时刻为准；严格对齐自然整秒；整秒瞬间输入归属下一整秒；测试边界条件 |
| 世界实例黑箱导致用户无法排查问题 | 世界时钟公开；系统内部保证一致性 |
| 导出包不加密，用户查看内部数据 | 接受用户查看；内部数据仍不可编辑 |
| 用户修改世界包文件出问题 | 项目不提供支持；后果自负；已创建实例不受影响；名称修改不生效 |
| 跨版本导入不兼容 | 导入时检查；不兼容拒绝导入；建议使用兼容版本；不允许手动部分迁移 |
| 转换工具缺失导致旧实例无法使用 | 重大变更版本必须提供转换工具；无转换器则提示用兼容版本 |
| 无云同步导致跨端体验割裂 | 明确告知用户手动同步方式；导出导入流程简洁 |
| 导入创建新实例导致多端副本分散 | 界面明确提示；用户自行管理副本 |
| 不支持世界合并 | 用户需理解副本独立演化；无合并路径 |
| 同名实例冲突 | 全局不允许同名；自动追加 `_2` 等序号；用户改名仍需保证唯一 |
| 倍率上限被误改导致异常 | 仅开发者可配置；用户不可见配置入口 |
| 插件进程隔离在安卓上受限 | 安卓端不开放插件，规避该问题 |
| 插件接口版本变化导致兼容问题 | 版本号显式声明；提示 + 尝试 + 报错反馈 |
| 内建聊天窗口拆分后桌面端与安卓端实现分叉 | 两端独立维护；共享协议与参考实现 |
| 回滚覆盖导致用户丢失进度 | 界面明确提示；建议回滚前手动提交 |
| 多时间线同时激活导致资源消耗 | 未激活时间线冻结；激活数可配置上限 |
| 多角色共享世界时钟导致状态复杂 | 世界时钟统一；角色状态独立存储 |
| 软认知约束被 LLM 绕过 | 认知上下文注入 + 后验一致性检查 |
