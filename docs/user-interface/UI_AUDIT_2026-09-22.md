> **口径**：正文 / 状态文字 ≥ 4.5:1；焦点描边与必要控件边界 ≥ 3:1（USER_INTERFACE_DESIGN §10.2）。
> 本报告与 §10.2 的补充修订都落在尚未入库的 `docs/user-interface/` 目录内，与实现会话的工作区互不冲突。

## 一、整体结论

- **界面主要目标**：不熟 AI 与电脑的用户，能按 README 完成配置，凭界面完成联络 / 写作 / 跑团，出错后能定位并回到原任务。
- **设计文档本身水准高**：错误四段式（对象 / 原因 / 完成范围 / 下一步）、不要求 JSON 与内部标识、状态不冒充角色发言、保存与生效分离——这些都在实现里有对应的落点，不是纸面条款。
- **当前最大问题不在设计而在实现侧的一致性与可访问性细节**：深色主题的状态色、控件边界色未达设计自己写的对比度门槛；模态焦点、「有新消息」提示缺失。另有少量文案小账。
- **最优先改三件事**：① 深色主题状态色与输入边界色对比度（P1）；② 模态焦点管理与「有新消息」提示（P2）；③ 新回复的读屏播报与文案小账（P3）。
- **可用性状态**：U1（首次设置 → 样例 → 联络 → 草稿保护 → 帮助 / 高级调试）已落地，真壳探针 **PASS**（2026-09-22 18:22 运行输出）；尾项是发行件封装（内嵌运行环境的安装程序）与 README 普通用户版；U2–U4（创作、写作、跑团工作区）未实现，页面如实说明。**现在还不能作为普通产品直接交付使用；开发机上 U1 路径可以真跑。**

## 四、具体调整方案

**A1（F1）深色状态色**——`user.css` 两处深色块各加一行：

```css
html[data-theme="dark"] { /* 与 @media (prefers-color-scheme: dark) 内的同名块一起改 */
  --u-ok: #5fbf8a;
  --u-bad: #ef8f8f;
  --u-warn: #d9a54a;
}
```

实测（对卡片 #1a1a1a / 下沉 #1f1f1f / 页面 #121212）：ok 7.71 / 7.30 / 8.30，bad 7.46 / 7.06 / 8.02，warn 7.82 / 7.40 / 8.41。

**A2（F2）控件边界色**——新增令牌，只在输入类控件上用：

```css
:root { --u-border-control: #808080; }
html[data-theme="dark"], @media→深色块 { --u-border-control: #787878; }
.u-input, .u-textarea { border-color: var(--u-border-control); }
```

**A3（F3）模态焦点**（`dom.ts` `dialog()`，最小改法）：

```ts
const restore = document.activeElement as HTMLElement | null;
// 入框后：
box.tabIndex = -1;
box.focus();
// close() 里：
restore?.focus?.();
```

**A4（F4）新消息提示**：`renderMessages()` 里当 `!wasAtBottom && 消息数增加` 时，在 `.u-messages` 容器角上放按钮「有新消息 ↓」→ `scrollHost.scrollTop = scrollHeight`；滚到底后移除。

**A5（F5）读屏播报**：contact 页加 `<span class="u-sr-only" role="status" aria-live="polite"></span>`（视觉隐藏，复用既有 sr-only 样式或新增 `clip-path: inset(50%)`），新回复到达写「收到一条新回复」。

**A6（F6）文案三处**：按问题清单 F6a / F6b / F6c 替换。

## 六、对设计的修订（已落）

`USER_INTERFACE_DESIGN.md` §10.2 增加一条可验证规则：**同一语义色与控件边界色要在浅色、深色下分别取值并分别实测，沿用另一主题的色值视为未验证；至少覆盖状态文字 × 各底色、控件边界 × 所在底色、焦点描边 × 所在底色**。理由：本轮 10 项失败全部来自「深色块复用浅色状态色」。
