### 4. 这次改造中由探针抓出的**真问题**（不是样式偏好）

1. **分区条丢了吸顶**：换成 `.u-tools` 时没把 `position: sticky` 带过来 → 内容一长分区条就滚走。已修（`user.css`）。
2. **「世界与素材」分区点击会被初始渲染覆盖**：`render()` 第一件事 `await refresh()`，期间点「世界设定 / 角色卡」会被随后的 `this.tab = "worlds"` 抹掉并在界面上回退（探针实测：必须先等页面画完再点）。已在 `render()` / `renderAssetsInline()` 两侧加竞态守卫。
3. **150% 字号下对话区被压到 16px**：状态行与两道发送闸搬进输入区后，输入区那一叠在放大字号时几乎吃光高度。给 `.u-messages` 加 `min-height: 140px`（宁可整块溢出由外层滚动）。实测 150% 下对话区回到 148px。
4. **boot 期间导航被"首启进向导"重定向覆盖**：深链/探针在启动瞬间进别的页面会被拽回向导。已改成「只有路由还停在默认 home 时才接管」。

### 6. 无障碍走查（2026-10-08 补做，可自动化的那部分）

产出：`a11y/*.png` 与 `a11y/a11y.json`。这不是"跑一遍扫描器看有没有报错"，而是量读屏用户实际会撞到的东西：

| 检查项 | 做法 | 结果 |
|---|---|---|
| 控件可访问名 | 每页枚举 `button/a[href]`，找既无文字又无 `aria-label/title` 的 | **9 页全 0** |
| 表单控件标签 | `label[for]` / 包裹 label / `.u-field-label` / `aria-label` 四条路都查 | **9 页全 0** |
| 图形有无名字 | 新增的比例条、进度轨、计量条是否带 `role="img"` + `aria-label` 或可见文字 | **全部有名字** |
| 标题层级 | h1→h6 是否跳级（读屏"按标题跳转"靠它） | **无跳级** |
| 键盘实走 | 每页从顶部连按 18 次 Tab，看落点与**焦点环是否可见** | **每一处都有可见焦点环**（0 处不可见） |
| 页面语言 | `<html lang>` | `zh-CN` ✓ |

**走查抓到并修掉的两处真问题（都在共用的弹窗实现 `dom.ts`）**：
1. **弹窗打开后焦点没有进窗**——`dialog()` 里 `box.focus()` 是同步调的，而调用方要等这个函数返回之后才把 overlay 插进文档：对游离节点调 `focus()` 是空操作，焦点其实留在被遮住的触发按钮上。改成挂上 DOM 之后再聚焦（微任务 + 下一帧双保险）。
2. **关窗后焦点回不到打开它的控件**——原来直接 `restore.focus()`；可列表重画过之后那个节点已经摘下，对游离节点聚焦同样是空操作，焦点掉回 `<body>`。改成：触发控件还在就还给它，不在了就落到正文容器 `#u-main`（`tabindex="-1"`）。

修完复跑：焦点进窗 ✓、Esc 关窗 ✓、焦点回到发起它的「删除」按钮 ✓，走查 **PASS**。

> 走查脚本自己踩过两个坑，都记在注释里：`make_root` 不带样例（不铺样例，向导走不到联络页，后面几页全是空态）；程序化 `.click()` 不会移动焦点，所以"关窗后回焦点"必须像真人那样先 `focus()` 再点。

## 一、先说结论：这些"怪"不是零散缺陷，是四件事的叠加

上一轮我按反模式清单逐条查（对比度、可点尺寸、断点……），查出的都是"点"上的问题。
你说的违和感我这次看到了，它来自四个**系统性**特征：

| # | 特征 | 一句话 |
|---|---|---|
| 1 | **只有一个视觉重量** | 全应用只有一种容器（黑描边 + 圆角 + 大留白）和一种按钮；页面 = 若干同重量盒子垂直堆叠 → 没有层级，眼睛不知道先看哪 |
| 2 | **一套外观对应三种交互** | 标签页切换、滚动锚点、普通动作**长得完全一样**（都是白底黑框圆角按钮）→ 学不到"这个形状 = 这个行为" |
| 3 | **没有页面骨架** | 标题纵向位置三种（y=77 / 94 / 154），有的页面压根没有标题带；返回按钮的语义在四种之间跳 |
| 4 | **几乎零图形，全部用文字顶** | 20 屏里 **19 屏没有任何 SVG/位图元素**（唯一一个在世界详情），进度、状态、比例、关系全靠句子和下划线表达 → 页面像文档，不像工具 |

再加两个放大器：**短页面下半屏全空 / 长页面要滚 4–5 屏**，以及**窗口滚动条紧贴内容盒右缘，看起来像盒子自己的滚动条**。

## 三、逐页：眼睛实际看到了什么

### 1. 首次设置·本机检查（`tour/01-onboarding-check.png`）
- 五步进度写成 **「本机检查　连接 AI　选择任务　准备材料　开始使用」+ 若干短下划线**。下划线是分隔线还是可点链接？当前步靠加粗 —— **看不出"走了几分之几"**。这是一个典型的"用文字顶图形"：本该是一条进度条或带编号的步骤球。
- 页面下半屏（约 35%）全白。
- 顶栏写 **「← 返回角色联络」**：用户第一次打开、还没见过"角色联络"这一页（那时它是空的）。返回箭头指向一个不存在于他心智里的地方。

### 2. 角色联络（`tour/06-contact.png`）
- 中间栏是一大片**空白**：上边一张有框的头部卡，下边输入区，中间什么都没有。对话区**没有容器**，所以三栏读起来不平衡——左右都有框，中间是个洞。
- 「已连接，可以开始联络」这行状态浮在空洞里，下面紧贴着输入区的一条分隔线，看起来不属于任何东西。
- 「还没有配置 AI 服务，暂时不能发送。去「设置 → AI 服务」配置」用告警色放在**页面中部**，而真正被禁用的「发送」按钮在下方隔着一个输入框；"为什么按不动"和按钮不在一起。

### 3. 首页（`tour/07-home.png`）
- 三个**同等重量的大盒子**：第一步：连接 AI / 继续上次 / 你可以做的事。每个都是同样粗细的黑边、同样圆角、同样内边距 → 没有主次。
- 「继续上次」为一行字占了一整个盒子（大量留白）。
- 任务卡里 **绿色圆点 + 文字「还缺：可用的 AI 配置」** —— 颜色说"OK"、文字说"缺东西"，两个信号打架。
- 按钮文案里**嵌了 emoji**：「打开💬 与角色联络」「打开✍️ 辅助写作」——图标被写进动作名里，像渲染故障。

### 4. 世界详情（`tour/10-world-detail.png`）
- 页面标题「世界与素材」在顶栏和正文各出现一次，紧接着又是一层盒子标题「灰潮纪」——三层标题。
- 内容区第一行按钮是「**返回世界列表**」，和「联络角色／在此写作／在此跑团／尝试世界变化…」并排 —— 一个"导航"混在"任务动作"里；同时顶栏的「← 返回角色联络」指向另一个地方。**同一屏两种返回目标**。
- 事实表里直接印 **`compatible`**（内部枚举）在"兼容性"这一行（`worlds.ts:471` 原样输出 `instance.compatibility`）。
- 22 个按钮、5 个同重量盒子、每个盒子内容都不满（「角色」盒子里只有一个项目符号 + 一棵按钮）。

### 5. 设置（`tour/11-settings-top.png`）
- 顶部是我上轮加的「跳到」索引：7 个白底黑框按钮 —— **和「世界与素材」的标签页、写作的四个分区长得一模一样**，但行为完全不同（滚动 vs 切页）。用户会以为点了会切页。

## 四、为什么这会造成你说的"说不出哪里怪"

1. **眼睛没有落点**：一屏里所有东西同重量同间距，视觉系统无法在 200ms 内建立"主要 / 次要 / 辅助"。人会感到"平"，但说不清哪里平。
2. **形状不再代表行为**：大脑靠形状分类（标签页 = 横排、当前项有底、切换内容；按钮 = 动作）。这里三者同形，每次都要读字才能判断 → 累。
3. **文字替图形还债**：当层级和状态没有视觉表达时，只能加句子解释。句子越多，页面越像文档；越像文档，越需要读；越读越慢 → "怪"。
4. **框架在跳**：标题 y 从 77 跳到 94 跳到 154，返回按钮指向三种不同地方。每换一页，眼睛要重新找"我在哪、从哪回去"。
5. **空白不表达结构**：短页面的空白在页面底部（像没做完），长页面的内容溢出（像表格）。同一产品里"一屏"这个词不成立。

## 五、建议的最小改动集（按投入产出）

**A. 立一个页面骨架（改 1 个 CSS 块 + 各页套用）**
每页固定三带：**① 标题带**（页面名 + 一句定位语 + 右侧主操作）→ **② 工具带**（分区/筛选，横向，有明确选中态）→ **③ 内容带**。
标题带高度、标题字号、左右内边距全局统一 → 标题 y 恒为同一个值，返回按钮语义固定为"上一级应用/首页"。

**B. 建三级视觉重量（改 CSS 变量即可）**
- 一级：页面级卡片（无边框，仅底色 `--u-sunken`）——用于分区
- 二级：内容卡片（1px 浅边 `--u-border-soft`）——用于条目
- 三级：行内元素（无边框，仅 hover 底色）
配套：主操作 = 实心黑；次操作 = 描边；导航 = 无边框下划线（当前项底部 2px）。
→ 「标签页 / 锚点 / 动作」自动分开：标签页用"下划线 + 当前项加重"，锚点用"小号灰底胶囊"，动作保持描边按钮。

**C. 补四个图形基元（`graphics.ts` 已有雏形，接上即可）**
1. **步骤进度条**（向导）：带编号圆点 + 连线 + 当前/已完成/未到三态。
2. **就绪状态条**（首页任务卡 / 跑团）：把"还缺什么"画成 3 段进度（世界 → 角色 → AI/规则），缺哪段空哪段；颜色只表达"完成/未完成"，不再用绿点配"还缺"。
3. **比例/计量条**（线索面板"已讲过 / 还没讲出口"、用量、世界进度）：现在是文字，`u-meter` 已在别处用。
4. **关系图**（世界线、大纲条目与章节）：世界详情已有分支图，同款搬到联络页顶部（当前线位置）与写作页（章节进度）。

**D. 消灭重复与死区**
- 写作页删掉盒子外重复的两个按钮；空态只保留一处动作。
- 短页面（世界列表 / 跑团列表 / 写作空态）把内容居中或让卡片撑满可用高度，不用"上挤下空"。
- 帮助页把顺序倒过来：常见问题（图形化入口 6 个磁贴）→ 状态 → 明细，技术明细收进折叠。

**E. 滚动与归属**
窗口滚动条与内容盒之间留 8–12px 安全距离（或让内容盒最大宽度受限、居中），避免滚动条看起来属于盒子。
