## 一、结论

**能跑起来，但一个普通人无法在没有外部帮助的情况下"和角色说上话"。**

这个项目的工程纪律明显高于同类项目：错误卡真的按"操作对象 / 直接原因 / 已完成范围 / 下一步"四段写，
不摆可点击的空壳，空态与读取失败大多分得清，破坏性操作有与之匹配的摩擦，发行说明甚至主动交代了"这一版还没有什么"。
**问题不在机械层面**——它确实基本做到了"不用命令行、不用手写 JSON"（全库仅剩 1 处"命令行"字样）。
**问题在概念层面**：整个产品默认用户已经知道"AI 服务 / 接口地址 / 模型名 / 密钥"是什么、从哪来，
并且把大量内部词汇（实例、时间线、水位、固化、候选、裁定、玩家面）直接摆在正文里。
对目标用户而言，这两件事加起来就是一道过不去的门槛。

三句话总结：

1. **第一次开门就是最大的一道坎**：密钥申请地址写在代码里却从未显示，模型名没有任何可用指引，地址要不要带 `/v1` 只能猜。
2. **说明书与屏幕对不上**：README 说"第一次打开会进首次设置"，实际第一屏是「选择应用」浮层；首页最显眼的主按钮「现在配置」把人直接丢进设置页全页（9 个区块）；发行说明让人去改 `config/config.yaml`，而全新安装根本没有这个文件（程序自己在向导里写着"还没有配置文件：保存设置时会创建"）。
3. **核心体验有两处硬伤**：收到的回复一出现，用户**刚发出去的那句话就从界面上消失**（每次对话必现）；"第一句可能要等 30–120 秒"这句唯一的心理准备只写在压缩包里的说明文件里，界面上一个字都没有。

## 二、真机走查：一个普通人实际会经历什么

以下每一步都是我跑发行件实测得到的界面原文（`.tmp-usability/plain-user/out*/walk*.md` 有完整逐屏记录与截图）。

### 第 0 步：解压、双击

- 双击到界面连上后台核心：**约 1 秒**（本机 Win11 已有 WebView2 运行时与常驻进程；干净的老 Win10 是否也如此未验证）。
- 干净数据根首次运行会生成 `backups / data / examples / logs`——**没有 `config/`**。

### 第 1 屏：不是"首次设置"，是「选择应用」

屏幕中央浮出一个三选一，主区文字如下（实测原文）：

```text
选择应用
💬 isekai Chat    与虚拟角色对话
✍️ isekai Writer  辅助写作和大纲管理
🎲 isekai GM      跑团主持和规则裁定
```

问题：

- **三个英文名**（Chat / Writer / GM）对一个还没建任何世界的人是无法回答的问题——选哪个都一样；"GM"对不玩跑团的人是纯噪音。
- **首启这一屏退不掉**：`launcher.ts:81-91` 只在"有退路"（从应用里点「返回选择应用」）时才挂 Esc 与"点空白"，
  首次启动没有退路就故意不给出口（注释写"保持「必须选一个」"）。实测两次浮层的原文差异正好印证：
  首启浮层没有提示行，第二次打开才出现"按 Esc 或点击空白处返回刚才的页面"。
  结果是用户必须先在三个他无法判断的英文卡片里选一个，才能看到首页的「推荐下一步」。
- README:14 与 发行说明:8 都写"第一次打开会进「首次设置」"——**与屏幕不符**。
- 主区其实是首页，但被浮层盖住；用户看不到「从这里开始 / 推荐下一步」，而后者才是真正该在首启出现的东西。

### 第 2 步：随便点一个 → 落到空空的联络页

实测：点 `isekai Chat` 后 `route = contact`，主区只有：

```text
角色联络
先选一个世界和角色
[选择 / 创建世界]  [从样例世界开始]
```

此时用户要做的事（配置 AI、准备材料）都不在这一屏；导航入口只有左上角"← 返回选择应用"和右上角一个 **`⋯`**。
`⋯` 里是：`首页 / 设置 / 帮助与诊断 / 世界管理 / 返回选择应用`——**"首页"两个字藏在 `⋯` 里**。

### 第 3 步：首页那条"最近的路"反而最重

回到首页，最显眼的主按钮是「现在配置」，实测 `route = {"pane":"settings","sub":"ai"}` ——
它把人丢进**设置页整页**，而不是五步向导。那一页在同一屏里依次出现：

`AI 服务 / 记忆检索 / 自动保存版本 / 数据与备份 / 从旧的开发目录迁移 / 用量 / 世界 / 通知与外观 / 扩展`（共 9 个区块），
其中包含"增强语义检索是独立服务""运行中按现实间隔或新增事件条数留下版本点""备份目录（相对数据根）"
"上限目前只能在命令行按世界调整""进程隔离不是完整安全沙箱"这类文案。
**一个只想和角色聊天的普通人，第一眼就被要求读这一页。**

次按钮「先看看样例,稍后再配置」才把人送进五步向导——但它**并不跳过 AI 配置**：
向导的 `entryStep()` 在"未配置 AI"时一律回到「本机检查」，用户还得再点一次「稍后配置，先整理素材」才能继续。
按钮名承诺的事和实际发生的事不一致。

### 第 4 步：向导「连接 AI」——最大的一道坎

实测这一屏的默认值与原文：

- 服务下拉框：`DeepSeek | 其他兼容服务（OpenAI 兼容接口）`，默认选中 **DeepSeek**；
- 服务地址：`https://api.deepseek.com`（在**折叠的**「高级选项：服务地址、等待时间、单次输出长度、生成随机程度」里，摘要文字里只有"服务地址"四个字）；
- 模型：`deepseek-v4-flash`，旁边一行说明是「名称从服务提供方取得；写错不会被自动纠正」；
- 访问密钥：一个密码框，下面唯一的提示是
  **「密钥在服务的官方密钥管理页取得（网页聊天账号登录与接口密钥可能不是一回事）。」**

**实测：整页搜不到 `platform.deepseek.com`。** 预置服务里写好的申请地址
（`onboarding.ts:44` 的 `key_url: "https://platform.deepseek.com/api_keys"`）只被用来做了一次三元判断，
**从来没有渲染给用户**（`onboarding.ts:215`）。也就是说，用户被告知"去官方密钥管理页"，
但**界面上既没有链接也没有可复制的地址**，只能自己开搜索引擎找——这正是最容易进仿冒站的一步。

同一屏还有两个坑：

- 什么都不填点「测试并保存」，实测提示是「还没有填访问密钥」——**密钥在事实上是必填的**，
  而这一屏没有任何一句"没有密钥也能先做别的"（只有旁边那颗「稍后配置，先整理素材」按钮隐含了这个意思）。
- 选「其他兼容服务」时服务地址留空，而该字段只在展开「高级选项」后才出现；此时提交会提示
  「服务地址与模型是必填项」（`onboarding.ts:237-244`）——**提示点名的字段在屏幕上找不到**。
  另外界面也不说地址要不要带 `/v1`（代码是往地址后面直接拼 `/chat/completions`，`isekai_core/llm.py:92`）。

### 第 5 步：向导第一步就把六项技术检查摊开

实测「本机检查」屏的六行：`核心程序可用`（版本 0.1.0（规则 0.1））、`受管目录可写`（后面跟一个完整绝对路径）、
`单一写入者`（本进程是唯一写入者）、`数据格式可读`（可读（记录格式 0.1，实例 0 个））、
`配置文件`（`…\config\config.yaml`）、`存储可写`。
下面还跟着一块「从旧的开发目录迁移」（"以前在这台或别的机器上用过 isekai 的开发版？"）。

对目标用户，这屏的正确形态应该是**一行绿字"这台电脑可以运行"**，六项收进"查看详情"。
现在它是首启的第一屏正文，还有"单一写入者""受管目录""记录格式"这类词。

### 第 6 步之后：材料准备好了，然后呢

「准备材料」这一步是全流程做得最好的一屏：样例下拉带一段世界观简介、选角色、填世界名、一颗「创建并开始联络」。
但接下来：

- 第一次说话后，等待态只有一句**静态**文案「已接收，正在等待回应」，没有预计时长、没有计时、没有取消；
- 8 秒后它会自己变成更吓人的「这条还没收到受理回执：可以查询原结果，或继续编辑原文重发」——
  这句提示与代码自己的纪律（`contact.ts:7-8`"受理结果未知先查结果，不重复当新消息发出"）相撞，
  而"重发"每次都是新的 ref，会把同一句话当新请求再发一次；
- 「查询原结果」查的其实不是那条请求（`contact.ts:577-589` 调的是 `storyTurn`），还会把内部状态码印上屏：
  「请求 `ab12cd` 的状态：`expressed`」。

## 四、重要问题（P1）

**首次配置与帮助**

- 设置页 AI 段能保存一个必然不通的地址并回「已保存未验证的配置」（无格式校验，`settings.ts:106-115`），
  而向导里同样的校验是有的（`onboarding.ts:241-244`）——两处不一致。
- 帮助与诊断页的「常见问题」是内部状态短语，不是用户的问题：
  「结果待确认 —— 用原操作身份查询结果，不要重复提交。」「正在补齐离开期间的进展 —— 读已经完成的记录即可。」
  （`help.ts:14-25`）；没有任何一条讲"密钥去哪申请 / 填哪个模型名 / 回复很慢 / 要不要花钱 / 怎么彻底退出"。
  而这一页最显眼的主按钮是「进入高级调试」（`help.ts:117`），会带用户进一个看不懂、还会暂停工作区的界面。
- 「复制诊断信息」复制出来的文本没有地方可去：发行件里没有任何联系方式或反馈入口。
- 发行说明让人去改"数据根下 `config/config.yaml`"（`发行说明.md:17`）——实测全新安装数据根里只有
  `backups/data/examples/logs`，程序自己在向导里写着"还没有配置文件：保存设置时会创建"。
- 发行说明没有提：使用 AI 需要注册与付费；点窗口 × 只是收进托盘、要真正退出得走托盘菜单；卸载前要先退出。

**等待与连接**

- 30–120 秒的心理准备只写在 `README.md:22-26` / `发行说明.md:13-17`；`desktop/src` 全目录搜"卡死/慢一拍/30–120"零命中。
- 等待态无时长、无计时、无进度、无取消；8 秒后改为"结果待确认"并劝重发（见走查第 6 步）。
- `buildClient` 未挂 `onClose`（`api.ts:756-760`），断线后界面仍写「已连接，可以开始联络」（`contact.ts:255`），
  也不重连——旧调试壳反而有这套（`desktop/src/main.ts:436,461-492`）。
- 发送闸只看"有没有选中角色/有没有连接"（`contact.ts:823`），连接失败后 `this.link` 不清空。

**写作与跑团**

- 弹窗按钮一律「先关窗、再执行」（`dom.ts:207-209`），失败提示写在已被移除的节点里——
  「决定」不写理由点「记下这个决定」，弹窗消失、页面毫无变化，用户以为记下了（两工作区共 14 处）。
- 「开始战役」承诺同时启动时间线，但首个战役时条件恒为假（`trpg.ts:807`：`campaigns[0]` 为 `undefined`），

## 五、轻微问题（P2，打磨）

- **标点不统一**：实测界面同时存在半角与全角逗号/冒号——"第一步:连接 AI"、"先看看样例,稍后再配置"、

  （`dom.ts:129-131` 用 `textContent` 渲染）。
- **弹窗无焦点陷阱、回车不提交**（`dom.ts:191-225`），只做了打开即聚焦与 Esc。
- **窄窗响应式失效**：媒体查询里写的是 grid 属性，容器却是 flex（`user.css:655-660` vs `817-849`）。
- **世界列表状态误报**：没有时间线的新世界会显示"已归档"，一条暂停一条归档会显示"全部暂停"（`worlds.ts:246`）。

- 「世界与素材」里"导入 / 从样例开始"是动作却做成了与"我的世界 / 世界设定 / 角色卡"同级的标签页。
- 联络页空态把主按钮给了最难的入口（"选择 / 创建世界"），"从样例世界开始"是次按钮。
- 角色一律称"她"（`writing.ts:795,814,822`），男性/无性别角色卡的作者会觉得提示不对。
- 条目列表最左边那个复选框没有任何文字或 `aria-label`，用户不知道它是"锁定"（`create.ts:797-801`）。

## 七、这个用户为了"开箱即用"必须自己知道的事（隐藏知识清单）

这份清单本身就是结论：**每一行都应该是产品告诉他的，现在是他在猜。**
