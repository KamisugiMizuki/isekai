# 首次使用、配置与错误恢复

> **已定稿 v1.0｜2026-09-22。实现状态：未实施。** 本文确定发行、首次配置、错误反馈、长任务和恢复的用户交互契约。与 [统一界面设计](USER_INTERFACE_DESIGN.md) 配套；后者规定工作区，本文规定进入应用和遇错后的处理。这里的安装流程与按钮仍待实现验证。

## 1. 交付目标与现状

普通用户只需会下载、安装、复制粘贴和选文件。README 把用户带到第一个可用任务；之后的操作由界面解释，不要求学习终端、JSON、世界内部标识或项目模块名。

当前 README 是开发入口：需要 Python 环境、依赖安装，以及桌面开发或构建命令。现有桌面程序启动时仍寻找仓库中的 Python 环境。**内嵌网页资源的桌面程序不等于包含核心运行环境的完整发行包。** 因此，新手可用性必须同时验收发行件、README 和 UI，不能只把现有按钮重新排版。

发行目标定为 Windows 10 22H2 / Windows 11 的 x64 桌面，单主窗口、本机单用户、远程 AI 服务、无云同步。它是首版需实测达到的支持范围，不是当前兼容性验证结果；其他架构、操作系统与手机端不在首版承诺内。

这是一份 README 改版契约，不是现阶段可照做的安装教程；本次不把尚未实现的按钮和下载步骤写进根 README 的运行说明。

## 3. 发行件与数据的最低条件

- 安装程序包含可运行的核心与前端；所需系统组件由安装程序检查、引导安装。用户不安装 Python、Node 或 Rust。
- 安装目录与用户数据分开。默认数据目录采用当前 Windows 用户可写的应用数据目录；首页不要求用户选路径。设置中可查看、打开目录，备份目标通过原生目录选择器选择。
- 首次启动即检查数据目录能否写入；失败停在启动修复页，给出具体目录与原因。不要先让用户填完设定，到保存时才发现无法写盘。
- 样例世界和角色卡随发行件提供；使用时复制成用户自己的材料，重复开始不会覆盖之前的世界。
- 更新保留用户数据，先检查兼容性。遇到不兼容的世界给出兼容版本或可信转换入口，不能静默重建为空世界。
- 卸载默认保留用户数据；删除数据须单独明确确认。重新安装不能作为清空数据的隐式入口。
- 重复启动唤起已有窗口。启动失败页仍能打开日志、查看数据位置和退出，不依赖核心先成功连接。

### 3.1 安装与目录定案

首版只提供一个面向普通用户的 Windows 安装程序，采用现有 Tauri 的安装路线；按当前用户安装，程序默认置于 Windows 当前用户的 Programs 目录下。核心解释器、依赖、前端、样例世界和样例规则随发行件配套提供；安装检查 WebView2 等依赖，缺失时引导官方安装，不能运行到空白页才报错。初次使用不需要管理员权限或下载大型本地模型。

用户数据根固定为 `%LOCALAPPDATA%\isekai`，程序和数据不得放在同一可覆盖目录。其下受管数据、素材、草稿、设置、日志各有明确位置，设置页显示真实解析后的路径并可打开。备份默认放在该数据根下的备份目录，用户可用目录选择器改为外部磁盘；提示“同盘备份不能防磁盘损坏”。不提供运行中直接改数据根的旋钮；换机器通过导出或备份恢复完成。

软件更新由用户下载并运行安装程序，首版不新建自动更新服务。升级先停止所属写入者，保留上个可用版本信息；数据格式变化须先有可恢复副本与兼容检查。新版打不开旧数据时停在诊断页，不创建空库顶替；旧程序也不得越过格式检查读取不兼容的新库。

卸载默认只删除程序，数据保留；数据删除另以明确名称、路径和确认呈现。安装器不自动启用外部规则或通道插件，内置样例除外。正式发行件不支持通过环境变量启用测试替身。

### 3.2 现有开发目录迁移

首次启动设置页提供“已有开发版数据”，用户用原生目录选择器选旧根；不扫描整盘寻找项目。步骤是检查格式与完整性、提示关闭旧程序、确认目标尚无用户资产（初始化的空库不算已有数据）、复制到暂存区、完整校验后启用。源目录始终保留，不直接移动或删除。

可迁移对象包括世界、会话、版本、规则状态、素材、作者草稿和对应非敏感偏好；API 密钥、通道凭据、进程锁与运行句柄不迁移。先保存并停止旧根的全部写入者，再取得一致副本；复制时发现源发生变化则拒绝启用并重新检查，不复制正在变动的单个数据库文件当作完整迁移。迁移后全部时间线先暂停，重新配置服务并绑定；不因复制耗时补算，不自动执行外部插件。规则版本需求保留，缺失依赖明确列出。目标已有正式数据时引导单世界导入或全量恢复，禁止合并数据库。

这些是后续发行阶段的义务；现有壳的进程监督、托盘、日志与设置持久化可复用，完整运行环境封装和迁移还需实现验证。

## 4. 首次设置向导

### 4.1 流程与退出

进入应用后的顺序：**本机检查 → 连接 AI → 选择第一件事 → 准备材料 → 开始使用**。每一步有标题、当前步骤、返回和继续；已填内容返回后保留。结束时不展示长篇功能教程。

用户可在 AI 配置页选择“稍后配置，先整理素材”。随后可导入、阅读本机已有记录、编辑设定草稿和大纲；AI 生成与新对话旁标“配置 AI 后可用”，点开直接回到设置中的缺失项。禁止用测试替身或固定回复伪装成已连通 AI。

下次启动有未完成向导时，首页显示“继续上次设置”，不强制用户反复从第一步开始。向导只保存选择、草稿和完成步骤；世界是否创建、设置是否生效仍以真实存储状态为准。

向导的步骤状态按真实结果计算，不以“目录里有任意文件”判断当前用户已配置好。状态表固定如下：

| 步骤 | 通过条件 | 返回 / 失败后行为 |
|---|---|---|
| 本机检查 | 核心版本可用、受管目录可写、单写入者确认、数据格式可读 | 保留在修复页，提供重新检查和诊断，不显示 AI 密钥错误 |
| 连接 AI | 当前编辑版本的能力测试通过且配置保存后生效；或用户明确稍后配置 | 失败不覆盖有效旧配置；跳过进入素材模式，不报“全部就绪” |
| 选择任务 | 用户选择联络、写作或跑团 | 返回不创建重复资产，不更改后台世界状态 |
| 准备材料 | 当前选定材料通过业务校验，用户确认实例 / 线与首个角色 | 缺哪一项就定位哪一项；已创建内容回到原对象继续 |
| 开始使用 | 目标对象真实可用，所属会话或战役读取成功 | 启动失败只重试失败步骤，输入草稿与创建结果保留 |

首次关闭向导可回首页，不丢已保存草稿；未发送密钥不作为普通草稿落盘。软件升级只展示新增必需步骤，不能重跑已完成向导或覆盖用户选项。

### 4.2 AI 连接页

```text
连接 AI

服务       [选择服务                     v]
            预置项填写发行时已验证的地址与推荐模型
            也可选择“其他兼容服务”
模型       [推荐模型                     v] [填写其他模型]
访问密钥   [••••••••••••••••••••••••••••••]
            [打开该服务的密钥管理说明]

将把生成所需的文字发送给你选择的服务。
测试只发送简短测试文字，不发送你的故事或聊天记录，可能产生少量用量。

[测试并保存]    [稍后配置，先整理素材]
[高级选项：服务地址、等待时间、单次输出长度、生成随机程度]
```

预置服务只是一组填写提示，不建立新的账号系统或在线服务市场。模型名称可手填，避免提供商无法列举模型时整条配置路径被卡住。预置地址与模型列表随发行件维护，不在本文写死未经当次测试的可用性承诺。

字段规则：

| 字段 | 交互 |
|---|---|
| 服务地址 | 预置服务自动带出；自定义服务展开填写。提示这是接口地址，不是聊天网页网址。格式错在字段旁指出 |
| 模型 | 预置推荐项；填写其他模型时说明名称从服务提供方取得，不替用户猜改拼写 |
| 密钥 | 默认隐藏，可粘贴；刚输入的值可临时显示。已保存密钥只显示“已设置”和允许的末尾片段，重新打开不读回全文 |
| 替换 / 清除密钥 | 编辑空白表示保持原值；清除是独立动作，提示新生成将停用。写失败保留旧配置 |
| 高级项 | 给单位、范围和默认值说明；默认折叠，普通路径无需调整。不要把内部参数直接堆在首页 |
| 记忆语义检索 | 首次设置不要求配置，默认基础文字检索；设置中可另配增强服务。未启用不标红、不称严重故障 |

“测试并保存”使用正在编辑的值验证，通过后一次保存该组配置并读取生效结果；失败不替换上一份能工作的配置。检查覆盖简短文本回复和最小结构化输出，分项展示；这些检查证明基础调用形态可用，不保证任意故事质量或大体量生成必然成功。

| 检查结果 | 保存与使用 |
|---|---|
| 文本与结构化均通过 | 保存并显示“基础能力已验证”，附测试时间、服务与模型；允许继续首次任务 |
| 只有文本通过 | 显示具体未通过项；推荐调整配置。未验证配置不能带绿色“就绪”，各任务按其能力要求启用 |
| 认证、网络或格式失败 | 保留编辑输入，旧配置继续生效；给定位与重试 |
| 测试通过但保存失败 | “连接可用，设置未保存”；继续按钮不将其算成完成，提供重新保存 |
| 用户明确跳过测试 | 展开的次要动作“保存未验证配置”；先确认替换范围，保存后标未验证，后续使用仍走正常错误处理 |

一个测试最多执行两类小请求，含内部重试的总调用上限为 4 次；不得生成世界或发送用户材料当作测试。默认沿现有 60 秒请求超时，总测试最多等待 120 秒；超时后停止新增请求，已在途结果记清，不以换身份无限重试。输出预算按被选模型的已验证预置值，结构化测试不得用一个注定截断的小预算误判服务。

测试结果只对同一服务地址、模型、密钥版本和相关输出参数有效；编辑后立即标“未验证”，旧测试回执不能覆盖新编辑版本。启用“保存未验证配置”不是绕过字段格式校验。

测试过程展示实际阶段，例如“检查地址 / 验证访问 / 检查回复格式 / 保存设置”。无法获知细阶段时，只显示“正在测试，已等待……”，不用动画假装某一步已经完成。网络测试失败时仍允许保留输入或退出；不强迫开通另一家服务。

保存设置时不打断已受理请求：当前请求沿开始时的配置完成，新请求使用新生效配置；页面显示生效时间。测试不临时切换整个核心的服务。凭据清除是显式动作，确认后只停用新调用，历史保留；普通空输入仍表示不更改。

关闭密钥表单清除未保存的密钥输入；保存后的密钥只在本机受保护设置中使用，不进入普通草稿、诊断、备份或示例文件。显示开关只作用于刚输入的值，离开输入后恢复隐藏。更改服务地址时拒绝包含内嵌用户名、密码或密钥参数的 URL，以免写入日志。

增强语义检索单独测试、单独保存；默认基础文字检索，既不复用聊天模型名充当嵌入模型，也不因增强服务失败禁用聊天。改模型后旧向量重建期间如实显示基础检索可用。

当前已有配置读写，以上临时测试、版本对应、生效保证、凭据清除与字段定位属于 U1 必须补齐的契约。

### 4.3 选择任务与准备材料

首页三个任务使用人话和结果说明：

- **与角色联络**：选一个世界和角色，和生活在其中的人对话。
- **辅助写作**：整理大纲，观察角色能知道的事，比较下一步方案并保存文字草稿。
- **进行跑团**：选规则与角色，声明行动，确认后得到裁定与后果。

任务选择不创建第三套“项目”数据。用户自己的世界、时间线、大纲与战役继续由各自模块管理，首页只是提供入口。

每条路径有明确就绪清单：

| 路径 | 开始前必须就绪 | 推荐第一步 |
|---|---|---|
| 联络 | 已确认的世界设定、角色、可运行时间线、可用 AI | 从灰潮纪样例开始，选一位角色 |
| 写作 | 世界、至少一个可用观察角色、大纲；需要 AI 建议时 AI 可用 | 选已有世界或样例，写下第一个故事目标 |
| 跑团 | 世界、角色与规则绑定、已安装兼容规则、初始场景 | 从经过验证的样例战役开始 |

灰潮纪目前有世界包与角色卡；**完整新手战役还需将样例规则、初始规则状态、角色绑定和场景组合并验证**。不能因为仓库里有一个规则示例，就在 UI 写“点击即可开团”。缺少材料时只显示真实可执行的创建或导入路径。

“开始运行并联络”等动作把最终确认与明确的启动意图放在同一个摘要页上。创建成功而启动失败时，显示“世界已创建，尚未运行”并返回该世界；重试启动不能再创建一个副本。

缺 AI 时，跑团仍允许用户手工填完整行动卡，由规则插件进行不依赖 AI 的规则裁定；需要 AI 解析的按钮提示配置服务。不得因“全局未配 AI”把所有本地功能一律关闭，也不承诺未知插件能离线工作。

## 5. 错误信息的共同格式

错误正文要让用户读懂四件事：**操作对象、直接原因、已经完成的部分、下一步**。错误留在发生处；影响整条时间线或整个应用时再加顶栏条幅。需要处理的错误不放在几秒后消失的通知里。

```text
AI 服务拒绝了这次连接
所选服务返回 401，通常是访问密钥无效或权限不足。
当前可用配置未被替换；这次测试没有创建故事内容。

[检查访问密钥]  [返回继续编辑]
[查看技术详情]  [复制诊断信息]
```

以上为设计文案示例，401 必须来自本次实际响应。不能在只收到“内部错误”时推断为密钥错误；也不能把所有 HTTP 429 一律解释成欠费。

| 层级 | 显示内容 | 原则 |
|---|---|---|
| 主信息 | 一句话说明什么没完成 | 使用“保存失败 / 等待回复 / 结果待确认”，避免只有“错误” |
| 影响说明 | 已保存、未保存、未生效或结果未知；指明对象 | 不能确认时写“尚未确认”，不得默认数据完整或默认失败 |
| 处理动作 | 一个推荐动作，必要时一个替代动作 | 直接定位字段、候选、规则或原任务，不只说“请检查配置” |
| 技术详情 | 模块、阶段、原始错误码、允许公开的原因、关联编号、发生时间、相关版本 | 脱敏；用于复现和查日志，不把正文变成堆栈 |

可修复的字段错误同时在页顶列出摘要，点一项定位并聚焦对应字段；例如“潮生 → 信息来源 → 所选来源已从世界设定移除”。底层只返回自由文本、无法精确定位时，先显示能确认的段与原始原因；字段路径作为待补契约，禁止前端臆猜后把焦点跳错。

普通用户不必复制内部标识。UI 显示名称，技术详情保留标识用于排错。未知状态要明确“当前版本无法识别此结果”，保留输入并停止危险写入，不猜成成功或可重试。

### 5.1 错误的最小返回信息

这是应用层的反馈契约，不要求创建新的错误服务。错误产生处提供：所属模块、目标身份、发生阶段、稳定原因码、安全短说明、是否可重试、已经完成的动作、尚未确认的动作、可定位的字段或条目，以及对应操作身份。可见层把身份翻为名称；原始错误码与允许公开的原因放详情。

完成范围只有“未开始 / 已受理 / 部分完成 / 已完成 / 结果未知”这些明确含义；不能收到内部异常就默认未写入。字段定位用稳定对象和字段，不解析中文错误句子猜位置。无法给出深层原因时显示“程序内部处理失败，已记录诊断编号”，不给用户一个编造的解决方案。

| 影响范围 | 呈现位置 | 关闭后的行为 |
|---|---|---|
| 字段输入 | 字段下方 + 页顶错误目录 | 修改并重检后清除，保留其他输入 |
| 单个任务 | 原任务的固定反馈卡 | 可折叠，未解决状态仍显示在原对象上 |
| 当前时间线 | 工作区顶栏 | 切其他线不带过去；回原线仍能处理 |
| 整个应用 | 全局启动 / 存储条幅 | 用户可看诊断和已有缓存，修复确认后才恢复写入 |

同一任务的重复轮询错误更新原反馈卡，不堆一串弹窗；成功提示留在对象的状态处。错误恢复后必须重新检查，不能靠手动关闭红条宣布就绪。

## 6. 常见问题与处理路径

| 情况 | 用户看到的判断 | 主动作与保留内容 |
|---|---|---|
| 核心无法启动 | “后台服务未启动”，附实际启动阶段 | 重启后台服务；仍失败可打开日志、复制诊断；不要求用户找进程或删锁文件 |
| 数据目录不可写 / 空间不足 | “无法保存到这个位置”，展示实际目录与已知原因 | 打开目录或重新检查；保留最近成功状态，不自动删除历史腾空间 |
| 未配置 AI | “还未连接 AI”，点名缺少的项 | 去连接 AI；保留当前输入，导入和编辑仍可用 |
| 401 / 403 | 服务拒绝访问，给出本次状态码 | 检查密钥、账号或模型权限；不无限重试 |
| 地址错误 / 模型不存在 | 指明服务地址或模型项，若服务未区分则如实保留两种可能 | 回到对应设置；不自动换模型 |
| 网络断开 / 超时 | “未在等待时间内得到结果”，说明本次是否可能已执行 | 测试可重试；写入操作先查询原结果；保留文本 |
| 429 / 服务端错误 | 服务暂不可用或被限流；原因不足不猜余额 | 按可重试信息稍后再试；账单问题引到所选服务，不把 Key 复制进报告 |
| 空回复 / 回复截断 / 格式不合要求 | “模型没有返回可用结果”，不是角色在故意沉默 | 保留已完成草稿，重试失败部分或调相应输出设置；内部重试仍计入预算 |
| 时间线暂停 | “世界已暂停，可阅读记录或编辑作者草稿；联络和行动需要恢复运行” | 明确“恢复运行”；查看与编辑本身不启动世界 |
| 世界正在补算 | “正在补齐离开期间的进展” | 读已完成记录或等待；时钟标明最后完成时刻，不冒充已到目标时刻 |
| 补算持续受限 | 解释当前速度超过处理能力或返回的实际原因 | 打开时间设置，降低速度或暂停；不猜精确完成时间 |
| AI 用量到达上限 | 指明本次受影响的是对话、建议还是后台任务 | 查看该世界 / 时间线的用量；按权限调上限或等重置，不以新任务身份绕过限额 |
| 消息已保存、显示 / 投递失败 | “回复已保存，尚未确认显示” | 重新获取或补送原回复；不重新生成一段不同内容 |
| 结果是否提交未知 | “操作结果待确认” | 查询原操作状态；确认前不显示“世界未改变”或再次扣资源 |
| 设定校验未通过 | 点名角色 / 条目 / 字段与违规关系 | 定位编辑；候选保留为草稿，正式设定不被坏值覆盖 |
| 候选过期 / 版本冲突 | “生成建议后，这条时间线已变化” | 重新读取并检查，再确认新候选；保留原文供参考，禁止写回旧世界 |
| 世界格式 / 规则版本不兼容 | 显示当前版本与所需版本 | 使用兼容版本或有损失说明的可信转换；先保留副本，不能一键忽略 |
| 规则插件未安装 / 失败 | 点名插件与运行阶段 | 安装已信任的匹配版本或查看诊断；原行动保留，不自动重新掷骰 |
| 等待玩家选择 | 这不是错误；明确“先处理这项选择” | 跳到对应选择卡，禁用的行动框旁解释原因 |
| 通知目标已被删除 / 恢复覆盖 | “这条提醒对应的记录已不在当前进度” | 返回世界列表；不偷换到其他角色，不启动暂停时间线 |
| 导入失败 / 同名冲突 | 文件类别、校验原因或实际冲突项 | 保留原文件和现有世界；改名或换件。大纲同标识冲突如实报告保留了本机哪份 |
| 备份部分成功 | 区分运行数据与素材草稿是否都保存成功 | 补做失败部分；不显示“完整备份成功”，保留此前完整备份 |
| 恢复失败 | 明确未开始、已恢复哪部分、或整体结果待核验 | 按实际阶段提供恢复前副本；不笼统承诺“现有数据完全没变” |

## 7. 重试、取消与长任务

“重试”不是通用按钮：

| 动作名称 | 实际含义 |
|---|---|
| 重新测试连接 | 再进行一次有用量的连接能力测试 |
| 重试生成 | 在允许的失败阶段重新调用模型，仍受预算限制 |
| 重新获取回复 | 获取已经保存的同一回复，不重新生成 |
| 查询提交结果 | 用原操作身份核对是否已成功，不重复提交另一份 |
| 重新裁定 | 用户明确要求重做随机裁定；说明可能产生不同结果 |
| 重新检查建议 | 根据当前世界重新评估，旧批准不自动套给变化后的内容 |

所有长任务至少显示目标对象、真实阶段（若可得）、已等待时间和退出后的行为。没有分段进度就不显示百分比。生成设定期间显示已完成的段落；某段失败只定位该段，不暗示整份已完成内容丢失。

本次界面基线只允许一个世界 / 角色设定生成任务同时运行；已有进度快照是共享状态，不能把它当多任务列表。用户可切页，状态入口可回到原任务；同类新任务按钮解释正在忙什么。其他独立工作是否可用由各自状态决定。

“停止等待”仅停止本地等待时，必须说明服务可能仍在处理、用量可能已产生；不能写“已取消调用”。能取消且收到取消确认才写“已取消”。关闭工作区先处理未保存输入；退出整个程序时明确哪些任务将中断。重开后从已持久化结果继续，没有结果查询能力的步骤要作为实现缺口，不能用重新运行冒充续作。

从设置修复错误后，“返回原任务”恢复原上下文与输入，由用户决定继续；不自动重新发消息、重新掷骰或应用世界变化。

### 7.1 请求身份与重复操作

请求发出前先持久保留其身份、目标与输入版本，受理后关联核心回执；这属于现有操作的恢复记录，不建立新的通用任务队列。创建、导入、授权、应用变化和规则提交都必须能核对原结果；客户端双击保护不能代替核心幂等保证。

| 中断点 | 界面下一步 |
|---|---|
| 确认未发出 | 原文仍在，可编辑后提交 |
| 请求已发出、受理未知 | 显示“正在确认是否受理”，查询原身份；不分配新身份重做 |
| 已受理、仍处理中 | 回到原任务观察状态，不自动再调模型或规则 |
| 已知失败且无写入 | 按该阶段允许动作显式重试；继续使用原任务关联 |
| 已写入、回执丢失 | 读取真实结果并呈现完成；不重复应用变化 |
| 核心重启且任务中断 | 显示已保存部分与中断阶段；原结果存在则恢复，否则用户明确决定重做 |
| 目标被恢复 / 删除 | 旧请求终止或作废，原文可另存；不自动给新目标提交 |

确认页到最终提交之间再次校验当前状态，旧预览或过期批准不得被复用。结果未知只锁定同一任务及会冲突的写入，其他世界和独立草稿仍可使用。

### 7.2 等待、离页与退出

任务栏只在有运行或未解决任务时出现，显示当前任务名称和目标，点击回原位置；没有需要处理内容时不建立常驻仪表盘。设定生成全局一次一个，正文编辑与其他对象只读操作可继续。进度只显示实际阶段与已完成段数，不显示猜测剩余时间。

默认反馈节奏：请求发出立即显示受理中；等待超过 15 秒追加“仍在等待此步骤”，超过 60 秒展开该模块等待说明与诊断入口。这两处只是界面提示阈值，不改变底层超时、睡眠期节拍或重试规则，也不推断角色的生活状态。

关闭主窗口到托盘不打断任务；显式退出才停止接收新工作并进入保存流程。退出前立即保存编辑副本，等待当前正在提交的数据完成或得到可恢复的中断状态。30 秒后仍未退出时给“继续等待 / 查看诊断 / 强制退出”；强制退出说明可能中断尚未保存的工作，不声称安全成功。它只处理应用所属进程，不杀其他占用端口的程序。

存储不可写且仍有未保存文字时，退出页优先提供复制或保存到用户选择的文件；只有用户明确“放弃未保存内容并退出”才继续。数据已正常保存、只是新备份失败时允许退出，但说明最后完整备份时间；备份失败不等于所有日常数据都丢了。

## 8. 帮助与诊断

“帮助与诊断”是永久可找到的入口，核心未就绪时也可打开。首屏按当前问题给出：应用是否启动、数据是否可写、AI 配置是否经过验证、当前时间线状态、插件兼容结果。没测过就标“未检查”，不凭字段非空报正常。

页面提供“连接说明”“最近一次失败”“复制诊断信息”“打开日志目录”“查看数据位置”。常见问题按用户看到的错误名称检索；没有自动代用户发消息、上传日志或重置世界的按钮。

复制诊断采用允许清单：应用 / 数据格式 / 规则 / 插件版本，模块与阶段，错误码，关联编号，现实时间，脱敏后的服务标识和任务结果状态。默认不包含密钥、访问令牌、完整本机用户名路径、请求 / 响应正文、聊天、记忆、世界秘密或 AI 提示词。复制前可预览；本机完整路径只在“在电脑上查看”中显示。

原始日志在本机打开，不承诺“原始日志一定不含敏感内容”；统一诊断材料必须单独按允许清单构造。当前错误有些只给通用内部错误，必要的关联信息要在产生错误处补齐，不能靠 UI 反向推断。

帮助页的检查不自动调用外部 AI。“重新检查本机”只读本机状态，“测试 AI”遵循配置页的有限请求与说明；用户不需要承担每次打开帮助的调用开销。最近错误只展示脱敏摘要，按原操作聚合；不把每次状态轮询保存成新的失败。

复制诊断默认包含最近一次相关错误及同操作的阶段记录，最多附最近 20 条安全摘要。日志目录可供用户自行查看原始文件，但“复制诊断”永不打包日志全文。路径展示与复制分别处理：本机按钮可打开完整路径，对外复制用占位后的路径类别与错误位置。

## 9. 备份、导出与恢复

| 用户动作 | 范围与放置位置 | 必须说清 |
|---|---|---|
| 导出这个世界 | 世界详情 / 版本页 | 携带该世界、时间线和引用到的创作资产；导入产生独立副本，不同步、不合并 |
| 导出文字草稿 | 写作工作区 | 导出用户选定文字，不等于保存世界进度；默认不夹带观察依据和幕后材料 |
| 备份全部数据 | 设置 → 数据与备份 | 包括运行数据、受管素材与草稿；凭据不随备份传播 |
| 恢复全部数据 | 同上，危险操作区 | 替换当前受管数据，和“导入一个世界”不同；先完整校验并保留恢复前副本 |
| 恢复一个版本 | 当前世界 → 版本 | 覆盖当前时间线的后续进展，保留恢复前运行 / 暂停状态；先保留当前分支或导出 |

### 9.1 备份记录、范围与默认策略

首版仍复用现有数据库与素材归档能力，但用户搬运单位定为一份备份文件（ZIP 容器，名称含时间）。容器包含配套运行数据、受管素材、设定草稿、写作资产、恢复所需非敏感偏好和完整性清单；每部分有版本与完整性校验，打包期间取得同一份一致读视图，不能混入不同保存时点的素材。读取压缩包仍需检查总大小、展开大小与路径边界；坏件不得先解包进受管目录。备份中不放 API 密钥、通道凭据、绝对设备路径、日志、缓存或可执行插件，规则只保留版本需求。旧数据库 + 配对素材文件仅经“导入旧备份”识别，缺件不伪装成完整备份。

默认备份间隔 24 小时，运行期间定期检查，保留最近 7 份完整自动备份；启动和退出补做到期检查。手动备份不会悄悄绕过空间错误：先验证所有部分成功，再发布为完整记录，再轮换旧自动备份；手动创建或另存的完整备份不参与自动轮换，用户在列表明确删除。UI 允许修改检查间隔和保留数，关闭自动备份不关闭日常保存。

备份列表显示时间、大小、完整 / 不完整 / 不兼容、所含范围和最近校验结果。缺素材、写入失败或摘要不符都不显示完整成功；不完整件不参与“最近成功备份”时间，不触发删除上一份完整备份。复制到其他位置后重新检查目标文件，才能显示“已复制完整备份”。

### 9.2 全量恢复的执行顺序

```text
选择备份 → 验证全套与兼容性 → 暂存并验证恢复内容
  → 展示替换范围 → 用户确认“保留当前数据并恢复”
  → 停止全部写入、保存草稿并处理在途操作 → 保存恢复前完整副本
  → 作废旧任务与连接 → 切换受管数据 → 重新打开并校验
  → 所有时间线暂停
```

预检和暂存阶段不改变现有数据，用户可取消。最终确认后先停止所有写入者，再保存最新的恢复前副本，避免用户在预检期间新增的进展丢失；若有未决提交，先查清或记录为可恢复中断再继续。副本失败则阻止切换，释放临时写入保护并保持原数据，不提供“略过备份仍恢复”的普通入口。开始切换后只显示进度和真实结果，不再提供会造成半套数据的取消操作。

一致性保护由核心承担：数据库、素材与受管草稿要作为同一恢复单元激活；不能先替换库再清空素材目录后任其失败。无需引入通用事务框架，但必须有暂存校验、切换记录和回退到恢复前完整单元的路径。切换中断后，启动先完成恢复判定，不并行启动世界推进。

| 失败位置 | 必须给出的结果 |
|---|---|
| 预检 / 暂存失败 | 当前数据未替换；指出坏件或不兼容部分，允许换件 |
| 恢复前副本失败 | 未开始覆盖；先处理空间或权限 |
| 切换后打开失败 | 自动回退到恢复前完整单元并核验，说明已回退；回退未确认则停止写入，提示恢复状态待处理 |
| 核心退出 / 系统中断 | 下次启动根据恢复记录继续判定或回退；不能出现数据库来自新件、素材仍来自旧件的正常运行态 |
| 恢复成功但缺 AI / 规则 | 数据恢复成功、所有线暂停；逐项引导重新配置和安装，不标整个恢复失败 |

恢复成功清空旧视角缓存、旧令牌和在途确认，重新读取列表；凭据若本机已有则仍用本机设置，不从备份覆写。用户明确恢复运行后才继续，不补算备份运送期间、不批量重发旧消息。实例导入、单线恢复和全量恢复的范围始终分别命名。

现有备份的素材归档失败可能只记日志，恢复也分开处理数据库与素材；本节单文件完整性、全套暂存切换与失败回退是 U2 的必做补强，当前尚未实现。

## 10. 首次使用与排错验收

这些是正式交付门槛，当前未执行新界面可用性测试。所有失败场景都使用隔离数据注入，不拿用户真实世界做破坏性验收：

1. 没有开发环境的 Windows 账户，仅按 README 能安装、启动、配置并进入样例世界；不要求输入内部标识或命令。
2. 不配置 AI 也能整理素材和保存草稿；点击需 AI 的动作能定位配置，返回后原文仍在。
3. 故意输错密钥、模型和服务地址时，提示包含实际失败项与可操作入口；有效旧配置不被测试失败覆盖。
4. 首次创建重复点击、创建后启动失败再重试，都只保留一个明确的创建结果。
5. 生成失败、网络超时和已提交但回执丢失三种情况分别处理；后者不得生成重复事实、回复或规则扣费。
6. 向量服务未配置或失败时仍能正常联络；用量达到上限时不以刷新或重试绕开。
7. 不可写目录、素材备份失败、坏备份和恢复中断均给出真实完成范围；不删除原数据或最后完整备份来“修复”。恢复前“已保留进展”必须有实际保存结果，不能只靠勾选框。
8. 技术详情、诊断复制与玩家公开面无密钥、提示词或隐藏剧情；错误名称可在帮助中找到同名处理条目。
9. 退出到托盘、彻底退出、暂停世界三者的后果清楚；再次启动不把补算误报为数据丢失。
10. 按 [统一界面设计 §12](USER_INTERFACE_DESIGN.md) 的新手试用任务，只给 README 与任务，不口头指导；记录阻碍与状态理解，自动化通过不能替代这一步。
