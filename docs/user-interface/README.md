# 用户界面设计定案

> **已定稿 v1.0｜2026-09-22。实现状态：U1 已实施；U2 已实施（时间线管理 / 尝试世界变化 / 单文件全量备份 / 创建向导含角色卡起草 / 开发目录迁移）；**U3 已实施**（辅助写作工作区 + §11.1 写作侧六条边界 + 正文锁定），已知边界见实施进度表；U4–U5 未实施。** 本目录是 isekai 正式桌面入口的交互设计依据。三份文档已经收口为可实施的产品决策；逐阶段的真实完成状态与证据见文末「实施进度」，设计条目本身不因实现进度改写。

目标：不熟 AI 和电脑的用户，能按项目 README 完成准备与配置，再凭界面完成联络、写作和跑团；遇到问题能知道发生处、实际完成范围与下一步。实现不要求用户操作命令行、填写 JSON 或复制内部标识。

## 定案决策

| 领域 | v1.0 决定 | 用户得到的结果 |
|---|---|---|
| 平台与宿主 | Windows 10 22H2 / Windows 11 x64；现有 Tauri 桌面工程、单窗口、本机单用户 | 一个安装程序打开整个项目，不另建三个应用 |
| 首页 | 首启首页，提供联络、写作、跑团；已有内容显示“继续上次” | 先选想做的事，缺材料时在任务里补齐 |
| 导航 | 首页、角色联络、辅助写作、跑团、世界与素材；底部设置与帮助 | 日常任务和全局设置位置固定 |
| 调试入口 | Core Debugging 进入帮助的高级调试；生成器和设置只保留一份正式入口 | 普通用户不必经过调试管理台 |
| 首次配置 | 先本机检查，再测试 AI；失败保留旧有效配置，允许稍后配置 | 能辨认配置在哪一步失败；无 AI 仍可编辑本机内容 |
| 样例 | 灰潮纪与两位角色；跑团采用灰潮纪与潮汐骰池，整套组合须随发行验收 | 有一条无需手工拼装文件的首次成功路径 |
| 创作 | 参数折叠但能力保留，条目表单可编辑、增删、复制、锁定 | 新手不用 JSON，创作者仍能详细调整 |
| 保存 | 自动保存编辑副本；发送、正式确认、世界应用分别操作 | “已保存草稿”不被误解为已改变世界 |
| 联络 | 完整回复，系统状态不冒充角色发言；转交需用户打开目标流程 | 改世界、版本、掷骰不会在聊天里假执行 |
| 转述 | 按完整消息授权，确认前显示全文 | 分享范围可核对，不用截短摘要代替实际授权 |
| 写作 | 大纲、合法素材、候选比较、文字编辑、锁定、Markdown / 纯文本导出 | 建议可变成用户保存的正文，世界变化另行预览提交 |
| 跑团 | 辅助裁定；玩家确认行动一次，合法结果自动联合提交；主持待审独立 | 不重复批准同一行动，也不自动重掷失败结果 |
| 世界与时间 | 选中不等于运行，退出不等于暂停，暂停战役不等于暂停世界 | 能预判切页、托盘、退出和回访的后果 |
| 版本恢复 | 默认保留当前进展再恢复；保存失败停止覆盖 | 有真正可找回的副本，不靠“我已保存”勾选框 |
| 出错 | 就地反馈 + 精确定位 + 完成范围 + 原任务恢复；结果未知先查原操作 | 修完能回原任务，不以重复发送掩盖超时 |
| 全量备份 | 单文件搬运、全套预检、暂存切换、失败回退 | 备份完整性可核对，恢复不留下半套数据 |
| 外观与可访问性 | 黑白系统风格、名称化控件、固定字级、键盘与放大可用 | 能看懂、找得到、操作后有清楚反馈 |

本版没有保留待拍板的产品默认项。函数形状、文件拆分和打包细节由实现者遵循现有结构完成，不另写一套框架；如果需要改变以上用户行为，应修订本规范而非静默改实现。

## 范围与边界

包含从发行安装到日常使用、错误恢复的完整桌面体验；三个任务共享世界事实和持久化基础，各自保留输入语义、受众与状态。首版只同时执行一个世界 / 角色设定生成任务，正文使用简单文字编辑，新手规则路径先覆盖经过验证的样例组合。

不包含云同步、联网房间、多人账号、世界线合并、全规则书导入、通用战斗面板、自动出版或完整 AI 主持。这里不新增通用 UI 插件框架、任务服务、文档引擎或第二套世界 / 行动状态机。正式入口没有完成时不摆可点击的空壳占位。

数据默认落在当前用户的应用数据目录，升级和卸载不清空用户世界；现有开发目录通过明确迁移入口复制并检查。模型调用可能把所需文本发送到用户配置的服务，本机存储与无云同步不等于全部计算离线。

## 实施与发布顺序

| 阶段 | 完整任务 | 主要前置与退出条件 |
|---|---|---|
| U1 启动与联络 | 安装 → 配置测试 → 样例 → 真实联络 → 错误修复 | 就绪检查、操作身份、草稿保护、单写入者和打包就绪；CLI 与桌面都能真实往返 |
| U2 创作与保存 | 创建自己的世界 → 时间线 / 版本 → 安全备份与恢复 | 结构化编辑、引用校验、锁定、完整恢复与中断保证；不要求用户手改文件 |
| U3 辅助写作 | 大纲 → 观察 → 建议 → 文字草稿 → 导出 / 显式世界应用 | 先修受众泄漏、覆盖已采用产物、状态冒充提交及重绑重置，再接对应 UI |
| U4 跑团 | 样例 / 新建 → 确认行动 → 规则 → 联合提交 → 选择 / 恢复 | 规则独立登记、有效初始化、友好名称、版本阻断恢复；插件必须真实执行 |
| U5 总体验收 | 三条路径、迁移、更新、恢复、无障碍与新手试用 | 每条行为验收有证据，已知阻断缺口清零，README 与实际发行件一致 |

U1–U4 是内部可验收增量，不等于全产品已达到普通用户发布条件；正式发布以 U5 为门槛。受众泄漏、数据损坏或“成功但未生效”不能列为可带病发布的小限制。若只发布某条路径，必须明确命名其范围并重做对应发布验收，不宣称三个工作区全部完成。

## 当前实现依据与待补账

现有桌面是核心调试与管理入口，三个应用层有核心语义与 CLI，尚未接入这套统一 UI。此前定向测试为 54 项通过，随后反例复核发现写作受众泄漏、重复提案覆盖、提交状态失真等未覆盖问题；这些已归入总设计第 11 节的阶段义务，不能因测试数量为绿而忽略。

本次深化与定案只修改设计文档。没有运行新界面、没有新发行件安装结果、没有真实 AI 可用性或新手试用结果。实现阶段按 [总设计的行为验收](USER_INTERFACE_DESIGN.md) 和 [首次使用验收](ONBOARDING_AND_RECOVERY.md) 实跑，设计状态与实现状态分别维护。
