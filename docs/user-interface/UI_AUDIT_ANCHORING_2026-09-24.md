# 界面审核：空间恒常性与操作锚定（2026-09-24）

原则原文见 `ui-design-audit` 技能第 16 条 / 第 30 条：**关键操作元素必须锚在稳定位置**，内容增长只能发生在独立滚动容器里，不能推挤操作区；先问「到底是谁在滚动」。本文件是按这条原则对 isekai 桌面端（正式界面 `desktop/src/user/`）的实测审核。

## 一、整体结论

- **外壳层合格**：顶栏（返回 / 首页 / 状态 / ⋯ 菜单）、⋯ 菜单浮层、启动器、对话弹窗都在滚动容器之外或 `position: fixed`，没有「整页滚动承载无限内容」的设计。
- **联络页不合格（P0，已修）**：结构本来是对的（`.u-messages` 独立滚动 + `.u-composer` 在列尾），但**高度链没接上**，等于整页滚动 + 输入框跟着消息跑。
- **弹窗不合格（P1，已修）**：标题、正文、按钮同在一个滚动体里，内容一长按钮就滚走。
- **列表页工具栏未锚定（P1，待定）**：世界与素材 / 写作 / 跑团的分栏条与工具行都在滚动内容里，长列表时会滚出视口。
- **合格项**：`有新消息 ↓` 不抢滚动、`加载更早的记录` 保持滚动锚点、错误/说明卡不再与消息列表抢高度。

## 二、问题清单

| # | 位置 | 问题 | 影响 | 严重度 | 处置 |
|---|---|---|---|---|---|
| 1 | 联络页 | 输入框随消息下移：1 轮往返后就出视口（底边 832 > 视口 720），9 轮时 910 | 要滚动很久才能打字；键盘/肌肉记忆全失效 | **P0** | 已修：`.u-pane` 给确定高度（`.u-pane{height:100%;min-height:0}`） |
| 2 | 联络页 | 修了 1 之后暴露出第二层：三栏容器行高仍按内容收缩，中间列没有余量，消息列表被 flex 压成 8px（对话被裁掉，输入框虽然不动但看不见内容） | 内容区不可见 | **P0** | 已修：`.u-contact` 由 grid 改 flex（`flex:0 0 240px / 1 1 auto / 0 0 300px`），列高由 stretch 决定，不再依赖百分比行高 |
| 3 | 联络页 | 系统卡（说明 / 失败卡）曾是列里的兄弟节点，`max-height:30vh` 且与消息列表争高度：卡片一长就把列表挤到 8px | 长对话时内容区被挤没 | **P0** | 已修：`.u-system` 移入 `.u-messages`（卡片属于对话内容，跟着滚）；`appendSystem` 在底部时跟随滚动 |

| 5 | 世界与素材（同样适用于写作 / 跑团的分区条） | 分栏条 / 工具行在滚动内容里，列表一长就滚出视口 | 切分区要滚回顶部 | **P1** | **待定**：给分栏条加一个类名（如 `u-toolbar`）后 `position:sticky; top:0`；涉及分区条样式，等确认 |

## 三、实测证据（真壳 + 假模型 + 临时数据根）

探针：`scripts/_probe_ui_anchor.py`（窗口 1350×937、视口高 720）。

**对照（去掉 `.u-pane` 高度那一行）** —— 探针会红，读数：

| 读数 | 0 条 | 1 轮 | 9 轮 |
|---|---|---|---|
| 输入框底边 | 533 | **832** | **910** |
| 消息列表 clientHeight | 8 | 8 | 8 |
| `#u-main` scrollTop/scrollHeight/clientHeight | 0 / 711 / 663 | 0 / 1010 / 663 | 0 / 1165 / 663 |

即：滚动发生在**页面容器**（scrollHeight 一路涨到 1165），列表从不滚动，输入框被一路推下去。

**修好之后**：

| 读数 | 0 条 | 1 轮 | 9 轮 |
|---|---|---|---|
| 输入框底边 | 688 | 688 | 688 |
| 消息列表 clientHeight | 175 | 175 | 175 |
| 消息列表 scrollTop/scrollHeight | 0 / 175 | 0 / 175 | 815 / 990 |
| `#u-main` scrollTop | 0 | 0 | 0 |

即：操作区三次读数一致（688）、内容区自己滚（815/990）、页面容器不再滚。

行为项：停在历史里来新消息 → `有新消息 ↓` 出现且**没有**被强制拉到底（scrollTop 76.8 保持在历史处）；点它才回到底部。

## 四、怎么复核

```bash
# 单跑空间恒常性探针（约 1 分钟）
.venv/Scripts/python.exe scripts/_probe_ui_anchor.py
# 回归：界面五支
.venv/Scripts/python.exe scripts/_probe_ui_u1.py   # 首次设置 → 联络 → 草稿
.venv/Scripts/python.exe scripts/_probe_ui_nav.py  # 导航与高亮
.venv/Scripts/python.exe scripts/_probe_ui_u2.py   # 世界与素材
.venv/Scripts/python.exe scripts/_probe_ui_u3.py   # 辅助写作
.venv/Scripts/python.exe scripts/_probe_ui_u4.py   # 跑团
```

探针断言：输入框底边在 0/1/9 轮三次读数一致且在视口内；消息列表成为滚动容器且不被压扁；`#u-main` scrollTop 恒为 0；新消息到达时列表停在底部；停在历史里时给提示且不抢滚动；点提示回到底部。
