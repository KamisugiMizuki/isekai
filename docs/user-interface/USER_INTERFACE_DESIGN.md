# isekai 统一人机交互界面设计

> **已定稿 v1.0｜2026-09-22。实现状态：未实施。** 面向首次接触 AI 应用、也不熟电脑操作的用户。本文确定正式桌面产品的页面、默认行为与交互验收；定稿不代表新界面或底层补强已经完成。
>
> 配套：[首次使用、配置与错误恢复](ONBOARDING_AND_RECOVERY.md)。既有应用层 SPEC 继续负责业务语义，本文负责入口、页面、用户动作和反馈；冲突或需要补能力的地方在末尾显式列账。

## 1. 要解决的问题与设计结论

当前有可运行的 Core Debugging 桌面壳，能聊天、创作设定、管理世界和设置；OC 故事层、Writing Assistant 与 TRPG 客户端层已有核心操作和 CLI，但现有壳没有消费这三个应用层的用户入口。它还把大量管理概念放在同一页，部分复杂编辑要求填写 JSON，启动仍依赖开发环境。

所以目标不只是“再加两个标签页”，而是让用户能走完：**拿到软件 → 配置可用 → 选自己要做的事 → 完成任务 → 看懂状态 → 出错后继续**。

本规范采用以下方案，后续实现不得再自行选择另一套默认行为：

1. **一个桌面程序、一个主窗口、三个任务工作区。** 对外叫“角色联络”“辅助写作”“跑团”；复用现有 Tauri 外壳、核心监督和连接语义，各工作区消费自己的应用层。
2. **首页按用途导航，世界与素材集中管理。** 不让用户先学习 UMP、实例、提交、认知投影才能开始；名称仍能在需要时对应到原项目概念。
3. **简单起步，完整编辑。** 首次路径用样例和合理默认值；世界、角色、大纲都可在主窗口完整展开修改，保留参数调节、条目编辑和锁定能力。
4. **把保存、批准、世界生效分开表达。** 当前视角、对象、状态与下一步始终可见；没有成功回执不显示“完成”。
5. **错误信息能定位和带回原任务。** 操作失败时说清发生处、已完成范围与恢复动作，技术详情可展开；具体规则见配套文档。

设计基线是 Windows 桌面、本机单用户。继续在现有桌面工程中使用 Tauri 与现有前端技术；不新建独立客户端仓库或替换框架。历史“本期不建应用层壳”作为已完成内核阶段的范围记录保留；后续用户界面阶段按本文实施。本次只定案设计。

## 2. 用户理解的对象与用词

| 界面用词 | 用户可以怎样理解 | 对应概念与限制 |
|---|---|---|
| 世界设定 | 创建世界用的底稿 | 世界包；修改底稿只影响以后创建的世界 |
| 角色卡 | 角色的初始设定 | 创建或加入前可修改，已进入世界的原卡不随模板改动 |
| 我的世界 | 一个已经创建、会保存进展的世界 | 世界实例；不另造“项目”实体 |
| 时间线 | 同一世界的一条独立发展路线 | 首条默认叫“主线”，可以另开分支；各线不合并 |
| 运行 / 暂停 | 世界时间是否继续前进 | 激活 / 冻结；暂停不等于退出程序 |
| 版本记录 | 可回到的进度点 | 提交；界面不要求懂 Git，也不展示内部快照 |
| 保存版本 | 给当前世界进度留一个点 | 手动提交；不是整份外部备份 |
| 另开分支 | 从一个版本开始另一条发展路线 | 分叉，新线先暂停，原线保留 |
| 恢复到此版本 | 把当前时间线回到旧进度 | 回滚，覆盖后续进展，须先解释范围 |
| 转述给另一位角色 | 明确把这段对话告诉谁 | 披露，首版按选定的整条消息授权，不能单独撤回 |
| 大纲目标 | 想让故事满足的约束或方向 | 大纲条目，不是已经发生的世界事实 |
| 建议 / 文字草稿 | 可选择、编辑或放弃的创作材料 | 候选未应用前不改变世界 |
| 应用到世界 | 确认让合法变化实际生效 | 预览后经现有提交路径完成；不是“保存文字” |
| 战役 / 行动 | 使用某套规则开展的游玩过程 / 一次声明 | 由规则插件和战役层处理，不借用普通聊天当行动 |

技术术语允许出现在帮助的“术语对照”与诊断详情中；不把 API 名、文件路径或标识作为用户必须填写的普通字段。内部标识由系统维护，同名对象通过所属世界、角色类型等消歧。

## 3. 信息架构与跨页面上下文

### 3.1 导航

```text
isekai
├─ 首页                       最近使用、未完成草稿、三个任务入口
├─ 角色联络                   角色列表 → 对话 → 已讲过的线索 / 转述
├─ 辅助写作                   大纲 → 当前素材 → 推进建议 → 文字草稿
├─ 跑团                       战役 → 当前场景 → 行动 / 选择 → 结果
├─ 世界与素材                 我的世界 / 世界设定 / 角色卡 / 设定草稿
│  ├─ 选中世界                详情、运行与暂停、时间线与版本、导入导出
│  └─ 新建 / 编辑素材         主窗口内创作工作区
├─ 设置                       AI、增强检索、默认保存与备份、通知与外观
└─ 帮助与诊断                 操作帮助、当前问题、诊断、日志、高级调试
```

首页与三个任务入口的顺序固定，不因是否用过自动重排。不使用只有图标的导航。世界级操作放在世界详情，工作区自身的生成、导入、导出和编辑放在对应工作区；设置只承载全局偏好。

Core Debugging 从“帮助与诊断 → 高级调试”进入，保留连接、运行与管理验证能力，不作为新用户默认首页。已有生成器移入素材工作区，设置只留一份入口，避免复制一套管理台表单。高级调试不提供普通工作区禁止的世界内部浏览或权限绕过。全部页面复用同一核心与数据身份。

### 3.2 页面骨架

```text
┌ isekai ─────────────────────────────────────────────────────────┐
│ 首页         │ 角色联络  /  灰潮纪 · 我的世界  /  主线             │
│ 角色联络     │ 世界：运行中 · 已完成的世界时刻          [世界管理] │
│ 辅助写作     ├──────────────────────────────────────────────────┤
│ 跑团         │ 当前任务的列表      │ 内容 / 编辑 / 对话             │
│ 世界与素材   │                     │                              │
│              │                     │ 当前对象与状态               │
│              │                     │ 本区主要操作                 │
│ 设置         ├──────────────────────────────────────────────────┤
│ 帮助与诊断   │ 保存 / 生成状态及需要处理的问题                    │
└─────────────────────────────────────────────────────────────────┘
```

布局共用导航、标题和反馈规则，不强行把写作与聊天做成同一种页面。编辑器给足中部空间，右侧依据面板可收起；窄窗口改成页内分区，主按钮和输入区始终可达。

### 3.3 上下文连续性

- 每个工作区分别记住最近的世界、时间线及角色 / 大纲 / 战役。进入某个入口不会静默继承另一工作区的写入目标。
- 顶栏显示本次操作将作用于哪里；写入确认再重复一次完整目标。切换对象后重读该对象状态，不把旧请求返回结果画到新对象下。
- 从联络转到写作、从跑团转到主持准备时，先展示目标与转入内容；只有用户确认才带入选定文本。返回能回到原位置和输入草稿。
- 未发送、未保存文本在本地按所属任务保留，标题显示“未保存 / 正在保存 / 已保存 / 保存失败”。这项 UI 草稿持久化必须补齐，不能把内存变量称作自动保存。
- 切换页面不暂停世界、不终止任务；暂停必须点明确动作。若原任务仍在运行，保留一个可返回的状态入口，不做新的任务调度系统。
- 某条线被阻断，只限制该线相关操作；核心或存储故障才显示全局阻断。错误弹层不遮住仍可查看的内容。

### 3.4 页面进入、切换与返回的定案

| 行为 | 确定规则 |
|---|---|
| 启动应用 | 先显示首页；有有效历史时首个主按钮为“继续上次”。不自动发送、不自动批准、不默认打开主持视图 |
| 打开工作区 | 顶栏固定为“任务 / 世界 / 时间线 / 当前对象”。世界与时间线均可按名称选择；对象不存在时清空选择并给补齐入口 |
| 最近使用 | 按最近打开排序，默认显示最近 5 项，更多进入各模块列表；只存名称、身份与访问时间，不生成故事摘要 |
| 切换同类对象 | 保留各自输入草稿、滚动位置和选择；接受结果前核对原目标与版本。旧对象仍运行的任务留在原对象下 |
| 跨工作区转交 | 点击转交卡才打开目标页，并显示带入的原文、来源和目标；只带入用户选中的内容，不复制另一角色的私密材料 |
| 返回 | 回到发起位置；自动保存成功无需弹框。失败时停在原页，提供“重试保存 / 复制未保存内容 / 放弃这次编辑” |
| 当前对象被删除或恢复覆盖 | 关闭写入入口，保留用户输入为“来源已失效的草稿”；可复制或另存，不自动贴到另一对象 |
| 切回玩家 / 联络视角 | 先保存作者草稿，再清除另一视角的派生内容并重新获取合法投影。清缓存不删除作者资产 |

### 3.5 三类保存与离开行为

“草稿已保存”“设定已确认”“世界变化已生效”是三个不同结果，不能共用一个绿色勾。

| 内容 | 自动保存什么 | 哪一步仍需明确操作 |
|---|---|---|
| 未发送联络 / 行动输入 | 当前对象下的原文与选择 | 发送、确认行动；保存草稿不等于已受理 |
| 世界 / 角色编辑 | 候选内容、参数、锁定与校验结果 | 确认设定；未过检查不覆盖正式材料 |
| 大纲编辑 | 未发布的编辑副本 | “保存大纲”，校验后更新定义并检查影响范围 |
| 正文草稿 | 未锁定的标题与文字 | 锁定正文、导出；保存正文不提交世界 |
| 已接收消息 / 已裁定行动 | 由所属应用层保存真实处理状态 | 重试或恢复按原操作身份执行，不作为新草稿重发 |
| 设置 | 不自动保存密钥和配置编辑 | “测试并保存”或明确的“保存未验证配置” |

草稿在停止输入 1 秒后保存；连续输入时最多间隔 5 秒保存一次。Ctrl+S、离开字段编辑区、切页和退出都触发一次立即保存。只有存储确认成功才显示“已保存”及时间；写入过程中继续编辑时，旧回执不能把新内容标成已保存。草稿失败保留当前内容，允许复制或另存文件，不声称崩溃后可恢复尚未落盘的字。

恢复草稿放在原任务与首页“未完成内容”两处同源展示。每个对象只保留当前编辑副本，不建设编辑历史树；系统重生成或用户选择新方案前可保留一份上一版供比较。正式世界版本与外部备份分别由版本页、设置页负责。

### 3.6 就绪状态与可操作范围

下表描述当前所选对象；其他世界的正常工作不因这一行被阻断。新写入在执行时仍由核心检查，不能只凭按钮启用状态放行。

| 状态 | 已保存内容 | 草稿编辑 | 读取当前世界素材 / 新生成 | 改变世界 |
|---|---|---|---|---|
| 核心、存储、目标都就绪 | 可读 | 可编辑、可保存 | 按所选 AI 与模块能力开放 | 按预览和确认规则开放 |
| AI 未配或失败 | 可读 | 可编辑、可保存 | 只读世界素材可用；需要 AI 的生成停用 | 无 AI 的合法确定性操作可用，不伪造 AI 输出 |
| 时间线暂停 | 可读 | 作者资产可编辑、可保存 | 旧素材标“历史参考”；不发新联络、当前素材建议或新裁定 | 只开放启动、版本等明确管理动作 |
| 时间线补算中 | 可读已完成记录 | 可编辑、可保存 | 等待业务就绪，不拿目标时刻生成当前内容 | 不提交依赖当前世界的变化；可按管理返回降低速度或暂停 |
| 时间线归档 / 版本不兼容 | 核心允许范围内只读 | 作者已有文字可另存 | 不发起依赖该线的新生成 | 只开放明确返回的导出、分支或兼容处理 |
| 核心断开 / 存储不可写 | 已显示内容标为缓存，只供参考 | 保留内存输入，可复制；不报持久保存成功 | 停止新请求 | 停止全部写入 |
| 某次写入结果待确认 | 保留最后确认状态 | 可写另一个本地草稿 | 不重复发起相同任务 | 锁住同目标的后续冲突写入，先查询原结果 |

“补算中”取核心的业务状态，不让界面每秒比较现实钟和世界钟来回开关按钮。暂停与补算页面显示“停留在 / 已完成至”，不显示仍在跳动的当前时钟。设定创作属于独立作者资产，其生成不因另一条世界线暂停而被关掉。

## 4. 首页与第一次成功

无数据时，页面只表达三件事：软件能做什么、当前还缺什么、推荐下一步。连接 AI 未完成时显示“连接 AI”，同时保留“先整理素材”。就绪后推荐“从样例世界开始”，旁边有“创建自己的世界”和“导入已有内容”。

从样例开始的摘要页只给公开简介、角色名称与身份，不展示隐藏设定。用户选首位角色、确认世界名称，看到“创建后将以默认速度开始运行；退出后再次启动会补算，暂停则不会”，再点“创建并开始联络”。无需自己复制三个文件、查 ID 或手动绑定会话。

已有数据时，首页优先显示“继续上次”，附任务类型、世界和时间线；下面是最近使用及未完成草稿。没有新消息或故事时不编造动态摘要，不建立全局剧情看板。

进入写作或跑团但缺前置材料时，就在该路径展示所缺项与补齐按钮。新手无需退回管理台拼装；这些引导复用世界 / 角色创作流程，完成后返回原任务。

首次配置、发行包与 README 详细要求见 [配套文档](ONBOARDING_AND_RECOVERY.md)。

### 4.1 三条首次路径的落点

| 用户选择 | 默认材料与动作 | 第一次成功 |
|---|---|---|
| 与角色联络 | 灰潮纪样例、默认选堤禾，允许改选潮生；摘要页确认后创建并以 1 倍运行 | 用户消息被受理并出现真实固化回复；失败另验排错，不计作首次联络成功 |
| 辅助写作 | 选择已有世界或样例，填写一条主题或目标；大纲默认独立，观察角色由用户选择 | 大纲保存成功，能读合法素材并把建议整理为保存的文字草稿 |
| 进行跑团 | 灰潮纪 + 潮汐骰池的随发行验收首场景；默认一个活动玩家角色 | 用户确认一次行动，真实规则结果完成联合提交，能处理下一选择 |

以上样例内容名称只定义首版导览用途，不预写胜负、固定骰点或捏造已发生剧情。首页样例每次新建都是独立副本，名称冲突用核心返回的新名称；已有实例仅在用户点“继续”时打开。

### 4.2 空态与页面主动作

| 页面 | 无内容时的文案与主按钮 | 主按钮完成后 |
|---|---|---|
| 角色联络 | “先选一个世界和角色” → 选择 / 创建世界 | 打开所选角色，按就绪状态提示运行或联络 |
| 辅助写作 | “先写下这个故事想做到什么” → 新建大纲 | 定位首条内容与成功判据，保存后进入当前素材 |
| 跑团 | “还没有战役” → 从样例开始 | 完成摘要确认，进入首个场景 |
| 世界与素材 | “这里保存你的世界和创作材料” → 新建 | 选择样例 / AI / 手动 / 导入，不立即调用 AI |
| 版本记录 | “尚无可用版本” → 保存当前版本（仅就绪时） | 新记录出现；无历史不能摆一个不可用恢复按钮 |
| 错误修复后 | “问题已处理，原任务尚未重试” → 返回原任务 | 保留原文与目标，由用户决定继续 |

## 5. 世界与素材：完整创作和管理入口

### 5.1 列表与世界详情

“我的世界”列出名称、来自哪个设定、时间线数量、是否有线正在运行、最近打开时间和需处理状态。只显示管理元数据，不自动生成内部剧情概述。每行主操作是“打开”，菜单放重命名、导出和删除。

打开世界后可直接选择“联络角色 / 在此写作 / 在此跑团”，下方是时间线列表与版本入口。角色只列可公开名称与创建时可公开信息，不用实时活动、情绪或记忆面板替代对话。

“世界设定 / 角色卡 / 设定草稿”分别列出正式材料与未完成内容；区分“可用于创建”“需要检查”“未确认”。世界和模板同名时，标题明确“正在编辑模板，已有世界不会变化”。

### 5.2 创建世界

顺序固定为：**选择来源 → 编辑世界设定 → 准备角色 → 检查与确认 → 创建世界 → 选择开始方式**。

- 来源包括样例、AI 生成、手动填写、导入。进入工作区只是开始编辑，不立即花费调用。
- 世界与角色可以分别保存草稿，返回后继续。检查页先汇总错误，再按条目定位修正。
- 创建摘要显示世界名、设定来源、选中的角色、起始世界日期与计划进入的工作区。
- “创建并开始使用”和“只创建，暂不运行”都是明确动作；创建固化设定，不能通过以后修改模板追溯改写。
- 失败按阶段表达：“角色卡还未确认”“世界已创建，但启动未完成”等，保留已经完成的产物。

创建是一个可恢复的用户流程：开始确认时固定本次设定、角色和任务身份；未结束前重复点击或断线重试回到同一结果。检查、创建、启动、连接分别显示真实完成状态。只有改了设定并主动点“创建另一个世界”才分配新的创建身份。

创建中可回首页查看状态，不能把“离开页面”当取消创建；核心尚未接受时可取消，已进入创建则先查询结果。创建成功、联络连接失败时只修连接，不再创建世界。没有绑定或角色不可联络时，标题不得显示“可联络”。

### 5.3 世界 / 角色创作工作区

沿用现有生成工作区的“两层控制”，但把复杂字段的 JSON 弹框替换为真正表单。

```text
世界与素材 › 世界设定 › 灰潮纪                       [返回列表]

[基本描述] [规模与取向] [内容要求]          草稿：已保存

分区目录             当前分区的条目                    检查与预览
世界规则             正在编辑：信息与历史 / 北堤信报   还有两项需处理
地区与社会           名称 [                    ]      [定位第一项]
人物与种族           内容 [                    ]
信息与历史           来源 [从已有来源选择      v]      [保存草稿]
生活与事件           [锁定此条] [复制] [删除]          [确认设定]
历法与初始状态       [添加一条] [重新生成本区]

[按一句话修改未锁定内容]                    模型与调用上限说明
```

默认先显示名称、一段描述及基本取向；规模、必含、禁忌、历史跨度和其他参数可展开，展开后保留完整能力。参数是生成要求，校验仍是最终硬边界；不能暗示“数量设为零”便可删除必需部分。

| 分区 | 使用的表单形式 | 需要防止的错误 |
|---|---|---|
| 基本规则、地区、社会、词汇 | 短文本、多行文本、可增删条目 | 必填缺失、同名混淆、引用已删除条目 |
| 种族、人物角色位、制度与职位 | 条目详情、数值带单位、关联对象选择 | 未登记对象、寿命不合法、职位归属错误 |
| 惯例、环境状态 | 允许值列表、当前值下拉、观察条件与来源选择 | 当前值不在允许范围内，声明不完整 |
| 信息来源、实情、说法、史料 | 分开编辑；每条说法与史料的来源用选择器 | 实情被直接当作角色已知，说法失去出处 |
| 事件与后果 | 类型下拉、目标选择、生效 / 解除条件表单 | 不支持的效果、非法目标、缺失解除条件 |
| 生活安排 | 世界历法下的时间段与活动表 | 空档、重叠、跨日错误；不用现实日期控件假装世界历法 |
| 角色初始知识与联络 | 包内来源 / 史料条目多选，联络方式字段 | 引用不属于当前世界，初始知道未来资料 |
| 历法与开始时刻 | 显式单位、结构化年月日和时段 | 自定义历法误当公历，初始时间超出合法范围 |

稳定标识由系统生成并保持；用户编辑名称不更换引用身份。删除被引用条目时先列出受影响项，阻止直接删除或要求完成明确的引用修复，不静默删一串相关内容。

每条可编辑、复制、删除、锁定；锁定用于保护生成时不被覆盖，手动解锁后才能重新生成它。整包重跑与局部重跑都保留锁定项，局部重跑不触碰其他分区。锁定与来源标记随草稿保存。

最终按钮使用“确认世界设定 / 确认角色卡”；“保存草稿”允许未通过校验但带问题清单。创建前仍做世界与全部角色的联合检查，不能把“文件保存过”当作已审定。

提示词预览只可在用户主动编辑自己的创作材料时作为折叠高级项；联络、玩家游玩与通用诊断不提供此入口，更不能透出会话运行提示词或他人的隐藏材料。

编辑行为进一步固定：

- 基础模式展示名称、描述、体裁、基调及必含 / 禁止内容；“更多参数”保留全部已支持计数与取向。不可选项显示约束原因，不静默纠正用户输入。
- 列表添加生成稳定身份；复制只生成新身份与副本名，不复制其他对象对原条目的引用。同名引用选项附所属分区 / 世界，搜索无匹配允许返回创建，不允许现场编造引用。
- 点击条目在中部详情表单编辑，不使用浏览器 prompt，也不以 JSON 编辑器作为高级字段的唯一入口。原始文件只读查看仅限用户自己编辑的模板与草稿，在高级调试提供；不读取锁定世界的内部运行快照。
- 条目锁定统一解释为“AI 不覆盖”；手改锁定条目需先点“解锁并编辑”。段级、整包级重跑都保留锁定内容，校验不能因为锁定而放宽。
- 重生成先保存当前草稿。新结果通过对应结构检查才显示为可采用；检查未过则显示问题候选并保留旧稿。用户选择“采用新结果”后替换未锁定部分；“保留原稿”丢弃本次替换但保留调用结果状态。
- 生成固定本次输入版本，正在生成的分区临时只读，其他分区照常编辑。返回后只替换本次允许变动的未锁定内容；跨区引用受其他手改影响时先重检并提示，不静默盖过后来编辑。
- 条目删除前展示被引用清单；有引用则阻止，提供跳转修正。未确认草稿的无引用条目可删除并在离开该工作区前撤销一次；正式材料删除总是明确确认。
- 素材文件名由应用管理，普通创建只填写显示名；导出时才选文件名与位置。名字合法性和冲突以共享校验结果为准。

### 5.4 导入、导出与加入角色

- “导入”先用原生文件选择，读取后显示实际类型：世界设定、角色卡、世界存档或备份。选错类型时给正确入口，不让用户靠扩展名猜。
- 世界存档导入总是新副本，导入摘要明确新名称、时间线与角色，完成后先暂停；不覆盖同名世界、不继续补算运输时间。
- 角色卡导入先选归属世界再检查。已有世界加入角色走独立向导：目标线 → 卡片审定 → 加入时间与说明 → 确认。不能把“加入当前线”写成“修改所有时间线”。
- 修改锁定公理或已有角色初始设定时，引导“修改模板并创建新世界”；在现有公理内改变局势走下文“尝试世界变化”。
- 大纲随世界存档按引用关系携带；遇到相同稳定标识的本机大纲时，按实际导入结果提示保留了哪一份，不承诺覆盖或自动合并。

导入统一为“选文件 → 识别与完整校验 → 显示摘要和冲突 → 导入”。检查期间不改正式目录；同名素材默认“保留两份”，覆盖必须明确选中并说明旧正式文件会被替换，已有世界仍使用自己的锁定设定。世界存档只支持独立副本；整库备份必须转到备份恢复页。

加入角色默认锚定当前最后完成时刻，只对选择的时间线生效。“曾经存在”和“现在进入可联络集合”分开说明；填写加入事件属于可选内容，不自动编造与其他人的关系。确认前列出目标、角色与加入说明，重复提交复用原结果。

## 6. 角色联络工作区

### 6.1 首屏与主要操作

```text
角色联络 › 灰潮纪 / 主线                   运行中  [时间线与版本]

角色                  与堤禾联络                              [线索]
堤禾 · 堤务吏          消息正文
潮生 · 盐户            现实时间 · 消息状态           [转述给另一位角色]

                      系统状态与错误在独立位置，不冒充她的发言
                      [写下想对她说的话……                    ]
                      Enter 发送，Shift+Enter 换行        [发送]
```

用户从角色名进入对话，不需创建“会话对象”。消息按真实历史分页读取；返回保留位置，用户正在看旧记录时新消息不强制拉到底部，显示“有新消息”。字符过长要换行，输入区不被长历史挤出窗口。

默认只展示对话、角色公开身份、当前世界与线名、已完成的世界时刻以及必要运行状态。没有角色活动监控、性格分数、记忆库或世界全知事件表。

### 6.2 状态与正常等待

| 情况 | 呈现 | 可操作内容 |
|---|---|---|
| 还没准备好 | 列出缺少世界 / 角色 / AI 配置的真实项 | 直接去补齐 |
| 可联络 | 普通输入框与发送 | 分享、询问、追问 |
| 处理中 | 当前消息下“已接收，正在等待回应” | 按允许状态继续输入或等待；不推断角色正在睡觉 |
| 回复已保存 | 显示正文；若投递另有问题，附加真实状态 | 继续聊天或重新获取原回复 |
| 角色暂不想讲 | 以实际角色表达呈现 | 正常继续联络，不显示“解锁秘密”按钮 |
| 模型生成失败 | 独立系统反馈卡，和角色的暂缓分开 | 修复 AI / 重试原请求，保留输入 |
| 世界追赶中 | “正在补齐进展，可先阅读记录” | 读已完成历史、保留输入；业务状态恢复就绪后才允许新发送 |
| 暂停 / 归档 / 不兼容 | 原因与可用动作明确列出 | 查看记录；显式恢复运行或处理兼容性 |

“等待回应”没有虚构进度、倒计时或角色状态解释。角色没有新故事可以是正常情况；系统没生成成功必须用技术反馈，不能写成“她今天不想理你”。

发送行为固定如下：点击发送后立即保留原文并标“正在提交”；收到受理回执才清空当前输入并移入历史。受理前失败原文仍可编辑；受理结果未知时保留同一请求并先查结果，不能再次当新消息发出。已受理后允许继续写下一条，发送节拍仍由会话层合并与排队，界面不发明自己的消息合并。

正式首版联络采用完整回复展示，不接入未完成的流式正文。等待状态不写成“对方正在输入”。重连按核心记录去重；“重试生成”和“重新获取回复”只在真实可用阶段显示，原消息状态会跟随更新。

### 6.3 请求转交

用户在联络框说“让北堤封闭”“回到昨天”“我要掷骰潜入”时，不通过角色说一句“好了”冒充执行。分类结果需要其他流程时，在原消息下出现系统卡：

> 这条内容需要在“尝试世界变化”中处理。当前世界尚未因本次请求改变。［查看草案］［继续联络］

按真实目标分别打开创作、版本或跑团流程，保留原文、世界和来源点；打开只准备草稿，最终生效需目的工作区的明确确认。误分类的固定出口为“仅作为联络发送”：先展开原文供修改，并说明只把这句话告诉角色，不执行其中的操作。确认后以新的联络请求提交，原转交记录保留并关联；这一明确意图只能改变分类，仍不改变角色认知与写入权限。应用层需支持此受控入口，不能用客户端直接调用普通生成绕过分类。

### 6.4 线索与转述

“已讲过的线索”默认是易读的文字列表，点开回到已显示的消息；关系图作为同源的可选视图。没讲出口的部分最多沿既有投影保留不含正文的记号，不因点开或追问而解锁内部材料。

转述顺序是：选择一条或多条已经显示的完整消息 → 选择同线接收角色 → 预览完整授权正文 → 确认。首版复用整条消息的授权粒度，不提供“拖选几个字，只分享这几个字”的承诺；候选摘要被截短时，确认前必须展开全文。候选未能在当前有效历史中确认时，不给授权按钮。

告知只授权这些消息，不共享整段聊天；完成后显示已授权，不假称对方已经读懂或相信。确认页说明不能单独撤回，恢复版本也不保证删除外部平台已经显示的消息。

转述成功后，在源消息显示“已转述给：角色名”，可打开同源授权清单；再次授权同一范围与接收人显示原结果。确认前世界恢复、消息失效或接收角色退出，按钮失效并保留原选择供查看，不自动换人。授权不自动发送一条接收角色回复，也不移走用户当前会话。

## 7. 辅助写作工作区

### 7.1 进入与版面

入口名用“辅助写作”，页内说明“一起组织大纲、观察人物、比较推进方案，文字由你决定”。支持小说作者独立使用；在跑团中打开时明确是“主持准备”，结果默认不发给玩家。

首次进入依次选世界、时间线、观察角色，再创建或选择大纲。世界不存在可从这里进入创建向导并原路返回。UI 不增加一套“写作项目数据库”；使用已有大纲与世界绑定。

```text
辅助写作 › 灰潮纪 / 主线 / 北堤故事              观察角色 [堤禾 v]
大纲已保存                                     [版本] [导出文字]

[大纲] [当前素材] [推进建议] [文字草稿]

大纲条目 / 草稿列表       当前编辑内容                  依据与检查
主题                     标题、内容、目标              来源属于谁
必达节点                 编辑 / 锁定 / 保存            关联大纲条目
禁止事项                 候选与待决定项                还缺什么条件
角色弧线                                               是否改变世界
节奏目标
可变素材
```

采用同一工作区内分区切换，保留编辑位置；不让用户同时面对四张密密麻麻的表。右侧依据可折叠，但“此操作会改变世界”的信息不折叠。

### 7.2 大纲编辑与状态

大纲条目按已有六类呈现，每类有一句示例说明。新增条目先填“希望发生 / 保持 / 避免什么”和“怎样算满足”，再展开范围、强度、前置、依赖、截止世界时刻、替代路径。对象与依赖通过名称选择，不手写 ID。

状态用“未开始 / 进行中 / 已达成 / 已偏离 / 已放弃”；禁止事项用“未发现触发依据 / 已触发 / 已放弃”的实际检查或决定结果，不给“已达成”按钮。严格目标必须有当前线可追溯依据才能标记达成，作者写下“已经发生”不代替世界证据。

点“检查大纲”展示：哪个目标缺条件、哪个目标偏离、现有依据是什么、接下来能选择什么。自然语言判据不是任意剧情的可靠自动识别器；未能建立可核验引用时写“还需作者确认或补依据”，不能把模型判断包装成已证明。

大纲定义可跨时间线复用，进度分别记录。修改被多条线使用的大纲前列出受影响范围，允许另存一份只给当前线用；删除被引用条目时保留必要历史指向，已放弃条目不静默复活。定义更新、绑定后条目同步和锁定持久化需先补齐；更换观察角色或章节标签只修改这些选择，不能通过重新初始化大纲把进度清零。首次绑定必须从合法初始状态开始，不能让模板夹带“已达成”绕过依据检查。

大纲编辑定案：

| 事项 | 规则 |
|---|---|
| 新建 | 名称必填；至少一条有效目标，首条默认“主题约束”。其他分类默认强度沿业务规范，用户可明确修改 |
| 保存 | 编辑副本可不完整；“保存大纲”只发布整份校验通过的定义。失败保持上一份定义及各线进度 |
| 当前大纲 | 一条线可保留多份大纲，但工作区每次明确选择一份；所有观察、提议与决定指定这一份，不隐式取第一份 |
| 跨线复用 | 同一条目身份复用结构，各线保留自己的进度和理由。修改共享定义先列出受影响线；默认提供“另存为当前线的大纲” |
| 定义变更 | 改名和说明保留状态；改变约束内容、范围、强度或判据会使旧判定标“需复核”，不能沿用原达成凭据。不删除决定记录来冒充未开始 |
| 更换观察者 / 章节标签 | 只更新工作区偏好与绑定元数据；不初始化已有进度，不制造新章节事实 |
| 依赖与引用 | 通过当前可见材料选择；没有合法材料时保持待补依据，禁止为了选引用而开放全局真值浏览 |
| 移除条目 | 未被引用且无决定记录可移除；已有引用或决定只停用，保留历史关联，不加入完整大纲版本树 |
| 标为达成 | 严格目标必须带当前线的合法依据；提示其内容仍需作者核对。不严格目标可以带理由作作者决定 |
| 接受偏离 | 给理由，选择调整目标 / 采用替代路径 / 放弃；不能把“接受偏离”换个标签显示成“已达成” |

禁止事项没有发现依据时写“未发现触发依据”，不能直接证明“绝未触发”；放弃禁止事项显示“已放弃”，不继续显示未触发。缺口报告、作者决定和世界结果分栏，不用一个进度条代替三者。

### 7.3 当前素材与建议

“当前素材”只给所选角色在当前完成进度上合法可知的材料。使用“亲历 / 看到 / 听说 / 推测”等来源标签；作者依据与下一步安排另放一组，不把幕后提示混进给角色或玩家看的文本。

每份素材显示观察角色、所属时间线与读取时刻。冻结或追赶时保留旧材料作“历史参考”，不标当前；等世界就绪后显式刷新。作者身份不等于可读取整个世界真值。

“给我推进建议”的参数定为当前目标、观察角色、关联大纲条目和建议数量（默认 3，允许 1–5）。题材、必含与禁止从已保存设定和大纲继承，首版不再增加一份平行约束表。结果每条包括：方案内容、对应目标、已有事实依据、因果解释、尚缺条件、是否含世界变化。

没有可用提议就说明缺少什么，不为填满卡片编造候选。模型输出无法解析时显示“没有取得可用建议”，不能与“检查后确实没有建议”混为一谈。每次“再给一组”产生独立的一组候选，已采用、已拒绝与已锁定内容不被同名覆盖。

修改、暂存、拒绝、采用都必须是真实候选操作；修改已批准或过期方案时生成新的待审候选，原来的批准不适用于新内容。普通采用可记录实际动作名作为理由；接受偏离、放弃严格目标等决定要求用户选择或填写理由，不让每次普通保存都弹一个空白问答框。

候选比较只对用户勾选的两条展开同字段并排对照；窄窗口上下排列。每条卡固定“方案 / 依据 / 待定问题 / 改世界与否”四组；没有依据时明确写缺失。候选状态与本次操作结果分别呈现：例如“已采用；应用被拒”。被拒绝、已过期或不处于待提交状态都不能直接解释为已发生。

### 7.4 三种结果，三个动作

| 用户想做的事 | 按钮 | 成功后的反馈 |
|---|---|---|
| 把建议留作文字 | “以此起草” → 编辑 → “保存文字草稿” | 草稿已保存；不代表世界已改变 |
| 看另一种后果 | “另开分支试演” | 显示新分支与来源版本；明确启动后再观察，原线保留 |
| 让变化在当前线生效 | “预览世界变化” → “确认应用到此时间线” | 只有真实提交成功才显示已生效及对应结果 |

当前自动建议是一两句话的情节方向，不能直接当作成稿或可执行变化。“以此起草”打开文字编辑区，把摘要作为可编辑的起点；“准备世界变化”另开结构化变化表单，让用户选对象、变化类型与范围后再预览。“另开分支试演”先建立暂停分支，显式启动后取得当前预览，再确认应用所选变化；仅仅创建分支不算已经完成试演。

世界变化预览必须列出目标、具体变化、作用时间、受众、规则或世界限制，以及不能执行的部分。出现不支持的资源 / 关系类变化时如实拒绝或指向规则层适用流程，不把近似文字当成实际效果。

战役内的直接变化进入 GM 的规则与世界联合提交流程，不能从写作页旁路改世界。只是“想让故事更紧张”属于创作目标，先提出方案；不是一条可以直接执行的变化。

“已采用，尚未应用”“应用失败”“结果待确认”“已生效”分别显示。世界在生成建议后变动，先重新检查；世代变化后的旧结果作过期处理，不能静默套用旧批准。

确认世界变化时固定提交对象与内容版本。若同一意图可在当前世界重新预览且目标、值、受众、时间与后果均未变，可显示最新检查结果继续原确认；任一项实质变化都撤销旧确认，让用户重审。存在未解决严格大纲冲突时，停在“先处理偏离”，作者决定后仍须通过世界 / 规则硬校验。

试演顺序固定为：保存来源版本 → 建立暂停分支 → 查看待试意图并点“启动分支并检查” → 取得合法当前预览 → 点“应用于试演线”。暂停态只展示意图，不伪装已经完成世界预览。任一步失败显示真实已完成步骤；启动成功、预览失败时保留新线并明确它是否仍在运行。只有用户明确进入分支后，任务才使用新线身份。试演比较只显示两个分支各自合法可见的素材、候选与大纲检查结果，不展开内部状态差分；采用某条线只切换继续使用的目标，不合并世界。未应用的旧候选在新线重新建立身份并检查，不搬主线的提交结果冒充试演结果。

### 7.5 文字草稿与导出

首版提供标题、正文、多份草稿列表、编辑、显式保存、锁定和导出所选文字。正文使用普通文字编辑，可保留 Markdown 文本；不扩展成排版出版软件。AI 建议引用到正文时保留“源于哪个候选”的作者侧关系，导出正文默认不包含依据、错误或隐藏材料。

锁定正文意味着后续生成与世界恢复不会覆盖它；需要改动时先解锁或复制成新稿。未锁定编辑也不能因为刷新观察材料而被抹掉。世界恢复后，文字保持原样，旁边显示“依据丢失 / 需要重新决定”的检查结果，创作者确认后才改变大纲目标状态；不强行改写正文来凑连续性。

**能力边界：** 现有编剧层可在批准文本候选时保存正文，但同标识重新提案仍可能覆盖它，不能把批准状态等同于可靠的锁定。锁定保护、自由编辑、持久自动保存、独立草稿浏览与正文文件导出都需补齐。先复用候选文本与现有存储，补窄的编辑保存能力，不另建通用文档引擎。整章续写、富文本排版和出版格式不属于本次界面最低闭环。

正文资产的归属与保存定案：

- 每份正文属于写作模块的现有候选 / 草稿域，带世界、来源时间线、观察角色、来源候选与标题；不建设平行“文章系统”。
- 新建正文可从空白开始或复制候选摘要。首版没有“一键生成整章”的承诺，使用者可以自行写作；AI 提供的建议与用户正文来源可区分。
- “保存文字草稿”立即保存未锁定文字；自动保存按第 3.5 节执行。“锁定正文”先保存成功再锁定，并显示锁定时间。锁定后新生成永远生成另一稿。
- “解锁并编辑”只解锁这份文字；无效输入、旧回执或另一任务不能覆写它。需要保留两种写法时点“复制为新稿”；不隐式生成无限修订历史。
- 分支和世界回滚不复制或撤销作者文本；用户在新线需要旧稿时显式“复制到当前线”，保留来源说明并重新检查依据。实例删除会删除随实例管理的草稿，确认页必须列出并提供导出。
- 导出使用原生保存对话框，格式为 UTF-8 的 Markdown 或纯文本，默认只导出选中的标题和正文。写入并读回确认后展示真实路径与“打开所在文件夹”；覆盖已有文件由保存对话框确认。
- 未保存内容先保存再导出；存储故障时可“仅导出当前编辑内容”，明确本机草稿未保存。两种成功状态不能混用。导出文件是普通本地文字，不随以后的世界恢复删除。

## 8. 跑团工作区

### 8.1 创建或继续战役

未选择战役时显示“继续已有战役 / 从样例开始 / 新建战役”。新建步骤是：填写战役名称 → 选世界与时间线 → 选规则及版本 → 选角色并核对规则绑定 → 建立初始场景 → 确认开始。首版新建固定采用辅助裁定；玩家 / 主持是进入后的操作视图，不用“主持方式”选择题暗示完整 AI 主持。

规则的初始角色数据应来自已验证的规则样例或支持该规则的导入材料。**现有插件没有通用角色建卡表单协议，不能声称任何规则都能自动生成完整属性编辑器。** 缺少适配的插件要在选择时说明“目前需要规则作者提供初始化材料”，保留高级导入，普通用户默认只走已验证组合。

| 设置 | 决定什么 | 不等于什么 |
|---|---|---|
| 玩家 / 主持视图 | 当前显示与操作的角色 | 不是登录账号或联网权限系统 |
| 辅助裁定 / 自动主持 / 共同主持 | 谁负责确认与推进的责任方式 | 自动主持不等于已具备完整自主讲故事的 GM |
| 公开 / 指定角色 / 指定玩家 / 仅主持 | 某项材料允许给谁看 | 不是切换标签就能读取所有人秘密 |
| 行动节拍 | 即时、持续、对抗、世界过程等规则语境 | UI 不自行制造统一回合制 |

新手默认采用辅助裁定、玩家操作模式和当前角色视角，保留显式行动确认；这三个默认值不做成必须理解的技术选择题。普通界面解释模式影响，技术枚举隐藏；实际可点动作取自战役与行动状态，不能因为选了“玩家模式”便跳过必须的确认。

战役创建摘要必须显示世界、时间线、规则名与版本、活动角色和场景名；名称保存到战役 / 场景自己的元数据，不能只在当前电脑临时改名。导入存档缺少友好名称时给可编辑建议，不把内部标识作为默认标题。

选择正在用于联络或另一战役的时间线时，明确本战役后果将影响同线其他使用者；默认建议“另开一条跑团时间线”，用户可明确选择共用原线。新分支与新世界都先暂停，最终“开始战役”同时明确启动目标线的意图。

准备不全时可保存为“准备中”；核心只在规则版本、参与者、初始状态和场景全部合法时允许开始。重复继续准备更新原战役，不再新建；部分失败返回原准备记录。已经创建的世界不因战役创建失败而删除。

初始场景采用名称、公开简介、地点、在场者、已知风险与可行动作的名称化表单。角色 / 地点必须来自所选世界；私密说明放“仅主持”分区，默认不公开。录入场景描述不成为世界变化，涉及真实改变时另走 GM 变化预览。样例战役必须包含这些有效材料及一段局部使用提示，而不依赖用户自己写规则状态。

### 8.2 场景与行动

```text
跑团 › 灰潮纪 / 主线 / 北堤调查                 视角：玩家 · 潮生
规则名称与版本                         战役进行中  [主持准备]

当前场景                           待处理
已经公开的局面与选定角色可知线索     行动确认 / 玩家选择 / 主持待审
过去结果                            指明为何当前不能继续

我想…… [                                  ]
行动者 [潮生 v]   目标 [选择已知对象 v]   方法 [              ]
[查看行动确认卡]
```

行动确认卡显示行动者、目标、方法、所需补充信息、受众、已知代价与世界时间影响。没有真实裁定就不展示骰点或宣称成功；无法事先计算的代价标明“由规则裁定”，不编一个估计。

确认后按实际阶段显示理解、等待确认、规则裁定、待提交 / 主持确认、已固化、新局面。等待选择时选择卡放在最明显位置，行动框旁说明“请先处理这项选择”；选完记录选择并重新读取局面，再由用户声明后续行动；当前选择登记不保证自动执行选项对应的世界后果，只有后续真实提交才可显示变化已经发生。

结果顺序固定为：行动结果 → 实际世界后果 → 相关角色能够知道的内容 → 当前可做的下一步。世界时间与现实时间分开标，规则时间只有插件给出才显示。世界变化未提交成功，不能提前写成“北堤已封闭”。

### 8.3 行动与恢复操作表

| 当前阶段 | 主动作 | 操作保证 |
|---|---|---|
| 输入草稿 / 缺信息 | “补充行动” | 模型只补空项；玩家明确填写的行动者、目标和方法不被静默替换 |
| 等待确认 | “确认并裁定” | 展示当前版本的行动卡；改任何关键项使旧确认失效 |
| 裁定中 | 等待 / 查看阶段 | 不取消后自动重掷；切页不发第二次裁定 |
| 玩家模式裁定合法 | 自动尝试联合提交 | 不再问一次同内容的批准；失败停在真实错误，不把裁定等同于世界生效 |
| 主持模式裁定完成 | “批准并提交 / 暂存待审 / 拒绝” | 只有仍有效且具有可提交载荷的结果可批准 |
| 待补材料、无合法载荷 | “补充后重新裁定 / 放弃” | 不显示可以绕过校验的批准按钮 |
| 等待选择 | 选择一项后“确认选择” | 显示选项及已公开代价，提交后以回执锁定；双击、断线复查不重复消费 |
| 提交结果未知 | “查询原结果” | 同操作身份核验；禁止在结果未明时重新裁定或继续冲突行动 |
| 已知插件失败 / 中断 | “恢复已保存结果”或“重新裁定” | 有结果先恢复；重做可能改变随机结果，需明确确认，不能被普通刷新触发 |
| 当前世界已变化 | “重新读取并确认” | 旧结果留作记录，重新检查后生成新确认卡 |
| 已提交 | “查看结果 / 继续行动” | 重开读取原结果，不重复扣资源，不提供伪装成编辑的改判 |

只要战役有待选择或未决关键行动，其他角色可以被查看，但声明新关键行动按战役闸门限制。当前角色退出、身故或不在场时，按规则与核心给出的资格原因处理，不自动换人代行动。

### 8.4 主持工作与信息边界

主持视图有待审行动、规则依据、直接变化、场景准备与“交给写作助手构思”。有裁定且可提交才显示“批准并提交”；材料缺失时只能补充、修改或拒绝，不能用万能批准按钮绕过校验。

玩家面不得包含原始规则状态、私密裁定、隐藏难度、补丁载荷或主持依据，即使某些跑团产品习惯公开骰点，本项目仍以当前规则可见面契约为准。主持切回玩家视图要重新获取受众投影并清空主持缓存，不靠 CSS 隐藏秘密内容。

本机单用户可主动切换自己查看的视角，但这不提供面向不受信多人用户的鉴权。首版不提供网络房间、邀请链接或远程多人同步；不能把视角切换包装成多人隔离产品。

主持面固定四组：“待处理行动”“场景准备”“直接变化”“故事构思”。结构化结果可由主持补充表达；发布时重新选择受众并预览玩家可见部分，发布的是有来源的表达，不是另一条事实写入路径。故事构思跳写作工作区，返回时仅带回所选候选。

“暂停战役”默认只停止该战役行动，页面明确世界仍可能继续运行。提供未默认勾选的“同时暂停这条时间线”，说明会影响同线联络和其他战役；两步分别回报成功，部分失败不显示整组已暂停。恢复战役也不自动恢复世界，缺哪一步就给哪一个按钮。

### 8.5 规则管理与升级

插件失败保留行动、给出插件名和阶段，不自动重新裁定。提供的动作区分“查询 / 恢复原提交”和“重新裁定”；后者必须明确可能产生新结果。断线后先恢复原状态，再决定可用动作。

规则管理放在设置的扩展页，战役中缺规则的入口直接带过去并返回。规则清单的选取、校验和本机登记需单独补齐；现有通道插件安装入口不能直接安装规则插件。界面把“规则”与“外部聊天通道”分组，不要求用户分辨底层协议。安装前展示来源、规则与版本、将运行本地扩展程序的事实，需用户主动启用；进程隔离不是完整安全沙箱。没有插件市场或自动从不明链接下载执行。

首版规则来源固定为随发行的潮汐样例，或用户在原生选择器中选择本机规则清单所在目录。识别规则身份、版本、协议、入口与所需本机依赖后先显示检查摘要，再明确“添加并启用”；选择文件时不执行未知程序。规则名和版本分别登记，同一身份与版本不同内容不得静默覆盖，已有战役固定引用已验证版本。

规则列表显示可用、未启用、依赖缺失、不兼容、被战役引用等状态。移除被引用版本前列出战役并拒绝破坏性移除；停用只阻止之后调用，进行中的结果按原任务恢复。导入世界只携带规则需求，不携带或自动启用可执行插件；缺失版本在战役入口定位处理。

升级使旧战役状态不兼容时停在原数据，提供保留副本、可信转换或使用兼容版本。转换未成功不把战役标可用；“接受新版本”的存在不能替代迁移与损失说明。当前被阻断战役的转换入口还受状态闸限制，交付前必须验证从“已阻断”到“可继续”的真实恢复链，不能只验证提前转换的顺利路径。

版本处理固定为：核对当前需求 → 检查可用转换器 → 保留可恢复副本 → 预览转换损失 → 明确执行 → 读取转换后兼容结果。无转换器时推荐使用匹配旧版本；高级“接受以新版本解释”必须明确不是数据转换，只对明确支持原状态的版本开放，不用改版本号绕过阻断。

## 9. 时间线、版本与尝试世界变化

### 9.1 时间线页

从任一工作区顶栏或世界详情进入，默认选中当前线。每条显示名称、来源版本、运行 / 暂停 / 归档、是否需要处理。操作包括查看、重命名、描述、运行 / 暂停、从版本另开分支、归档与删除。

打开或选中一条线只改变视图；运行状态显式改变。已有其他线运行时，启动摘要提示它们会继续，允许用户主动暂停原线，但不默默冻结。新分支默认暂停，确认“开始运行”才启动。

速度输入是当前线的世界速度，显示清楚单位与含义。默认 1 倍，自定义正整数取核心允许范围；开发者上限不做可编辑控件。变速显示“等待生效”直到实际生效，不用前端计时器代替世界钟。

关闭窗口默认到托盘并继续运行，首次关闭给一次清楚说明；托盘有打开与退出。显式退出后原运行线下次启动仍会补算。用户想停止故事进展应点“暂停这条时间线”，不能让“退出软件”承担两种含义。

### 9.2 版本记录与恢复

版本列表只显示现实保存时间、世界进度点、来源关系、用户备注与保存类型；没有自动剧透摘要和内部差异树。

- **保存版本**：可填备注，成功后出现实际版本记录。
- **从这里另开分支**：选版本、填新名称，预览来源关系；原线保持。
- **恢复到此版本**：先列被覆盖范围和外部消息限制，推荐先保存当前状态为保留分支或导出。保留“现在”须先保存当前版本，再从这个新版本建保留分支；不能从准备恢复的旧版本建分支后声称保住了当前进展。仅创建一个版本点不代替保留未来。
- **归档 / 删除**：说明目标和影响，明确哪些源模板、其他线和存档不受影响；最后一条线不能删时给实际原因。删除用名称确认，取消默认安全。

确认页在实际取得保留分支或导出成功结果后才显示“当前进展已保留”，不把勾选“我已保存”当成保存证据。不保留而继续的路径需单独确认。外部已投递条数如为全线统计，要标“此线已投递总数”，不能冒充本次将覆盖的数量。

恢复单条时间线保留恢复前的运行 / 暂停状态；确认页说明运行中的线会从恢复点继续，与全量备份恢复后全部暂停不同。恢复成功必须重新加载该线历史与工作区状态，失效任务不再写回。写作大纲重新评估，标注依据丢失、等待作者决定；锁定文字保留。已发往其他平台的消息不能保证被删除，这句话放在确认页而非只放帮助文档。

恢复确认页同时列出当前线内受影响的所有角色会话、战役、待执行事件与在途请求；写作的定义、候选与文字不随世界自动撤销，但其依据将重评。信息数量来自同一份真实覆盖检查，拿不到数量就只描述范围，不显示估算的“将丢失 N 条”。

默认主按钮为“保留当前进展并恢复”：由所属服务暂时阻止该线新写入并处理在途提交，在同一受保护的操作范围内建立一致的当前版本、保留分支，再恢复所选目标；后台推进也不得插入覆盖前的新写入。该保护不改写用户的运行 / 暂停意图，完成或失败退出时按真实结果释放。若保留分支或导出失败立即停止，不继续覆盖。仅勾选“我知道了”不能代替保存结果。

“直接恢复，不保留”放在展开的危险操作区，需要单独确认范围。提交后禁用关闭确认框的执行按钮直到结果明确；允许离开查看其他内容，但原任务状态必须可返回。新线要求填写名称，删除要求再次输入目标名称确认；归档优先于删除且先暂停；归档后默认从常用列表隐藏，可通过“显示已归档”找到。首版不增加取消归档业务入口；要继续归档路线，从其可用版本另开分支，原归档记录保留。

### 9.3 尝试世界变化

从世界详情或联络转交进入：用户描述想改变的局势 → 查看可执行草案 → 确认来源版本与新线名 → 在新线应用。草案只展示用户输入和可公开的可执行内容，不为了解释拒绝而泄露幕后原因。

这条路径遵守既有“引入事件并新建时间线”语义。写作 / 跑团对当前线的显式提交则沿各自权限与提交管线；UI 不把所有写入都错误改成另开分支，也不让普通聊天获得相同写权限。

预约事件显示为“已安排，尚未发生”，到点条件失效时显示实际取消原因。创建与注入失败不留下半条可用时间线；不支持的请求指向可行替代路径，不把一段生成描述当作发生证明。

世界变化草案使用“改变对象 / 变化种类 / 新状态 / 何时生效 / 持续到何时”表单。可选对象来自当前入口合法可指涉集合；不支持的类型没有自由文本后门。预约时间使用当前世界历法，不把操作系统日期控件用于非公历世界。新线确认摘要标“原线保留，新线暂停”，之后通过“启动新线”继续。

## 10. 设置、帮助与通用交互

### 10.1 设置归属

| 设置分组 | 内容 |
|---|---|
| AI 服务 | 服务、模型、密钥、测试与高级输出参数；修改不重写旧内容 |
| 记忆检索 | 基础文字检索 / 增强语义检索，增强服务独立配置；默认基础模式可用 |
| 自动保存版本 | 开关、间隔、事件阈值；说明关闭不影响日常数据持久化 |
| 数据与备份 | 数据位置只读、备份目录选择、保留策略、立即备份与全量恢复 |
| 用量 | 设置只说明计量方式并链接各世界；实际实例 / 时间线 / 任务额度在对应世界详情调整，不新建未接入的全局额度表 |
| 通知与外观 | 桌面提醒、明暗随系统、文字大小；通知不能当第二份历史 |
| 扩展 | 规则与外部通道分组，安装 / 启停 / 状态 / 兼容诊断；默认不要求启用任何外部通道 |

设置分组各自有保存与结果槽；不放一个跨整页的大保存按钮导致用户不知道改了什么。错误修复入口定位到具体分组并保留返回原任务的入口。路径使用原生浏览，闭集用下拉 / 单选，不能让用户通过自由文本输入非法枚举。

不把全部底层配置展开成“专家模式”大表。需要用户调整的值应有明确用途、范围、当前生效值与保存结果；受保护的内部阈值保持开发者配置。

### 10.2 视觉与可访问性

沿用黑白语义、系统无衬线、细描边、少量状态色。重点是长文本可读与操作可辨，不做仪表盘式数值首页或装饰背景。

- 默认正文以舒适阅读为先，提供文字放大；说明不能小到成为“看不见的免责条款”。标题、正文、辅助信息形成稳定层级。
- 主操作有明显外观且使用动作名；“确认”“确定”应替换为“创建世界”“应用到主线”等，普通保存无需反复弹窗。
- 图标旁有文字；选择、警告、错误、完成不能只依赖颜色。表单标签常驻，placeholder 不替代标签。
- 键盘可走完整路径，焦点清楚；返回后恢复合理焦点，校验后定位首个错误，模态确认可安全取消。
- 联络 Enter 发送、Shift+Enter 换行；编辑器 Enter 换行、Ctrl+S 保存。中文输入法确认候选时不误发送。
- 屏幕阅读器播报阶段变化和错误，不逐秒播报等待计时。正文新增不把所有历史重新朗读。
- 长名称可换行 / 查看全文；列表为空、筛选无结果、尚未加载和加载失败分别说明，不能都写“暂无数据”。
- 普通桌面、窄窗口和 200% 缩放都能操作。辅助列收起或切成页内分区，主要操作和错误不被挤出可视区；这不等于承诺手机应用。
- 外部文本按安全文本或受控 Markdown 展示，不执行 HTML、脚本或文本中的命令。

视觉参数作为首版基线固定，使用现有系统字体和原生控件能力：

| 项 | 默认值 / 行为 |
|---|---|
| 明暗 | 跟随系统；设置可选择浅色、深色。浅底白、深底近黑，正文高对比，色彩仅辅助状态 |
| 字体层级 | 标题 24、正文 16、辅助 14 个逻辑像素；统一行高约 1.6，正文最大宽度约 70 个拉丁字符的阅读宽度 |
| 尺寸 | 主按钮和单行输入最小高度 36 个逻辑像素；焦点描边至少 2 个逻辑像素。点击目标之间留清晰空隙 |
| 布局 | 首启目标 1200×800，常规最小 820×560 个逻辑像素；实际大小与最小值都不得超过当前屏幕工作区。内容宽度不足 960 时辅助区改页内切换，不足 640 时左导航改为带文字的菜单；不靠横向滚动操作表单 |
| 放大 | 文字大小提供 100%、125%、150%；200% 系统缩放作为验收场景，逻辑尺寸随系统缩放 |
| 层次 | 左导航、任务主区、可收起辅助区；确认用短模态，长编辑一律在工作区，不堆叠多层弹框 |
| 快捷键 | Ctrl+S 保存当前编辑副本；Ctrl+F 聚焦当前列表筛选（无筛选时不抢占系统行为）；Escape 取消未执行对话框，不撤销已受理操作 |
| 动效 | 只用于展开与状态切换，约 150 毫秒；遵循系统减少动态效果，等待进度不靠装饰动画传达 |

这些参数用于一致性与可访问性，不新建组件框架。正文与控件至少满足常规文本 4.5:1 对比度，键盘焦点与必要控件边界至少 3:1；按最终渲染实测，不能只核对设计色值。

同一语义色（成功 / 警告 / 错误）与控件边界色要在浅色、深色下**分别取值并分别实测**，沿用另一主题的色值视为未验证。测量至少覆盖：状态文字 ×（页面底 / 卡片底 / 下沉底），控件边界 × 其所在底色，焦点描边 × 所在底色。

### 10.3 同一套反馈纪律

每个动作就近显示反馈，只有全局问题上升到顶栏。成功状态有可核验的对象，例如“草稿已保存，可在草稿列表继续”，而不只是绿色“成功”。网络请求返回成功信封仍要检查业务结果，拒绝、待审和过期都不是完成。

完整错误格式、重试语义、首次配置和帮助入口见 [首次使用、配置与错误恢复](ONBOARDING_AND_RECOVERY.md)。这套共用规则不能抹掉 OC、写作和跑团自己的状态差别。

以下是当前阅读和定向验证形成的设计依据，不是已完成 UI 清单。既有核心可用不代表所有边界都已经验收，也不代表可以只接按钮就满足新手要求。

| 领域 | 当前可复用 | 为本设计仍需完成 |

| 桌面宿主 | Tauri、核心监督、受信连接、托盘、日志、基本设置与原生选文件 | 面向发行的运行环境封装、独立可写数据位置、统一导航、首次设置 |

| 跑团 | 客户端层工作区状态、行动流程、受众视图、规则提交、选择与恢复 | 可视客户端、战役 / 场景显示名称、新手战役材料、规则登记与初始化、阻断后迁移、工作区持久恢复 |

| 长任务与错误 | 部分错误码 / 阶段、设定生成进度、各模块的部分幂等与恢复 | 稳定字段定位、提交结果待确认查询、任务身份持久化、脱敏诊断；缺信息在源头补 |

当前不需要新增通用 UI 插件框架、第二套状态机、统一剧情数据库、全局工作流引擎、独立账号系统或任务服务。复用各应用层提供的语义，新增能力只补在实际拥有它的模块里。

刻意限定：首版只支持一个设定生成任务同时执行；写作正文用简单文本编辑；新手跑团先覆盖经过验证的规则样例；不支持世界合并、联网多人、云同步、出版排版。这些限制在对应入口说明，不用“以后支持”占位按钮干扰当前用户。

### 11.1 界面上线前必须通过的业务边界

复核既有实现后发现，部分 UI 保证还需要所属应用层修正。下表只列直接影响本设计的事项，不在本次文档任务中顺带修改业务代码。

| 事项 | 本次核验结果 | 交付条件与归属阶段 |
|---|---|---|
| 写作材料按受众隔离 | 临时数据实跑：玩家观察结果仍带主持候选的正文与私有依据 | 在应用层裁剪候选、依据与大纲缺口；UI 不接收后再靠隐藏控件挡住。U3 完成，U4 玩家面复验 |
| 候选不覆盖已采用内容 | 临时数据实跑：再次生成沿用标识，覆盖已批准建议；同标识重新提案也可覆盖已批准正文 | 每次生成独立身份，核心拒绝覆盖受保护产物；批准与文本锁定分别保证。U3 |
| “已生效”有真实事实依据 | 临时数据实跑：普通候选决定能将状态标为已提交，世界事件数量却不变 | 仅真实提交结果能产生“已生效”状态；历史显示也需可追溯提交依据。U3 |
| 改章节或观察者不清进度 | 临时数据实跑：重新绑定会把进行中的目标重置为未开始 | 把初次绑定和元数据修改分开；保留各线进度，模板不夹带已达成状态。U3 |
| 严格目标状态合法且可操作 | 临时数据实跑：开始一个尚无依据的严格目标也被“达成需要依据”挡住；静态核对发现定义初始状态会随绑定进入进度 | 只对需要依据的决定施加相应条件，初始绑定也不能绕过达成检查。U3 |
| 无效模型输出可排错 | 临时数据实跑：不可解析的建议返回成功与空清单 | 区分“没有建议”和“没有取得可用输出”，提供实际失败信息。U3 |
| 规则扩展与通道扩展分开 | 规则样例经当前通道清单检查被拒，原因是缺少通道协议声明 | 规则有独立的选择、校验和登记入口；复用界面样式，不误用通道安装业务。U4 |
| 已阻断战役也有恢复出口 | 迁移入口静态核对加状态闸实跑：阻断状态会拒绝转换规则版本 | 验证从真实版本冲突产生阻断，到保留副本、转换、继续战役的全程。U4 |
| 新手就绪与可读名称 | 静态核对：现有进入步骤和战役 / 场景名称投影不足以直接支撑全部向导反馈 | 就绪取选中对象的实际校验、运行、成员与连接结果；补战役 / 场景显示名称，不把 ID 当标题。U1、U4 |

其他必须实跑的边界包括：恢复 / 分支后角色消息全文仍可读取；大纲及正文不因恢复或刷新被覆盖；GM 变化在世界变更后重新检查，失败后可查询原结果；转述只接受确认页实际展示的有效消息；暂停与追赶时显示最后完成状态。它们属于后续实现验收，未在本次凭静态怀疑判为全部失败。

## 12. 实施顺序与交付门槛

这是设计实施顺序，**本次不执行代码改造**。每阶段都以真实任务可用为交付单位，不能把静态页面搭好就称阶段完成。

| 阶段 | 范围 | 能交付给用户的结果 |
|---|---|---|
| U1 启动与首次成功 | 发行件、README、首次配置、统一导航、样例创建、OC 联络、基础错误恢复 | 新用户可独立安装并与样例角色联络；这个阶段不宣称三个应用全部可用 |
| U2 创作与安全保存 | 世界 / 角色表单、完整时间线管理、草稿保护、备份可靠性、诊断 | 不写 JSON 也能创建自己的世界，出错能定位和恢复 |
| U3 辅助写作 | 大纲编辑、观察与依据、建议、候选决定、分支试演、文本保存与导出 | 从一个目标走到可带走的文字草稿，清楚哪些改变了世界 |
| U4 跑团 | 验证样例战役、规则选择、行动确认、受众面、主持准备、选择与恢复 | 新手可完成一轮有真实规则与持久后果的行动 |
| U5 总体验收 | 三条完整路径、跨工作区、冷启动 / 断线 / 故障 / 更新、无障碍、新手试用 | 达到用户要求的整体人机交互，而非仅具备开发验证入口 |

U2–U4 的界面可以基于已明确的边界分工，但它们依赖的能力补齐不能被“UI 阶段”这个名字掩盖。若发行时只完成部分入口，首页只承诺已可用范围，根 README 同步如实说明。

### 12.1 行为验收矩阵

| 场景 | 验收结果 |
|---|---|
| 干净账户第一次启动 | 仅按 README 安装并配置，进入样例；无需命令行、JSON 或 ID |
| 创建自己的世界 | 描述 / 编辑 → 校验定位 → 审定角色 → 创建 → 联络完整走通 |
| 重生成与中断 | 锁定内容不被覆盖，其他分区不误改；重开能找回已保存草稿 |
| 切世界 / 角色 / 时间线 | 标题、内容、写入目标一致，旧返回不污染新页；不会自动启停世界 |
| 联络转交 | 改世界 / 恢复 / 掷骰请求进入对应确认流程，原联络没有假执行回复 |
| 信息隔离 | OC 无世界内部浏览；玩家无主持材料；通知、错误、导出正文不旁路泄漏 |
| 写作完整链 | 目标 → 观察 → 建议 → 编辑并保存草稿 → 导出；仅存文本不改变世界 |
| 应用候选 | 采用、应用、结果未知与已生效可区分；冲突、过期和重试无重复事实 |
| 大纲更新与恢复 | 修改观察者不清进度；重复生成不覆盖已采用内容；恢复只报告依据缺失，状态由合法决定更新，正文保留 |
| 分支试演 | 新分支、来源版本与启动确认真实存在；原线不受试演污染，无合并承诺 |
| 跑团完整链 | 选择规则 → 角色绑定 → 场景 → 行动确认 → 裁定 → 提交 → 下一步选择可完成 |
| 跑团故障 | 插件中断、版本冲突与提交回执丢失分别恢复；无自动重掷、重复扣资源或半提交 |
| 版本与全量恢复 | 覆盖范围清楚，先保留副本；备份不完整时挡住完整恢复，失败范围不谎报 |
| AI 与存储失败 | 错误能定位到设置或任务；旧有效配置、草稿与最后完整数据得到保护 |
| 操作可访问性 | 键盘、输入法、读屏、放大与长文均不丢操作入口；只靠颜色的提示为不通过 |
| 新手试用 | 不口头指导，只给 README 与任务；能解释所在世界、当前状态、下一步和错误发生点 |

程序验证用真实桌面 → 管理 / 通道 → 应用层 → 核心 → SQLite / 规则进程链路；远程 AI 另做真实配置与输出能力验证。测试替身验证边界，不能代替真实 AI 能否工作；自动化不能代替新手可用性试用。

### 12.2 新手试用与新增边界验收

正式发布至少安排 3 位未使用过本项目、对 AI 配置不熟的试用者；只给 README、所需服务账户条件和任务，不口头带路。外部注册、购买额度与网络中断分别记录，不算产品可用性耗时，也不能代替产品步骤已通过。

每位完成样例联络、编辑并锁定一条设定、保存一份写作草稿、确认一次样例行动；再给错误配置、提交超时和版本恢复说明三种情境，要求指出问题发生处、实际保存状态与下一步。记录停住位置与误操作，出现需要解释内部 ID / JSON、误以为候选已发生或把恢复当导入，即不通过对应任务。修改后重测失败任务，不能以平均完成率掩盖数据损坏或信息泄漏。

自动化同时补充：输入期间保存回执倒序、重复创建、强制退出后的草稿恢复、正式设定不被坏候选覆盖、设置测试期间换模型、无 AI 的手工规则行动、暂停战役但世界仍运行、试演启动失败、迁移中断、完整备份缺件、全量恢复切换中断。每项断言真实产物与界面回读；测试输出、版本、使用的数据根与外部依赖状态一起记录，不能只拍一张成功页。

### 12.3 当前实现核验依据

草案核验阶段在隔离临时数据中运行样例世界、设置、OC 故事层、Writing Assistant、TRPG 客户端、编剧导出与备份的现有定向测试，结果 **54 passed**。相关测试走真实 WebSocket / SQLite，模型使用测试替身，部分跑团用例调用真实规则子进程。另核对现有桌面源码，未发现三个应用层的管理调用入口。

随后在临时数据上补做本节设计边界反例，复现了第 11.1 节列出的写作隔离、候选覆盖、提交状态与规则接入问题。因此，54 项通过不代表应用层已满足全部交付约束。没有新界面运行结果、完整发行安装验证、真实外部 AI 服务验证或普通用户试用结果。本轮是设计深化与定案，未修改业务代码；新向导、表单、诊断与工作区仍属本规范的待实施义务。上述读数来自草案核验阶段，不重复解释成新界面验收。

### 13.1 唯一责任与变更边界

| 决定 | 维护位置 | 其他文档如何引用 |
|---|---|---|
| 页面、命名、主操作、默认交互、跨页保存 | 本文 | 各应用层只链接，不另复制页面规范 |
| 安装、配置测试、诊断、备份与灾难恢复 | 配套文档 | 本文仅给入口；错误格式与恢复顺序只有一份 |
| OC 分类、表达、披露和会话规则 | OC 与会话规范 | 本文呈现其真实结果，不增加普通聊天写事实权限 |
| 大纲、候选、文本与作者决定 | Writing Assistant 规范 | UI 新需求在所属模块实现，不能用临时界面状态冒充持久业务结果 |

| 事实、时间、认知、版本与原子提交 | WorldRuntime 规范 | 不因新界面把作品、章节或规则字段放进底层世界模型 |

本版已确定所有面向用户的默认行为；没有留给实施者自行拍板的产品选择。具体文件组织、打包实现和窄接口形状在实现中按既有项目结构选择，不是未定案的用户体验。发现底层无法满足某条保证时，先修所属模块或明确提出规范变更，不能悄悄改文案降低验收标准。

设计版本独立于实现版本。完成某一阶段后只更新其真实完成状态与证据，不把“已定稿 v1.0”改写为“界面已完成”；下一次改变默认语义才修订设计版本。
