## 一、先立标准

### 1.1 优秀 UI 应该有的表现（可检验）

| 维度 | 可检验的判据 |
|---|---|
| **可读性** | 正文对比度 ≥ 4.5:1、大字与控件边界 ≥ 3:1；行高 ≥ 1.5；不用纯色靠颜色传语义；字号设置对**全部**界面生效（含浮层、弹窗、菜单） |
| **可扫读** | 一屏一眼能分出"我在哪 / 我能做什么 / 下一步是什么"；相关信息成组、无关信息分离（接近原则）；同类控件位置固定 |
| **不做记忆题** | 识别优于回忆：能在界面上看到可选值，不需要记住 id、编号、路径、上次说了什么 |
| **认知负担** | 一次决策的选项有分组、有推荐默认；长表单有分步或页内导航；不把与当前任务无关的选项摆在第一屏 |
| **可预期性** | 同一动作永远同一名字、同一位置；按钮文字描述**点击后会发生什么**，而不是当前状态；破坏性动作与普通动作在视觉与摩擦上有区分 |
| **反馈与控制** | 每个操作 ≤ 400ms 内有可见变化；长任务有进度与预期时长；用户能取消；危险动作可撤销或至少二次确认 |
| **容错** | 危险操作有与后果匹配的摩擦；普通操作不该被反复打断（确认疲劳会让用户盲点"确定"）；错误提示说清"哪一步、什么原因、已经完成了什么、下一步做什么" |
| **布局健壮** | **在应用自己的默认窗口尺寸下，主操作可见且不重叠**；窗口变化 / 字号放大时布局不崩；可点目标 ≥ 44×44（触控）或 ≥ 32×32（鼠标） |
| **无障碍** | 键盘可达全部功能；焦点可见、焦点不丢在浮层背后；浮层能 Esc 退出并有焦点回收；读屏有名称与语义 |
| **一致性** | 一套术语、一套配色语义、一套交互约定；平台惯例优先（Jakob 定律） |

### 1.2 「合法但有病」的 UI 长什么样

这类问题**语法合法、测试通过、代码评审看不出错**，但真实使用时会让人皱眉、点错、或者干脆用不下去。常见形态：

**A. 尺度类**
1. **断点失配**：响应式断点比应用自己的默认窗口还宽 → 开箱即用状态直接进"窄窗"分支。
2. **溢出不可见**：flex/grid 子项内容比容器高，而容器 `overflow: visible` → 内容压到相邻板块上；不报错、不滚动、只是叠在一起。
3. **主操作掉出折线**：发送、保存、下一步落在可视区之外，用户以为"没有这个按钮"。
4. **触控目标缩水**：主按钮 44px，旁边的小链接 36px、表格行内动作 38px，且没有间距保护 → 手一抖点错。
5. **粘性遮挡**：sticky 表头/分栏把内容压住，或滚动容器套滚动容器。

**B. 继承类**（最隐蔽）
6. **浮层脱离设计体系**：弹窗/菜单挂在 `document.body` 上，拿不到 `#root` 的字号与前景色 → 字号不跟随设置、深色主题下变成黑字黑底。
7. **硬编码颜色 + 只认系统深色**：应用里有显式主题开关，样式却写 `@media (prefers-color-scheme: dark)` → "系统浅色 + 应用深色"组合下白底白字。

**C. 语义类**
8. **一名两义**：按钮写"暂停 / 启动"，用户看不出点下去会发生哪个。
9. **同事不同名 / 同名不同事**：同一功能三四个叫法，或两个不同东西共用一个词。
10. **状态冒充事实**：界面写"已连接"其实早断了；写"已保存"其实是草稿。
11. **危险动作伪装成普通链接**：删除和打开长得一模一样，还是并排。
12. **数字无单位 / 内部标识外泄**：`129600000`、`draft-3f2a`、`world.institutions[0].holder` 直接上屏。
13. **术语自造**：把内部模型的名字（水位、固化、传本、裁定）当用户词用。

**D. 摩擦类**
14. **确认疲劳**：什么都弹确认 → 用户闭眼点"确定"，真正的危险动作也就失守了。
15. **反向摩擦**：危险操作零摩擦、普通操作高摩擦（丢弃草稿一键生效，删除世界却要键入名称——修反了）。
16. **无出路**：对话框只有"取消"；空态没有下一步；点了按钮什么都没发生。
17. **不可撤销且无预告**。

**E. 结构类**
18. **首屏塞入与当前任务无关的东西**（升级迁移、兼容说明、内部检查明细）。
19. **选项平铺无分组**：一页九个段落、没有目录，找一项要滚三屏。
20. **必备入口藏在"⋯"里**：设置、帮助、世界管理都靠一个图标。
21. **状态与动作混排**：标签页和"导入/从样例开始"排在同一行。

**F. 无障碍类**
22. **键盘死角**：菜单没有方向键、关掉后焦点不回到触发它的按钮、焦点能跑到浮层背后。
23. **颜色是唯一语义**。
24. **没有 `prefers-reduced-motion` 尊重**。

## 二、逐项筛查：本项目实测结果

先说结论：**功能语义层做得好，视觉与布局层有 3 个必须马上修的问题**，其中 1 个在**默认窗口 + 默认字号**下就会出现。
下面每条都给了真机读数。

### 🔴 P0-1 默认窗口下，联络页三栏互相重叠、发送按钮在视口外（主题无关、字号无关）

**反模式**：1（断点失配）+ 2（溢出不可见）+ 3（主操作掉出折线）

- 应用默认窗口是 **1080×720**（`desktop/src-tauri/tauri.conf.json:width/height`），
  而联络页堆叠布局的断点是 **`max-width: 1100px`**（`user.css:872`）——**默认窗口天生落在"窄窗"分支里**。
- 真机读数（深色、2026-10-08 发行件，实测 `window.innerWidth=1080`）：

| 元素 | 100%（默认字号） | 150% |
|---|---|---|
| `.u-col-center` 容器高 / 内容高 | **181px / 495px** | **151px / 610px** |
| `.u-col-center` 的 `overflow-y` | `visible`（不裁剪、不滚动） | `visible` |
| 输入框 `.u-contact-input` 位置 | y=611..703（父容器只到 472） | y=669..800 |
| **发送按钮** 位置 | **y=711..755（视口 720）→ 看不到** | **y=808..860 → 看不到** |
| `.u-col-left`（角色/这个世界） | 高 197px / 内容 239px（内部滚动条） | 197px / 251px |

- 机制：堆叠后 `.u-col-center { flex: 1 1 0 }` 只拿到"剩余高度"（181px），而它的固定子项
  （页头 + 输入区）本身就超过这个高度，容器又没有 `overflow` → 内容直接画到下一栏
  `.u-col-right`（"已讲过的线索"）上面。
- 视觉证据：`out8/contact-text100.png`（默认设置就重叠）、`out7/03-contact-dark-150.png`（150% 更严重）。

> 这是最值得记的一条：**所有 20 项 UI 探针都 PASS**——它们只验证"元素存在/文字对不对"，
> 不验证"看不看得见"。这就是"合法但有病"。

### 🔴 P0-2 深色主题下，顶栏是白底白字（对比度 1.12:1）

**反模式**：7（硬编码颜色 + 只认系统深色）

- 真机读数：`.u-topbar.u-topbar-focused` 背景 `rgb(255,255,255)`，标题文字 `rgb(242,242,242)`
  → **对比度 1.12:1**（WCAG AA 正文要 4.5:1）。
- 原因：`style-focused.css:39 background: white` 是写死的，深色覆盖写在
  `@media (prefers-color-scheme: dark)`（`:113-121`），而应用自己的主题是 `html[data-theme]`。
  本机系统是浅色（`AppsUseLightTheme=1`），用户在应用里选「深色」→ 变量变深、顶栏还是白 → 白底白字。
- 顶栏里放着：返回按钮、页面标题、后台状态、首页、⋯ —— 全是导航。
- 视觉证据：`out7/01-first-dark-150.png`（"返回角色联络　首次设置"几乎不可见）。
- 同类：`style-focused.css:62` 的 `#f5f5f5`、`:115-121` 的 `#1e1e1e/#444/#2a2a2a`。

### 🔴 P0-3 深色主题下，弹窗与 ⋯ 菜单是黑字深底，且不跟随字号设置

**反模式**：6（浮层脱离设计体系）

- 真机读数：

| 浮层 | 字号（设置=150% 时） | 前景/背景 | 对比度 |
|---|---|---|---|
| `.u-dialog`（弹窗） | **16px 固定**（页面是 24px） | `rgb(0,0,0)` / `rgb(18,18,18)` | **1.12:1** |
| `.u-dialog-title` | 18.72px | 黑 / 深 | ≈1.1:1 |
| `.u-more-menu-item`（⋯ 菜单） | **14px 固定** | `rgb(0,0,0)` / `rgb(31,31,31)` | **1.27:1** |
| `body`（浮层继承来源） | 16px | — | — |

- 原因：`dialog()` / `showMoreMenu()` 把浮层 `appendChild(document.body)`，而
  `font-size: var(--u-font-size)` 与 `color: var(--u-fg)` 只写在 `#user-root.u-app`（`user.css:65-69`）。
  于是浮层：① 字号永远是浏览器默认；② 深色底用的是主题变量、文字色却回落到浏览器默认的黑色。
- 影响面很大：**全项目 30 处 `dialog(` 调用**（`worlds.ts` 13、`writing.ts` 6、`create.ts` 4、
  `trpg.ts` 4、`contact.ts` 2、`migrate.ts` 1），加上 ⋯ 菜单、启动器浮层（启动器已单独修过字号）。
- 视觉证据：`out7/05-dialog-dark-150.png`（"删除世界「灰潮纪」？"正文几乎读不出来）。

- `settings.ts` 用 7 个 `section(...)` 依次拼成一个页面，加上嵌入的迁移卡与扩展块，
  界面上共 **9 个平级标题**：AI 服务 / 记忆检索 / 自动保存版本 / 数据与备份 /
  从旧的开发目录迁移 / 用量 / 世界 / 通知与外观 / 扩展（含跑团规则）。
- 没有页内锚点、没有分组标题、没有折叠。凭"按钮小很多状态"这个诉求进来的人要滚 3 屏才到"数据与备份"。
- 首页"现在配置"直达 AI 段是好的，但设置页整体仍是一根长条。

### 已经做对的部分（同样是"优秀 UI"的判据，别改坏）

- **按钮一律动作名**，没有「确定/取消」这类空话（`dom.ts:186-189`）。
- **没有假按钮**：未实现的入口如实标注，不摆可点空壳。
- **错误卡四要素**（对象 / 直接原因 / 已完成范围 / 下一步 + 可折叠技术详情）。
- **不强制拉到底**：不在底部时给「有新消息 ↓」；读屏只播报摘要。
- **危险动作有匹配摩擦**：删除世界/世界线要键入名称；恢复要"先保存当前进展"。
- **空态与读取失败分开**；可行动失败升级为错误卡带动作（2026-10-08 修复后）。
- **关键控件够大**：主按钮 `min-height: 44px`、focus-visible 2px 描边、字号 100/125/150 三档。
- **尊重 `prefers-reduced-motion`**（启动器浮层）。
- **术语与标点已统一**（2026-10-08：实例→世界、水位→进度、时间线→世界线…）。

## 三、建议（按投入产出排序）

1. **修断点与溢出（P0-1，改 3 行 CSS 就能救）**
   - 把 `@media (max-width: 1100px)` 的阈值降到 **900px**（默认 1080 窗口就不再进窄窗分支）；
   - 堆叠时让整页滚动：`.u-contact { height: auto; overflow-y: auto }`，并给 `.u-col-center { min-height: 60vh }`
     （不要让它去分"剩余高度"）；
   - 或者保留堆叠，但把输入区做成 `position: sticky; bottom: 0`，保证发送永远可见。
2. **修浮层继承（P0-2/P0-3，改 CSS 一个区块）**
   - 顶栏背景改 `var(--u-bg)`，删掉 `style-focused.css` 里只认系统深色的那一段；
   - 给 body 级浮层补一句：`.u-dialog, .u-more-menu, .u-launcher { color: var(--u-fg); font-size: var(--u-font-size) }`
     （或给它们加 `.u-app` 类，直接继承整套变量）。
3. **首屏把迁移卡收起来**：折叠成「已有旧版本的数据？」，或只在"设置 → 数据与备份"里出现。
4. **危险动作与普通动作分开**：`删除` 改红色/加间距/二次确认样式，行内动作最小高度提到 44px。
5. **设置页加分组与页内索引**（或拆成"AI / 数据 / 外观与通知 / 扩展"四个子页）。
6. **菜单与状态按钮收口**：⋯ 菜单加方向键与焦点回收；「暂停 / 启动」改成按当前状态命名的单义按钮
   （如「暂停这条世界线」/「启动这条世界线」）。
