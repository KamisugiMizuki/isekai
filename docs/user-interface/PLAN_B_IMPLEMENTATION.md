## 工作原理

```
启动 → 首页（枢纽：三块任务入口 + 继续上次）
                    ↓ 从首页卡片 / ⋯ 菜单 / 世界详情进
        工作区（角色联络 / 辅助写作 / 跑团）
                    ↓ 左上角「← 返回首页」回枢纽
                    ↑ 右上角 [⋯] → 首页/角色联络/辅助写作/跑团/世界管理/设置/帮助与诊断
```

2026-10-08 二次修订（删掉「选择应用」浮层）：

- **浮层删除**。它是「一个窗口只服务一个应用」那个模型的入口（`launcher.ts` 头注释），
  而现在的结构是**一个壳 + 首页当枢纽**：首页已经有同样的三块入口，浮层只是把用户从页面上
  挡住再问一遍同样的问题；首启顺序调整（可用性评审 P0-2）之后它也早已不在首屏。
- **层级改直连**：三个工作区与首页的上一级关系从「选择器」改成 **工作区 → 首页**，
  顶栏写「← 返回首页」；**首页是枢纽，不出返回键**（不再有指向自己的「返回首页」）。
  其余页面（设置 / 帮助与诊断 / 世界管理 / 首次设置 / 创建世界）照旧挂在当前工作区下。
- **切换入口**：⋯ 菜单第一组补「角色联络 / 辅助写作 / 跑团」三项，与首页卡片同一套去处，
  从任何页面都能一步进工作区，不再经浮层中转。
- **「当前应用」改为隐式维护**：`app_mode` 不再由用户选，而是在**真的走进工作区时**记下
  （`open()` 里只在值变化时写一次），顶栏归属、子页面返回去处、首次设置「选择第一件事」
  的默认值仍读它；`app_launched_at` 与「5 秒内不打扰」守卫随浮层一起删除。
- **样式与代码清理**：删除 `launcher.ts`、`style-launcher.css` 与 `index.html` 的引用。

2026-09-24 修订（真壳实测后）：

- 左上角按钮不再是一个看不出用途的 emoji，而是写清楚去处的返回键：
  **应用三页（联络 / 写作 / 跑团）与首页**的上一级是选择器（「← 返回选择应用」）；
  **设置 / 帮助与诊断 / 世界管理 / 首次设置 / 创建世界**挂在当前应用下（「← 返回辅助写作」，点它回应用根）。
- [⋯] 菜单补「首页」：方案 B 删掉侧栏后首页失去了唯一入口，而「未完成内容 / 本机状态」都在那一页。
- 启动器里「刚选过（<5 秒）不打扰」的守卫只作用于**启动时的自动弹窗**：用户自己点返回是明确意图，不能被它吞掉。
