# isekai 普通 OC 用户视角评价草案

> 方案 A：持续生活的 OC 故事世界
>
> 状态：评价草案，不是产品规范；用于判断普通 OC 用户需要什么，以及 WorldRuntime 应向故事层暴露什么。
> 评价对象：不熟悉 AI 和世界模拟概念，只想创建自创世界与 OC，并通过持续对话慢慢认识其生活的用户。
> 与 TRPG 方案的区别：用户是世界外的联络者和观测者，不扮演玩家角色，不声明行动，不要求每轮由规则裁定成败。

## 一、方案选择

这个方案的核心不是“让模型写得更像小说”，而是让用户相信：

> 她不在聊天时也有自己的生活；我每次联系她，接触到的是她当下愿意让我知道的一小部分。

用户体验应当是探访一个持续运行的世界，而不是启动一局游戏。

因此，故事层优先解决四个问题：

1. 世界是否在用户离线时继续运行；
2. 角色是否只使用自己已经接触到的信息；
3. 经历能否跨轮形成连续但不强行收束的故事；
4. 角色是否有权沉默、保留、误解或改变主意。

不把规则骰点、玩家回合、胜负条件和任务清单塞进这个方案。那是 TRPG 方案的职责。

## 二、用户得到的产品

### 2.1 首次进入

用户只需要完成三件事：

1. 描述世界的基调、范围和想创建的角色；
2. 确认生成的世界与角色设定；
3. 开始第一次联络。

“世界包”“实例”“时间线”“倍率”等概念可以保留在高级管理面，但首次流程不要求用户理解它们。系统在后台创建一个已锁定的生活实例，并为用户准备可继续联络的角色。

### 2.2 日常使用

用户看到的是角色对话、角色主动联系、少量自然的生活迹象，以及必要的创作反馈。用户可以：

- 问角色最近在做什么；
- 分享现实中的想法或新信息；
- 追问某个已经提过的话题；
- 请求认识另一个角色；
- 让角色知道一件事，但不能直接改写世界真值；
- 在高级模式中保存、分叉或回到某个创作版本。

用户不需要浏览事件表、记忆表、认知表或内部评分。

### 2.3 用户应该感知到的差异

同一句问题，在不同时间、对不同角色提出，可能得到不同回答，因为：

- 角色经历不同；
- 角色获知的说法不同；
- 角色对同一说法的确信不同；
- 角色当前正在做的事不同；
- 角色此刻愿不愿意谈不同。

这不是模型随机性，而是世界运行、认知边界和表达取舍共同产生的结果。

## 三、故事层与 WorldRuntime 的分工

故事层是表达中介，不是第二个世界内核。

```text
WorldRuntime
  -> 世界时刻、角色处境、事件、后果、经历、获知、可见说法
  -> 角色认知过滤与记忆召回
  -> 故事层：候选、回接、有限编织、表达取舍
  -> 会话层：生成、后验检查、固化、投递
  -> 用户看到角色的表达
```

### 3.1 WorldRuntime 需要提供的最小只读面

故事层只需要能够取得一份一致水位的角色视图：

| 视图 | 故事层要知道什么 | 不应暴露什么 |
|---|---|---|
| 当前处境 | 当前活动、已生效后果、角色是否能行动 | 未发生的计划、幕后原因 |
| 经历 | 角色实际经历过的事件与结果 | 其他角色未授权的经历 |
| 获知 | 角色听到或观察到的说法、来源、时间、确信 | 尚未获知的实情 |
| 未竟之事 | 角色自己的打算、阻碍、等待和改变 | 强制完成义务 |
| 近期对话 | 合法的共同指涉和已经说过的内容 | 其他会话的私密内容 |
| 运行状态 | 水位、时间线状态、成员资格、世代 | 内部数据库与实现细节 |

### 3.2 故事层可以返回什么

故事层返回的是派生表达材料，而不是消息和事实：

- 可考虑讲述的主题；
- 材料之间的补充、对照、连续或未知关系；
- 角色当前想分享、想求意见、想确认、想保留或暂不确定的范围；
- 必须保留的来源身份、时间距离和不确定性；
- 本轮是否适合主动提起；
- 已讲述单元与引用材料的消费记录。

故事层不得直接：

- 创建事件或效果；
- 改写角色卡、公理、制度或历法；
- 将候选变成记忆事实；
- 向通道发送消息；
- 用戏剧性填补未知因果。

## 四、故事体验的核心设计

### 4.1 角色生活优先

用户没有发消息时，世界仍按既定时间和事件规则推进。角色的活动、事件和后果可以形成素材，但“不发消息”也是合法结果。

主动消息必须同时满足：

- 角色在该水位有合法可见材料；
- 材料仍有表达价值；
- 角色当前状态允许表达；
- 没有违反睡眠、归档、配额和投递约束；
- 生成内容通过来源、时间、范围和处境检查。

没有合适素材时，系统不为了活跃度硬编一段剧情。

### 4.2 有限编织

多个经历只有在存在共同指涉或明确关系时才可组织成一个故事单元。允许：

- 把连续几次活动说成“最近一直在处理某件事”；
- 回接用户和角色此前已经谈过的话题；
- 并列呈现互相矛盾的传闻；
- 保留一个角色无法解释的空白；
- 只讲入口、局部结果或仍在进行的部分。

禁止：

- 为了戏剧性新增责任人、秘密、动机或结局；
- 把同时发生写成因果；
- 把听说写成亲眼见过；
- 把未来计划写成已经发生；
- 把漂亮的生成文本反写成世界事实。

### 4.3 角色拥有表达取舍

角色可以：

- 主动分享；
- 只讲一部分；
- 先问用户是否愿意听；
- 明确表示不想谈；
- 暂时没有合适的话题；
- 以猜测、转述或犹豫表达；
- 在新的经历出现后改变原来的看法。

重复追问不自动提高权限，也不应把角色的沉默解释成系统故障。

### 4.4 创作者反馈不等于内部面板

用户需要知道设定是否生效，但不需要看到数据库。建议提供自然语言级反馈：

- “她最近确实经历了和港口封锁有关的事。”
- “她听说过北岸的消息，但还不确定真假。”
- “这个世界最近没有适合她主动提起的新进展。”
- “你上次告诉她的内容被记作你的说法，不会直接改成世界事实。”

反馈必须来自当前角色视图和已完成水位，不泄漏未获知真相。

## 五、版本、回滚与用户心理

普通 OC 用户把回滚理解为创作保存点，而不是游戏中的死亡重试。

产品应提供两种清晰语义：

- **保留分支**：从旧提交创建另一条生活线，原线仍保留；
- **恢复版本**：当前线回到旧状态，之后的故事不再属于当前线。

高级操作需要说明：已经投递到外部通道的消息无法被现实世界撤回。日常界面不应把回滚按钮放在普通聊天操作旁边，以免用户误把持续生活当成可随时重写的草稿。

## 六、验收标准

普通用户视角下，方案 A 只有满足以下条件才算成立：

1. 用户离线后，世界仍能按一致规则推进；
2. 角色不会引用自己尚未获知的事件、未来计划或幕后真相；
3. 不同角色对同一世界可以保留不同认知；
4. 连续经历可以形成可追溯的局部故事，但没有依据时保持并列或未知；
5. 主动消息失败不会撤销已经发生的经历，也不会重复消费素材；
6. 角色可以不主动说、不想说、只说一部分或说错；
7. 用户的输入不会绕过世界事件与认知边界直接改写事实；
8. 回滚和分叉不会把另一条线的未来混回当前线；
9. 故事层不会创建新的世界事实；
10. 用户能通过自然表达理解“发生了什么、她知道什么、她愿意说什么”的区别；
11. 没有新故事时，系统能安静地返回，而不是生成填充剧情；
12. 真实模型生成失败时，系统仍能给出不新增事实的保守表达。

## 七、用户旅程与体验契约

### 7.1 第一次使用：先遇见角色，再理解系统

普通用户第一次进入时，不应先面对世界包、实例、时间线、倍率和认知接口。推荐的体验顺序是：

```text
描述想要的世界与角色
  -> 查看并修改生成结果
  -> 确认「这是一个会继续运行的世界」
  -> 进入第一次联络
  -> 在对话中逐渐发现她的生活
```

首次流程必须让用户理解三件事，但不要求理解内部术语：

- 角色不是只在用户发消息时才存在；
- 用户告诉角色的话，会先成为角色听到的内容，不会自动成为世界事实；
- 角色有不知道、不愿说和说错的可能。

如果用户在第一次对话中就必须学习时间线、提交、认知和事件的区别，说明产品把内部管理模型泄漏到了入口。

### 7.2 持续使用：用户是在拜访，不是在打卡

一次联络应有明确但轻量的心理模型：

```text
打开会话
  -> 看到她此刻的状态与回应
  -> 可以追问、补充或换一个话题
  -> 记住一个可回访的线索
  -> 下次回来时发现世界已经过了一段时间
```

系统不需要每次都提供新剧情。平淡的一天、角色不想展开、只回接旧话题，和一段新经历一样都是有效结果。产品不应以未读数、每日故事数或连续签到把用户推回“必须消费内容”的游戏化节奏。

### 7.3 用户的四种输入及其含义

| 用户动作 | 角色 / 世界应如何理解 | 不应发生的事 |
|---|---|---|
| 分享现实信息 | 角色获得一条带来源的联络内容 | 直接改写世界公共事实 |
| 询问近况 | 从当前角色视图回答，必要时承认不知道 | 从幕后实情拼出全知答案 |
| 追问旧话题 | 回接已说过或已知的片段 | 重复追问自动解锁保留内容 |
| 请求改变世界 | 转为明确的创作 / 世界事件操作 | 把普通聊天里的愿望静默写进世界 |

这一张表是普通 OC 方案和 TRPG 方案的关键分界：这里用户是在提供信息、询问和联络，不是在声明一个需要裁定的世界内行动。

### 7.4 用户可感知的反馈，而不是内部状态面板

用户需要能够判断“她为什么这样回答”，但不需要看到分数、候选池或认知表。可见反馈应落在三种自然表达上：

- **来源反馈**：她亲历、听说、观察到，或只是自己的猜测；
- **时间反馈**：刚发生、最近一直在处理、已经过去一阵，或尚未发生；
- **意愿反馈**：她愿意讲、只想讲一部分、想先听用户意见，或现在不想谈。

这些反馈应嵌在角色表达中。只有发生创作操作、导入失败、版本冲突或世界停止推进时，才需要在管理面用明确的产品语言说明原因。

## 八、失败体验与降级语义

普通 OC 产品最危险的失败不是“少讲一件故事”，而是让用户误以为世界发生了本不存在的事。因此降级优先级应是：

1. 保住已固化的世界事实和角色认知边界；
2. 保住已发生经历，即使表达任务失败；
3. 给出不新增事实的自然回应；
4. 延后可选的故事组织和主动表达。

| 情况 | 用户应该看到什么 | 不能用什么掩盖 |
|---|---|---|
| 没有可分享材料 | 平淡回应、当前活动或诚实的“没什么可说” | 临时编一件新鲜事件 |
| 叙事编织失败 | 分开讲片段，或只讲确定部分 | 把未知因果补成完整剧情 |
| 模型不可用 | 保守模板或明确暂缓 | 假装角色完成了复杂表达 |
| 世界正在追赶 | 等待、状态提示或只读历史 | 把目标时刻当成已发生 |
| 角色不知道 | 承认未知、给出有限猜测 | 读取幕后真相代答 |
| 用户要求改写既有事实 | 引导到创作 / 分支操作 | 在普通聊天中暗改原线 |

用户不应因为一次生成失败而失去经历、重复收到同一主动消息，或看到一条后来无法解释来源的“补发剧情”。

## 九、方案 A 的取舍与明确边界

### 9.1 方案 A 选择的价值

方案 A 把主要成本放在世界连续性、认知边界、经历回接和表达取舍上。它换来的不是每轮更热闹，而是用户在数天或数周后仍能相信：角色有自己的时间、关系和局部理解。

### 9.2 方案 A 有意放弃的东西

方案 A 不承诺：

- 用户可以控制角色做任何事；
- 每次选择都有成功或失败结果；
- 每个世界事件都能被用户直接查看；
- 每次对话都推进一条可命名主线；
- 角色必须回应用户的所有追问；
- 用户可以通过回滚反复试验并保留最佳结果。

这些不是“以后顺手加上”的细节，而是会改变用户位置的产品决策。加入玩家角色、行动风险和规则裁定后，产品就进入 TRPG 方案，而不是继续增强普通 OC 方案。

### 9.3 与 TRPG 方案的共享与隔离

| 能力 | 普通 OC 方案 | TRPG 方案 |
|---|---|---|
| 世界事实、时间、事件、后果 | 共享世界运行基础 | 共享世界运行基础 |
| 角色认知与说法 | 角色局部视角 | 玩家 / NPC / GM 多层视角 |
| 用户身份 | 世界外联络者 | 玩家或玩家队伍的行动者 |
| 输入含义 | 分享、询问、追问、创作请求 | 行动声明、目标、风险承担 |
| 结果形态 | 角色表达与可回访线索 | 规则裁定、效果、后果与新局面 |
| 叙事层位置 | 表达生活素材 | 表达已裁定结果 |
| 回滚意义 | 创作版本恢复 / 分支 | GM 调试、战役分支或明确重试 |

共享的是事实底座和认知纪律，不共享用户身份、行动语义、结果提交和回合推进。

## 十、体验验收场景

除了 §六 的不变式，方案 A 至少要用以下连续场景判断是否成立：

1. **离线回访**：用户离开一段时间后回来，角色能基于已完成水位表达新的处境；没有合适材料时可以平淡，不强行制造剧情。
2. **同世界不同角色**：两个角色面对同一事件给出不同但各自有来源的说法，互不自动共享私聊内容。
3. **连续追问**：用户追问一个角色暂时保留的话题，角色可以继续保留或只扩大已允许的部分，不能因重复提问越权。
4. **模型失败恢复**：世界推进和经历固化成功，但叙事生成失败；恢复后不丢经历、不重复消费、不把补发内容伪装成刚发生。
5. **用户误传信息**：用户告诉角色一个错误说法，角色可以把它当作联络内容或形成误解；系统不把它静默写成公共真相。
6. **分支隔离**：从旧提交创建分支后，两条线分别继续推进；一条线后来形成的表达和选择不会回流另一条线。
7. **平淡日**：连续一段时间没有可分享故事时，系统保持安静或自然闲聊，不出现每日配额式剧情。

这些场景观察的是用户能否形成正确心理模型，而不只是检查某个字段或某次回复是否成功。

## 十一、结论与实现优先级

方案 A 的核心价值是“角色像一个有自己生活的人”。因此 WorldRuntime 应优先稳定以下边界：

1. 一致水位的角色可见视图；
2. 事件、经历、获知、后果和角色打算的统一来源；
3. 叙事候选与故事单元的派生语义；
4. 生成后的来源、时间和认知后验检查；
5. 面向普通用户的创作向导与自然语言反馈。

不应为了让故事更热闹而向 WorldRuntime 增加剧情规划器、好感数值或用户可见的故事评分。那会把表达问题重新污染成世界真值问题。

最终产品定位：

> 一个持续运行的 OC 世界。用户通过与角色联络，逐步认识她经历过什么、知道什么，以及她愿意告诉自己的部分。
