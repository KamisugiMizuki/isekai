## 一、定位

OC 故事层是面向普通创作者的应用层。它把 WorldRuntime 已经提供的世界时刻、角色视图、会话、记忆与叙事材料编排成“持续联络一个生活中的角色”的产品体验。

它不拥有世界真值，也不实现第二套会话核心或叙事中介。WorldRuntime 负责事实、认知边界、消息固化和叙事候选；OC 故事层负责低门槛入口、联络语义、用户可见反馈与创作操作编排。

核心体验：

> 用户在世界外拜访角色，逐步认识她经历过什么、知道什么，以及她愿意告诉自己的部分。

## 二、用户位置与输入语义

用户默认不是世界成员，也不是玩家角色。用户输入按以下主类别解释；主类别一旦确定，后续只能进入该类别的处理路径：

| 输入 | 处理语义 | 禁止结果 |
|---|---|---|
| 分享现实信息 | 作为用户向角色传达的联络内容 | 直接成为公共世界事实 |
| 询问近况 | 请求当前角色视图的表达 | 读取角色未知的实情 |
| 追问旧话题 | 回接已说过或已获知的内容 | 重复追问自动扩大权限 |
| 请求改变世界 | 转入明确的创作 / 世界事件流程 | 在普通聊天中静默改写原线 |
| 版本操作 | 分支、恢复、导入或导出创作状态 | 把回滚当成普通聊天重试 |
| TRPG 行动 | 转入玩家行动、裁定与场景流程 | 在 OC 会话内猜骰点或生成行动结果 |

普通聊天中的“我希望这里发生……”是用户表达愿望，不是已确认的世界事件。改变世界必须进入独立、可确认、可追溯的管理流程。

## 三、模块边界

### 3.1 上游消费

OC 故事层只消费以下核心能力：

- 一致水位的实例、时间线和角色视图；
- 角色合法可见的经历、获知说法、当前处境和记忆；
- 会话创建、绑定、历史读取、消息提交和投递状态；
- 叙事候选、有限编织、表达取舍和后验审计；
- 提交、分叉、回滚和实例 / 时间线管理语义。

### 3.2 本层负责

- 首次创作向导与第一次联络入口；
- 以角色、世界、时间线为中心的普通用户导航；
- 把用户输入归类为联络、询问、追问或创作请求；
- 将核心错误翻译为用户可理解的产品状态；
- 展示角色表达、世界时刻和必要的创作反馈；
- 引导用户保存分支、恢复版本或进入世界事件操作；
- 保持普通 OC 体验不暴露事件表、记忆表、认知表和内部评分。

### 3.3 本层不得负责

- 创建事件、效果、计划、公理、制度或角色卡事实；
- 绕过会话核心直接写消息或直接向通道投递；
- 把候选、模型文本或用户愿望写成世界事实；
- 为了活跃度生成每日剧情或补发错过的主动消息；
- 增加好感、信任、关系或故事质量等平行真值；
- 把 TRPG 的玩家角色、骰点、回合和失败裁定混入普通联络。

### 3.4 输入分类与唯一处理路径

OC 故事层必须在进入生成前确定输入类别。自然语言可以由模型辅助分类，但分类结果不能改变权限；无法确定时按“联络内容”处理，并保留为角色听到的原文。

| 输入类别 | 角色 / 世界语义 | 允许的写入 | 禁止的解释 |
|---|---|---|---|
| 联络分享 | 用户把信息、感受或愿望告诉角色 | 由会话核心固化为角色收到的入站内容 | 直接改公共事实、替角色决定行动 |
| 近况询问 | 请求角色按当前合法视图回答 | 只写会话消息与记忆任务 | 读取实情、把未知填成答案 |
| 旧话题追问 | 回接已有共同指涉 | 只写会话消息与合法表达取舍 | 因重复提问提升权限 |
| 请求改变世界 | 用户明确要求创作或世界变化 | 进入独立的 preview → commit 流程 | 在普通轮次旁路写事件 |
| 版本操作 | 分支、恢复、导出或导入 | 进入管理操作 | 把回滚当成普通聊天重试 |
| TRPG 行动 | 玩家身份、行动目标与风险承担 | 转入 TRPG 规则层 | 在 OC 会话内猜骰点或生成行动结果 |

一次请求只能有一个主类别。生成过程中发现它其实是“请求改变世界”或“TRPG 行动”时，当前轮次停在澄清 / 转交状态，不先发送一条假装已经执行的角色回复。

### 3.5 调用作用域与返回类型

每轮读取和写入都绑定 `instance_id`、`timeline_id`、`character_id`、会话绑定和已完成的 `observed_revision` / `runtime_generation`。用户当前打开的角色或界面缓存只是展示状态，不能替代这些作用域字段。

本层向会话核心提供“场景意图 + 角色视角”，不提供事实文本。会话核心返回的产品结果只有以下几类：

- `expressed`：回复已由会话核心固化，是否送达另由投递状态表示；
- `waiting`：世界追赶、存储恢复或用户需要补充选择，当前轮没有新增事实；
- `blocked`：版本、成员资格或持久化闸门阻止继续；
- `deferred`：没有合适素材、角色暂缓或生成任务延后；
- `handoff`：明确转入创作 / 世界修改 / TRPG 流程。

`expressed` 只表示消息固化成功，不暗示用户已看到，也不暗示角色说出的内容成为世界公共事实。

## 四、体验流程

### 4.1 首次进入

```text
描述世界与角色
  -> 查看 / 修改生成结果
  -> 确认设定
  -> 创建锁定实例
  -> 选择第一次联络的角色
  -> 进入会话
```

首次流程必须让用户理解三件事：角色在离线时仍生活；用户告诉角色的话先是角色听到的内容；角色可以不知道、不愿说或说错。内部术语不应成为必经步骤。

### 4.2 日常联络

```text
打开角色会话
  -> 读取当前合法历史与角色视图
  -> 用户询问、分享或追问
  -> 会话核心生成并固化回复
  -> 角色表达当前知道什么、愿意说什么
  -> 留下可回访的线索
```

没有新故事时，平淡回答、回接旧话题或自然沉默都是合法结果。产品不设置每日故事数、连续签到或未读压力来替代真实素材。

### 4.3 离线回访

用户离开后，世界按 WorldRuntime 规则推进。重新进入时只能使用已经完成的水位；追赶中不得把目标时刻冒充为已完成事实。错过的主动表达不自动集中补发，素材是否仍值得讲由核心重新判断。

### 4.4 产品状态与底层状态的映射

OC 层不复制会话核心状态机，只把底层结果翻译为用户能理解的产品状态。一个产品轮次只允许显示一个主状态，投递结果作为附加状态显示。

| OC 产品状态 | 进入条件 | 用户可做的事 | 不得暗示 |
|---|---|---|---|
| 准备中 | 首次实例、角色或视图尚未就绪 | 等待、修改创作输入 | 角色已经生活在完整世界里 |
| 可联络 | 角色视图与会话绑定有效 | 分享、询问、追问 | 当前一定有新故事 |
| 世界追赶中 | 目标水位尚未完成 | 等待或查看已完成历史 | 目标时刻已经发生 |
| 生成中 | 会话核心已受理当前轮 | 等待、取消仍可取消的本地操作 | 回复已经固化 |
| 已表达 | 回复已固化 | 查看投递状态、继续联络 | 通道已经送达或世界事实已改变 |
| 暂缓 | 没有合适素材、角色暂不想讲或可选叙事延后 | 继续普通联络 | 系统丢失了一个必达剧情 |
| 需转交 | 输入属于创作、世界修改或 TRPG | 打开对应流程 | 普通聊天已执行了请求 |
| 被阻断 | 版本、成员资格、持久化或实例状态不允许继续 | 查看原因、恢复或导出 | 可以靠重试绕过闸门 |

底层 `queued`、`processing`、`fixed`、`accepted`、`failed` 等状态仍保留在会话 / 投递层；OC 层只消费其公开投影，不重新定义成功语义。

## 五、故事表达契约

OC 故事层向会话核心提供的是用户场景和联络意图，不直接提供事实文本。会话核心从角色视图与叙事中介取得表达材料。

角色表达至少要让用户能够区分：

- 这是角色亲历、观察、听说还是猜测；
- 事情刚发生、持续了一段时间还是尚未发生；
- 角色愿意完整讲、只讲一部分、暂缓还是明确不想谈。

角色可以改变看法，但必须有新的经历、获知、处境或对话依据。重复追问不自动解锁保留内容。

## 六、用户可见面与黑箱边界

### 6.1 默认可见

- 当前角色、世界和会话名称；
- 已完成的世界时刻，且明确现实时间 / 世界时间；
- 角色消息及其正常投递状态；
- 创作、导入、版本冲突和世界停止推进等必要反馈；
- 高级模式中的提交、分支和恢复操作。

### 6.2 默认不可见

- 实情层和未获知事件；
- 事件生成表、角色记忆表、认知条目和内部评分；
- 候选池、分享分数、后验审计细节；
- 模型 prompt、规则内部字段和数据库结构。

用户需要理解角色为何这样说时，优先通过角色自然表达来源、时间和意愿，不打开内部报表。

## 七、失败与降级

失败处理按以下顺序保留用户信任：

1. 不损坏已固化事实、经历和认知边界；
2. 不重复消费或重复投递同一素材；
3. 生成失败时给出不新增事实的保守表达；
4. 延后可选的叙事编织与主动表达；
5. 明确区分模型失败、世界追赶、存储失败、通道失败和版本阻断。

| 情况 | OC 故事层表现 |
|---|---|
| 没有可分享材料 | 平淡回应、回接旧话题或诚实说明暂无进展 |
| 叙事生成失败 | 分开表达确定片段，不补造因果 |
| 世界追赶中 | 显示追赶状态，禁止发起依赖未完成水位的新轮次 |
| 角色不知道 | 让角色承认未知或有限猜测 |
| 版本恢复 | 明确当前线被覆盖，已投递外部消息不保证撤回 |
| 用户要求改写事实 | 引导到创作 / 世界事件流程 |

## 八、版本与创作操作

普通用户需要两种清晰语义：

- **保留分支**：从旧提交创建另一条生活线，原线继续保留；
- **恢复版本**：当前线回到旧提交，之后的故事不再属于当前线。

日常聊天界面不放破坏性回滚入口。执行恢复前必须说明覆盖范围，并先提供保存当前进展为分支或导出的路径。OC 故事层只编排操作，不自行复制、合并或修补运行状态。

## 九、跨角色体验

同一世界的不同角色可以对同一事件拥有不同经历、说法和确信。角色之间默认隔离；用户主动披露仍须经过既有授权流程，不能因为用户同时打开两个会话就自动共享内容。

普通 OC 层把跨角色体验呈现为“认识不同的人”，而不是展示一张全局关系或知识图谱。

## 十、与 TRPG 方案的隔离

| 维度 | OC 故事层 | TRPG 规则层 |
|---|---|---|
| 用户身份 | 世界外联络者 | 玩家 / 队伍行动者 |
| 输入含义 | 分享、询问、追问、创作请求 | 行动声明、目标与风险承担 |
| 结果 | 角色表达与可回访线索 | 裁定、效果、后果与新局面 |
| 核心节奏 | 联络与生活时间 | 场景、行动与回合 |
| 失败语义 | 保守表达、暂缓、不新增事实 | 失败等级、代价、风险和状态改变 |

两者可以共享 WorldRuntime 和会话 / 叙事基础设施，但不能共享同一条输入解释路径。

## 十一、设计不变式

1. OC 故事层永远不拥有世界真值。
2. 普通聊天永远不等于世界事件确认。
3. 角色表达只来自其当前合法视图和已固化对话。
4. 没有新素材时，安静或平淡优先于填充剧情。
5. 主动消息失败不撤销经历，也不重复消费素材。
6. 回滚和分支不能把另一条线的未来带回当前线。
7. 用户看见的是角色表达与必要操作反馈，不是内部数据面板。
8. 加入玩家行动、骰点、回合和结果裁定后，应转入 TRPG 规则层，不在本层加补丁。

## 十二、行为验收

| 场景 | 必须观察到的结果 |
|---|---|
| 首次创作与第一次联络 | 用户无需理解实例、时间线和认知接口即可完成；失败时停在准备 / 修订状态，不生成假角色回复 |
| 普通分享 | 入站消息固化为角色收到的联络内容；世界公共事实、事件和效果数量不因分享自动增加 |
| 近况询问 | 回复只来自当前已完成水位和角色合法视图；未获知事件、未来计划和实情不进入回复 |
| 同一话题重复追问 | 角色保持既有完整讲述 / 暂缓 / 拒绝边界，不按次数扩大权限 |
| 请求改变世界 | 普通轮次返回 `handoff` 或澄清；只有显式 preview → commit 成功后才出现世界变化 |
| TRPG 行动文本 | 转入 TRPG 入口，不在 OC 会话中生成骰点、成功或失败结论 |
| 离线回访 | 只使用已完成水位；追赶中不把目标水位冒充已发生；错过主动消息不批量补发 |
| 叙事生成失败 | 已发生经历与获知保留；回复降级为保守表达或暂缓；不重复消费素材 |
| 投递失败 / unknown | 固化状态与投递状态分开；不把未确认送达说成成功，不重新生成同一回复 |
| 同世界不同角色 | 相同事件可产生不同合法表达；角色之间不自动共享对话、私密认知或记忆 |
| 分支与恢复 | 分支后未来不回流；回滚前有明确覆盖提示；外部已投递内容不宣称可撤回 |
| 世界冻结 / 版本阻断 | 只读或显示可操作恢复入口；不靠普通重试绕过阻断 |

以上场景必须通过真实会话核心、真实 WorldRuntime 接口和真实持久化链路验收；设计文本本身不算实现证据。
